# C3 delivery budget: post-K2 exploratory arithmetic

This proposal was developed after the K2 compile-cap refusals and is not an
independent preregistration, new scientific gate, release, or claim of equal
FLOPs. Fixed known roots 0/1 and fixedH1, staticH3_progress, adaptive remain
the six slots; each retains 144 request identities, with no padding, retries,
threshold changes, best-partial release or result-based selection.

The requested full-tree common ceiling already exists: the original C3 K17
protocol. Its original 12-slot actual report
`results/agent_p3_c3_compact_host_cuda_20261029_v1_cuda_MAIN01/report.json`
SHA256 `88e7ac468dbcda7dddd07ba72e3c42793ff0a3d10f61e2e0c338ff1e85521dfe`
contains all six K17 slots with `tree_complete_not_admitted`; the existing
consume file SHA256 is `cdd61fc20ff4b819e64092f226cbe84ce3777edfc2a2c8472322a01ec3a0601f`.
These are references, not a newly reconstructed strict consume. Repeating the
same known-root K17 is not an independent contrast and is not proposed here.

For a hypothetical distinct run with exactly the original bounded tree and
cost semantics, use per-slot `17*(S+R3)+V`, S the paired H1/H3 parent signals
and schedule, R3 the full eight-candidate plus paid-zero R bank and post-J,
V the maximum two actual final full-chain replays. The proof emits all 27
named axes and six-slot totals. Depth3 with beam8 gives at most 1+8+8=17
parents and 136 of 144 request identities. Each progress H1/H3 width4/8 and
R1 cost is componentwise bounded by R3; each legal final chain is bounded by
two replays of nine tokens. For each prefix of 0..16 worst-case parents the
test checks both the next signal and the complete queue plus V against the
same ceiling. Use strict `>` for rejection; reservation is not paid usage.

This is conditional budget sufficiency, **not guaranteed delivery**: no
eligible witness, native failure, source/shape/cost drift, storage overflow,
wall/memory caps, or a failed final replay remain failures/null and consume
actual attempted costs. No relaxation, fallback or fabricated witness is
allowed. The proof does not certify output storage, wall, memory, model load,
physics, or real execution. A new production adapter would need its own
presealed source/loaded-byte closure, actual cost instrumentation, durable
intent/return, full failure denominator and independently proven transport
budget and would require MAIN approval. No such runner is provided here.
