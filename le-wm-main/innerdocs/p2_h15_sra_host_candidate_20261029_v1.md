# P2 H15 spectral candidate: fixture execution seam

This is a partial HOST engineering candidate, not a runnable CUDA host or authorization. The real target ABI is `agent_p3_parent_native_cuda_20261029_v1.NativeTree`: signal is H3 with a 192x30 raw-at-zero Jacobian; candidate and final verification are 15-step native replay calls. `host_backend` deliberately refuses all calls until model, source, precision and lifecycle closure exist. No existing prepare or gate is modified.

The exclusive fixture runner emits native callback events to a durable chained journal, uses the existing native resource ledger, and retains a failure report when storage remains writable. The saved consumer refuses partial outputs, invokes the existing per-call native IO auditor, checks the 27-axis ledger, rebuilds the 40-candidate bank, scores, fixed-index tie selection and both full/segmented paths. Per root, completed fixtures require 132 predictor samples and 192 VJP directions; these are actual recorded fixture operations, not evidence of a GPU run or equal FLOPs. The spectral bank's internal two SVDs/ridge solve are not separately instrumented by this ledger. The journal bound is an engineering limit, not proof arbitrary real transcripts fit. SVD basis and numeric reproducibility depend on the runtime; the current consumer fails closed if the rebuild differs.

`validate_case` compares a prepared case and native task without assuming names imply equal hash namespaces; it is a necessary check, not a producer certificate. The two-root production lifecycle and authenticated task adaptation have not been integrated. No fresh preparation, CUDA model loading or actual physical execution is performed by this module. Existing saved prepare MAIN02 independently rebuilds, but its `ready_to_execute=false` remains in force.

Remaining work before a HOST runner can be eligible for separate authorization: explicitly authenticate the original H15 task mapping and source hash semantics; bind the exact checkpoint and installed implementation with before/after state hashes and precision guards; implement two-root exclusive lifecycle including startup and durable partial failure, enforce output/floor/wall/GPU caps with validated worst-case storage; preserve and independently audit native call chronology and math including actual array operations; validate the entire host consumer on realistic transcripts and review the unchanged research protocol. Disk or journal failures can prevent a final failure report; a missing report is never a completion receipt. Physical adapter and independent fresh roots remain separate gaps.
