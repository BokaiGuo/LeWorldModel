# K17 paid replay to live guard: saved-source bridge

No neural/physics dispatch, no new saved strict and no scientific admission.
Six fixed original K17 slots (3/4/5,9/10/11) remain the denominator. The tool
inherits externally pinned original 12-slot MAIN strict receipt and checks
the actual HOST reader, result references, report/prepare/manifest/completion,
source closure and selected capsule. It does not rerun the complete 12-slot
fullstrict. Each slot requires exactly one `verification` ledger replay for
`whole` and `segmented`, distinct matching original native calls, the same
full root task and full original plan/actions/path, a returned paid operation,
whole capsule identity, and the original `audit_native` for both calls.

From each actual step0 `program_packet` it validates raw/mean/std, full3
latent and two-token history at float32 bit precision. It extracts the real
`token` and validates that the `outgoing` bytes exactly equal the actual
`action_encoder:0` input including that token. Frozen `action_guard` verifies
once-normalization against this actual paid token. Whole and segmented token
and encoder input must be byte-identical. No inferred or re-encoded token is
presented as paid native IO; inverse-to-raw is only a diagnostic and the
original literal raw is never replaced.

`check_live_from_sources(slot,live)` is a non-dispatching integration seam:
it rebuilds the above source-bound replay extraction, pins the original two
gzip task exports, H3 physical prepare/report/strict receipt and both saved
original PNG file hashes for that root, and builds the original warm10 / root
goal reference. It passes the verified replay token and caller-supplied live
capture to frozen `history_guard` and `action_guard`. Caller capture is not
automatically a genuine native environment observation: a future adapter must
authenticate and meter its constructor/reset, observations, actions and PNGs.
No external caller dictionary can create a dispatch authority here.

The frozen guard compares the supplied goal-frame dictionaries exactly. The
two original H3 plan0 frames have identical fields and image hashes but
different branch-specific `receipt.png` filenames; a new physical run will
likewise use its own name. This bridge explicitly removes **only** that local
filename from both reference and live projection. Both original files are
independently checked against their saved file SHA; file SHA, pixel SHA,
snapshot, state, goal and renderer are not removed or relaxed. A future real
adapter must hash its live PNG bytes before supplying the projection. The
other eight historically unpaired intermediate on frames remain unknown.

`physical_budget_authority` and `live_source_authority` remain null and the
tool has no `run` or action-dispatch entry. MAIN must preapprove full six-slot
physical horizon/caps/wall/storage/failure contract, bind actual native live
capture and source, and review a separate bounded writer/consumer. This is not
equal actual resources, FLOPs, control benefit or P1/P3 release. The handoff
and frozen guard are not modified.
