# E3 CPU startup closure and pre-dispatch seal

The new entry `agent_e3_startup_closure_20261029_v1` uses the existing chunked HOST authority. `collect` runs the actual frozen config through Hydra construction and reads and remaps the exact SHA-pinned checkpoint on CPU; it takes a point-in-time inventory of loaded file-backed modules inside the project and venv, independently hashes every distinct file, and exclusively writes a closure artifact. There is no CUDA allocation, model forward or physical environment. It is a CPU surrogate of loader startup, not the actual CUDA loader execution.

`prepare` joins an explicit closure path/SHA and original authority path/SHA, rehashes every closure file, preserves all original pins and rejects collisions, and exclusively creates a new HOST authority. `verify` reconstructs the authority from those inputs. `precheck` additionally repeats the CPU loader probe, requiring each loaded module name, canonical path and SHA to exist in the independently sealed closure. `run` requires the original explicit HOST authorization, performs that same precheck before invoking the existing HOST, and leaves its before/after census intact. Use this wrapper, not the prior direct HOST entry, to enforce precheck. Neither the closure nor the wrapper authorizes CUDA execution.
