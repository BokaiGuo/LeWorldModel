# Fixed-prefix physical handoff and same-time capability: design only

Status: prospective design for MAIN review, not a physical authority, runner,
prepared manifest, or preregistration of the model run already underway. It
does not inspect that run's results. Two known roots × their two fixed
conditions remain four task slots; fresh roots are zero. No model training,
physics or neural execution was performed for this document. P1 admission and
physical release remain false.

## Authority and fixed actions

The future handoff must first rebuild the complete strict consumer of
`agent_p1_fixed_prefix_host_cuda_20261029_v1`, compare its canonical bytes with
the actual persisted receipt, and bind the actual prepare/report/receipt SHA,
their source and model/precision closure, and the transitive parent physical
and task authorities. Partial, missing, modified, or unverified input is not a
deployment authority. The host consumer provides 64 ordered groups and 576
candidate slots, not four chosen plans.

Proposed *outcome-blind* rule: preserve all 64 group identities
`(slot, source_arm, source_iteration)` in producer order. For each sealed group
use exactly its `selected_iteration` when the producer reports
`model_witness`; its prefix is `chart(request.prefix_logits)` and its suffix
is the corresponding saved `iterates[selected_iteration].commands`, together
10 raw float32 actions in time order. Recompute bits and identities from the
actual prepare, result and audited native events; bind the original goal,
normalizer, raw chart, full three-latent/two-action root history, initial Q,
original-winner Q, model method and strict original conjunction. A null
selection remains an abstention; never substitute `winner_replay`, the old
winner, a different iterate or another group. No physical outcome, success,
endpoint or capability score can select, filter, rerank or retry candidates.
This rule is a proposed all-witness diagnostic, not a claim that any group has
already qualified. If MAIN wants a smaller physical panel, its independent
model-only selection and fixed denominator need a separate pre-physical
protocol; this document does not silently choose one.

Keep a four-slot roster, all 64 group rows, and all 576 source candidate
identities even if only a subset is eligible. The actual count of eligible
groups is a model-only availability count, not the experiment denominator.
The old winner is a *separately labeled comparison*, never substituted for an
abstention. Only reuse an old physical execution after verifying source strict,
same task, root, raw10 bits, history, timeline, native goal and renderer; an
uncertified or different action is not a same-action replay.

## Same time, task and physical guard

Each physical branch reconstructs the original seed, both reset/placement
operations, goal binding and ten warmup controls from the authoritative native
recipe. Require exact root/source/goal and warmup evidence before any new plan
action. The model's first packet is control 1–5 (cp5), second packet control
6–10 (cp10); compare native states, reward, success and goal-relative metrics
only at the same control time. Root/goal identity and goal RGB bytes are
separate from model goal192/Q and must be joined from their actual authorities.
Compare cp5 to cp5 and cp10 to cp10; absence after native termination remains
null, not zero, a copied frame, or a shorter endpoint relabeled cp10. Preserve
native seven-dimensional state and native success/reward unchanged; report
position, velocity and wrapped angle diagnostics separately, never replacing
the official gate. Same root and time are necessary but do not mean identical
state after distinct prefixes.

Important distinction: the prior midpoint seam's original prefix51/cp5 guard
is valid only when its complete raw prefix and all authority identities match
bitwise. Fixed-prefix source iterations can have different prefixes; requiring
the *old* cp5 state for those would be wrong, as would claiming a new prefix
was certified by that guard. For a new prefix, execute its first independent
branch from the certified original recipe, seal its cp5 state/snapshot,
action history and PNG evidence, then compare each subsequent branch for that
exact prefix against that newly sealed reference before dispatching its suffix.
The first cp5 observation is not itself proof of full hidden contact/solver
state identity; each replay uses the same recipe and records this limitation.
No `set_state(cp5)` shortcut or tolerance-based merging. Reproduce original
warmup/control0 guard, exact raw bits, all guard inputs and fresh observations;
stop on native termination/truncation or any failed guard and preserve failure.

## Capability diagnostic: fixed common task direction

If MAIN separately approves a capability experiment, use the existing
common-prefix probe design, not a new optimizer. For each distinct certified
root/condition/prefix/history identity and an independently specified original
winner-prefix comparison position, preseal identical 21 five-step suffixes:
`[0, +0.25 e0, -0.25 e0, ..., +0.25 e9, -0.25 e9]`, with time-major ten
logit coordinates, the original float32 tanh chart, and the original suffix
ball. Zero is a real five-step branch, not the static cp5 observation. The
entire list, ordering, native recipe, goal and action hashes must be frozen
before any probe outcome. All branches run independently from the original
recipe and verify their own position's sealed cp5 reference; do not apply one
position's cp5 equality guard to a different position.

For original pre-prefix native root `s` and the same native goal `g`, define
`p` as agent XY concatenated with object XY and `u=(p(g)-p(s))/||p(g)-p(s)||`.
The same `u` is used for all positions of that same root/condition; zero norm
means undefined, not a new direction. At cp10 for each fixed suffix, report
`Delta=p(probe)-p(zero)` and `T=u·Delta`, plus zero drift from cp5. For every
coordinate report `B=(p(+)-p(-))/(2*0.25)` and
`E=p(+)+p(-)-2*p(zero)`. Require the zero and both signed endpoints at cp10;
otherwise each affected quantity is null with its reason. Report both signed
responses and four-dimensional components; this is a finite single-scale
secant, not an exact Jacobian, trained controller, P1 success, or a license to
execute the best probe. Angle uses a separately reported cosine/sine chord;
do not combine pixels with radians or use a position's own residual to change
the common direction. Evaluator-only native state and response must never feed
the model selector.

## Fixed roster, alias and budget boundary

Logical candidate roles remain 64 plus four separately identified original
winner comparators. A physical prefix can be deduplicated only by exact
root/condition, task/goal and recipe, raw float32 prefix bits, action-history,
source/render contract and time identity; retain every logical alias and never
merge across roots or on approximate state/PNG equality. Pre-physical prepare
seals the exact mapping and all nulls; zero witnesses means no candidate
position, not a fabricated comparator intervention. At most 68 distinct
positions give at most `68*21=1428` capability branches, *in addition to* up
to 64 selected-plan executions and any separately needed baseline execution.
These are branch counts, not evidence that the present physical driver can
transport or afford them. Exact deduplication, early stop, new actual versus
verified reusable work, and all attempted/completed operations must be
reported separately; no assumed savings or equal-FLOPs statement.

Before implementation/production MAIN must approve a concrete full roster and
native-operation/PNG/event/output/disk/wall budgets derived from the chosen
actual driver and presealed source assets; the illustrative 1428 is not an
approved cap. Maintain full probe and role denominators on missing witnesses,
partial failure, guard failure and budget refusal; do not fill unknown costs
with zero. No physical call is authorized by this document. A new driver and
saved consumer must reconstruct native events, action and guard ordering,
PNG hashes, all resources, nulls and source lineage; fixture tests must include
raw prefix one-bit mismatch, distinct prefix versus old guard, same-position
replay failure, zero/signed missing, early stop and no-witness.

The existing [midpoint seam](agent_p1_midpoint_physical_seam_20261029_v1.md)
illustrates authority and original-prefix guard, but its four-row schema is not
a 64-group adapter. The existing [common-prefix capability design](p1_constructive_common_prefix_capability_probe_design_20261027_v1.md)
supplies the probe and direction definition, not production evidence for this
new panel. No causal superiority, physical success, fresh-root confirmation,
full P1, or global controllability follows from this design.
