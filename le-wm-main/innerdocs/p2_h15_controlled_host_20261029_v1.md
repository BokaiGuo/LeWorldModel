# P2 H15 受控 HOST 候选

独占 prepare 对固定历史 attestation、398 项历史来源和本候选代码重建并封存；运行时要求外部 prepare SHA 和明确授权标记。仅实际 `run` 才导入 CUDA、申请设备、加载真实权重，同一份 checkpoint 字节用于哈希和反序列化。沿用 NativeTree、双根 task、逐调用账本、单槽 native saved audit，模型、buffer、精度和源码做前后检查。两根顺序执行，失败不启动下一根，固定分母不变。成功的 saved consumer 重新核验 loader、所有槽和生命周期；失败报告不可冒充完整结果。

继承工程预算：外层 3600 秒、输出 1536 MiB、空闲地板 512 MiB、CUDA 峰值 allocated 4 GiB/reserved 6 GiB；每文件另设 128 MiB 的 RLIMIT_FSIZE，可能导致过早失败。时间、空间和 CUDA 峰值只在调用/写入边界合作式检查，不能中断已进行的单次 CUDA 调用；CUDA 上限不是硬分配上限，磁盘剩余空间可能被其他进程竞争。RLIMIT_FSIZE 在文件达到限制时可能使进程收到信号；I/O、进程或系统崩溃时可能没有最终报告。每次原生调用前后对完整历史清单和模型重哈希，耗时可能明显，计入外层壁钟。

不进行物理和训练。不证明没有未记录调用、宿主真实性或端到端源码动态依赖完整闭合，不声称等 FLOPs 或科学准入。尚无实际 CUDA 测试；真实运行若来源漂移、运行时类不在清单、文件大小、内存、超时或保存审计不满足会 fail-closed。保存报告可作为运行记录而非独立物理证据。
