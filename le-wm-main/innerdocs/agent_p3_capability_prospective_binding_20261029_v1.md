# P3 capability future-batch binding: conditional preflight only

The previous actual same-time probe completed its five cp10 roles, seven signals, five U dual replays, ten physical branches and cp15 RGB. Those observed results are not a new prospective independent cohort. The old Stage B source is pinned to the old cp10 bridge authority; reusing it does not automatically support a future cohort. This tool provides a reviewable pre-dispatch artifact and conditional signature linkage for a future batch; it is not a runner, does not change any scientific gate, and cannot force the old executors to use it.

`proposal` binds the exact original protocol and this source/test/doc closure, opaque caller-supplied cohort, prepare, and executor bytes, a run ID, and the original fixed seven-signal/five-U budgets and physical denominators. It hashes the opaque artifacts without interpreting them or reading their outcomes. It rejects the exact known old cp10 task-bundle SHA, but cannot prove that differently encoded data do not reuse the same roots or history. No arbitrary file hash proves cohort authority, source selection before outcomes, future executor ABI, freshness or independence; all these remain false/unverified and the proposal is explicitly blocked. Historical results were already observed and must be disclosed; do not call this independent blinded replication.

For a commitment before the first new physical dispatch, `prepare` must be a static pre-dispatch batch plan, not a future actual-cp10 latent file, which cannot yet exist. The later real cp10 bridge, Stage B plan/witness and Stage C execution each require their own separately authenticated source, approval and externally evidenced order; this preflight does not produce or verify those future handoffs. The opaque future cohort input must itself be fixed without looking at future outcomes; this tool cannot prove that condition.

The optional `check` reuses the sealed existing P1 Ed25519 verifier: the externally supplied witness signs the proposal file SHA plus the same future prepare/executor and policy SHA, and a distinct authorizer signs a reference to that commitment. It emits conditional cryptographic verification only. Neither signatures nor local timestamps prove actual chronology, honest independent witness, non-backdating, non-viewing of outcomes, or launch linkage. MAIN must independently select and authenticate trust keys, use an external append-only or equivalent independently auditable record and controlled launcher, prove actual commitment precedes actual dispatch, prevent bypass/reuse, and review the adapted future execution/consumer and full source/identity/guard contracts. The output **never authorizes execution**, even if both signatures validate. Do not read future outcome while preparing or sign an old observed experiment as new. Missing artifacts/credentials reject, not synthesize.

CPU/RAM/fixture only; no NN, physical, optimizer or full strict. `proposal` and `check` exclusively create a new absolute output under this stem; `verify` repeats the signed check and compares the whole saved output. All external input paths and SHA values must be actual; no future value is hardcoded. The old P1 verifier is reused only for conditional signatures; its P1-only status does not grant P3 authority. Signature test keys are ephemeral fixtures, not trusted authorities.
