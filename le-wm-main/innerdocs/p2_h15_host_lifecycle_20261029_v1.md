# P2 H15 双根 native 执行与 saved 审计候选

统一单槽执行核心通过 signal、40 个原始动作候选和全程/分段两次重放调用 callback，ledger 在实际 callback 内计量。真实 HOST 工厂构造 `NativeTree`，每次调用前后核对双根 task、预算、模型、精度和来源；`run_host` 已连接该工厂，但统一执行核心当前对 HOST 无条件拒绝。fixture 工厂走相同算法和保存审计，身份为 RAM_FIXTURE，不作为 HOST 证据。

生命周期采用独占日志和报告，先保存模型、精度、来源前快照，再保存各根 start/seal/fail，最后保存后快照或认证错误。每槽记录原生输入输出和资源事件；成功槽的 saved consumer 审核原生调用、重算谱 bank、40 分数、稳定选择和重放并核对实测账。失败槽只审核可恢复资源账及文件绑定，不声称失败 native 调用的完整神经数值正确；外层故障缺少槽报告时显式标记。第二根不会在第一根失败后启动，固定分母始终为二。

HOST 格式消费路径可检查已存调用和前后摘要，但当前没有真实 HOST 产物，也不赋予 HOST 认证。验证日志不能证明没有未记录调用，也不能独立证明模型真实执行；来源检查不能证明进程加载的所有依赖。模型前后证据还需经真实运行采集和审计，CUDA 资源/总磁盘与最终预留、壁钟、进程崩溃恢复、独立受信调度和完整 class/source 闭合尚未完成。日志/文件系统本身故障时无法保证最后报告；物理和训练不在接口范围。
