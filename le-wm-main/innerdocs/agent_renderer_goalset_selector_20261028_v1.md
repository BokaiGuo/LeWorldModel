## 数学、原算法对照及输出ABI

每root固定两原型 `G=[g_off,g_on]`；原goal和Q不被覆盖。

`D_r(z) = mean192((float64(z)-float64(g_r))**2)`；`L(z)=min(D_off,D_on)`。

恰好除192一次，原生输入必须float32。JSON模型literal必须精确可表示为float32，禁止静默把不精确double压缩成“原坐标”。无权重、tau、softmin、beta调节、readout或Q拟合。goal分支strict tie取off，candidate按 `(L,index)`；两库分别选、不取跨库union、不去重重叠first42、不按物理结果决定branch。

pure ABI：

```python
score(z_float32_192, goals_float32_2x192)
# -> {branch_Q: [off_Q,on_Q], value: min_Q, active_branch: 'off'|'on'}
select_panel(slot, original_panel, original_model_result, target_authority, count)
# -> 完整count行 + 原stage/ridge winner + 原terminalQ winner + 新goalset winner
```

每candidate保留原stage、ridge、original_objective、nonlinear_terminal_Q、raw10 float32 SHA、prefix/terminal SHA和原model-uphill标记，新增两个branch_Q、goalset_Q、active_branch、prefix_goalset_Q与新loss下model-uphill。原single-condition terminalQ还必须精确等于同分支新复算值，不以新loss覆盖它。新model-uphill不是物理non-greedy标记。

每panel包含原task/context/goal/Q/physical-goal/goalset绑定和三种winner；新winner提供原完整commands/raw SHA，不从params重造动作。全JSON `.selection` 含完整1056候选与8panels及 `.selection_sha256`，不是只封best几项。`.target_authority`保存4slots、16image receipts与全部原file绑定；`.bindings`连接原model evidence、source/helpers及新source/tests/doc。

`.prepare/.analysis`均为本模块自有schema，不冒充旧selector或renderer分析receipt。verify从原authority和原模型证据重建整报告并canonical精确比较，不只看status。输出无clock字段，便于确定性verify。
