# E1 same-target candidate intervention: prospective fixture

Fixed engineering question: does access to a compiled model-witness prefix as
one extra evaluated candidate alter the selected plan or subsequent tracking,
holding the target and original controller objective fixed? This is an
information intervention, not a comparison of the old proposal methods and
not a claim that a model witness is physically reachable.

For each of the two already fixed known roots use the sealed original compiled
prefix postcondition as the shared f32 target. Before observing any new physical
outcome seal task, history, goal, target, original prefix raw5 and source SHA.
Run the original 3x24 H2 controller independently per arm with the same root
seed, context, target and Q; require the full 72-candidate banks bit-identical
before comparing. No target selection from outcomes. After the final CEM update,
add exactly one candidate: control raw10 is all zero; intervention raw10 is
the original literal prefix raw5 followed by five zero actions. No clipping,
inverse fitting or reoptimization. Evaluate both with original H2 Q, then choose
minimum of 73 with original index tie break (the extra has index 72). Thus the
extra cannot change the CEM distribution; it can change only final selection.
If prefix is zero the interventions coincide and that fact must be recorded.

Each slot pays 144 base packet predict/AE/projection calls, two extra packet
calls and four whole/segmented selected-plan replay calls: 150 each; four fixed
slots total 600 per module axis if all complete. Attempts are charged before
dispatch and failures are not refunded. The extra/replay fixture meter covers
only six logical calls, not the 144 or real CUDA hooks. Proposal generation,
source witness, encoding, native reset/physics/render, storage, wall, memory,
and any upstream inherited cost must be measured separately; equal packet
counts do not establish equal FLOPs or equal information. All selected plans
and replays must seal before native evaluation; preserve missing slots and
whole/segmented differences, no outcome-dependent replacement, threshold or
winner. Native same-time cp0/5/10 and actual RGB evaluate tracking and the
common task goal separately; no scientific gate change.

The included `select_and_replay` is an executable RAM seam using the bank ABI
from frozen `agent_e1_six_slot_controller_core_20261029_v1.optimize`: index,
cost and commands. Its injected dispatch and score are not authenticated and
it cannot run production. The saved original compiled source must still be
authenticated to supply literal prefix bytes, task/history/target and receipt;
paired independent 72-bank identity, original Q, real module counts, raw-token
replay, durable barriers, native execution, strict consumer and bounded failure
transport require a new production adapter. In particular don't infer that
existing target source or model prefix is a native physical arrival witness.
Before authorizing production MAIN must approve this prospective information
intervention and budgets and specify the native/RGB resource bounds. Known two
roots are calibration, not new confirmation. No frozen files are modified.

RAM test: `.venv/bin/python -B -m pytest -q -p no:cacheprovider tests/test_agent_e1_same_target_candidate_intervention_20261029_v1.py`.

## MAIN audit: score failure must poison the meter

The initial fixture allowed `score` to raise after the two extra packets had
returned without setting `Meter.failed`; a subsequent dispatch was possible.
MAIN reproduced this path and changed the seam so a scoring exception poisons
the meter while retaining the two attempted and returned packets. The added
regression checks the original exception and rejects a later dispatch. The
shared-target and intervention fixtures now pass 15 tests together. The
revised source SHA256 is
`31ad853db50dba2b47d88582d612a689ccf471406c9d06ed8ed67718b5878de9`;
the revised test SHA256 is
`bd18f3ad931f06a53b3b6b8121ff2a6b942bcd0ba295c6f3bce7d00639611ec7`.
This seam has not run production, so the bug is not evidence about prior
negative outcomes. Full production source binding and resource guards remain
required.
