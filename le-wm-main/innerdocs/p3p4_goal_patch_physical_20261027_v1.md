## Source contract

Only the NEW `p3p4_goal_patch_replay_20261027_v1.selected_actions` can authorize
actions. Source preparation freezes its preparation, source closure and original
four root/goal/reset RGB references, without any new replay outcome. Once main
has executed replay, `--bind` accepts an explicit actual replay report byte SHA
into a NEW directory, reruns the complete exporter, and binds all eight complete
fresh double witnesses, whole candidate bank digest, root/context/goal0,
both Q matrices/costs, raw commands and horizons. Never edit/reseal either old
source preparation or a completed CUDA report. No old consumer whitelist and
no old physical endpoint substitutes fresh execution, including old-Q controls.

## Execution and durable guards

UPFRONT. Every reset validates original RGB history and independent goal RGB,
full state/goal consistency across arms and exact raw-warmup-to-float32-normalized
incoming tokens against saved predictor_context.action_history. Eight root-arms,
fixed counterbalanced order, one fresh physical repetition each. Uses only old
low-level durable step/journal and root/reset validation helpers, not an old
runner or its allowlist. No physical state enters planning or scoring selection.

RoyalBlue observability guard before dispatch and after EACH raw command,
including all15 H3 commands. Attempts charged before env.step; returns before
render/evaluation; missing RGB, failed step, render failure and termination all
retain partial durable receipts. Unexecuted slots become blocked, never dropped.
An endpoint whose last successful observation does not match returned steps is
stale and cannot be encoded. All physical branches plus physical_report.json
must be fsync-durable before optional HOST CUDA setup. No auto retry/refund.

## Main-only commands

From repository root use module
`experiments.spectral_reachability.p3p4_goal_patch_physical_20261027_v1`:

1. `--prepare --output NEW_SOURCE_PREPARED` (model/physics-free).
2. After real replay: `--bind --prepared NEW_SOURCE_PREPARED
   --prepare-sha256 SOURCE_SHA --replay-output ACTUAL_REPLAY_DIR
   --report-sha256 ACTUAL_REPORT_SHA --output NEW_BOUND_PREPARED`.
3. `--verify --prepared NEW_BOUND_PREPARED --prepare-sha256 BOUND_SHA`.
4. Main only: `--execute-physics --prepared NEW_BOUND_PREPARED
   --prepare-sha256 BOUND_SHA --output NEW_PHYSICAL_DIR --encode-terminals`.

Omit --encode-terminals for physical-only. Tests use metadata, saved arrays,
and fake environments, not actual simulator or neural execution.
