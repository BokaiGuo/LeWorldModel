# 时序最低分与前缀条件信息：开发审计协议

在已有 40 个已曝光 TwoRoom episode 的 119 次共同历史决策上，重建三个前缀与每个前缀的零参考、两个 A 探针，共 9 条实际已评分链；不改变候选、checkpoint、归一化、RGB 输入或动作时钟。重放已派发动作以重建当前 RGB，核对历史真实距离、终止标志和原保存的末帧与时序最低分；若不一致即停止。

对每条链记录所有动作包边界的预测代价。前缀长为 `prefix_steps`，时序最低点位于此前或恰在边界时，标记为“前缀内或边界”。分别计算全时域最低分与严格前缀后最低分，比较每个前缀内三个探针的动态范围（绝对容差 1e-3）以及两个最低机会前缀的保留集合。严格前缀后定义只用于诊断动作效果是否被共同前缀掩盖，不直接替代“25 步内曾成功”的任务目标。

以决策和任务为单位统计，不将同根探针作为独立任务；提供逐决策原始时序分数与身份。报告新增 GPU 查询和模型时钟成本；不读取未来物理标签选动作、不重新执行规划器、不更改原配置或历史结论。预期不预设胜负；若退化普遍，再考虑另立同权限、同完整预算的条件尾部实验，若不普遍，则该解释不足。此协议与代码在运行前写入并以哈希绑定，面板已曝光，不作为独立确认。
