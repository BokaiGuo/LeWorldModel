# v10 E0：后验可行性与固定尾覆盖

根据[后验固定协议](PC_RECURSIVE_RESPONSE_V10_E0_FEASIBILITY_COVERAGE_PROTOCOL_20261104_CODEX.md)，已有解析构造器在此前八个开发任务的每一根都给出了两条合法、15 步内的成功见证，共 **16/16 条**，均由声明的精确动力学和 float32 动作重放确认。因而该面板上五臂 0/8 并非仅因任务在声明动作域和时域中无解。解析见证使用任务特权信息，没有输入规划器，也不代表方法能够找到解。

将每条见证的最后十步固定，分别拼接同根 v10 单模态和双模态各自首层的所有自动候选，共 **448 条完整链**：满足 `<0.05` 的候选为 **0/448**；既然全集没有成功链，原保留集合在这个固定尾检验中也没有成功链。每条见证前五步到同根首层候选最近的归一化动作欧氏距离约为 `0.821–1.307`。

该结果为“首层候选没有覆盖两类已知成功链所需的特定前缀—后缀组合”提供有界证据；它不是对动作空间或其他后缀的穷尽，不能证明生成候选都不可优化，也不能从零成功中量化保留造成的独立损失。固定尾是事后特权见证，并非可部署的搜索器输入。

[逐见证、逐候选结果](../le-wm-main/results/pc_recursive_response_v10_e0_dev_20261104_codex/feasibility_coverage.json)及[重算审计](../le-wm-main/results/pc_recursive_response_v10_e0_dev_20261104_codex/feasibility_coverage_audit.json)绑定 v10 封存输出；审计重算全部 448 条候选和 16 条见证，但仍使用相同解析后端。此结果不构成 PC2 同链机制、PC3 优势或独立复现。
