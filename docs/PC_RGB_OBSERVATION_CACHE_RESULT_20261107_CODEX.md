# 规划内 RGB 编码缓存：配对重算结果

原 RGB 边界每次评分都重新构造上下文，导致同一次规划中相同当前图和目标图被上游模型反复编码。本轮新增仅限**单次规划**的评分会话：复用上游首次计算的两个 embedding，不缓存动作条件后继；每次核对当前图、目标图和动作历史的形状、dtype 与内容，变化时拒绝继续。会话要求冻结模型和无梯度推理，不跨重新观测或任务复用。

对此前四个已曝光 TwoRoom 根、三臂的全部 **57 次**决策，重建同一真实 RGB 观测；每次分别运行原边界和缓存边界，并交替运行顺序。结果如下：

| 指标 | 原边界 | 缓存边界 |
|---|---:|---:|
| 决策数 | 57 | 57 |
| 模型评分调用 | 1,425 | 1,425 |
| 图像编码器 forward 调用 | 2,850 | 114 |
| 同步规划计时合计 | 13.403 s | 9.898 s |

全部 57 次的候选分数逐值一致（最大绝对差 **0**），保留前缀、获选动作与原决策一致。缓存实现每次规划首次计算两次图像编码，后续 24 次评分复用；上表编码器调用减少 **96%**。在本次同期配对测量中，含边界构造、输入指纹检查、候选生成和同步的规划耗时合计下降约 **26.1%**；57 次中缓存版本均更快。各根的原／缓存合计分别为 3.118／2.228、3.433／2.556、3.427／2.557、3.424／2.557 秒。

目标／当前图和动作历史变化拒绝缓存、额外状态输入拒绝、不同候选批量、梯度路径拒绝、候选保留及预算等相关测试 **37 项通过**。复算时继续按原始选中动作真实推进并核验逐步状态距离；由于每次缓存决策都一致，这支持该固定轨迹的决策等价，但尚未单独运行缓存版本的完整控制 episode。

**边界：**这是同一模型、同一硬件、单次配对重算的开发计时，4 个根彼此共享多次重规划，不能当作 57 个独立任务；它不含模型加载、整个环境交互和独立任务确认，也没有证明 Planning Compiler 的描述组件贡献。此处未减少动作候选评分或动力学预测次数；编码缓存可用作后续版本的工程优化，但不能据此宣称完整系统成本优势、非劣效或 PC0–PC5 通过。缓存必须在每次重新观测时新建，不能把过去的 embedding 用于新状态。
