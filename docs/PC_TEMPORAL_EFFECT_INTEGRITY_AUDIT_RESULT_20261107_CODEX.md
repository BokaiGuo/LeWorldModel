# 时序后果保留：实现完整性与数值审计

## 检查结果

对前一轮 30 个已曝光 TwoRoom 任务，在同一冻结 RGB LeWM 上重新计算 A、每臂有权查询的 B 并集与 incumbent 的逐时刻分数，并验证候选身份、原保留和封存动作：

- 逐时刻最大分数绝对差为 **0.00100708**；四臂保留前缀均不变，但质量约束臂 root 46 的最终链从 A56 变为 B56。因此未满足本次数值审计的 `1e-3` 边界，也不能笼统声称批次无影响。
- root 46 的 A56 与 B56 前 10 个动作完全相同；各自最低预测代价均来自第 5 步，旧值相差约 **0.000042**。实际重放证实其共同前缀轨迹一致；两条链都曾成功、最终都未成功，但末距分别为 **21.73** 和 **34.21**。这说明浮点差异改变尾部选择且可能影响实际轨迹，并未在这一对链上改变“曾成功”。
- 原描述先按相同时长参考减探针、再逐行中心化；参考在该运算中被**完全抵消**。它保留探针的相对形状而不保留参考绝对幅度。该性质符合旧实现但比“利用参考基准的行动效果”更窄，不能据此判定所有行动后果描述无效。

## 有界修复与事后重放

新增 `pc_causal_prefix_scores_20261107_codex.py`：只对原始动作前缀完全相同且时间一致的候选，使用按完整动作字节确定的代表值；超过调用方声明的误差边界则报错。它不访问其他臂的候选，也不自动合并近似前缀。测试覆盖共享前缀、超阈值失败、候选顺序置换和时钟检查。

对已有固定池进行事后审计，四臂各有 **1/30** 个最终动作改变，均为 root 46；四臂可访问候选内的最大共享前缀分数差为 `9.1553e-5`。对修正后 root 46 的新动作进行实际物理重放，其余任务复用原先真实轨迹：

| 方法 | 曾成功 | 终点成功 | 平均终点距离 |
| --- | ---: | ---: | ---: |
| lookahead | 28/30 | 22/30 | 11.268 |
| vector | 28/30 | 22/30 | 12.078 |
| gated | 28/30 | 23/30 | 10.546 |
| shuffled | 28/30 | 22/30 | 12.001 |

以上是**在已知问题和历史结果后进行的事后重放**，不是预定开发出口或独立结果；不能把单个终点成功差异作为新方法增量。原协议以曾成功为开发出口，修正后该指标仍为四臂 28/30；原有具体构造未通过的结论不变。

测试：时序保留、代数性质、新工具和模型包时钟共 **9 项通过**。历史实验文件及结果未覆盖；修复工具尚未接入正式规划器，也未认证跨设备、不同模型、一般近并列或完整闭环。原分数和新的重算存在批次组成差异，但本次没有隔离 GPU kernel、批大小及运行状态的各自因果贡献，因此仅称数值敏感性，不断言唯一根因。
