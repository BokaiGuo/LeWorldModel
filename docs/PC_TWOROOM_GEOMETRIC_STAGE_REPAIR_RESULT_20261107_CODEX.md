# TwoRoom 几何候选阶段切换修复结果

## 结论

在 40 个已曝光的跨墙开发任务、相同初态及相同候选索引下，修改阶段
容差并禁止单步超调后，开放环候选成功数从 **222/640 升至 599/640**；
377 条由失败变成功，0 条由成功变失败。这个配对结果支持：先前候选
成功差异很大程度受生成器实现影响，不能把它直接解释为模型理论能力。

| 候选组 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 零动作 | 0/40 | 0/40 |
| 增益 1.0 | 200/200 | 200/200 |
| 增益 0.8 | 10/200 | 199/200 |
| 增益 1.2 | 12/200 | 200/200 |

修复同时修改了容差与防超调规则，因此该结果**不能分离两项修改各自
的贡献**。修复后所有 600 条非零链均在内部路径跟踪中到达第三阶段；
其中 1 条仍在真实物理 25 步内失败。内部阶段推进不是物理成功判据。

模型从修复后的候选池中选择的开放环链为 **40/40 成功**，固定几何链
同样是 **40/40**。没有表现出模型评分相对固定规则的成功率增量。
每个任务的 16 条候选实际上只有 **11 条字节级不同**：五对增益 1.0
和 1.2 的链完全一致。不能将这些重复动作当作独立样本；由于非零
候选几乎全部成功，本池也无法有效检验细粒度路线成功辨识。

## 核验与边界

预先写入[修复协议](PC_TWOROOM_GEOMETRIC_STAGE_REPAIR_PROTOCOL_20261107_CODEX.md)；
相关测试 **8 项通过**，覆盖三个增益的阶段推进、合法动作与不超调。
独立脚本重建全部候选并重放 **640 条链、16,000 个物理步**，核验
距离与终止；未重新计算 GPU 模型分数。运行前后冻结模型指纹一致，
评分总计 640 条完整链、3,200 个预测 packet。

物理评价使用真实状态重置；规划候选和模型选择使用 RGB、合法动作及
冻结模型分数。两者仍在同一进程，未做进程级隔离。任务和生成器已
曝光，不能用于独立确认；该几何先验是 TwoRoom 专用，也不能证明
后果描述或完整 Planning Compiler 的增量。PC0–PC5 未改判。
