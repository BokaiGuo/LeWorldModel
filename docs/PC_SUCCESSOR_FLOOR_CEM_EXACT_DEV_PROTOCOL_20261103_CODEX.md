# 后缀尺度下限的新版本：精确动力学配对开发协议

固定一个新版本，只改变后缀和直接全时域 CEM 的标准差下限：
`1e-5 → 0.05`；联合精修保持旧实现与下限不变，避免更改多个环节。
保留原 RGB successor 首次决策的响应生成、后继组合、75% 后缀预算、
联合精修、完整链选择和末尾 zero-prefix 比较。将 `0.05` 同样用于
所有对照臂的后缀或全时域 CEM。不可输入解析见证。

在旧 exact 数据的 24 个已暴露任务上比较新 successor、同库 greedy、
随机桥接、普通 lookahead 和 direct CEM。各臂沿用此前 exact controls
协议的随机种子、候选生成及 480 预测 token 上限，每个 token 表示
一条 5 步 packet 的一次预测；所有生成、筛选、后缀、精修和最终比较
均从同一上限扣除。新旧 successor 有共同根和其原随机种子；四个对照
臂使用其原控制种子。记录全部调用动作、转换、位置、评分、token、
结构调用、候选和最终链；以旧计划和旧对照作为已封存上下文。
报告逐臂均值、`<0.05` 成功根数、配对差与 token，并验证逐根链确实
被评分。结构运算和 wall time 单独报告，不能把 token 等价于完整成本。

新版本和新对照只在当前已暴露根做一次开发比较，不追调参数、种子、
根或预算。阈值、采样策略与对照不是独立确认；不以任何结果通过
PC2/PC3，不重新打开已停止的 block-program 协议。若自动候选仍失败，
记录负结果和后续候选覆盖问题；不能以某个臂的优势单独宣称谱增量。
