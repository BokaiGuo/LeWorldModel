# TwoRoom RGB 单帧动作响应与物理对齐：开发协议

在已暴露的既有 10 个 TwoRoom 数据行上，以 25 个物理零动作作为名义链；零动作不是保证物理静止。固定四个方向：第一包或第五包各五步的 x 或 y 轴同时增加单位物理动作。只改变一个方向，不裁剪。对每个方向以物理动作单位 `±0.002、±0.02、±0.2` 查询同一冻结 RGB 模型；在名义链处对原模型归一化动作反向求导，按 normalizer 的尺度换算成物理方向导数。比较标量末帧目标代价的 AD 与各尺度中心有限差分。输出每方向的梯度、正负模型后继、代价、绝对误差；对低于 `1e-4` 的 AD 不解释相对误差。AD 与 FD 仅验证模型内数值，不证明物理真实性。

模型查询阶段只读取当前 RGB、目标 RGB、合法动作和冻结模型，先排他封存候选、表示和评分。随后评价端从数据对应的物理状态重放 `±0.02、±0.2` 的动作，共每根 16 条、全体 160 条 25 步链。逐步记录终止、物理目标距离及最终 RGB；冻结编码器编码末帧及同一数据目标图，比较模型与真实编码的同动作差分，以及模型、真实编码和物理末距对正负动作的偏好。必须逐任务汇总并记录平局；全部候选和失败保留。真值不参与规划或更改候选，数据属于开发暴露且独立性未知。

预定仅作诊断出口：若 `0.002` 上 AD 与 FD 绝对误差超过 `0.1` 或（AD 绝对值至少 `1e-4` 且）相对误差超过 `0.1`，标记该方向需检查数值／实现；不以大尺度差分偏离证明代码错误。真实编码或物理正负排序不一致单独计数，说明该支持内潜在失配，不视为 PC1 通过、描述增量或独立收益。每个物理后继与模型预测绑定同一动作、目标和时刻；完整 gate 不改判。
