# P1 固定前缀、各自后缀优化内核

新增 `codex_p1_fixed_prefix_common_suffix_20261030_main.py`，用于将固定候选
前缀与同一个两段后缀优化器连接。每个候选先以冻结模型从共同历史预测
后继；其后继历史包含对应的归一化前缀动作，再从同一个固定初值独立优化
后缀。所有完整三段动作从原历史重新 rollout，按固定目标和顺序选最优。
提供的事件回调必须保存输入、各候选后继与后缀以及最终动作和分数。

每个候选需要 `4 + 2 * steps` 次 action-encoder/predict、`steps` 次
backward，以及一次完整 replay 和 selection；上述计数不包括前缀产生、
视觉编码、模型加载、物理执行和未截获的底层操作。调用者须提前保留
足够账本额度，不能把这些数量当作完整 FLOPs 或等预算认证。

这是**模型侧性能比较接缝**，不是同一后缀的物理机制干预。后者仍由正在
运行的 H10 负责。内核不读取物理结果、不使用模拟器状态选择动作、不
训练模型，不自动授予物理执行或 P1 准入。

三个新增合成测试覆盖了候选前缀历史归一化和逐段对齐、完整重放的解析
分数、成本扣记、预算不足与合同漂移的 fail-closed 行为；连同原优化器
测试共 5 项通过。尚未接入生产候选生成或真实 CUDA 模型，也没有新的
物理性能结果。下一步需要将模型、固定候选、可持久账本和同频率真实
反馈接到独占运行入口，随后做多预算和强基线比较。
