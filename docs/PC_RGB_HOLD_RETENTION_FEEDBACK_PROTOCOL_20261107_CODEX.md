# Hold-relative retention: exposed RGB feedback development protocol

Hypothesis: preserving each prefix's zero-reference-relative response to two
common actions can change diversity retention beyond the old row-centered
two-action vector. This is a new representation, not a claim that extra
queries or zero actions have already been proven useful.

On the previously exposed TwoRoom roots 10–49, reuse the current RGB-only
feedback contract, frozen checkpoint, reset state, 25-step task deadline,
five-step action packets and incumbent tail. Four arms use the same three
parent chains, zero-reference and two shared random probes per prefix, and two
shared tail proposals per retained prefix. All spend 16 complete-chain scores
per planning call, including the final one-packet fallback.

All non-parent arms use the lowest-cost zero/probe continuation as their first
retained prefix. The second is respectively: second best ordinary lookahead;
farthest old centered two-probe vector; farthest two-dimensional zero-relative
effect vector; or farthest independently coordinate-permuted zero-relative
vector. This last control is action-identity shuffle, not cross-root shuffle.
Every scored parent and probe chain remains eligible for final selection, as
in the existing implementation. All arms share this rule. Zero is a legal
reference action; hold semantics are qualified only at previously checked
states, not asserted for every prefix generated here.

Predefined development exit (not a gate): compare full effects to ordinary
lookahead and centered vectors on paired task success; require at least three
exclusive wins and at most one exclusive loss against each, and no lower
success than identity shuffle. Otherwise do not scale this specific
configuration. Report all tasks, first packet actions, costs, and actual
trajectory query counts. This panel is exposed and does not establish a final
effect, independent significance, or cost advantage.
