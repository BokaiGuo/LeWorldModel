# V5 响应保留臂：事后同库机制诊断协议

固定 [v5 已完成开发面板](PC_V5_CANONICAL_RETENTION_E0_DEV_RESULT_20261104_CODEX.md)中 24 根 `response` 保留臂的最终执行链；不使用其他版本的 selected。逐根保留其自身首层候选库、最终链的前缀和尾部。对九个候选及最终前缀使用相同零尾初值和 119 个后缀 CEM 样本、共同随机种子；对每个前缀另施加同一个最终选中尾部。以完整库中最低的重新规划终距作为 same-bank lookahead，即时评分最低为 greedy，zero 来自同一库。均记录绝对终距及相对于各自零尾的变化。

在封存结果上追加与原 v4 局部诊断相同的 `.01/.05` 两尺度、四前缀响应和障碍分支稳定性检查；selected、zero、greedy、lookahead 全部使用同一 selected 尾部，记录尾部裁剪和任务方向梯度差。对全部 24 根报告非即时、共同尾相对零尾收益、同预算自行规划及响应分支稳定性交集，不筛出有利见证。另以确定性五组常量尾加最终尾作为共同后缀族对四种前缀评价，固定每个前缀和尾部，不根据结果选择动作。

此前已看到 v5 的面板结果，候选和任务均暴露，本诊断是后验排查，不是事前确认或 PC2 gate 通过；lookahead 从九条独立 CEM 结果中取最低，存在选择偏差，selected 也可能属于库。尾部优化只有一套 119 样本 CEM，不证明优化充分；响应在裁剪后名义尾部计算，不能无条件外推。random bridge 需要独立构建与计费，本次如未实施须明确列为未覆盖。
