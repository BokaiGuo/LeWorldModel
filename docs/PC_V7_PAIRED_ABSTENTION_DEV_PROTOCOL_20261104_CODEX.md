# v7 配对弃权比较：事前开发协议

v6 在 Cube 已暴露单根的模型内决策中，精修前完整链与清零前缀比较链转成实际 float32 动作后完全相同；两次不同批调用的评分却相差约 `1.21e-8`，导致记录为未弃权。这是可复现记录支持的选择语义错误，不足以推断物理收益或其他任务的失败原因。

另立 v7，不改写 v6。v7 沿用 v6 生成、保留、CEM 和精修，预留两个完整链评分的 token；将精修后的 incumbent 和清零前缀链放入同一批，在当前上下文重新评分再作最终选择。如两个实际 float32 完整链逐元素相同，无论浮点评分微差，确定性地选择清零前缀并记录相同动作。否则按同批分数比较，清零得分小于或等于 incumbent 时弃权。这个规则不引入后验调节的近似相等阈值；近似相等但不同动作的数值稳定性仍需独立研究。

先用合成回归验证相同实际动作、不同动作、预算余量和 15/10/5 时域；再在相同已暴露 Cube 源上下文、原 checkpoint、合法输入与 1920 token 总预算上另存一项 v7 首轮诊断，使用与 v6 相同的 TF32 设置、两个 nominal 和 chart。v7 给原搜索的预算少于 v6，故两者具体链和得分不应作为匹配算法优劣比较；v7 重评分作为规划的一部分计入总预算。保留全部 v6 结果，不把新版本结果拼作 v6 或 PC gate 证据。
