# v22 PushT 动作派发和历史归一化审计

对已有 v22 开发记录，逐条核对 response、CEM 两臂，各三次重规划、各五次派发。审计器见[代码](../le-wm-main/experiments/audit_pc_jepa_v22_action_dispatch_20261105_codex.py)，[结果和输入哈希](../le-wm-main/results/pc_jepa_v22_action_dispatch_audit_20261105_codex.json)独立保存。

30/30 个记录的命令均与对应决策文件内最终选中链的前五步逐元素一致，也与 journal 中对应 step 的意图及决策哈希一致；逐个检查上一帧记录的 agent 位置，并重建 `absolute_target = agent_xy_before + 100 × action`。6/6 份重规划上下文中的历史动作包，可以从对应的十条已记录动作、保存的均值和标准差，按 float32 的乘 100、除 100、归一化及每五步打包规则精确重建。

这排除了这些**已保存记录**中所检查范围内的选择链与命令不匹配、历史包错位或目标位置计算多乘 100；不证明全部实验没有尺度或时间错误。journal 是调用意图而不是对运行中 `step` 参数的独立拦截。此前[同后端物理重放](../le-wm-main/results/pc_jepa_v22_contact_feedback_dev_20261104_codex/physical_replay.json)报告各帧状态和 RGB 一致，但与本审计都不能排除共同后端错误，也不能证明 checkpoint 训练来源、正常画面分布、规划性能或完整信息流权限。

30 条命令中 23 条至少一个相对动作坐标为负；由于环境声明的是 `[0,512]²`，这仍是声明空间与相对动作接口的已知冲突，不应简单把负动作当成执行出错。30 次派发前 agent 中心均在 `0–512` 画布内，CEM 有一次计算出的绝对目标在画布外；中心在画内不保证物体或全部运动过程可见。

本审计不改变 PC0–PC5，也不能把旧 v22 实验与新搜索核心拼接成同版本证据。下一步仍需预先固定动作域、画面边界和有效物体运动的任务合同，并分别审计真实视觉评分、规划与物理执行。
