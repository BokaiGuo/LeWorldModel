# 固定 cp10 动作排序的 normalizer 敏感性

固定两个开发根各自已执行的开放和反馈动作，共四条，不重新优化、
不新执行物理动作。以相同真实 cp10 RGB 历史和同一冻结模型，比较
已有部署 normalizer 与先前封存 PushT 归档动作统计；按同一备选
参数重建前缀、已执行第一片段及最后片段的全部动作 token。
目标 latent 和物理 RGB 均不变。部署路径必须复现已封存的同 cp10
预测向量；保存两套全部向量、分数、动作 token、模型和来源散列。

这是观察结果后提出的敏感性诊断，不按结果选择部署参数；归档统计
不证明 checkpoint 训练时的实际 normalizer。两根共享数据和历史，
不得据此声称独立确认、P1 通过或训练来源已认证。
