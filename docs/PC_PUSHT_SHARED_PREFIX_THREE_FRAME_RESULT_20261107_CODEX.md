# PushT 共同前缀尾部：三帧真实历史比较

四个已暴露开发任务复用各 301 条封存共同前缀候选。与单帧重评分的动作池、目标编码和最小末帧代价选择规则相同，三帧版本增加实际已执行的第 0、5、10 步 RGB 编码及前两个动作包。重新回放前十步，并逐步核对动作和物理快照；第 5、10 步编码与此前记录相符。先封存预测和选择，再关联先前物理回放结果。

任务 0 和 2 的选择发生变化，但没有改变这四个任务的成功数。每任务三帧重评分另需 903 次候选动作包预测、三次 predictor 调用；同步预测耗时约 0.054、0.020、0.020、0.020 秒，不包括编码、物理执行、候选保存和完整闭环。三帧历史与原生 rollout 的窗口对应关系有合成回归测试；相关测试合计 8 项通过。

这是事后固定池的条件实验，不是新的完整反馈策略评测；原闭环实际执行的首前缀更长，物理结局来自之前的全池回放，不是本次重新执行选中尾部。四任务不具独立确认效力，不能证明三帧历史总体无用，也不能把排序变化归因于行动后果描述。此结果不改变 PC0–PC5。
