# PushT RGB 旋转切向投影：固定池开发协议

基于已曝光任务 1 的静态角度交叉，检验与上次“三目标最小值”不同的
假设：用目标 RGB 的 `-8°/+8°` 合成旋转编码之差作为一维局部旋转
切向，从候选预测与原目标编码之差中去掉该方向，再计算平方距离。
旋转图只来自公开目标 RGB；不训练新模型，不读取物理姿态或后继标签。
合成旋转、质心、背景修补均非物理认证，投影也可能丢失有用目标信息。

复用四个已曝光任务各 301 条相同共同前缀链、两张合成目标及原目标
编码、该前缀真实执行后可观测 RGB 的既有编码和相同冻结 LeWM。
重算相同候选的条件预测并核对原目标评分；比较原始评分、投影评分及
固定种子一维随机方向投影。每个方向归一化，非有限或范数低于
`1e-6` 时对该目标回退原评分。所有方向和选择在访问物理标签前封存；
目标编码、预测以及相同随机向量均计入相应的成本说明。

按任务报告每臂选择、25 步内曾成功和末步成功、成功候选排名；不把
共享前缀的 301 个候选当作独立任务。事前开发出口：投影评分的任务 1
首选必须末步成功、任务 0 必须保持末步成功，且任务 1 的随机方向
首选不能末步成功；否则停止扩大这个固定投影。该出口是针对已知失败
案例的开发筛选，不是统计或 PC gate 门槛。候选中真实后继仅由独立
评估步骤读取，不可作为部署时的评分输入；共同前缀真实观测是过去已
执行的合法 RGB，但本实验是固定池反事实，不是实时闭环。

使用同源 GPU 评分和先前物理轨迹，不宣称独立环境、完整成本或方法
优势；如通过出口，还须在事前固定的新任务与共享同样评分权限的
基线上验证。
