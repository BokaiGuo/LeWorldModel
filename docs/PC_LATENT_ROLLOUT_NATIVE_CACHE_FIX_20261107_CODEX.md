# TwoRoom latent rollout：使用原生缓存接口的修复

## 根因与修复

此前候选参照仓库 `jepa.JEPA.rollout` 重新实现了多步预测，实际使用的
checkpoint 却实例化了 `stable_worldmodel.wm.lewm.lewm.LeWM`。两者的
动作编码和自回归张量构造路径不同；候选不应假定它们数值和梯度完全
等价。先前真实模型检查观察到多步梯度差，不能归因于理论失败。

已将 [候选接口](../le-wm-main/experiments/pc_latent_rollout_safe_20261107_codex.py)
改为调用当前安装版 LeWM 原生 `rollout`，通过 `info["emb"]` 提供
单帧缓存表示；不再替换模型的 `encode` 或自行重写预测循环。接口限制
为精确的 LeWM 类型和单初态批量候选，拒绝其他模型类，编码表示按原生
图像编码路径 detach，动作仍可求导。假像素张量只用于设定时钟 H=1，
不是额外图像观测。

## 验证

在两个已曝光 TwoRoom 图像上，冻结 RGB checkpoint，分别取 8 条合成
归一化动作包，覆盖模型时域 1、3、5。相对于旧的单线程原生注入路径：

- 全轨迹输出、全轨迹平方和对动作的梯度、最终 RGB 目标编码距离对动作
  的梯度，最大绝对差均为 **0**；原路径自身重复运行最大差也为 0。
- 两个不同输入在两个线程同时执行 GPU 推理，相对顺序执行的最大差为 0。
  这是一次有限并发检查，不是所有并发调度或训练模式的安全证明。
- 加载前后权重指纹一致；记录了模型类和实际实现源码哈希。
- 新旧路径相关测试 **9 项通过**，包括缓存路径不调用编码器、保留动作
  梯度和拒绝其他模型类型。

[GPU 机器记录](../le-wm-main/results/pc_latent_rollout_safe_gpu_audit_v4_20261107_codex.json)
与[审计代码](../le-wm-main/experiments/pc_latent_rollout_safe_gpu_audit_20261107_codex.py)
保留输入指纹及各条件数值。这个检查使用暴露过的开发根与合成归一化
动作，不是动作合法性、环境控制或独立任务证据。只覆盖当前安装版
LeWM、单帧输入和当前硬件；依赖升级后必须重新认证缓存语义。原历史
诊断脚本和结果未覆盖，接口尚未用于新闭环或宣称方法收益。

本次 `code-debugging` 检查揭示了此前以错误模型实现为参照的问题；
它没有证明 LeWM 动力学正确，也不改变 PC0–PC5 判定。
