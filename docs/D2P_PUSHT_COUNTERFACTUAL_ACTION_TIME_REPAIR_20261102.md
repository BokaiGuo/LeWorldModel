# PushT 反事实脚本：动作与时域修复

历史 `run_pusht_counterfactual.py` 将直接传给 `env.step` 的相对动作再次除以 100；但当前 PushT 环境内部才将这个相对动作乘以 `action_scale=100`。本地 HDF5 动作的物理重放合同也按相对命令处理。新脚本 `run_pusht_counterfactual_aligned_20261102.py` 使模型输入直接标准化同一环境命令；常量的 checkpoint 训练来源仍未知，不以此声称来源认证。历史脚本被既有 dev305 合同绑定，直接修改后会导致来源复验失败，因此已逐字恢复，不能用其原样生成新实验。

修复前脚本对每个物理动作步生成一个五步模型 packet：默认八个物理步却预测八个 packet，模型与真实终点未对齐。现在必须以五的倍数指定物理 horizon，模型 packet 数为 horizon/5；不完整的原生停止轨迹触发错误而不是按完整时域报告。冻结模型显式使用 eval 并禁止梯度，神经运行强制 CUDA，新输出目录不得覆盖旧结果。

动作单位、packet 数以及提前停止报告的三个回归测试通过。在主机 CUDA 使用 8 条校准轨迹、4 个配对根和每个根的正／负／零三条十步轨迹完成开发 smoke；输出 `le-wm-main/results/pusht_counterfactual_contract_repair_20261102_DEV01/counterfactual.json`，SHA-256 `3b789280a4cf3834c66f14ed6fc33250b3811e7979f7394e2c16109bae5a180b`。该次运行临时修改过的旧脚本 SHA-256 为 `13a97d1732231712542aa7f221e386b2368f2ade1fa85cd96340326af9def95d`；之后将相同推理逻辑复制至独立脚本并加入输出目录防覆盖约束，原脚本已经恢复，历史 dev305 核验重新通过。

此次只有一个初始 RGB，而非训练配置中的完整三帧真实历史；线性 Ridge 是使用独立校准数据的离线评估读出，不是部署规划器，也不是无训练方法的一部分。四个根仅用于 smoke，无法提供确认性统计。脚本未保存每一步动作／图像和预测向量，也没有完整成本账本及冻结前后权重哈希，因此不能据此认证独立泛化、完整闭环或 P1 通过。历史上由修复前脚本产生的结果应视为带动作尺度及时域错配限制，不能原样用于模型预测准确性的证据；其他运行脚本需按各自路径检查，不能一概认定同样受影响或已修复。
