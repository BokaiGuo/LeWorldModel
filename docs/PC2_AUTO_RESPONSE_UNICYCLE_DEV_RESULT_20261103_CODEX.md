# 自动响应前缀：精确动力学开发结果

本记录对应事前协议 `PC2_AUTO_RESPONSE_UNICYCLE_DEV_PROTOCOL_20261103_CODEX.md`。计划先封存，再对所选链干预；原始计划及干预 JSON 均保存在 `le-wm-main/results/pc2_auto_response_unicycle_dev_20261103_codex_*`，干预文件绑定计划哈希。

16 个已暴露方向任务，两步精确 unicycle；响应生成使用四个人工设定的名义点，有限差分和 SVD，后缀为固定转角的 33 点速度网格。以下为开发结果，距离越小越好：

| 方法 | 平均终距 | 非即时进展数 | 完整有限机制见证数 |
| --- | ---: | ---: | ---: |
| 响应生成＋完整链选择 | 0.05058 | 2 | 2 |
| 同库即时 greedy | 0.28186 | 0 | 0 |
| 同库五点 lookahead | 0.05643 | 3 | 2 |
| 随机桥接＋完整链选择 | 0.31980 | 10 | 5 |

响应臂的有限见证为任务 3、12；lookahead 也是 3、12；随机桥接为 2、3、4、10、12。响应臂 16/16 终距优于随机臂，但随机候选没有目标响应信息，且这个对照未匹配同一名义点和完整计算成本，不能据此声称谱分解增量或公平性能优势。

有限见证要求同一实际选中前缀同时满足：首步无即时进展、所选共同后缀相对零后缀的响应优于 zero 与同库 greedy、同预算各自后缀重规划优于两者。前缀为相同时严格优势自然失败。结果支持可复算的开发机制线索，不能把未选候选的性质赋给执行链。

每个响应库的四个名义点共需 20 次两步 rollout 和 4 次 SVD；每个库额外缓存 5 次前缀评价和 165 次两步后缀评分。greedy 和 lookahead 在该诊断实现中复用全库缓存，所记录的 165 次是实际共享诊断缓存，而不是其独立执行所需最少成本；随机臂不支付响应/SVD 成本。不能把这次比较当作等总成本评测。

边界：任务和精确状态已暴露，名义点是人工设定，候选只由一次局部响应生成，后缀是一维网格；这里没有完整动作联合优化器、视觉观测、来源合格独立任务，亦未实现跨后继自动组合。因此不是 PC2 全合同通过，不是 PC3、公平规划优势或 SVD 独立贡献的确认。原 gate 和历史结果未改。

新增两个测试检查动作合法性、封存不可覆盖、选择与干预绑定及共同后缀计算；测试通过不构成机制或性能证据。
