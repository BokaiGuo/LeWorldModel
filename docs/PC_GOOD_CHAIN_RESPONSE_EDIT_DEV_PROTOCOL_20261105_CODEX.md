# 好链局部响应修改：固定机会与等 token 开发合同

使用已暴露 ranked 开发面板的 16 个 root，每根取 `random_min` 日志中共享全局候选库按原终距稳定排序后的第一个合法去重完整链作为共同父链；不使用特权见证。对该父链事后诊断，不宣称新任务、独立确认或完整端到端方法。

分 3 个五步片段：其余片段包括原尾不变。响应臂在父链每个片段的 10 个动作坐标做裁剪后的 ±0.05 完整链割线（每坐标的实际 float32 差作为分母），得到终点二维响应矩阵，取 `Jᵀ(goal - parent_feature)` 方向并按最大绝对坐标归一化；零范数保留零方向并记录。随机臂使用按 root、重复编号和片段确定的正态方向，采用同一归一化。每片段生成 ±0.25、±0.5 的 4 个动作修改，共 12 条；所有候选完整链保留原尾、裁剪到动作域、计费并参与 incumbent。选父链与候选的最低代价者，交由相同完整链 CEM 修复；记录来源、实际裁剪后幅度、起始与最终动作及分数。

每根两个预定优化随机流 `2051100000 + root*2 + repeat`。固定机会实验：响应、随机修改各使用同样 84 次完整链 CEM 评分；直接 CEM 从相同父链使用 84 次评分。两类编辑分别额外支付 73 次和 13 次评分，所以这不是等总成本比较。等总成本实验：每臂总计 157 次完整链评分；响应臂 `1+60+12+84`，随机臂 `1+12+144`，直接 CEM `157`。CEM 配置 batch 12、elite 4，全部评分包含父链和 incumbent，返回实际已评分最佳链。每评分完整 15 步计 3 prediction tokens；随机臂不计算响应或 SVD。

按 root 和预定随机流逐项记录初始、候选、最终质量、成功阈值 `<0.05`、编辑归属、评分次数、token、墙钟时间；分别汇总根级配对差和失败。固定机会只回答候选是否有用，等 token 才比较预算挤占；两者的输出不得混算。prediction-token 不等于 CPU/GPU 总成本，显式计时只作开发测量。所有运行均封存协议、源码、动力学、原任务和输入输出；任何异常保留为失败。

该实验只测特定局部任务梯度和随机方向，不证明任意谱方向无效或重配置机制。完整链修复可改变所有片段，不应称为固定前缀后缀机制干预；若发现收益，须在新预定开发面板、同链机制和强基线下重新验证。
