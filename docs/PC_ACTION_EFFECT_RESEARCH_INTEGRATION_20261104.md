# Planning Compiler 研究扩展：受控诊断与冻结模型行动后果描述

日期：2026-11-04；状态更新：2026-11-05。本文件是研究合同，不代表全部实验已通过。行动后果描述与候选保留已有精确动力学开发实现及实验；这些开发结果不是独立确认，也未建立规划优势。冻结视觉模型的描述可信性和同版本真实闭环仍待验证。

本文件是现有研究规范的增补，不替换任何历史协议、冻结依赖、结果或 PC0–PC5 判定。既有实验须按各自版本、权限与协议解释，不自动升级为确认性证据；本文件不授权重开已停止面板。

全项目分工见[研究体系总图](RESEARCH_SYSTEM_MAP_20261104.md)：本候选属于冻结 Planning Compiler，不另立训练方法或替代历史迁移诊断。

## 1. 在研究体系中的位置

本方案归入第一篇 **冻结视觉世界模型上的 Planning Compiler / D2P**，不是两篇互不相干的“表征分析”和“规划算法”：

> 冻结模型能否通过共同动作查询识别控制相关的状态差异，并利用这些差异发现、保留和执行有效动作程序？

第一篇的中心是行动后果信息的可信性与规划利用，而不是预设谱方法必须胜出；谱是待独立消融的候选工具。

证据链为：受控变化 → 行动后果描述的可信性 → 未查询动作上的预测性 → 程序搜索的净收益 → 真实闭环及泛化。

本方案服从统一总问题：

> 世界模型是否保留了支持决策的信息？如果保留了，怎样有效利用；如果不足，怎样识别，并通过独立训练路线修复？

因此，动作—任务传递、行动后果描述和真实控制收益是共同证据对象；谱、局部响应、
受控图像配对和接触分析是工具，不是新增的并列方法线。

| 研究部分 | 本方案职责 | 不允许越界的结论 |
| --- | --- | --- |
| 受控视觉/物理诊断 | 检验外观变化、几何变化和控制机会变化如何影响表征、评分与动作后果 | 静态因素替换不等于动态控制正确，也不证明潜变量已语义解耦 |
| 冻结模型 Planning Compiler | 不训练新模型，从已有动力学发现、组合并利用有效动作程序 | 模型预测不是物理真值；更多探针不自动证明独立贡献 |
| 谱/局部响应路线 | 作为候选生成、局部描述和强组件对照，与有限动作后果路线比较或受控组合 | 新描述有效不自动证明高维谱增量 |
| GDD-OPD / 训练新表示 | 如需训练 encoder、predictor、adapter 或学习度量，另立有训练声明的分支 | 不得用后训练结果替代冻结模型主结果 |

诊断与规划属于同一篇研究，但信息权限分开：诊断端可使用受控环境和物理真值；
正式规划器只能使用合法观测、目标、历史和模型预测。训练新表示或 adapter 时，
证据进入 GDD-OPD 等独立训练分支。

## 2. 同一个对象，两套隔离的数据通道

令 `h_t` 为时刻 `t` 的合法观测与动作历史，`g` 为目标，`p` 为候选前缀，`H=H_t-|p|` 为该候选的剩余时域，`Q_H={u_0,…,u_(K-1)}` 为本层所有候选共享且长度为 `H` 的后缀探针库，其中 `u_0` 为零尾。

定义：

- `D_hat_theta(h_t, g, p; Q_H) = {c_hat_j(p)}_j`：绑定历史、目标、前缀和剩余时域的行动后果描述；
- `c_hat_j(p) = C_hat(h_t, p ⊕ u_j, g)`：冻结模型预测的完整链绝对目标代价；
- `b_hat_j(p) = c_hat_0(p) - c_hat_j(p)`：相对该前缀自身零尾的改善；
- `s_hat(p)`：描述的可审计记录，至少包含绝对代价向量、相对改善向量、后缀动作身份与顺序、上下文/目标/时域/模型指纹、请求成本和失败状态。

正式写法为：

`D_theta(h_t, g, p; Q_(H))`

绝对代价不能删除：相对改善大不代表最终结果好。描述必须绑定具体动作、模型上下文、目标、时域、代价单位和模型指纹；不同剩余时域不能未经定义直接比较。有限探针不是完整可达集合，不保证定位语义潜变量或识别因果状态。

**部署通道：**合法输入 → 冻结模型预测 → 描述 → 保留/优化分配 → 完整链选择 → 实际派发。不得读取真实后继、模拟器状态、接触标签、干预类别或验证后缀结果。

**评估通道：**封存计划/候选 → 受控渲染或可执行环境重置 → 同动作真实后果 → `s_real`、物理指标及审计。评估端只能报告结果，不能向当前运行回传候选或分数。

开发标签可用于明确标记的开发选择，但必须计入开发暴露；测试标签不能调规则。若用物理真值拟合投影、权重或评分，必须披露监督来源并另立版本，不能称作无额外监督的冻结模型主方案。

## 3. 三项可证伪假设

| 假设 | 实验问题 | 失败时如何处理 |
| --- | --- | --- |
| H1：控制相关性 | 物理后果不变的外观变化是否较少改变描述，而真实控制机会变化是否被正确反映？ | 定位编码、评分、动态预测或描述误差；不直接扩大规划实验 |
| H2：样本外预测性 | 描述能否预测未参与构造的后缀/优化随机流下的质量，优于即时距离、局部岭值和简单探针统计？ | 收缩为有限 lookahead 统计，不宣称一般控制能力描述 |
| H3：规划净收益 | 描述带来的收益能否抵消其查询、编码和筛选成本？ | 保留有界负结果；不将诊断可信性提升为规划优势 |

不要求所有图像都有“对立面”。采用可核验的受控关系；同一物体身份不意味着完整 latent 或控制状态相同。视角变化可能改变遮挡、可观测性或动作解释，必须单独认证，不能一律当成无关干扰。

## 4. 诊断设计：变化 × 动作

三类配对：物理状态不变的外观对照；固定相机的几何变化；尽量匹配即时目标距离而改变接近方向、接触侧或通路的控制机会变化。

### 4.1 既有视觉结果与下一次诊断的边界（2026-11-05）

已有同动作视觉诊断，不应重复声称接口尚不存在。v11 的 64 条链只有两个物体位置结果；v12 的 56 条规划器候选没有产生物体姿态差异，另 8 条是仅供评估的特权见证变体。后续对 v12 进行了同实现、同批形状神经重跑，64 条评分逐项一致，但不是独立实现或独立任务复现。两者都是暴露过的单根事后诊断，不能把相关动作对当独立任务，也不能证明正式规划器能发现特权链。详见 [v11](PC_JEPA_V11_SAME_BANK_PHYSICAL_SCORE_DIAG_RESULT_20261104_CODEX.md)、[v12](PC_JEPA_V12_CONTACT_SCORE_BANK_POSTHOC_RESULT_20261104_CODEX.md) 和 [v12 神经重跑](PC_JEPA_V12_NEURAL_REPLAY_AUDIT_RESULT_20261105_CODEX.md)。

后续 [v22 特权接触库 latent 诊断](PC_JEPA_V22_CONTACT_LATENT_ERROR_RESULT_20261105_CODEX.md) 区分了预测后继与真实编码的误差，以及真实编码评分与物理角度的排序；结果提示两类问题均需继续检查，但 agent 位置等因素同时变化，不能认定 encoder 丢失角度或证明评分因果失效。该库包含特权见证、共享已暴露目标和相关动作，不能作为独立确认或公平规划成绩。

下一次视觉开发诊断须在运行前固定以下合同；下列是要求，不是已完成的实验或确认性预注册：

1. 指明开发任务来源、模型与 normalizer、历史动作对齐、动作单位、物理时钟及终止规则；来源不明项保持 unknown，不以新 seed 替代独立性证明。选择包含可执行物体姿态变化的受控候选，同时保留未产生变化与失败的样本，不能根据实验结果事后筛选分母。
2. 封存相同合法历史和目标下的前缀与共同构造后缀，以及动作身份、长度和顺序；将未查询的验证后缀及其评分隔离，不能用于构造描述、选择候选或确定阈值。可用评估端物理状态构造并验证诊断配对，但禁止进入正式规划器。
3. 对每条相同动作分别保存预测后继评分、真实后继 RGB 编码评分和物理指标；完整绑定动作、初始状态、图像、模型与上下文哈希，记录失败、终止和实际费用。分别检查预测与真实编码的差异，以及真实编码评分与物理结果的关系，不能把任何一项失配直接认定为另一项的原因。
4. 预先定义物理变化尺度、排序并列和失效处理；按根汇总而非将候选对视为独立样本。构造探针、未查询后缀和不同根的结果分别报告；诊断性特权候选不得混作规划候选或预算匹配性能。
5. 在开发结果和预定标准支持后，才将同一冻结版本接入 RGB 反馈及公平规划比较。若候选不足以覆盖物理后果，应报告不可识别，不能据此推断评分有效或无效。

每类配对均检查重置、历史、目标图、相机、动作坐标和物理时钟。静态几何替换只用于视觉诊断；动态机制需使用合法状态与可执行轨迹，不能把任意合成图像当成可达反事实。生成模型产生的对立视角只能提出假设，不能自证因素已隔离。

同动作记录四种量：

1. 原始 latent/任务评分差异；
2. 冻结世界模型预测后果；
3. 真实后继经同一冻结 encoder 得到的评分；
4. 评估端物理任务结果。

由此分别定位外观敏感性、模型预测误差、代理评分失配和搜索不足。接触标签或分支变化仅是解释变量，不能单独认证因果机制。

构造探针库、验证后缀库和最终确认任务必须分开。验证后缀不得参与描述构造、候选选择、阈值选择或优化机会分配；验证同时覆盖新动作序列及新优化随机种子，不能仅换 seed 后把几乎相同的动作视为充分泛化。验证费用与部署查询费用分别记录。

## 5. 首版算法：只替换保留依据

首版固定现有候选生成、共享全局库、动作域、后缀优化器、精修、incumbent 和弃权规则；先不同时修改评分和生成器。

1. 为同一层候选生成共同、合法且固定剩余长度的探针。
2. 每次请求前记录动作、上下文、探针身份与预计费用。
3. 计算 `s_hat(p)`；所有实际评分的完整链都参与 incumbent 比较。
4. 固定保留一个 greedy 槽，其余槽比较机会互补规则。
5. 保留后的完整链使用共同优化器；精修/弃权后重新绑定机制评价。
6. 剩余尾部长度为零时直接用完整链评分，不添加末层后继探针。

候选集合目标可从下式开展开发验证：

`F(S) = Σ_j w_j max_{p∈S} [τ - c_hat_j(p)]_+`。

它鼓励覆盖不同探针上的较好绝对结果，而非仅奖励描述距离。`τ`、`w_j`、尺度和零值退化时的决胜规则必须在开发阶段预定/冻结；此式不是已验证默认方法。若全部低于质量要求则按预定规则回退，不按根手工选策略。

必须同时比较：

- 同探针最小终距、均值/简单统计、完整描述互补规则；
- 即时 greedy、状态多样性、原局部岭值和随机保留；
- 真正不计算响应/探针的 global CEM，省下预算允许用于优化；
- 跨候选独立打乱非零探针身份对应的消融，保持各候选分数集合和零尾基准不变。

固定机会比较只定位信息价值；端到端比较包含全部生成与描述成本。随机动作需报告裁剪后的幅度和时序结构差异。只计算同一组探针的最低分属于有限 lookahead，不能重新命名后当成新贡献。

## 6. 实验矩阵与原 gate 的关系

| 阶段 | 交付物 | 对应证据 |
| --- | --- | --- |
| 精确动力学预检 | 固定候选、真实动作后果、匹配后缀优化机会及消融 | 排除视觉误差，验证搜索假设；不是视觉 PC1 |
| 冻结视觉配对诊断 | 外观/几何/控制机会配对与模型—真实后果对照 | PC0/PC1 的输入、评分及任务相关性 |
| 验证库泛化 | 未查询后缀上的质量预测与误差分析 | 描述可信性；不等于 PC3 |
| 最终链干预 | 自动选中、精修及弃权后的链；共同尾和等预算重规划 | PC2；区分光滑与非光滑解释 |
| 完整规划比较 | 强基线、关键消融、完整质量—成本曲线 | PC3；独立任务和预定统计要求不变 |
| 合法 RGB 闭环 | 同核心执行、观测、更新历史与重规划 | PC4 |
| 跨来源复现 | 未见目标、独立 checkpoint、另一架构 | PC5 |

PC2不要求基线永远找不到同一条链；响应/描述组件的独立增量需单独消融。若保留谱独立增量主张，新描述不能替代原谱增量合同。旧 matched-alignment 跨模型预测真实规划后果的问题仍独立，不能由新描述的局部收益倒推通过。方法只在机制、预测性或成本中的某一项成立时，应相应缩小主张，而非修改 gate。

## 6.1 统一推进顺序

1. **验证信息**：输入、时钟、可解性、评分和动作后果可信性；
2. **验证利用**：比较行动后果描述、即时距离、局部岭值和普通 lookahead，先固定优化机会，再核对完整成本；
3. **验证机制**：对最终实际选中链做同链干预，区分链本身的机制与组件的发现贡献；
4. **验证价值**：冻结候选后进行强基线、真实闭环和独立泛化确认。

训练路线可以并行开展，但不改变 Planning Compiler 的冻结模型边界。

确认前冻结主要物理指标、最小实际效应、样本量/功效依据、配对单位、失败处理、多重比较和停止规则。任务/根为统计单位，候选、探针和多臂重复不是独立任务。开发外、normalizer 拟合外、checkpoint 训练外分别认证；未知保持 unknown。

## 6.2 机制存在与发现贡献的双实验合同

对最终自动选中的 `Π = B ∘ P`，其中 `B` 为重配置前缀、`P` 为后续进展动作，必须报告两类不同证据：

### Experiment A — Chain Mechanism Test

在同一物理起点固定最终链，比较 `B ∘ P` 与时长、动作约束、预算匹配的 `B0 ∘ P`。该实验回答：`B` 是否改变了真实后继控制条件，使 `P` 变得有效。它认证链本身的机制性质，不认证响应/描述组件的独立发现贡献。

### Experiment B — Discovery Contribution Test

固定候选生成预算或候选全集，比较普通目标评分、局部 reachability value、ordinary lookahead、action-effect description 及不同 retention 规则。该实验回答：新增组件是否提高有效链的发现概率、质量或成本效率。

A 成功/B 失败只能支持“环境存在机制、组件未显示独立搜索价值”；B 成功/A 失败只能支持“规划结果可能改善、但尚不能归因于声明机制”。两者均须保留完整失败分母，并在 PC2/PC3 中分开登记。

## 6.3 最小消融矩阵与公平性

附件中的“Spectral + Effect”和“Full Planning Compiler”若三列因素完全相同，不构成两个独立方法臂。正式最小矩阵改为：

| 臂 | 候选生成 | 后续评价 / 保留 |
| --- | --- | --- |
| A | 非谱、预定生成器 | 普通 lookahead |
| B | 谱生成器 | 普通 lookahead |
| C | 与 A 相同 | 行动后果描述 + 机会互补保留 |
| D | 与 B 相同 | 行动后果描述 + 机会互补保留 |
| E | 与 D 相同 | 同样计算描述，但仅按探针最小代价保留 |

A–D 检验谱候选生成与行动后果利用是否互补；D–E 使用相同描述及探针，检验机会互补保留是否优于同探针最小代价保留。它不能单独证明描述本身的独立预测价值；还需未查询后缀、简单统计及动作身份打乱等对照。固定候选池实验只隔离评价和保留，不能同时证明生成器贡献；端到端实验允许候选不同，但必须完整计费。若另设 Full，必须显式说明相对 D 新增的组件并单独隔离。

第一层固定候选池和相同后缀优化机会，用于识别评价/保留作用；第二层删除响应计算并将节省预算交给对照，用于端到端净收益。全部 probe、Jacobian、SVD、编码、筛选、缓存、反馈和同步成本均计入。global CEM 保留为合法强对照，不得删除以迫使响应臂产生阳性。普通 lookahead 必须事前定义，不能用同一探针最低分换名为新方法。

## 6.4 三项主张及失败收缩

第一篇只检验三项逐层主张：

1. **Information**：模型预测的行动后果与真实后果一致，并能预测未查询动作的质量；静态 latent 差异或构造探针拟合不能替代它；
2. **Utilization**：行动后果描述确实改善候选保留、程序组合或优化分配；多做模型调用或库中存在好链不能替代它；
3. **Realization**：完整成本下获得真实执行与独立任务收益；模型评分下降、单根成功或旧版本闭环不能替代它。

若仅有诊断准确性，结论收缩为信息诊断；若仅更多 probe/lookahead 有效，按额外搜索计算归因；若必须训练 readout、encoder、predictor 或 adapter，转入 GDD-OPD/独立训练协议。不得用任一层结果替代其他层。

## 7. 并行开发与联合验收

依赖顺序固定为：**协议与权限固定 → 两条并行开发路径 → 联合验收**。

- **精确动力学路径**：先验证行动后果描述与保留算法是否有作用，排除视觉编码、预测或代理评分误差；
- **冻结视觉路径**：并行验证受控外观/物理变化、预测后果与真实物理结果是否一致；
- **联合阶段**：将同一候选接入 RGB 反馈，完成最终链机制、完整成本和公平规划比较。

视觉诊断不阻塞精确动力学算法开发；但在描述可信性未建立前，不得宣称视觉规划机制成立。

## 9. 配置、成本与待冻结项

训练：无参数更新，无新增 optimizer/epoch/learning-rate 配置。任务评分首版沿用共同合法评分；若更改评分，单独版本且基线共享。

开发起点建议为每根最多16候选、每候选8探针（包含零尾）。15步完整链、5步packet且不缓存时，描述查询为 `16 × 8 × 3 = 384` prediction-token/根。该例不是已批准运行预算；候选生成、编码、精修、分解与反馈另计。若沿用2880-token开发上限，384必须从中扣除。

GPU/CPU身份、计时起止、预热、同步、内存峰值、编码与载入成本、缓存命中和复用政策需预先明确；不适用字段记 N/A，不能填零冒充测量。构造与验证/物理干预成本分开保存。

未冻结：环境与checkpoint来源、任务生成范围、探针参数、候选数、权重/阈值、预算点、确认样本量、实际效应标准及停止规则。上述缺项完成前不得称为确认协议。

## 10. 最终交付与失败分支

单篇主线按“可信性 → 预测性 → 规划效用”组织，而非三份实验日志：

- 问题与方法：为何需要行动后果描述、合法输入和冻结模型边界。
- 可信性：受控变化及模型—物理后果一致性。
- 预测性：未查询后缀，排除仅复述探针评分。
- 效用：同链机制、强基线、真实控制及完整质量—成本曲线。
- 泛化与限制：来源、架构、局部/接触失效、未建立的谱或语义解耦主张。

若描述准确但无控制收益，只能形成诊断性结论，不算原 Planning Compiler 闭环；若仅更多探针有效，应归因于计算/lookahead；若必须后训练才有效，转入明确训练分支。新颖性与外部相关工作需独立文献核查，本文件不宣称首次提出。

最终交付分为两条方法主线：

- Planning Compiler：可信的控制相关信息如何被冻结模型规划器利用；
- GDD-OPD：缺失或失真的决策结构如何通过训练内化并在独立动作上验证。

两条主线共享评估工具和合法基础资产，但不互相借用成绩；诊断正确、代码完成、
机制见证、性能优势和独立复现分别登记。
