# Planning Compiler 研究扩展：受控诊断与冻结模型行动后果描述

日期：2026-11-04。状态：纳入研究体系的候选方案；未实现、未预注册、未运行本方案实验，未建立新贡献。

本文件是现有研究规范的增补，不替换任何历史协议、冻结依赖、结果或 PC0–PC5 判定。已有实验只作为设计依据，不自动算作本方案的证据。首轮仅整合研究设计，不授权重开已停止面板。

全项目分工见[研究体系总图](RESEARCH_SYSTEM_MAP_20261104.md)：本候选属于冻结 Planning Compiler，不另立训练方法或替代历史迁移诊断。

## 1. 在研究体系中的位置

本方案归入第一篇 **冻结视觉世界模型上的 Planning Compiler / D2P**，不是两篇互不相干的“表征分析”和“规划算法”：

> 冻结模型能否通过共同动作查询识别控制相关的状态差异，并利用这些差异发现、保留和执行有效动作程序？

证据链为：受控变化 → 行动后果描述的可信性 → 未查询动作上的预测性 → 程序搜索的净收益 → 真实闭环及泛化。

本方案服从统一总问题：

> 世界模型是否保留了支持决策的信息？如果保留了，怎样有效利用；如果不足，怎样识别，并通过独立训练路线修复？

因此，动作—任务传递、行动后果描述和真实控制收益是共同证据对象；谱、局部响应、
受控图像配对和接触分析是工具，不是新增的并列方法线。

| 研究部分 | 本方案职责 | 不允许越界的结论 |
| --- | --- | --- |
| 受控视觉/物理诊断 | 检验外观变化、几何变化和控制机会变化如何影响表征、评分与动作后果 | 静态因素替换不等于动态控制正确，也不证明潜变量已语义解耦 |
| 冻结模型 Planning Compiler | 不训练新模型，从已有动力学发现、组合并利用有效动作程序 | 模型预测不是物理真值；更多探针不自动证明独立贡献 |
| 谱/局部响应路线 | 作为候选生成、局部描述和强组件对照，与有限动作后果路线比较或受控组合 | 新描述有效不自动证明高维谱增量 |
| GDD-OPD / 训练新表示 | 如需训练 encoder、predictor、adapter 或学习度量，另立有训练声明的分支 | 不得用后训练结果替代冻结模型主结果 |

诊断与规划属于同一篇研究，但信息权限分开：诊断端可使用受控环境和物理真值；
正式规划器只能使用合法观测、目标、历史和模型预测。训练新表示或 adapter 时，
证据进入 GDD-OPD 等独立训练分支。

## 2. 同一个对象，两套隔离的数据通道

令 `h` 为合法观测与动作历史，`g` 为目标，`p` 为候选前缀，`U={u_0,…,u_(K-1)}` 为本层所有候选共享的后缀探针库，其中 `u_0` 为零尾，所有尾部长度等于剩余时域。

定义：

- `c_hat_j(p) = C_hat(h, p ⊕ u_j, g)`：冻结模型预测的完整链绝对代价；
- `b_hat_j(p) = c_hat_0(p) - c_hat_j(p)`：相对该前缀自身零尾的改善；
- `s_hat(p)`：绝对代价向量、相对改善向量、后缀身份、时域、有效性标记共同组成的临时描述。

绝对代价不能删除：相对改善大不代表最终结果好。描述必须绑定具体动作、模型上下文、目标、时域和代价单位；不同剩余时域不能未经定义直接比较。有限探针不是完整可达集合，不保证定位语义潜变量或识别因果状态。

**部署通道：**合法输入 → 冻结模型预测 → 描述 → 保留/优化分配 → 完整链选择 → 实际派发。不得读取真实后继、模拟器状态、接触标签、干预类别或验证后缀结果。

**评估通道：**封存计划/候选 → 受控渲染或可执行环境重置 → 同动作真实后果 → `s_real`、物理指标及审计。评估端只能报告结果，不能向当前运行回传候选或分数。

开发标签可用于明确标记的开发选择，但必须计入开发暴露；测试标签不能调规则。若用物理真值拟合投影、权重或评分，必须披露监督来源并另立版本，不能称作无额外监督的冻结模型主方案。

## 3. 三项可证伪假设

| 假设 | 实验问题 | 失败时如何处理 |
| --- | --- | --- |
| H1：控制相关性 | 物理后果不变的外观变化是否较少改变描述，而真实控制机会变化是否被正确反映？ | 定位编码、评分、动态预测或描述误差；不直接扩大规划实验 |
| H2：样本外预测性 | 描述能否预测未参与构造的后缀/优化随机流下的质量，优于即时距离、局部岭值和简单探针统计？ | 收缩为有限 lookahead 统计，不宣称一般控制能力描述 |
| H3：规划净收益 | 描述带来的收益能否抵消其查询、编码和筛选成本？ | 保留有界负结果；不将诊断可信性提升为规划优势 |

不要求所有图像都有“对立面”。采用可核验的受控关系；同一物体身份不意味着完整 latent 或控制状态相同。视角变化可能改变遮挡、可观测性或动作解释，必须单独认证，不能一律当成无关干扰。

## 4. 诊断设计：变化 × 动作

三类配对：物理状态不变的外观对照；固定相机的几何变化；尽量匹配即时目标距离而改变接近方向、接触侧或通路的控制机会变化。

每类配对均检查重置、历史、目标图、相机、动作坐标和物理时钟。静态几何替换只用于视觉诊断；动态机制需使用合法状态与可执行轨迹，不能把任意合成图像当成可达反事实。生成模型产生的对立视角只能提出假设，不能自证因素已隔离。

同动作记录四种量：

1. 原始 latent/任务评分差异；
2. 冻结世界模型预测后果；
3. 真实后继经同一冻结 encoder 得到的评分；
4. 评估端物理任务结果。

由此分别定位外观敏感性、模型预测误差、代理评分失配和搜索不足。接触标签或分支变化仅是解释变量，不能单独认证因果机制。

构造探针库、验证后缀库和最终确认任务必须分开。验证同时覆盖新动作序列及新优化随机种子，不能仅换 seed 后把几乎相同的动作视为充分泛化。验证费用与部署查询费用分别记录。

## 5. 首版算法：只替换保留依据

首版固定现有候选生成、共享全局库、动作域、后缀优化器、精修、incumbent 和弃权规则；先不同时修改评分和生成器。

1. 为同一层候选生成共同、合法且固定剩余长度的探针。
2. 每次请求前记录动作、上下文、探针身份与预计费用。
3. 计算 `s_hat(p)`；所有实际评分的完整链都参与 incumbent 比较。
4. 固定保留一个 greedy 槽，其余槽比较机会互补规则。
5. 保留后的完整链使用共同优化器；精修/弃权后重新绑定机制评价。
6. 剩余尾部长度为零时直接用完整链评分，不添加末层后继探针。

候选集合目标可从下式开展开发验证：

`F(S) = Σ_j w_j max_{p∈S} [τ - c_hat_j(p)]_+`。

它鼓励覆盖不同探针上的较好绝对结果，而非仅奖励描述距离。`τ`、`w_j`、尺度和零值退化时的决胜规则必须在开发阶段预定/冻结；此式不是已验证默认方法。若全部低于质量要求则按预定规则回退，不按根手工选策略。

必须同时比较：

- 同探针最小终距、均值/简单统计、完整描述互补规则；
- 即时 greedy、状态多样性、原局部岭值和随机保留；
- 真正不计算响应/探针的 global CEM，省下预算允许用于优化；
- 跨候选独立打乱非零探针身份对应的消融，保持各候选分数集合和零尾基准不变。

固定机会比较只定位信息价值；端到端比较包含全部生成与描述成本。随机动作需报告裁剪后的幅度和时序结构差异。只计算同一组探针的最低分属于有限 lookahead，不能重新命名后当成新贡献。

## 6. 实验矩阵与原 gate 的关系

| 阶段 | 交付物 | 对应证据 |
| --- | --- | --- |
| 精确动力学预检 | 固定候选、真实动作后果、匹配后缀优化机会及消融 | 排除视觉误差，验证搜索假设；不是视觉 PC1 |
| 冻结视觉配对诊断 | 外观/几何/控制机会配对与模型—真实后果对照 | PC0/PC1 的输入、评分及任务相关性 |
| 验证库泛化 | 未查询后缀上的质量预测与误差分析 | 描述可信性；不等于 PC3 |
| 最终链干预 | 自动选中、精修及弃权后的链；共同尾和等预算重规划 | PC2；区分光滑与非光滑解释 |
| 完整规划比较 | 强基线、关键消融、完整质量—成本曲线 | PC3；独立任务和预定统计要求不变 |
| 合法 RGB 闭环 | 同核心执行、观测、更新历史与重规划 | PC4 |
| 跨来源复现 | 未见目标、独立 checkpoint、另一架构 | PC5 |

PC2不要求基线永远找不到同一条链；响应/描述组件的独立增量需单独消融。新描述不能替代原谱增量合同。方法只在机制、预测性或成本中的某一项成立时，应相应缩小主张，而非修改 gate。

## 6.1 统一推进顺序

1. **验证信息**：输入、时钟、可解性、评分和动作后果可信性；
2. **验证利用**：比较行动后果描述、即时距离、局部岭值和普通 lookahead，先固定优化机会，再核对完整成本；
3. **验证机制**：对最终实际选中链做同链干预，区分链本身的机制与组件的发现贡献；
4. **验证价值**：冻结候选后进行强基线、真实闭环和独立泛化确认。

训练路线可以并行开展，但不改变 Planning Compiler 的冻结模型边界。

确认前冻结主要物理指标、最小实际效应、样本量/功效依据、配对单位、失败处理、多重比较和停止规则。任务/根为统计单位，候选、探针和多臂重复不是独立任务。开发外、normalizer 拟合外、checkpoint 训练外分别认证；未知保持 unknown。

## 8. 配置、成本与待冻结项

训练：无参数更新，无新增 optimizer/epoch/learning-rate 配置。任务评分首版沿用共同合法评分；若更改评分，单独版本且基线共享。

开发起点建议为每根最多16候选、每候选8探针（包含零尾）。15步完整链、5步packet且不缓存时，描述查询为 `16 × 8 × 3 = 384` prediction-token/根。该例不是已批准运行预算；候选生成、编码、精修、分解与反馈另计。若沿用2880-token开发上限，384必须从中扣除。

GPU/CPU身份、计时起止、预热、同步、内存峰值、编码与载入成本、缓存命中和复用政策需预先明确；不适用字段记 N/A，不能填零冒充测量。构造与验证/物理干预成本分开保存。

未冻结：环境与checkpoint来源、任务生成范围、探针参数、候选数、权重/阈值、预算点、确认样本量、实际效应标准及停止规则。上述缺项完成前不得称为确认协议。

## 9. 最终交付与失败分支

单篇主线按“可信性 → 预测性 → 规划效用”组织，而非三份实验日志：

- 问题与方法：为何需要行动后果描述、合法输入和冻结模型边界。
- 可信性：受控变化及模型—物理后果一致性。
- 预测性：未查询后缀，排除仅复述探针评分。
- 效用：同链机制、强基线、真实控制及完整质量—成本曲线。
- 泛化与限制：来源、架构、局部/接触失效、未建立的谱或语义解耦主张。

若描述准确但无控制收益，只能形成诊断性结论，不算原 Planning Compiler 闭环；若仅更多探针有效，应归因于计算/lookahead；若必须后训练才有效，转入明确训练分支。新颖性与外部相关工作需独立文献核查，本文件不宣称首次提出。

最终交付分为两条方法主线：

- Planning Compiler：可信的控制相关信息如何被冻结模型规划器利用；
- GDD-OPD：缺失或失真的决策结构如何通过训练内化并在独立动作上验证。

两条主线共享评估工具和合法基础资产，但不互相借用成绩；诊断正确、代码完成、
机制见证、性能优势和独立复现分别登记。
