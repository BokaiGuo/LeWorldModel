# v7 E0 特权前缀后缀优化：事后开发诊断

## 问题和隔离

此前已验证 v7 的 18 条链与 v5 逐元素一致；18 根每根均有两条事后特权解析可行见证，而把首条见证前缀加入保留库仅 3/18 被保留。这里检验：**即使给予已知可行的五步前缀，既有固定预算 CEM 能否自行找到有效十步后缀？** 这不检验编译器是否自动发现、保留或实际选择该前缀。

对已暴露 18 根，按现存见证记录顺序取第一条成功且合法的见证，使用其 float32 前五步；其解析后十步只做可行性上界重放，绝不作为 CEM 起点、样本或选择输入。对每根复用原干预的 zero 和 same-bank greedy 结果：相同精确动力学、目标、10 步零尾、四结点 CEM、初始完整链一次评分加 480 样本、三条相同种子 `2027112400 + 100*root + repeat`。各根逐流记录所有实际 float32 动作、得分、每代状态和最后 incumbent；核验原对照的哈希和任务身份。

预定报告三种前缀的逐流 `<0.05` 成功数、至少一流成功根数、各根三流平均终距及与两对照的逐根胜平负（绝对容差 `1e-10`），并报告解析全链成功数。随机流并非独立任务；三次未成功不证明给定前缀不可用，也不能排除优化器配置、有限预算或受限四结点参数化导致失败。解析见证长度和动作域必须检查；不扩容、不挑选另一侧、不得依据结果调种子或阈值。

新协议在计划和历史干预结果已暴露之后产生，是特权后验诊断，不可计入 PC2 自动发现、PC3 强基线性能或独立确认。依赖清单、原始样本与新结果排他写入；同后端参考路径逐条重新计算动作、得分和汇总后另存审计。此诊断不改变正式方法或历史协议。
