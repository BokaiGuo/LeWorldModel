# RGB 历史时钟与动作边界：实现核查

仓库已有 `score_future` 多帧组包及 PushT 反馈开发运行器；此次没有重建或替换它们。新增的 `TimedHistoryRGB` 复用原有组包路径，供明确选择该合同的调用方使用：

- 单帧或多帧 RGB 与目标图、`H-1` 个共享历史 packet 和非空未来候选；前后动作均按同一 normalizer 检查物理边界。
- 帧时刻必须为非负整数、相邻间隔等于 packet 的物理步数，末帧时刻等于声明的当前时刻。错误长度、越界、非有限值和设备不一致会报错，不补帧或补动作。
- 沿用冻结模型检查与动作梯度；单帧空历史也明确支持。测试过程中发现空历史 reshape 因零元素无法推断动作维度，已改为显式维度，并加入回归测试。

真实 checkpoint GPU 复验使用已封存的 PushT 四根、左右各一条真实 RGB 历史，检查了 0/5/10 步帧与对应两个历史动作包。八条多帧预测与此前正确组包的封存预测最大绝对差 **0**；新历史边界退化为单帧时，其评分与严格单帧适配器最大差 **0**。单帧／多帧接口、权限、时钟、越界和梯度相关测试共 **41 项通过**。原始记录为 `le-wm-main/results/pc_rgb_timed_history_contract_gpu_20261107_codex.json`。

这些检查只证明调用者提供的时间戳在内部一致，**不能证明其与实际环境派发事件相符**；实际闭环仍须使用独立派发／观测日志审计。该适配器尚未自动接入已有反馈运行器，也不是安全沙箱或官方模型来源认证。已暴露轨迹上的实现等价不证明历史改善预测或控制；此前反馈结果及 PC0–PC5 不变。
