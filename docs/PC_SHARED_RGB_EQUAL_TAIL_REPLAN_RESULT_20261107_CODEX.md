# 实际派发链前缀的等预算尾部重优化：开发结果

## 结论

在三个已曝光 TwoRoom 任务上，各前缀使用相同的事后提供尾部起点、
相同随机数及每臂 48 次模型评分重优化后，原前缀和零前缀均为 3/3
曾成功。这一结果没有支持原前缀相对零前缀产生不可替代的后续控制
机会；三个任务太少，不能据此断言一般情况下不存在此类机会。

| 前缀 | 曾成功 | 前五步内成功 | 首次成功在尾部 |
| --- | ---: | ---: | ---: |
| 原实际前缀 | 3/3 | 0/3 | 3/3 |
| 置零 | 3/3 | 0/3 | 3/3 |
| 随机 | 1/3 | 0/3 | 1/3 |
| greedy | 3/3 | 3/3 | 0/3 |
| lookahead | 3/3 | 1/3 | 2/3 |

各任务的曾成功结果依次为：root 10 全部成功；root 11、12 仅随机臂
失败。原前缀在此前共同尾部重放中为 2/3，本次重优化为 3/3；这
是不同的事后动作链，不是原反馈规划器成功率的改善证据。
greedy 的所有成功均发生在前缀内，不能计作尾部利用机会。

## 方法与审计

协议见 `PC_SHARED_RGB_EQUAL_TAIL_REPLAN_PROTOCOL_20261107_CODEX.md`。
三任务、五前缀、三轮各 16 条，共 720 次完整链逻辑评分；
前缀产生及原反馈的成本不包含在 720 次中。每臂的起点是原执行
链尾部，由评价端事后提供，lookahead 前缀同样借助事后尾部；
这些不是可部署规划器的免费信息，也不是公平的端到端成本比较。

单元测试 2/2 通过。独立审计脚本复核协议、运行器、来源计划和
候选池哈希，并从记录的分数与随机流重建了 15 臂全部候选、精英、
更新与选择；逐臂校验物理轨迹的动作与所选链一致，以及停止条件。
这是账本和同环境重放核验，不是独立动力学实现或 GPU 分数重算。

原始记录位于 `le-wm-main/results/pc_shared_rgb_equal_tail_replan_20261107_codex_{plan,physical}.json`
和对应 `_pool.npz`；审计脚本为
`le-wm-main/experiments/pc_shared_rgb_equal_tail_audit_20261107_codex.py`。
运行时 Gymnasium 提示 reset 返回 Tensor 与声明空间不一致，以及动作
类型转换；本实验未解决这些环境合同问题。

## 证据边界

这些是重优化生成的新链，而非正式算法自动选中并实际执行的原链；
只有已曝光的三个开发任务，也没有独立任务或同总成本强基线。
因此不能将结果用于通过 PC2、证明描述组件收益或改变 PC0–PC5
状态。共同尾部与等预算尾部干预均未发现原前缀优于零前缀的证据。
