# P1 混合候选 SVD 符号修复及重跑

## 缺陷与修复

RUN01 对 SVD `J=UΣVᵀ` 的右奇异向量逐行确定符号，却未同步变换
左奇异向量，然后计算 `V diag(σ/(σ²+λ)) Uᵀr`。这种单侧变号改变
阻尼解，污染目标方向候选；它是新混合实现的代码错误，不是 P1
机制或冻结模型的负证据。旧的独立 `goal_conditioned` 实现没有使用
此单侧规范化，不能据此推断它受同一错误影响。

修复后先用原始成对 SVD 计算阻尼解，再仅对生成对称谱候选所用的
右奇异向量做符号规范化。增加负对角 Jacobian 回归测试，将输出
目标方向与直接阻尼线性方程求解逐元素对照。原目标条件化与混合
路径测试合计 5 项通过。

## 已知根 1 主机 CUDA 重跑

RUN02 使用同一已知根与历史实验协议重新封存，主机 CUDA 完成四次
规划、20 步真实反馈，原生成功 false，物体位置误差 63.20777，
角度误差 0.25724。RUN01 受缺陷影响，其相应误差为 66.00148 和
0.19442、原生成功也为 false；两项物理指标方向不同，不可概括为
修复后整体变好或变坏。

两次初始 RGB 像素哈希一致，前 15 个实际动作一致，第 15 步状态
和 RGB 一致，最后 5 个动作不同。四个节点所选序号均为 0、1、1、6，
但相同序号不能证明候选动作相同；末节点恰好选中了修复影响的
目标方向。这个已知根开发对照表明代码错误改变了真实轨迹，不能
说明独立泛化、P1 机制成立或理论不成立。

RUN02 保存态检查通过四个节点的候选去重、选中动作与执行绑定、
模型冻结、hook 与 Python autograd 调用账本。它不独立复演完整物理
事件链，调用账本也不是完整 FLOPs 或公平总预算认证。
