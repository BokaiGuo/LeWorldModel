# 全切分支持上界：固定5/10是否是覆盖限制

## 问题与决策

已封存二维交叉版本的16条名义链、共同查询、完整272格池与选中链均覆盖27/48运行。分段物理重放无误。这只排除了“继续改当前5/10池的排序”，没有排除“合法切分位置选错”。

本次穷举所有整数切分点`k=0..15`，实际非平凡切分为1..14；k=0和k=15作为身份对照。每个k都由同一16条完整15步名义链构造：

`U_i[:k] + U_j[k:]`，另加相同时长的hold尾部。

每个k为16×17=272条，仍只有15个物理转换；不改变动作缩放、墙障后端或成功规则。没有动作优化、平移/旋转尾部、重新编译或按成功挑选来源。

输出每个切分的全池成功覆盖、全部切分并集、相对原始16链与k=5的新增覆盖、原始对角见证和完整轨迹。

- 若任何固定切分或全切分并集比k=5新增至少4/48成功，认为切分支持存在值得另立预算匹配实验的开发信号；不能直接据此采用事后最佳k。
- 若不满足，则停止将“仅换切分位置”当作主要修复；无论是否满足，都报告全部切分和失败分母。
- 所有结果都是特权有限候选oracle上界，不是规划器成功率、描述贡献、独立确认或Gate通过。
