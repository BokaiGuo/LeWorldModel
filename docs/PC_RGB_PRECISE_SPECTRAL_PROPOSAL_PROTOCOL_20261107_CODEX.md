# 精确导数后端下的 RGB 谱候选开发验证

事前固定范围：已曝光 TwoRoom 开发 episode 9000、9013、9022、9032；原 RGB CEM16 首次选中计划逐坐标截断至 `[-0.7,0.7]` 作为共同名义链。25 个环境动作、每 5 个动作组成一个模型包；规划输入是评价器重置后实际渲染的 RGB，目标为封存数据目标图。真实物理状态仅供初始化和评价，不能进入规划器。

对名义链，在物理动作坐标逐坐标计算冻结模型末时刻 192 维表示的完整 Jacobian，使用已核验的 math SDPA 和禁用 TF32 上下文。SVD 取两个最大右奇异方向；对照从独立种子 `27127000 + episode` 的高斯分布生成两个同维随机方向。每个方向按最大绝对坐标归一化，每个方向加减 0.3，包含共同名义链，构成每臂 5 条合法候选；均以同一冻结 RGB 模型评分，选各自最低分，固定索引顺序处理平局。输出候选动作、分数、方向、奇异值、实际裁剪数、查询数及同步耗时；两臂评分机会相同但谱臂另付 Jacobian/SVD 成本，因此不是等计算比较。

先封存计划，再在同一物理初始状态和目标下分别重放两臂的各自选中链及两臂全部候选；记录每步距离、成功、截断及 25 步动作。采集不按成功筛任务，选择过程不能读取物理后果。每臂报告选中链成功、同候选池存在成功，以及相对共同名义链的终距变化；这些是开放环开发现象，不宣称完整控制优势、描述增量或统计显著性。记录所有后向、JVP 和评分调用，两个臂不同计算不能称为公平成本。保留所有失败和数值异常，输出排他创建，源、模型与合同校验。
