# 前缀保留对未查询尾部的预测：开发协议

复用第二次规划的三个 lookahead 开发任务 15、25、35 已保存初态和
首轮候选。每任务采用首轮前 12 条合法链的前两个 packet 作前缀；
不按真实结果选择。用独立固定种子产生共享的 A 库 8 个和 B 库
24 个三 packet 尾部，组合为完整链后以同一冻结模型评分。A、B
随机流分离；A 不用于生成或选择 B。样本受动作域裁剪，记录种子。

候选前缀的保留排序比较：原父链模型代价、A 最低值、A 平均值和
固定种子打乱前缀身份的 A 最低值。目标是在同一任务内保留 4/12
个前缀后，命中多少个 B 库中最好的 4 个前缀，以及保留集合的 B
最优完整链代价。所有方法看到相同 A；B 只用于评估，不反馈
给保留规则。每任务再对每个前缀的 B 最佳尾部使用独立随机流、
相同 3×16 次机会进行固定前缀尾部优化，报告保留集合与全体的
优化后模型代价。构造、B 查询和优化成本分别计费。

优先级是判断这些简单统计能否预测未查询的模型评分，不是宣称
对真实后果有预测性。真实物理重放／成功、前缀描述超出普通
probe-min 的独立增量、完整成本和独立任务均需另外验证。
本开发协议来自已暴露的任务及当前方法结构，不作独立确认或
确认前阈值。禁止把评估端真实后继送回规划器。
