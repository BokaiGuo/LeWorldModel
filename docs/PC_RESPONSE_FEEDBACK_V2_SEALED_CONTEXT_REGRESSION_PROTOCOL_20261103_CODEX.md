# V2 末时域修复：封存上下文回归协议

目标是验证末五步 incumbent 修复在真实精确动力学上下文中的行为，而非
重新优化旧单次规划或选择开发方法。使用此前已封存反馈轨迹的全部 24 个
`response_diverse` 末次上下文，直接读取第 10 步状态、目标和 V1 的 carry；
不重新规划前 10 步、不改变任务根、动作时钟、随机种子或 480-token 上限。
只运行一次 V2 第三决策，显式保存所有实际评分动作及结果，并分别与原 V1
对应决策的动作、分数、实际五步终态、耗费、完整链最低分比较。

逐批按 float32 动作和原 exact 后端重算位置、目标分数和 token，验证 carry
是输入的封存旧尾，所选 V2 链曾被评分且分数等于该决策所有评分最小值；
逐段执行后的真实终态不得延长 15 步。记录决策耗时和 SVD 开销，不把
搜索次数相等或重复硬件执行当作独立复现。仅一次 24 根开发回归，无新
种子、预算或参数调整。报告改变、平局和负结果；结果只验证修复范围，
不是 V2 三轮闭环、RGB、PC2、PC3 或训练外证据。
