# RGB 表示导数伴随差异：精度诊断

针对已曝光、事后选中的任务 9000、25 步、方向 0，复用封存动作、方向、RGB 输入及表示投影，以 math SDPA 比较三种运行方式：原始 float32 设置、关闭 cuDNN TF32 的 float32、将原 float32 权重精确转换为 float64 后计算。每种计算 JVP、VJP 和步长 0.001／0.002／0.01 的投影中心差分，各重复 3 次；记录动作、输入、checkpoint、归一化器和代码指纹。

float64 是**诊断副本**，不是原 checkpoint 部署协议；权重从 float32 转换到 float64 后数值精确但计算路径、表示和部署成本不同。对每个模式记录 dtype、TF32 标志、后端与表示及目标分数，报告与原 float32 的差异。原始权重文件不修改，模型参数不训练，运行前后分别核验对应内存模型指纹。

本实验不修改上一实验判据或失败结果。如果误差随精度消失，支持浮点数值效应，但不自动排除其他数值实现因素；如果不消失，则进一步定位计算图。仅分析同一已选样本，不推广到其他模型和状态，不改判 PC gate。

首次执行中两个 float32 模式均完成，但在 float64 模式遇到上游动作编码器强制 `x.float()` 与双精度权重不匹配；未写出结果。重试前明确：仅在 float64 诊断副本上，运行时替换该编码器前向中的强制 float32 转换为匹配权重 dtype，其余计算顺序不变；先用 float32 对照核对替代前向与原实现一致。不修改安装包或权重文件，且双精度结果不是原始部署实现。
