# 固定终点 RGB 闭环与同 token 强对照：开发协议

本协议在结果前固定；使用四个已复用 PointMaze 开发根、冻结 checkpoint、合法 RGB 及真实动作历史、相同热身、目标和 MuJoCo 后端；不作为独立确认或训练外证明。

执行上限固定为热身后 15 个动作。决策在相同步数 0/5/10 得到真实 RGB，分别只规划剩余 15/10/5 步，最终评分全部对应同一个物理时刻（热身后第 15 步），不为达到阈值延长执行；每次执行计划前五步。评分是模型的既有 RGB 任务投影，不是物理真值。记录所有选择前计划、未执行尾部、在新真实 RGB 下尾部重评分和选中结果。

两臂均有每次决策 480 个五步预测 token 样本上限；按实际预测 horizon × batch 数扣费。上下文/目标编码相同、时间分别记录。每次重规划先将旧计划未执行尾部按新上下文、剩余长度重新评分（若存在），并按同一完整链评分保留更好的计划；包括最终 5 步。原始五步动作方向、标准化、观测时钟及执行值必须绑定。旧尾部重评分费归各臂；无旧尾部则不收费。

目标谱臂：既有生成器在 RGB 模型上生成 zero 和目标谱两个方向（若退化则只保留实际候选），生成成本及 SVD 计入。对于 15/10 步，所有候选相同后缀 CEM（最多相差 1 个完整样本），12 样本一批、每批 4 精英、保留最佳，耗尽可整除资源；对照 zero 的完整链收益不严格为正则回退 zero。5 步时已无后缀：对 zero、谱方向、完整时域 CEM 同一终点评分，CEM 充分利用剩余预算，若其选中则记录为直接搜索而非谱候选；回退 zero 规则照旧。之后与旧尾部比较。不能将一条链的资格赋给另一条链。

反馈 CEM 对照：无生成/SVD，全剩余时域搜索，使用同批大小、精英、观测、旧尾部重评分、token 上限与执行机会；可利用目标谱节省出的预测预算。不同 horizon 不同每样本 token；预算余数可小于一个完整样本，不做无意义填充。相同 token 不等于相同全部计算；分别记录调用、预测样本、token、时间、SVD 次数与时间、编码、执行步数，不能据此认证总成本公平。

每决策在派发前保存计划、候选、最终完整链、旧尾部及评分、动作绑定、来源和 hash；执行只派发前五步，真实图像与时间戳分别保存。全部动作执行后在同一后端重放并逐步记录物理状态、终距、原约定成功阈值，重放结果不输入选择器。开发根和三次反馈决策不是独立样本；未计算跨根显著性、不判 PC2/PC3 通过，不宣称完整 PC 方法或谱独立增量。
