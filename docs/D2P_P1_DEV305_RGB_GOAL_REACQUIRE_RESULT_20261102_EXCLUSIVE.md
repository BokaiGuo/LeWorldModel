# dev305 目标重采集接线：开发验证

按独立文件协议，对固定 dev305 已保存的目标与 warmup 第 10 步观察做
CPU RGB 检查。目标物体框 `[65,162,120,220]` 不通过既有 8 像素 guard；
当前物体框 `[20,37,83,93]` 与推杆框 `[143,55,155,67]` 均通过。
新接口返回 `goal_visibility_failed`、`selector_called=false`、
`action=null`；这表示规划前阻塞，不是零动作、完整时域负结果或新物理试验。

保存记录只有一张目标图。没有伪造第二次采集，没有因 guard 不合格换根、
换目标、移动图像或调整 margin。正向双采集路径仅以合成图测试接口，
未完成同目标重采集的真实验证。可信采集端负责保证目标、相机、会话、
顺序和时间戳的真实性；该接口无法从 RGB 自行认证这些元数据或同一物理
任务。目标 mask 完全一致和可见性检查也不保证无同色遮挡或感知准确。
TTL 由部署方提供，当前未校准；成功状态不应解读为 P1、安全或生产认证。

实现接收两张目标 RGB 和一张当前 RGB，先运行原 guard、检查采集声明及
两个目标的 object/pusher mask 精确一致，再可调用只接受 RGB 的选择器。
它只返回候选动作，不派发动作；实际接入方必须保证所有动作都经过该
屏障和其余既有 gate。发生输入、selector 及数值错误时返回 blocked，
记录是否调用过 selector；不将工程异常记作科学负结果。

回归测试包括真实保存根核验、有效接线、目标或当前图失败、缺帧、重复
采集 ID、任务身份不一致、过期、mask 差异、guard 源变化、异常和无效
动作；与此前轮廓对照一并运行 `21 passed`。正向用例是 fixture。
