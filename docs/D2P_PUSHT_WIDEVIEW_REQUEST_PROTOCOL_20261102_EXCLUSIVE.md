# PushT 边界目标：固定宽视野重观测开发协议

本协议在运行前固定，适用于已打开的 dev305 RGB 目标；不使用确认根、
不使用 simulator state、物理 outcome、GPU 或训练。原始目标与当前图
必须通过来源哈希验证，原 guard 保留并记录其判定。原目标不合格时，
不将其变换成合格目标，也不改 guard；仅生成一次新的、请求更宽真实视野
的采集请求，动作保持未派发。

备选方案是固定安装的宽视野 RGB 相机，或由受控采集系统移动相机后，
在物体与目标不变的前提下，从同一新视角分别重采目标图和当前图。
这要求有可信采集端、相机安全控制、目标身份和采集时间绑定。更换视角
会改变图像和动作坐标关系；须用独立开发数据校准、验证模型适配及
观测—动作映射。在这些条件满足前，不可连接实际 planner 或执行器。

本接口只输出重观测请求及对后续 RGB 的诊断检查；不移动相机、不发送
动作、不认证相机、目标身份、标定或旧 P1 gate。新图必须保持两者同一
新相机和相同目标声明，且各自通过未修改 guard；不合格、缺图、元数据
不全、异常均明确阻塞。通过检查仍为 `calibration_required` 而非可执行
或安全认证，且不能覆盖原 guard 的失败。边界截断、同色遮挡及目标身份
无法仅凭 mask 和自报元数据全面验证。

固定开发核验使用已保存的 dev305 原始目标和 warmup10 RGB，调用可用
性为 false 的采集适配器，验证只提出请求并原样记录不可用，不重置环境、
不运行物理轨迹、不读取任何候选 outcome。不尝试其他根或选择优质目标。
在独占新输出中记录哈希、状态、原因、检查与调用成本。
