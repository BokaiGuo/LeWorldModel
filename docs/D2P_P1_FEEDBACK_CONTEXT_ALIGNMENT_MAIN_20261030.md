# P1 中间帧反馈：时间与动作 token 接线核查

本核查针对已封存的 24 行 cp5 输入、48 条已执行后缀，以及
`codex_p1_two_stage_feedback_20261030_v1.py` 的第二阶段上下文。
不运行神经网络，不修改 checkpoint，不改变原实验。

当前仓库 `train.py` 将长度为 3 的观测序列与同位置的动作 token
输入预测器，监督下一观测；`jepa.py` 的 rollout 在每次预测后
追加预测观测，再将动作和观测窗口都向前移动一格。此前 cp5 输入
生成器验证了 warmup 原始动作经所记录均值、标准差归一化后，
逐字节等于保存的两包动作历史。

本轮针对固定 48 条后缀，逐行检查真实反馈上下文为：

- 观测：`[root 最后一帧, 真实 cp5, 真实 cp10]`；
- 已执行动作历史：`[prefix 五步, 后缀第一包五步]`，两者都使用
  同一行记录的均值和标准差归一化；
- 目标：保持该行原目标不变；第二包候选在优化／预测调用时另行
  接入，不冒充已经执行的动作。

新增测试使用实际封存 roster 和动作，但使用确定性的人工 latent
只检查索引、顺序和数值计算；还验证越界动作被拒绝。连同既有
反馈与中间帧绑定测试共 8 项通过。测试见
`le-wm-main/tests/test_codex_p1_feedback_context_alignment_20261030_main.py`。
这支持反馈接线与当前源码 ABI 的局部一致性，不证明历史 checkpoint
确实由当前训练源码生成，也不证明 normalizer 来自其训练数据。
测试不构成 CUDA 模型推理、实时环境执行或独立结果。

两阶段实际控制仍需完成固定 24 行入口、逐步 journal、资源计量、
停止处理和 saved consumer；共同后缀干预与各前缀独立后缀优化的
效果必须分栏。P1 科学门仍未通过。
