# PointMaze 动作、时钟及真实历史核验

本轮按 `PC_POINTMAZE_PACKET_CLOCK_REPLAY_PROTOCOL_20261106_CODEX.md` 与 `PC_POINTMAZE_HISTORY_ALIGNMENT_DEV_PROTOCOL_20261106_CODEX.md` 执行。数据来自已暴露的 1884–1891 八条轨迹；使用完整 proprio，属于 state-assisted 开发而非 RGB-only。

## 动作和时钟

用各条轨迹记录的初态及前 15 个动作，在 MuJoCo 按上游动作裁剪、速度裁剪、每步 5 个物理子步重放，逐步对比记录的后续状态。120 个环境步中，最大绝对状态误差为 `2.2779e-7`，低于预定 `1e-4`；物理子步为 `0.01s`，时钟最大偏差 `4.44e-16s`。这支持本面板数据的动作索引与执行时钟一致，但不是对全部环境和接触状况的认证。

本地完整数据集算出的动作和 proprio 均值、标准差与本地上游源码 PointMaze 常量一致。五步归一化动作拼包后还原的最大误差 `1.11e-16`。在一条轨迹的三帧上，本地 `(1,1)` 与配置中 `(1.777,1.777)` 的尺寸变换数值最大差为 0；该抽查不能推广到所有图像或所有数据增强设置。

## 真实动作历史

对真实帧 0、5、10 及相应真实历史动作，以同一固定动作 10–14 预测帧 15；未来数据只用于离线对照。真实 GPU 冻结模型的任务平均编码 MSE：单帧 `0.015693`、三帧历史动作嵌入补零 `0.023772`、三帧真实历史 `0.016802`。真实历史在 4/8 任务上优于单帧，未达到预定 6/8 和平均改善标准。部分任务真实历史明显改善补零，但仍不能证明其整体优于单帧，更不能作为原有帧 0 案例的修复。

新历史诊断首次运行时，数据归档动作是 float64，而网络线性层为 float32；导致 dtype 错误。已在诊断读取入口明确转换 float32，并在同一固定任务上成功重跑。这是诊断程序修复，**不是造成此前相机案例排序错误的已证实原因**。

此前 1887 偏移视角的模型预测与真实编码排序仍不一致；本轮未发现足以解释它的动作统计或时钟 bug，也没有证明本地视觉编码和预训练官方实现完全等价。不能声称问题已修复；不得用事后真实后继做规划选择。PC0–PC5 不改判。
