# E0 后缀预算调度与逐批动作审计

按 `PC_TRACED_SUFFIX_ALLOCATION_E0_DEV_PROTOCOL_20261103_CODEX.md` 事前固定的两档预算，运行上一轮 12 个已暴露 unicycle 开发任务。每档比较相同响应候选库的平均分配、自适应分配、即时 greedy，以及不支付候选生成开销的全时域 CEM。每臂按各自实际生成、筛选与规划调用收费；总共 96 条规划轨迹。

数值为平均终距，越小越好。自适应相对平均分配在两档均为 11 胜、1 负；相对 greedy，480 档为 7 胜、5 负，720 档为 3 胜、9 负。720 档虽有略低均值，却在多数配对任务上落后；不能将它表述为稳定优于 greedy。两档使用同一 12 根，不能视为 24 个独立样本。

480 档候选搜索总量为 108 个完整链样本；平均分配为每候选 36，greedy 全给一个候选，自适应先每个 12，再逐批按当前完整链分数分配。720 档总量为 168；均分为每候选 56。剩余预算均用于同一全动作精修；各候选 CEM 状态与随机流跨批保留。所有臂均用满各自 token 上限，响应臂另各有两次 SVD；等 token 不是等 FLOPs，也不代表 CEM 达到调优上界。

## 动作绑定与复现

新预测入口保存每批原始动作、预测位置、评分、阶段和 token，共 **4812 批、21360 条候选轨迹**。计划封存后独立审计全部动作合法性、逐批位置和分数、资源总和、最终选中链在已评分样本中的存在性，以及联合精修不丢弃已有最佳链；96/96 条完整规划记录通过审计。动作是新运行中实际进入预测入口的动作，不再像上一轮后验诊断那样缺少原始采样序列。

480 档平均分配、greedy 和 CEM 的最终动作与上一轮已封存的对应策略逐根一致；连续 CEM 对照与原优化器的输出逐项一致。相关接口、预算、旧策略复现与审计测试共 **34 项通过**。

## 边界

该面板为上轮已暴露任务上的调度开发，不是来源合格独立确认；精确模型没有视觉误差或接触，也没有跨后继响应程序组合。它支持继续研究预算分配，不证明响应结构自身或 SVD 分解具有独立优势，更不构成非即时机制见证。此轮没有修改 PC2、PC3 或历史 gate。

原始逐批数据与独立审计分别为 `le-wm-main/results/pc_traced_suffix_allocation_e0_dev_20261103_codex_plans.json` 和 `le-wm-main/results/pc_traced_suffix_allocation_e0_dev_20261103_codex_audit.json`；两者以源码、协议与计划 hash 绑定。
