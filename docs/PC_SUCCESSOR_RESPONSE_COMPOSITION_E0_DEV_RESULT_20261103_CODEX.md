# 后继响应自动组合：wall 精确动力学开发结果

按运行前的 `PC_SUCCESSOR_RESPONSE_COMPOSITION_E0_DEV_PROTOCOL_20261103_CODEX.md`，在 8 个已暴露碰墙任务、两档预算上，实际从每个第一段候选的预测后继状态生成第二段候选；随后对完整动作链做后缀 CEM、评分及联合精修。所有生成与搜索预测计入该臂预算，所有精修保留之前最佳完整链。结果为平均终距（成功数，阈值 `<0.05`）：

| 方法 | 960 token | 1920 token |
| --- | ---: | ---: |
| 后继响应自动组合 | 0.50703（0/8） | 0.50188（0/8） |
| 同第一段、无后继响应的名义组合 | 0.50988（0/8） | 0.50203（0/8） |
| 同第一段、随机第二段组合 | 0.50623（0/8） | 0.50117（0/8） |
| 第一段＋完整十步优化，不预组合 | 0.50235（0/8） | 0.50094（0/8） |
| 同库即时 greedy＋完整十步优化 | 0.50362（0/8） | 0.50141（0/8） |
| 完整 15 步 CEM | 0.52929（0/8） | 0.52926（0/8） |

后继响应相对不预组合在两档分别只赢 1/8、3/8；相对随机组合均为 3/8。两档都没有方法在该预算和配置下达到成功阈值。CEM 是预定的具体实现，不是充分调优或全局最优保证；此表不证明谱结构独立收益、程序组合优势或任何 gate 通过。两档预算共用同一组 8 根，不是 16 个独立任务。

## 同一选中链的机制干预

计划与独立审计先封存，再对每个任务、每档预算的**最终精修后选中链**比较 selected、zero 和第一段同库 greedy：共同后缀族及各自同 120 次评分的后缀 CEM 均有保存。

| 条件 | 960 token | 1920 token |
| --- | ---: | ---: |
| 首五步无即时进展 | 2/8 | 0/8 |
| 实际选中后缀的相对响应优于两控制 | 2/8 | 6/8 |
| 各自同预算重规划优于两控制 | 5/8 | 3/8 |
| 三项在同一选中链同时成立 | **0/8** | **0/8** |

不能把不同候选或不同预算的条件拼成见证。这个具体构造在该开发面板未建立非即时机制；也不能据此断言任何程序组合或其他任务都不存在机制。

## 工程与可行性检查

- 后验独立回放的解析可行轨迹在每个任务上均有不超过 15 步、终距数值为零的解；共核验 16 条（每根两侧）。这些带特权信息的轨迹**从未进入候选或选择器**，只说明按声明动力学任务可解。
- 后继响应臂在两档各有 7/8 条最终选中轨迹至少发生一次墙体阻挡；平均终态 x 分别约为 `-0.0020` 和 `-0.0011`。这是与绕墙失败相符的诊断，不证明唯一失败原因。
- 后验重算 960 档的 48 个第二段响应矩阵：原尺度 `0.05` 全部重现；名义链中 8/48 有碰撞。把差分尺度改为 `0.01` 或 `0.1` 时，分别有 4/48、6/48 个矩阵相对原矩阵差异超过 0.1。候选和尺度未据此重选；这提示部分局部响应对尺度／碰撞敏感，不说明所有矩阵或负结果均为代码错误。
- 后继响应每次规划提取 168 个五步／十步响应样本、8 次 SVD；六臂各用满 960 或 1920 个五步预测 token，但 SVD、批大小和 wall time 等额外成本不同，不能称等总 FLOPs。生成较多候选也压缩了各候选后缀预算。
- 96 条计划中 **9600 个模型批次、49152 条候选轨迹**的动作、位置、分数与 token 均封存并在精确动力学上逐批重算；最终选中链确实出现在评分记录中。16 条选中链干预已与封存动作和同库 greedy 绑定。相关测试 **42 项通过**。

原始计划、逐批审计和事后干预位于 `le-wm-main/results/pc_successor_response_composition_e0_dev_20261103_codex_*`；独立事后可行性及有限差分审计也保存在该前缀下。此版本还没有接入真实 RGB 反馈，也没有独立来源任务、跨模型或总成本确认；PC2、PC3 与历史 P1 均未修改。
