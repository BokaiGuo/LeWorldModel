# RGB 多帧历史显式组包：开发结果

## 已修复的接口风险

现有上游 `JEPA.rollout` 会覆盖输入字典中的 `action`，并从候选序列的开头读取观测时段动作。因此，调用者即便提供了历史字段，若候选开头没有显式包含已执行历史，多帧推理仍可能用错动作。这个行为此前已在 `PC_RGB_ACTION_CLOCK_INTERNAL_RESULT_20261107_CODEX.md` 中观察到；本次将其转为可调用的防错接口。

新接口 `score_future` 接受 H 帧、严格 H−1 个共享已执行动作包和未来候选，先将历史拼接到每个未来候选前，再交给既有 `RGBLeWM` 权限封装。它拒绝错误长度、非共享历史、空未来候选、非有限值和不一致设备／动作 dtype，且保留未来动作梯度。动作必须由调用者使用相同归一化坐标；该接口不能自行证明这些动作确实由环境执行。

旧封装及上游代码未改动，因此历史文件哈希和旧结果不被覆盖。**新接口目前是显式调用的安全路径，不会自动拦截绕过它的旧调用。** 历史采用正确手动组包的实验并未因这个风险被证明无效，也不能把其他负结果归因于此。

## 验证与边界

以四个已暴露 PushT 开发根、左右两侧共八条真实 RGB 历史及实际动作，在冻结模型 GPU 上比较新接口与先前正确组包的已封存预测；逐元素最大绝对差为 **0**。模型与动作统计数组指纹一致。单帧、多候选共享历史、错误长度拒绝和动作梯度等相关测试共 **23 passed**。

这证明该面板上的新组包与既有正确预测一致，不证明物理后果排序、整体规划收益或闭环已改善。新接口尚未接入正式 MPC；旧输入权限校验仍是 API 边界而非 OS 安全隔离。PC0–PC5 状态不变。
