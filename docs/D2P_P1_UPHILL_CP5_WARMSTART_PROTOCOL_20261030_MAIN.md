# 真实 cp5 后缀暖启动开发对照

目的：排查相同重选前缀下，原联合后缀曾真实成功，而真实 RGB
刷新后零初始化重规划未成功的断点。本协议在观察此前结果后制定，
不是确认实验，不能保证成功。

对全部 24 个固定 selected、zero、greedy 前缀，使用与零初始化
实验相同的 cp5 RGB、动作历史、冻结模型、20 次更新、步长 0.05
及逐类计费；唯一规划变化为初始化：该逻辑臂的事前封存重选动作
的后十步。三种前缀使用同一初始化，避免只让 selected 获取原
后缀。该初始化来自 selected 的联合候选，不是对基线的公平原生
初始化，且生成成本尚未合入；不宣称此实验公平强基线或 P1。

每行须记录初始化字节哈希、输出动作、模型调用和编码账本；动作
不得越界或使用物理状态作规划输入。CUDA 模型前后哈希相同；
真实执行全部 24 个候选，独立核对早停和删失。原后缀不重优化
对照使用既存重选物理轨迹验证 selected；zero 和 greedy 的
原后缀由待执行的共同后缀面板获取，不能用 selected 的结果代替。
该实验的暖启动和零启动都是相同反馈机会，但历史不重优化轨迹
未获取反馈；比较时须将这一差异明确分栏。
