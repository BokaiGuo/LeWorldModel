# RGB 接触面板目标推杆反事实：开发诊断协议

目的：检查原面板目标 RGB 中固定在 `(80,80)` 的推杆是否影响三动作
选择，而不是假定其解释全部物理遗憾。对原 16 根、白背景及两侧
接触就绪条件，保留全部动作、当前图、预测后继、真实后继和物块目标。
在独立评价环境生成两个目标图：原目标及把目标图中的推杆放到该侧
当前推杆位置。物块目标位置、角度和目标标记必须一致；记录替换后的
重叠情况，重叠条件保留并单独标记。

先封存反事实目标图和物理几何，之后 GPU 进程只编码目标图；以先前
冻结的模型预测与真实后继编码为输入，重算目标 latent 距离，
不重用目标图推导真实后果。逐条件比较模型和真实编码的选择、并列
感知物理遗憾及分布，按根聚合；物理代价、轨迹和评估分母不变。
原目标编码与已封存编码应在 `atol=1e-5, rtol=1e-5` 内一致。

该替换目标基于评价端物理状态，是反事实诊断，不是 RGB-only
规划器可获得的新目标；不能用改善的数字当控制收益或 gate 证据。
若存在合法性或渲染匹配问题必须报告，不据此调整标准协议。
