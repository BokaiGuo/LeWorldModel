# TwoRoom 旧尾精英更新：修正及配对开发结果

旧版将旧尾放入首轮评分和最终竞争，但无条件排除其参与 CEM 的参数更新。核查历史四任务、三个搜索臂的 45 次重规划：45 条旧尾都可精确表示为五步恒定动作块，且都排在首轮前十，因此均被排除在本可进入的精英集之外。这是搜索更新的实现限制，不证明该设计导致此前失败。

修正版仅在动作逐值精确满足块参数化时，将旧尾映射到相应参数并按稳定排序进入精英集；不满足时维持旧版行为。原实现及历史结果未覆盖。13 项单测通过，包含无旧尾时三臂跨三个时域的逐评分与最终动作等价、不可表示旧尾的原版等价、稳定排序、动作边界和查询数。

按[事前协议](PC_TWOROOM_INCUMBENT_ELITE_FIX_PROTOCOL_20261107_CODEX.md)，在 RTX 5060 Ti 上对 40 个已曝光 TwoRoom roots 进行实际 RGB 反馈配对运行。两臂每次规划均评分 680 条链，使用相同种子、目标、动作范围、5 步执行周期和 25 步上限；各自从真实后继重观测。

| 指标 | 原版 | 修正版 |
| --- | ---: | ---: |
| 实际曾成功 | 40/40 | 40/40 |
| 规划次数 | 144 | 147 |
| 候选评分总数 | 97,920 | 99,960 |
| 模型动作包步 | 336,600 | 340,000 |
| 实际执行步数 | 625 | 640 |
| 同步规划耗时之和 | 30.157 s | 30.398 s |
| 整任务计时之和 | 35.274 s | 35.605 s |
| 旧尾首轮前十 | 104/104 | 107/107 |

逐次核验了全部决策的 680 个评分与批次数、最低分选择、所选动作 SHA-256、动作派发前缀、旧尾块恒定及首轮稳定排序；修正版 107 次旧尾均进入精英。两臂首轮选择在全部 40 根一致；31 根在后续至少一次所选计划不同，但成功数无差异。各臂早停时刻不同，因而整任务总查询并不相等；时钟仅为本次顺序运行，不可用于效率优势结论。

这是对已曝光开发根的工程检查，不是独立确认，不能归因于行动后果描述，也未显示控制或成本优势。当前评估器与规划器同进程，物理状态用于重置和评价，模型评分接口使用 RGB 上下文及动作；尚不能据此宣称严格进程级权限隔离。PC0–PC5 不改判。
