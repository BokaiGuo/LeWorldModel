# 共享父链的响应修改：多预算开发曲线

按[事前协议](PC_GOOD_CHAIN_BUDGET_CURVE_DEV_PROTOCOL_20261105_CODEX.md)，在 16 个已暴露 E0 开发根、每根两个预定随机流上，分别从相同全局父链运行响应修改、免响应随机修改和直接 CEM。四个有限预算点共 384 次运行均完成。每个单元格为平均最终终距（成功次数 / 32）；成功阈值 `<0.05`，32 是根×随机流，不是独立根数。

| 每臂 prediction tokens | 响应修改 | 随机修改 | 直接 CEM |
| ---: | ---: | ---: | ---: |
| 471 | 0.35065（4/32） | 0.34495（7/32） | 0.33723（7/32） |
| 939 | 0.32723（10/32） | 0.32875（11/32） | 0.32660（9/32） |
| 1875 | 0.32044（12/32） | 0.32424（11/32） | 0.32004（12/32） |
| 3747 | 0.31882（12/32） | 0.31734（12/32） | 0.31839（12/32） |

在此面板中，更大预算下三臂平均终距差距缩小，最高点成功次数相同；并未出现响应臂随预算上升而明显胜过直接 CEM 的证据。以每根先平均两个随机流，再比较响应与 CEM，四个预算点分别有 4/12、12/4、9/7、8/8 根响应更好/更差；平均差分别为 `+0.01342`、`+0.00063`、`+0.00040`、`+0.00044`。根数和效应幅度都应报告，不能用多数根略好替代平均效果。小面板不能据此证明两者等价。

最高预算是此前 471-token 点的约 8 倍，**不是无限预算，也未证明收敛或全局最优**。每个预算点独立重跑；不同点的 CEM 最后一批大小可能不同，不能将该表当作单次运行严格嵌套的轨迹。每次运行均包含所示方法在父链之后的预测开销，父链原始生成成本未计入。CPU 墙钟包含 journal 持久化；最高点三臂平均约 0.209、0.228、0.222 秒，不能当作 GPU 或全系统成本。

[独立审计脚本](../le-wm-main/experiments/audit_pc_good_chain_budget_curve_dev_20261105_codex.py)对 384 次的模型调用哈希、token、父链、预测与最佳评分重放通过；471-token 的 96 条最终动作和得分与 V2 逐项相同。该审计复用同一预测实现，不是独立复现；12 项预算和已评分最优链测试通过。原始 [审计数据](../le-wm-main/results/pc_good_chain_budget_curve_dev_20261105_codex/audit.json)保留逐根配对差、成功与计时。

实验不涉及真实视觉执行、独立来源或强基线全系统成本，不改变 PC0–PC5。若要判断更高预算是否存在真实差异，需在新开发任务、足够的重启/随机流和明确的总成本合同下继续；不能把这条有限曲线外推为“不限制 token 的最终结论”。
