# v3 封存候选库普通 lookahead 事后对照

对已暴露的 24 根，读取事前封存的 response 第一次决策候选库和
最终实际选中链；最后精修的 selected 前缀可能不在候选库中，必须
独立列出。每个候选及 selected 前缀均使用相同的十步零尾初值、
四结点 CEM、一个零尾评价加 119 个采样；每根所有前缀采用相同
随机数种子，以减少搜索噪声。每个前缀的 120 次完整链评价和
原始 float32 动作全部记录，不把生成候选和后缀诊断成本省略。

普通 lookahead 定义为：在全部封存候选中，选择各自 CEM 最终
距离最低者；并列按候选库顺序。另报即时 greedy 及 selected；
对三者执行同一封存 selected 尾部和零尾，报告绝对距离及相对
零尾的变化。被选尾部对所有前缀共享，仅供事后机制干预，不是
免费部署信息。逐批重算每条完整链、优化选择及候选身份。

该对照在同一候选库、同一优化器与每前缀预算下比较，能修正旧
记录中将整链 CEM 前缀称为普通 lookahead 的问题；但 lookahead
从多次带噪搜索中选最优，存在选择偏差，而 selected 经联合精修
可能库外，不能用此诊断直接宣称公平完整方法优势。面板和原见证
均已暴露，不改变原 PC2 事前结果；旧负结果不重开。
