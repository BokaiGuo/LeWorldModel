# 固定前缀、等资源反馈后缀优化诊断协议

## 问题和范围

先前事后审计发现，四个非即时 selected 前缀的原 120 样本 CEM 未找到后续
反馈实际执行尾部。检验另一种解释：对每个已封存前缀给予完全相同、从零
初始化的两次反馈优化后，selected 是否仍落后。24 根已暴露任务、五类
原前缀及非即时标签原样读取，未选择新根；该诊断不是重启已停止的首次
全链规划构造，也不是方法选择或确认实验。

## 固定过程

对每根 selected、zero、same-bank greedy、random bridge、lookahead 五个
五步前缀，精确动力学执行前缀得到后继状态。此后各自：

1. 固定原 floor-CEM 算法、scale floor 0.05、批大小 12、零均值及标准差
   1/3，10 步尾部独立规划 240 条，计 480 个五步预测 token。
2. 执行最优十步尾部的前五步；保存后五步 carry、新状态和执行阻挡。
3. 新状态重评分 carry 一次，计 1 token；从同样零初始化独立执行 479 条
   五步 CEM 样本，计 479 token。完整链分数严格较小时替换 carry；平分
   保留 carry。各前缀获得相同反馈次数、随机规则和总资源上限 960 token。

第一、二决策每根分别使用 `2027010100+root` 和 `2027011100+root` 作为
独立随机种子；同根五前缀共同种子，不从历史实际尾部或其他前缀取得候选。
保留请求动作、float32 模型动作、每批评分、carry、完整执行链、状态、
样本和 token；每个预测批都重新计算对照精确动力学。此前首次 CEM 的
120 次评估是另一资源配置，仅作为历史参照，不计入本实验预算。

## 报告和停止

逐前缀报告最终终距及 selected 对其他前缀的逐根优胜、四个既定非即时根
及 24 根总计；说明各臂成功阈值 `<0.05` 只是开发任务指标。记录每轮真实
总样本/预测 token 和完整轨迹，不将不同方案混为相同成本。每个样本
原始动作转为 float32 后输入同一精确后端，所选动作须来自已评分链；
分段执行结果须与从原任务完整回放一致。

每个固定配置运行一次；不以结果重新挑种子、预算或子集，也不对旧产物
覆盖。仅比较给定 prefix 的同资源后缀规划，不能声称完成充分性上界、PC2
事前同链机制、PC3 确认或 RGB 执行。
