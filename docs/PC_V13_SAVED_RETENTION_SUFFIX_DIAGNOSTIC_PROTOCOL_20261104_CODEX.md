# Saved v13 candidate retention and suffix diagnostic

After the v13 prospective mechanism panel stopped, compare its actual
first-layer retention with the separately saved lookahead diagnostics.
The latter ran the same 119-sample, four-knot CEM with the same random
stream separately after each first-layer candidate and one zero prefix.
No new optimizer, predictor, or environment invocation is permitted.

For each of the 12 roots, bind the response-bank actions and order exactly
to the sealed compiler layer (the extra zero prefix is excluded). Validate
each saved optimized chain's prefix and the number of sampled CEM proposals.
Report the best recorded suffix score among all ten response prefixes,
among the four actually retained, and among the four smallest immediate
prefix distances. Report how many roots have a strict loss from retention,
whether the best recorded successful continuation under the established
0.05 threshold was retained, and per-root gaps. Ties are evaluated by
score, not by choosing one arbitrary candidate. Include all 12 roots.

Verify the recorded plan and intervention audit hashes before analysis;
bind all inputs and the analysis code and write once to a new output.
Treat failures or inconsistent records as errors. This is an exposed-root,
post-hoc diagnostic using one finite optimizer and its original seed; it
does not establish global suffix optimality, scientific significance,
complete-method budget parity, PC2, or PC3. The zero control is reported
but is not inserted into the ten-candidate retention comparison.
