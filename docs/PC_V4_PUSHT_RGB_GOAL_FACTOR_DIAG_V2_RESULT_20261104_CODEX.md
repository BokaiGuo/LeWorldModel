# PushT 静态目标图像因子诊断 v2

对已暴露单根的两条轨迹各四个边界，将推杆位置、物体位置与角度分别或同时替换为固定目标，生成静态图像并用同一冻结 encoder 评分。所有原边界重渲染均与实际保存 RGB 逐像素相同；单独重编码 32 张封存图像的评分最大偏差为零。

| 臂 / 边界 | 原图目标 MSE | 仅推杆到目标 | 仅物体到目标 | 两者到目标 |
|---|---:|---:|---:|---:|
| response 0 | 2.169 | 1.956 | 1.789 | 0 |
| response 1 | 2.235 | 1.956 | 1.627 | 0 |
| response 2 | 2.127 | 1.956 | 1.794 | 0 |
| response 3 | 1.893 | 1.884 | 0.038 | 0 |
| CEM 0 | 2.169 | 1.956 | 1.789 | 0 |
| CEM 1 | 1.997 | 1.945 | 0.189 | 0 |
| CEM 2 | 1.958 | 1.945 | 0.054 | 0 |
| CEM 3 | 2.137 | 2.077 | 1.512 | 0 |

这八条记录中，仅替换物体姿态造成的目标 MSE 降幅都大于仅替换推杆位置，因此**不支持这些图像上“评分只由推杆位置主导”的简单解释**。两臂第 0 行是同一个暖身后起点，不是独立样本。两者同时替换时图像与目标完全相同，MSE 为零；因子效应不相加，例如共同起点的交互项约 −1.576，因而不能把单因素分数当作可加的贡献分解。遮挡、位置和纹理变化均可能参与，未在此实验中单独识别。

前版尝试将非零速度状态交给官方 reset，在首个边界就发现推杆坐标偏移约 1.07 并依合同停止；环境 `_set_state` 包含一次物理 `space.step(dt)`。[失败记录](../le-wm-main/results/pc_v4_pusht_rgb_goal_factor_diag_20261104_codex_failure.json)已保留。v2 按[新协议](PC_V4_PUSHT_RGB_GOAL_FACTOR_DIAG_V2_PROTOCOL_20261104_CODEX.md)将 reset 速度置零，严格检查位置、角度和 base RGB；它只复现静态图像，不复现原速度或接触隐状态。
