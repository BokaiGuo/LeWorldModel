# cp10 时间相关候选：同调用预算开发对照

在看到 dev303 的物理 oracle 结果后，使用已有的通用 `coherent_seeds` 构造器，依据当前 RGB 的接触方向生成固定幅度和旋转组合；没有将 oracle 最优动作注入模型。原 CEM 与新版本均在实际 cp5／cp10 RGB 和两包已执行动作历史上，用第一包 latent 距离评分、执行相同 5 轮 × 64 候选 × 5 扰动、两包模型 rollout；每臂均为 10 次 predictor 和 3200 预测样本、两次 RGB 编码。两方法只比较记录到的模型调用预算，不代表全流程 wall-clock 或完整资源认证。

这个设计与动作在 cp10 后执行前已封存，但同一个根已用于开发和 oracle 检查，**不是结果未知的开发 holdout**。原 CEM 版本来自此前已完成的固定实验，两组均从逐槽核验一致的物理 cp10 快照执行各自选定的五步后缀。未进行事后选动作。

## 结果

八臂均完整执行且原生成功 0/8；112 帧、动作与共同 cp10 状态通过保存态核验。相关种子相对原 CEM 的 native reward 在 2/8 臂上升、6/8 臂下降。两条谱前缀的 reward 分别下降 166.133 和 46.511，物体位置误差分别增加 25.235 和 2.182；角度误差分别降低 0.373 和 0.075。

其中 `candidate_19_terminal_latent` greedy 状态 reward 提高 10.565、物体位置误差降低 16.931、角度误差降低 0.813；另一个 greedy 状态位置误差降低 33.204，但角度误差增大 0.624，reward 下降 127.165。这些是单根依赖性分支的描述，不证明稳定优势或重配置机制。

结果支持继续研究候选分布，但当前方法不应冻结为有效方案。下一步应避免把相关候选直接等同于谱程序，检查模型偏好与实际物体位置／角度的失配，并在结果未知的新开发根上按事先固定的方法做同预算比较；独立来源无法认证时不得称独立泛化。
