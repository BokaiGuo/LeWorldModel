# 保留完整链的固定机会精修开发协议

制定于本次固定机会优化之前；输入面板及其最终结果已暴露，因此本协议是后验开发诊断，不是独立确认。

## 设计

- 使用 `pc_action_effect_ranked_end_to_end_dev` 中 16 个 root、随机/谱方向和 min/effect 四臂的已审计完整计划，不重新选择候选、不读取人工见证。原始各臂最终选中结果作为既有背景，而非新优化输入。
- 每个 root 用旧计划记录的共同 global proposal bank 和相同评分，稳定排序选出前两个动作不同的全局起点。所有四臂共享这两个起点；另按原末层保留顺序加入本臂两条完整链。即使与其他起点相同也保留槽位并计费，不能默默替换候选。
- 使用同一逐步共享 CEM，`sample_budget=628`、四起点、每起点 157 次评分（包括起点评分）、批量 12、精英 4；seed 为 `2046000000 + root`，每起点位置使用优化器既有子随机流。同一位置在各臂使用相同初始随机规则；因得分而产生的自适应分布可不同。
- 每臂完整记录原始动作、模型预测、每个起点的预算与质量、四起点共同最佳完整链、保留起点子集中的最佳质量、调用及 prediction-token 成本。使用 CEM 输出的每起点最终最佳分数比较保留起点；它是固定随机种子和有限计算下的检出质量，不是最优可行性。
- 按同一 root 的 effect 相对 min 分别报告两类方向：四起点最终分数、仅保留起点最佳分数、`<0.05` 检出以及 16 root 配对差异。额外模型预测按 1884 tokens/臂单独计费，不混入已有 2880-token 端到端成绩；token 不等于完整系统成本。
- 必须验证 64 个来源计划及旧审计状态、跨臂全局起点动作与分数一致、两个保留起点都来自对应末层，失败不得被丢弃。保存全部源文件哈希、协议、优化器及运行器哈希和调用 journal。没有动作差异的配对允许出现并原样报告。

该实验不能分离候选生成与保留，也不证明完整成本净收益、同链机制、真实物理、来源独立或 PC2/PC3。低预算求解器漏检时不可宣布前缀不可行。
