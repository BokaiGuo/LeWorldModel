## Native success decomposition for selected candidate

The model selected candidate 0 in each of the eight dependent groups. In
the four slot/condition cases, its complete step-15 pusher position errors
were 75.53, 79.55, 41.45 and 38.19; corresponding object position errors
were 17.58, 14.07, 45.87 and 46.38, and native angle terms were all below
pi/9. The second arm repeats the same candidate-0 actions and outcomes,
not four further independent cases. The installed PushT `eval_state` requires
the joint norm of pusher and object XY errors to be below 20, as well as the
native angle condition. Thus the first two slots satisfy the object-only
position and angle thresholds but fail the original joint-position predicate
because the pusher is far from its target; the other two also miss the
object-only threshold. Velocity contributes to the recorded seven-dimensional
distance, not this native success predicate.

This identifies an actionable evaluation mismatch to examine: objective
improvements in object pose need not satisfy the original task's pusher
target. It does not prove that the encoder ignores the pusher, justify
changing the original success criterion, or authorize using simulator state
as input to an RGB-only planner. A prospective task-aligned image-based
planner and comparable feedback baselines would still require separate
implementation, fixed protocol and physical validation.
