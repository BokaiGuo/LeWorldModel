# 统一入口的冻结 RGB 模型重放协议

这是既有多方向 v1 封存决策的**确定性接口验证**，不是重新执行原
研究配置、增加开发根或独立性能实验。四个暴露根、每根三轮均使用
原决策的已保存 RGB 历史、历史动作、ticks、目标图像、normalizer、
checkpoint 和投影，物理环境不再前进。所有模型输出来自重新加载的
冻结模型；不得用物理状态作为模型输入。

每个上下文分两部分：

1. **固定请求重放**：逐批将旧决策的已封存 float32 模型动作输入真实
   模型，直接对照封存的 position 和 score；检查批次数、形状、时钟
   和 token。预先规定逐元素绝对容差 `2e-5`（`rtol=0`），超过则
   保留为失配，不通过修改阈值重试。
2. **统一入口重新编译**：使用原 RGB 目标图像编码得到的真实目标投影、
   原计划 carry 和同一预测器运行新入口，保留全部实际模型请求与
   输出。对比旧计划的完整 selected、前五步、弃权、每批形状和分数；
   判断 selected/派发动作是否在绝对 `1e-5`、评分 `2e-5` 内。若分支
   或 batch 数不同，记录不同而非强制配对或声称一致；禁止将新行动
   送入旧 RGB 轨迹再称其闭环。

恢复编码上下文前验证 checkpoint、参数、normalizer、图像哈希、原
决策和执行文件绑定；记录真实目标向量、历史动作、源码及配置哈希、
CUDA/PyTorch/NumPy 版本、编码调用、预测批次、样本、token、wall
time，检查模型参数未修改。使用 GPU 协作锁，结果排他创建。
全量保存统一入口重新编译的预测轨迹；固定请求阶段保存逐批误差、
阈值结果和索引。严格区分实际模型重放、封存物理反馈和新执行；
不据此声明 PC0–PC5、泛化、强基线或独立来源通过。
