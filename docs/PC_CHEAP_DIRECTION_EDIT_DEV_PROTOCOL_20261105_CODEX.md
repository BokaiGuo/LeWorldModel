# 低调用任务方向修改：E0 开发协议

目的：在同一已暴露开发面板验证，少量方向割线能否提供有用的完整链精修起点，以及节约的预测预算能否改善最终质量；不是自动微分、VJP、完整响应、谱贡献或 PC2 机制证明。

沿用 V2 的 16 根、两个随机流、共同父链、15 步、三个五步片段及完整链评分。cheap 臂对每个片段独立生成一条 Rademacher 方向，使用当前父链的可行裁剪 `±0.05` 动作计算两个完整链特征；按各坐标实际扰动差得到有效方向，再将 `(goal-parent_feature)` 投影到特征割线并乘以有效动作方向，按最大绝对值归一化。若全零则记录零方向；不把其称为完整梯度或无偏估计。全部六条探针、父链及 12 条与 V2 相同幅度编辑均可进入 incumbent，随后运行同一全链 CEM。

八臂分别为 cheap_fixed、response_fixed、random_fixed、cem_fixed、cheap_total、response_total、random_total、cem_total。各 fixed 编辑臂使用 84 次相同 CEM 精修评分、CEM 对照总计 84 次完整评分；cheap 固定机会 `1+6+12+84=103` 次，不是等成本。total 四臂均 157 次：cheap `1+6+12+138`，其他三臂与 V2 相同。每次完整链计 3 prediction tokens；共同父链生成费用不计，各臂都无法用 prediction token 表示全部 CPU 成本。随机流沿用 V2，cheap 方向使用 seed+200000。所有已评分链参与最终 incumbent；日志逐调用保存输入、输出与哈希。

报告每根两随机流的配对终距差、初始精修质量、成功数 `<0.05`、预算与外部统一计时；固定机会和等 token 不混为独立样本。父链、任务均已暴露，本次是候选开发而非独立确认。不可证明跨片段组合、真实 RGB 闭环、独立来源或完整墙钟／GPU／内存成本，不能改变 PC0–PC5。异常不得伪装成有效数据。
