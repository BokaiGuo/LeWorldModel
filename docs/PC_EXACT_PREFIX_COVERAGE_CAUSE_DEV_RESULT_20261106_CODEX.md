# 精确墙障前缀覆盖与尾部优化：开发诊断

按[事前协议](PC_EXACT_PREFIX_COVERAGE_CAUSE_DEV_PROTOCOL_20261106_CODEX.md)，
对上一轮 24 个已暴露任务的全部八个固定前缀进行后验尾部精修，同时将
解析可行见证用于独立诊断，不提供给部署规划器。

| 诊断 | 任务成功数 | 跨任务平均最好终距 |
| --- | ---: | ---: |
| 原八前缀，各 36 次评分，评价端选最好 | 0/24 | 0.51039 |
| 原八前缀，各 384 次评分，评价端选最好 | 0/24 | 0.50088 |
| 几何可行见证的前缀，从全零尾部优化 384 次 | 1/24 | 0.63351 |
| 完整几何可行见证重放 | 24/24 | 接近零 |

每个任务在更大预算下的后验最好终距均有改善，但没有达到
`<0.05` 成功标准。扩大预算的前 36 条动作及成本逐项重现上一轮；
这不是同总预算的算法对比。八前缀的评价端最优也是 oracle 指标，
不是任何部署臂的成绩。

这一次至少有一个任务中，原池扩展搜索失败而可行见证前缀上的
同预算搜索成功，说明有限预算下原池可失去可利用前缀。另一方面，
其余 23 个任务的见证前缀都有一条真实可执行的成功尾部，但以全零
起点运行的当前 CEM 未能找到成功尾部。因此不能把上轮 0/24 仅归因
为描述器或前缀覆盖：当前高维、逐步参数化尾部优化也有明确缺口。
这不证明原候选前缀不可达，或所有优化器都会失败。

可行见证仅用于确认任务与诊断前缀；没有将见证尾部用于优化初始化、
选择或先前规划。每条见证均核验动作界、无阻挡事件和最终状态；
独立审计重算全部 82,944 条完整链评分，检查前缀固定、初始零尾部和
数据绑定。相关选择及成本边界回归测试 **4 项通过**。

下一轮若继续开发，应先另立协议检验不使用特权见证的时序一致动作
参数化／多样化尾部优化，并与当前逐步 CEM 在相同总评分及共同起点下
比较；只有候选池具备区分力后，才能再次测试新的后果信息利用。
不能把这次诊断当作当前已封存描述的阳性证据，也不改变 PC0–PC5。
