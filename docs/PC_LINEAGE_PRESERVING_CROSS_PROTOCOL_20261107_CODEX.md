# 完整链来源保持：等128查询的交叉信息开发协议

日期2026-11-07；事前冻结，**不是独立确认**。接续交叉查询已定位的构造损失，不重开已停止的8×32配置。旧文件和停止规则均保留。

## 1. 修改依据与边界

旧实现从39条名义链的前8条取前缀、后31条取尾部，8次运行丢掉原本存在的成功完整链。仅事后添加39条免费候选不合法；即使付费增加为167查询，也不能把预算增加当作方法增量。

本版本保持128条完整查询，把候选池改为同一批16条名义链的前缀与尾部：16行×17列（列0为10步合法hold，其余16列与原链一一对应）。每条原始完整链都在池中，且先实际查询16个 `(i,i+1)` 配对、保留incumbent。该修改同时改变行列支持，**不是声称只修改了一个选择开关**；因果比较在新候选池内进行，旧新版差异仅是开发描述。

这解决“原始配对被拆散”的不变量；不保证覆盖新好链，也不保证低秩近似在非平滑区域可靠。

## 2. 任务、查询和信息隔离

- 使用前一版已曝光的24个任务、2个生成流；仍为24个统计任务，不是48个独立样本。
- seed仍为 `2831000+100*root+repeat`；取同生成流前16个offset，均匀[-2,2]，不按成功筛选。
- 精确state/dynamics，15步完整链，5步前缀+10步尾部；物理动作和成功规则不变。不是RGB-only。
- 先查询16条名义链。再查询全部前缀×A列 `[0,1,2,3]` 的未查询项。
- 仅从A选3个锚点：最小实测机会为首锚点，再按响应残差确定性选两个枢轴。与旧算法相同。
- 补齐锚点行其余列，跳过已计费的原始配对。共同查询数为113–116，剩余12–15次分给提案，全部最终候选必须实际评分。
- 对未知格保持NaN；已查询的名义配对恢复真实模型分数，不能用近似值覆盖。
- 逐次保存完整动作、来源和预算。原始配对在最终比较中不可丢失。所有候选都符合动作边界。

交互公式、最大残差秩2、`pinv rcond=1e-8` 不变。只从当前查询拟合数值近似，无离线训练、无评价标签输入。预测范围是未查询配对，不声称全新尾部泛化。

## 3. 比较臂

7个同共同信息臂：`cross_interaction`、`additive`、`parent`、`row_mean`、`probe_min`、`shuffled`、`random_missing`。分别用交互、全部观测的加性最小二乘、原始完整链代价、A行均值、A最小值、动作身份打乱交互、随机未知格分配剩余查询。

打乱只作用于锚点的未作为固定A或原始配对的列；保留其可打乱分数集合，最终原始已查询矩阵不变。若某锚点原始配对位于A之外，它的身份也不能被打乱后当真值覆盖。

4个128查询对照：

- `uniform_lookahead`：共同16个名义配对，再按列优先、行轮转查询112个未查询组合。
- `random_pairs`：共同16个名义配对，从其余格随机选112个。
- `waypoint_random`：相同生成流前128条完整waypoint链；前16条正是所有臂的名义链，后112条重新实际查询。
- `nominal_cem`：先相同16条名义链，取实测最好链，7轮×16样本全链CEM，elite4，初始std1/3、最小std1e-5；每轮首样本为均值，保留所有已评分incumbent。优化随机流 `seed+60000`，不得使用评价端最优尾部。

冷启动CEM已经在旧版运行，本轮不以其作为主要增量参照。这里的warm CEM仍是固定开发配置，不冒充正式充分调优强基线。

## 4. 验收与停止

工程验收：16条名义动作字节与对角组合一致；全被实际计费，最终选择不差于最好的名义链；共享查询去重且所有臂恰好128条完整链。验证独立标量/旧批动力学、精英更新、名义保留、近似公式、所有真实查询来源。异常不删除任务。

信息出口：剩余共同未知配对的MSE按任务先平均两个流；至少16/24根分别优于加性和打乱。排序/成功区域误差辅助报告，不能替换出口。

部署出口：48运行中，交互臂相对每个同信息臂及4个同预算对照均至少净增4次成功，平均终距也更低。成功仍为终距 `<0.05`。报告24根配对bootstrap，seed2839000、10000次。保持与前版同等严格的开发标准，不事后选择非劣效阈值。

只有二者同时满足才允许进入同版本实际链机制及RGB适配；否则停止扩大该配置。工程不变量通过不是科学gate通过。即使descriptor未增益，完整链保留组件仍可作为经测试的工程工具，不能单独构成Planning Compiler论文贡献。

## 5. 完整失败分解与成本

全11臂计划封存后再计算16×17池的完整真值和真实轨迹；报告池覆盖、原始16链成功、共同查询成功、提案增加的成功、漏解及最终选择损失。名义链质量和方法成绩分别列出。

每臂128×15个动力学步；生成、查询、近似、优化、选择CPU时间分开。共享计算每臂逻辑计费；实际runner次数单列。源代码/后端/协议/任务/动作哈希绑定；支持逐根恢复、不覆盖完成产物。原始轨迹、图、报告和停止状态均保留。不是GPU、完整视觉闭环或独立泛化成本。
