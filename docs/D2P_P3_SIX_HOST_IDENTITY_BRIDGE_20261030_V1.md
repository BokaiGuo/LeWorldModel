# P3 六槽主机身份前置接线

本次新增独立桥接模块，复用现有六槽 source-bound producer，不修改原 journal、封存或科学门。它只接受调用方已构造的原生 factory、模型及显式 CUDA 设备；导入时不加载模型、不探测设备，也不启动物理环境。

桥接在 producer 前后检查源合同与 producer/本桥源码哈希、模型 state_dict 和全部 buffers 哈希、模块源码、eval/frozen 状态、所有参数和缓冲的设备、可用的运行时设备 UUID 和精度合同，并检查 hooks/forward 恢复。调用方必须提供合同和代码的外部哈希；不接受 CPU 作为 CUDA 替代。producer 异常仍向上传递，后检失败不会返回成功收据。

返回值只是在内存中将首尾身份快照与 producer 的 terminal 哈希关联；它不是耐久的身份事件，也不是硬件证明。原有 producer 自行封存，因此不能在其目录或 journal 追加身份事件。前置失败发生在 producer 运行之前，不会生成 producer 失败记录；后置失败可能发生在 producer 已发布之后，不能将该发布物单独当作完整 HOST 认证。

尚未闭合：主线程的生产授权、模型加载与 CUDA 分配验证、六槽整体显存/存储/墙钟预算及协调、贯穿运行的资源和精度守卫、backend 确实使用同一模型/设备的强制绑定、独立耐久身份 journal 与其严格保存消费者，以及原生构造器返回句柄前异常时的资源回收。设备 UUID 的取得依赖运行时属性；缺失即拒绝，UUID 也不是硬件远程证明。首尾快照不排除中途变化后恢复。此模块不是完整生产 driver，不授权任何运行或科学结论。

测试仅使用 CPU 对象替身；未实际加载权重、探测 GPU、分配 CUDA 或运行物理环境。
