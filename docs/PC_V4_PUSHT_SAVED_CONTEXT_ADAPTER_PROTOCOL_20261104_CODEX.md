# PushT 保存上下文 v4 接口开发协议

只用四个历史校准根的封存 latent 三帧、动作历史及 goal0；不使用旧候选库、不读取物理终态挑选动作。依赖原 PushT checkpoint/config、公开示例动作均值与标准差和原报告哈希。该统计与本地 HDF5 统计不同，checkpoint 的真实训练统计和训练成员未知；goal0 图像生成及整个历史预处理来源不因此自动获得认证。

对每根先构造固定的零动作、常数动作与时间变化动作，在 5、10、15 步分别比较 v4 的批量多 packet 转换和 PushT 既有逐 packet CUDA 重放，逐元素最大误差不超过 `2e-5`。原始命令始终直接标准化为 time-major 5×2 packet，不额外除以 100。然后冻结 model eval，使用原 v4 response、15 步终点、1920 prediction-token、目标 latent 方向加固定随机正交方向的二维 chart，运行一次模型内决策。记录所有请求动作、分批预测、生成与选择结果、预算、模型参数和 buffer 哈希，以及源报告、权重、配置、所用代码的依赖哈希。

各根结果排他写入，已有部分结果不覆盖；完成后独立重算完整链评分、选择和参考重放。此为历史已暴露校准 context 的模型内适配诊断，未执行真实 PushT、未证实接触、目标物体姿态、合法观测来源或完整计算公平；不能当作 PC0、PC1、PC3、PC4、E3 或泛化通过。
