# P1 轨迹感知目标诊断协议

当前 P1 Adam 规划只以第 10 步终点 latent MSE 作为优化和选择目标，
而物理环境允许在中间步提前成功。若中途达到任务目标、后续动作又
使终点偏离，终点目标会把这类候选判为差。这里新增一个只用于已知
根诊断的目标，不修改历史结果和 P1 gate。

固定输入为 `p1_uphill_cp5_bundle_20261030` 的 24 行、同一冻结
checkpoint、同一四起点、Adam 学习率 0.05、20 次更新和动作盒
`[-1, 1]`。每个候选按两个五步 packet 的预测端点计算：

```text
L5  = MSE(predicted_packet_5, goal)
L10 = MSE(predicted_packet_10, goal)
J   = -tau * logsumexp([-L5/tau, -L10/tau]), tau=0.02
```

选择器最小化 `J`，同时保存 `L5`、`L10` 及达到较低端点的 packet。
不读取真实物理状态、成功标签或 RGB 终点，不训练模型，不降级 CPU。

该诊断只检验“终点目标与提前停止语义是否存在代码/协议错配”。
即使它改变了候选或后续真实结果，也不能替代同一动作链上的真实
能力干预、独立根、等预算和强基线 P1 合取。任何物理执行必须在
主机 CUDA 上另行执行并保存完整失败/提前停止分母。
