# E0 特权固定前缀：逐步与四结点 CEM 对照

## 待证伪假设

既有诊断中解析可行前缀配合四结点 CEM 在 18 个暴露根上仅 4 根至少一次成功；四结点对解析尾的动作均方投影也未成功。检验将十步后缀改为十个结点、即每步独立动作，是否在相同预算下改善搜索；此前的投影并不是四结点性能上界。

## 固定设计

使用已有[特权前缀诊断](PC_V7_E0_ORACLE_PREFIX_SUFFIX_DEV_PROTOCOL_20261104_CODEX.md)的相同 18 根、同一首个解析见证的前五步、每根同三条种子、同精确后端和零后缀基底。既有四结点记录直接复用；新臂仅将后缀结点数从 4 改为 10，其余 CEM 批大小 12、精英数 4、初始标准差 0.35、标准差下界 0.07、初始链一次及 480 条采样与原代码一致；保留历史最优、float32 实际动作与每代信息。两臂虽然使用相同整数种子，但随机数形状不同，不能当作逐样本配对。

预先报告两臂成功流数、至少一流成功的根数、根均终距均值及逐根三流平均胜平负（`1e-10` 平局容差）。另报告完整解析见证重放，仅验证可行性，不用于任何优化或选择。验证同样的根、前缀、种子、初始链、样本数和时域；以同一后端逐动作重算全部新链、最优和统计。根级比较亦非独立确认：根与方法均已暴露，随机流不是独立任务。

该协议只诊断固定特权前缀下两个搜索配置，不证明自动发现、PC2 机制或 PC3 优势；不将结果写入正式方法，也不依据结果调节预算、种子或阈值。若逐步参数化未改善，仍不能证明四结点最优或搜索已充分；若改善，也不能区分表达能力与高维采样的交互或普遍外推。保留所有既有负结果和新产物，排他写入。
