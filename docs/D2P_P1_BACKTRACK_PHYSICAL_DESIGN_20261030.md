# P1 回溯候选：完整物理验证设计

本设计在模型输出已观察后、任何本版物理结果之前固定；它是已知根探索，不是独立新根或预先注册的确认试验。输入为 `p1_backtrack_action_inventory_20261030_MAIN01.json`（SHA256 `27b3f1016efa0affe5c8b38c2da0d48cf0ce0ef4db11de974e1c5dc30e1c863e`）。其结果是动作清单而不是部署许可：必须先重验上游模型产物和保存分析，绑定原任务、环境、渲染、归一化和原始历史。

该模型运行只记录 runner 自身哈希，没有完整封存新增辅助模块的执行前后哈希，也未单独完成两包 whole/segmented 重放；因此清单不能作为完整源码认证的生产凭据。先在新来源合同下对固定动作进行主机 CUDA 重放并审查结果，再决定是否可进入物理 adapter；不得将新重放追认成历史运行时源码证明。

新重放已完成，详见 [CUDA 重放结果](D2P_P1_BACKTRACK_CUDA_REPLAY_RESULT_20261030.md)：16 条报告双路径一致，分段记录经保存复核；连续路径数组未保存，不能从保存数据独立复算两路径相等，GPU normalization 也未独立复算。故其为后续接线提供动作证据，但尚未替代完整物理来源／部署认证。

## 固定分母和比较

8 个逻辑臂（四任务槽 × 两种候选生成臂）各保留 `incumbent`、`model_selected` 两角色，共 16 行；每角色执行清单原始 prefix5 + suffix10，共 15 个控制动作。每臂在 cp5、cp10、cp15 分别比较原 native success、原 reward 和原 native7 目标距离，另分列位置、角度、速度和实际 RGB 编码目标代价。新方案相对于同臂 incumbent 的同时间差异全部保留；不可用或提前终止为 null，不以早停状态顶替 cp15。模型上的 `stage_uphill` 不等于物理上坡。

不根据物理结果筛选两个模型上坡槽，不把两臂或两个条件当作独立根；如计划去重，必须事前证明 task/goal、reset/warmup/history/renderer、动作位级和终止合同完全相同，保留全部逻辑别名及成本。仅按本清单中 `(slot, raw15 bits)` 有 9 种组合，这不是跨环境身份认证或已批准去重。

## 真实能力探针

对每一角色的 prefix5，以原先固定的 common-prefix 合同在相同目标方向上施加 21 个五步 suffix：zero、十个坐标各正负 0.25，按 `p1_constructive_common_prefix_capability_probe_design_20261027_v1.md` 的原 chart、坐标顺序、球约束和指标定义。保留 16 × 21 个逻辑探针，连同 16 条主轨迹，缺项不补；不能从探针中按真实收益选择动作。若确切身份允许物理去重，先封存映射并报告实际执行与全部逻辑分母。

每条环境从原 authority 独立 reset/place/warmup，确认 cp0 的状态、目标、RGB、完整动作历史和原配方后才执行 prefix。不同 prefix 不能复用旧 cp5 守卫：每个精确 prefix 首先建立新 cp5 参考，后续相同 prefix 复演须逐项核完整 state、snapshot、pixels、动作历史；失败时不派发后缀。cp5 无足够隐状态证明时必须披露限制，不使用 set-state 捷径。探针同一位置按同一步、同目标比较，保留方向未定义、原生早停、缺帧和所有失败。

## 执行前尚缺的工程证据

需要新的独占 adapter 及 strict saved consumer，连接该清单与原任务 authority、完整部署 raw chart、独立 reset、动态 history 和原物理配方；执行前固定 352 条逻辑轨迹的资源上限、PNG/事件字节上界、磁盘余量及实际操作计数，覆盖失败不退款、已有输出拒绝、来源/动作一位篡改和 early-stop 测试。可分阶段执行，但不能按已知物理表现调整分母。模型预测与真实 RGB 应使用同动作、同时间的独立 CUDA 编码；所有模型计算和真实执行成本单列。

本设计不授权伪 fresh、不改变 P1 gate、不训练模型。即便同一物理方向和真实目标收益改善，也仍须满足原合取、强基线和独立根确认，才可评估完整科学主张。
