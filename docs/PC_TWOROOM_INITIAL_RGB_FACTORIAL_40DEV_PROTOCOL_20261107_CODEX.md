# TwoRoom 初始化图像来源：40 根固定候选开发审计

前期 50 根像素审计发现当前图最多 11 像素、目标图最多 9 像素
存在最大 1/255 的通道差；仅一根事后候选组做过评分排序核查。
本协议固定 root 10–49（已曝光，不是独立确认），检查同一候选池
中差异是否改变模型决策及物理执行结果。

每根复用 block-CEM、block-random 各 300 条中的模型分数最低 16 条，
共 32 条合法完整链；该候选池事后依赖数据图生成，不是两种输入
各自重新优化，也不能用于比较实际端到端规划收益。保持冻结模型、
动作尺度、模型时钟、候选动作一致，比较：

1. `data_data`：数据当前图和数据目标图；
2. `render_data`：相同复位状态的实时当前图和数据目标图；
3. `data_render`：数据当前图和相同目标状态的重渲染目标图；
4. `render_render`：实时当前图和重渲染目标图。

仅 `render_data` 是具有数据目标图和实际当前图输入的部署模拟；
目标重渲染使用评价端真实目标状态，仅作图像来源因子诊断，不能
作为 RGB-only 规划证据。所有状态只用于设置评估环境与生成受控
渲染，不作为规划器输入。先封存四臂每条预测代价和各臂最低分
链，再从同一物理初态分别执行选中链，记录逐步成功和距离。

对数据／实时当前图、固定数据目标的主对照，报告逐候选最大绝对
分数差、每根选择变化、逐任务曾成功与末步成功的配对变化；目标
图因子及交互单独报告。报告分差小于 0.01 的近并列，不因小差异
推断完全等价。若 40 根没有动作变化或结果无净变化，停止把此类
像素差视为该固定面板退化的主要解释；若观察到变化，仅作为继续
诊断依据，不宣称环境、隐藏状态或闭环整体等价。渲染前后核验 agent
与目标位置未改变（不是完整隐藏状态认证），记录像素差和固定候选身份。四臂查询各 32 次，重新评分
总量计入实验，不宣称完整成本优势或 gate 通过。
