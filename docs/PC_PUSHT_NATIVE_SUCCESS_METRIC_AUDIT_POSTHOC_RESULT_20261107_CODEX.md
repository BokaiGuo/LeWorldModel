# PushT 原生成功与奖励语义：后验核验结果

## 关键修正

上一轮“三方动作排序”中的物理指标仅衡量**物块**位置与角度；它不能替代本地 PushT 环境的原生奖励或成功规则。环境成功要求推杆和物块的四维联合位置距离小于 20，且物块角度差小于 `pi/9`；原生奖励是七维状态距离的负数，还包括推杆速度与原始角度差。因此，latent 评分偏向推杆目标并不自动是错误：推杆位置在这一具体任务合同中也是成功条件的一部分。

## 同一封存面板的核验

对 16 根、64 个状态条件的全部 192 个候选末态，独立调用当前环境 `eval_state`，重算成功标志与状态距离，并与采集时的成功标志逐条核对，全部一致。**原生成功为 0/192**；这些条件不是独立任务，不能据此推断整体 benchmark 成功率。所有候选的推杆位置误差平均约 240.46，说明此面板主要是局部接触诊断，并非满足原生目标位置的完整任务。

| 事后评价量 | 模型预测选择的平均遗憾 | 真实编码选择 | 零动作 |
| --- | ---: | ---: | ---: |
| 历史物块姿态诊断代价 | 0.1665 | 0.0879 | 0.1665 |
| 原生七维状态距离（奖励的负数） | 15.0021 | 16.8955 | 8.3452 |
| 联合位置／角度连续代理量 | 21.2154 | 23.0688 | 12.9782 |

各遗憾相对同一条件下三个候选的最小评价量；连续代理量不是原生成功规则或奖励，不能据此宣称成功。两种背景共享物理轨迹，四个条件先按根平均等价于这里的条件均值，但不构成 64 个独立任务。真实编码是评价端可获得的上限式信息，不能作为在线规划器的输入；零动作也不是一般场景的通用解法。

此次修正的是**实验解释和评价边界**，不是证明世界模型或原代码存在 bug。不同评价目标下排序不同，无法仅从物块指标判断目标图的推杆信息是有害干扰；同时原生奖励包含速度，也不能直接当作纯物块 pose 指标。
