# P3 动态 chunk 原型与科学门

本文件与独占代码、测试构成探索性原型，不是预注册或部署授权。
固定基础 chunk；每次拟延长前，使用冻结模型对当前动作序列给出当前
和延长后的模型代价，以及事前模型分歧。只有预测改善达到固定阈值、
分歧不超过固定阈值时才增加一个固定长度；首次拒绝即停止，且有上限。
阈值、动作、模型与预算须在独立评估前冻结。不能输入物理成功、未来
观测或事后标签；模型分歧阈值不是物理安全保证。

代码提供纯 CPU 调度内核和显式向量计费接口，不运行神经模型或环境。
每次信号获取在调用前扣除固定资源向量，失败不退款；超预算不派发。
固定臂不执行人工信号工作。计数轴独立、可能嵌套，不可相加称为 FLOPs。
相同上限不等于相同实际成本；模型初始化、wall、内存、能耗仍未测。
调用方必须保证信号确来自当前模型上下文、候选动作及执行前信息，
并在实际模型调用处可靠计数；本原型无法验证外部回调是否诚实。
同一个 meter 应覆盖搜索、信号和其他所有被比较的操作；这里仅提供
通用计费接口，不假装已接入既有 host 或完整审计链。

后续固定/动态比较需同根、目标、候选生成、总上限及动作执行规则，
记录所有实际资源、失败和删失；预算耗尽不能悄悄重试或扩大额度。
须先完成真实模型接线及来源、事前时序和资源账本核验，再进行独立
物理配对评估。已知根、历史面板和单元测试不构成泛化或调度收益。
P1、freshness、P3 与物理安全准入均未因此改变。
