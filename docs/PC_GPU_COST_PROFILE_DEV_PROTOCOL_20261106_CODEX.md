# 冻结上下文规划成本：同步计时开发协议

复用已记录的第二次规划 lookahead 任务 15、25、35 的同一张实际
观测图和目标图；仅使用 pixels、goal 两个视觉输入，规划器不使用
物理状态或成功标签。比较有界全链 CEM 105×6（632 条）、300×10
（3002 条）、300×30（9002 条），以及固定前缀 lookahead（632 条）。
每个方法／任务用 seed 42、1042、2042 各独立求解一次，额外对
同模型做一次 105×6 暖机，使用真实数据正常化和有界动作。

每次开始及结束进行 CUDA 同步，记录总规划墙钟、所有 `get_cost`
累计同步墙钟、其内编码累计同步墙钟、CUDA events 测得的总 GPU
及编码 GPU 时间、候选数和调用数、显存峰值。编码包含目标和
初始图像的重复编码；记录包含 instrumentation 和同步开销，时间
是嵌套量，不能相加；CUDA event 包括流上的工作，计时同步会
改变批处理调度。这是固定上下文计时，不含数据加载、模拟器执行、
图像预处理、反馈次数和整个任务闭环，所以不是完整系统成本或
完整质量—成本曲线；成功率须引用独立的实际闭环结果。不给未测量
项填零。失败时保留结果和错误，不能偷偷回退 CPU。
