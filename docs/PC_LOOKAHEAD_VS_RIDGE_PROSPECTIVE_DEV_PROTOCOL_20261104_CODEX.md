# 后继探针的保留准则与最终链测量：配对开发协议

这是使用原窄束面板 16 个已暴露任务的新开发比较，不重开、改写或重新判定旧停止面板；不声称独立确认。先完成两臂全部计划并审计、封存，之后才能读取计划做任何机制干预。失败保留分母。

两臂均采用同一 v25 全球候选、响应生成、探针动作、束宽 2、greedy 槽 1、多起点优化和 2880 prediction-token 上限，配对使用同一随机种子。唯一配置差异是同一组后继探针的保留值：ridge 臂用原输出空间局部岭残差启发式，probe_min 臂用该组已评分合法完整链的最小任务终距。两臂均计算岭值，避免把消除该计算的潜在节省提前计入；probe_min 是有限动作探针，并非额外完整 lookahead 优化。记录实际 token、墙钟和谱耗时；墙钟包括记录开销，不声称完整 GPU、内存或全系统成本相同。

预定报告每根最终链终距、`<0.05` 成功、配对差值、两臂各层保留集合与探针值。比较是否存在响应保留决策与最终链质量变化；无预定统计功效，不能作为 PC3。

干预针对精修、弃权后的每臂实际最终链：selected、zero、首层 greedy、固定随机前缀，共同尾部包含零、四个常量以及实际尾部；每前缀另做三次四结点零初始化重规划，每次 1+480 个完整链评分，配对复用随机种子，报告绝对分数及分布。全尾部 20 坐标在 0.01、0.05 两尺度由最终链响应接口测量，保存请求、实际 float32 分母、每坐标分支及模型调用；分支重放另计。非光滑跨分支割线只描述离散分支变化，不被称为光滑 Jacobian。该开发协议不定义新 PC2 通过阈值，不删除旧条件，不把测量差异当机制成立。

每阶段捕获并校验声明依赖哈希、计划哈希及预测请求日志，失败保留已请求动作及费用；声明依赖不等于完整环境闭包。无真实 RGB、来源独立认证、强基线或全系统成本，不可用于 PC0–PC5 通过声明。
