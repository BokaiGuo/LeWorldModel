# TwoRoom 两阶段稀疏查询结果

按[协议](PC_TWOROOM_SPARSE_RETENTION_QUERY_PROTOCOL_20261107_CODEX.md)，
在 GPU 上实际先查询 65 条 A 链，然后对三个保留策略分别只查询
各自保留前缀的 8 条 B 链。40 根合计查询 **3560 条链**，即每根
共享 65 条加三臂各 8 条；每个独立臂的逻辑查询量为 73 条、
365 个模型 packet。实际每根批次为 `32,32,1,8,8,8`。
这验证了先前报告中仅作事后估算的查询流程；不代表已经测得三个
独立端到端规划器的墙钟。

| 方法 | 保留索引与旧全矩阵一致 | 最终索引一致 | 旧物理重放中选中链成功 |
| --- | ---: | ---: | ---: |
| 普通 lookahead | 39/40 | 39/40 | 40/40 |
| 描述多样性 | 39/40 | 39/40 | 40/40 |
| 任务内身份打乱 | 39/40 | 39/40 | 40/40 |

三臂中发生索引变化的都是 seed 1888821。旧计划的前缀 1、3、11
动作逐元素相同，但旧矩阵中的重复动作在不同批次得到约
`5.7e-6` 的最低 A 分数差；稀疏批次中该差异消失，稳定排序因此选了
不同索引。对全部 120 个最终决策逐元素比较后，**实际完整动作链
120/120 与旧计划相同**。物理成功是读取这些链此前的物理重放，
不是本次新做的环境执行。

所有 A 分数最大绝对差为 `2.14e-4`；三个臂中 B 分数最大绝对差分别
为 `2.14e-4`、`4.88e-4`、`3.60e-3`。因此不能声称不同批次逐位等价；
此面板的完整动作一致也不保证其他候选池的决策不变。

此次共享 A 的同步模型评分时间中位数约 30.1 ms，各臂 B 分别约
9.21、9.20、9.19 ms；仅涵盖评分调用，不含候选构造、完整数据处理、
物理执行、初始加载或独立臂的完整计时。不能由此宣称端到端成本优势。
候选身份、只访问保留 B 的测试及原保留测试共 4 项通过。
