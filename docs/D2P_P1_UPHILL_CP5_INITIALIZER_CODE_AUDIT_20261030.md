# P1 cp5 初始化与动作接线核查

针对已封存的 24 个零初始化与暖初始化规划结果，核查现有调用
链，不改动运行代码或历史合同：

- cp5 上下文使用真实 cp5 latent，保留根历史后两个状态，将最后
  一个历史动作包与本前缀五步归一化动作包拼接；输入构造器
  逐字节检查 warmup 动作归一化与已存历史一致。输入白名单不
  包含物理真值；文件系统级隔离仍未认证。
- 两组都使用同一有界原始动作优化器、20 次更新、相同步长；
  零组以全零原始动作初始化，暖组使用同一逻辑条件下 selected
  的原联合后缀初始化三种前缀。优化器对每个动作包应用同一
  mean/std 再调用动作编码器，并在原始动作空间约束至 [-1,1]。
  静态检查没有发现这里存在显然的初始化尺度接错；这不是对
  checkpoint 训练 normalizer 来源的认证，也不等于证明链路无 bug。
- 直接逐 index 比较两个已保存规划目录的 `result.score`，暖组
  有 20/24 条更低、4/24 条更高；更高的四条是 root 1 的 greedy
  在 on/off 两个条件各两次重复臂。不能将 24 条视为独立任务。
  分数是模型内规划分数，不是成功率，也未对预测分数另行 CUDA
  复算；上述只是对已有报告值的事后描述，不能证实初始化在
  更广任务上更好。

已完成的真实物理结果仍是：零初始化 0/24 成功；暖初始化仅在
root 0 的 selected 与 zero 达到原生成功，重复臂和 on/off 不
应作为独立成功。暖初始化来源于 selected 候选，生成开销没有
纳入公平预算；这些结果不允许宣称 selected 前缀带来了可规划
能力优势。详细物理终止和删失见
`D2P_P1_UPHILL_CP5_WARM_RESULT_20261030_MAIN.md`。

这个检查优先排除了当前源码中一个具体的动作缩放/历史拼接
疑点，但没有消除训练来源、模型预测误差、真实目标错配和后缀
优化器初值敏感等其他解释。独立确认与完整共同后缀结果仍待
完成；P1 不因此开放。
