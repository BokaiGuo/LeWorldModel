# RGB 真实动作历史反馈开发协议

目的：验证五环境步动作包、观测历史和 future-only 候选在真实 PushT
反馈中的接线；并探索真实历史是否改变相同 CEM 预算下的行为。
此试验不是 Planning Compiler 性能或 PC4 验收。

使用已暴露的受控 PushT 根 0、8，白色外观、side=+1；同根同初态和目标
配对。两臂分别使用最新一帧与最多三帧真实图像；后者仅在每个五步包
完成且获得实际渲染后添加对应动作和图像，不填充虚假历史。两臂使用
同样的冻结 RGB LeWM、动作 normalizer、候选随机流、3 个未来动作包、
两轮各 32 个 CEM 候选、8 elite，每轮候选第一条为当前均值；每次执行
一个动作包，最多执行三个包。重规划时将旧尾补全后作为初始均值；
最终均值和旧尾分别重评分并选择低代价者，计入模型候选成本。所有
候选按物理动作域裁剪，实际派发动作及其结果由评价端记录。

只允许规划器看到当前和历史 RGB、目标图像、已派发动作及旧尾；真实
物理状态仅供 reset 和评价。真实轨迹、选中链、候选计数、时间及输入
指纹写入新文件，旧结果不覆盖。目标是发现实现/时钟问题并记录探索性
结果，不设事后成功门槛；短时域、两个已暴露根和有限反馈不支持收益
结论，不允许更改历史 gate。
