# 新 C 后缀开发验证协议

制定于 C 后缀及其得分生成之前。性质是既有精确动力学候选池上的开发验证，不是来源独立确认或 PC gate 通过证据。

- 使用既有随机探针 v2 面板的全部 16 roots、3 arms、depth 0/1 的完整候选；不得按结果筛选候选。若输入失败、键重复或无法匹配，停止而不是缩小分母。
- 每个剩余时域构造 8 条共同 C 后缀：`numpy.default_rng(20411000 + 100 * length + 2)`，逐步正态 `N(0, 0.35)` 后裁剪至 `[-0.5, 0.5]`，转换 float32。旧 A、B 分别使用 split 0、1；逐条核查 C 不与 A/B 完全相同。相同长度、不同候选共用完全相同的 C。
- 行动输入从候选质量源读取 prefix，测试 `prefix + zero` 与 `prefix + C_i`，重算零尾代价并与旧描述 `baseline_score` 检验一致。保存真实派发动作和预测记录、前缀哈希、源哈希及每次调用成本；严禁 C 结果进入构造、筛选、保留、优化或规划。
- 对每个留出 root，用其他 15 roots 的旧 B 最大改善拟合固定岭回归，输入为旧 A 的 `scalar`、`ordered`、`sorted` 三组各加相同即时分数、零尾分数和剩余时域。用该模型预测留出 root 的 C 最大改善，报告每 root MAE、平均 MAE 和 ordered 与 sorted 配对差值；同时报告基于零尾转换的 C 绝对代价 MAE。同一根所有候选不视为独立任务。
- 唯一主开发比较：ordered 相对 sorted 的 root 等权平均 MAE 差，负值有利于 ordered；另报告 16 root 胜/负/平。作为开发效应描述，不设事后显著性或 gate。必须报告所有 root，不只择优。
- 有限 C 探针不是后缀最优质量；B→C 泛化不是新任务、物理可信性、独立重规划、动作身份因果证据或规划收益。下一阶段仍需事前确定的独立后缀与重规划随机流、来源认证及公平全成本比较。
