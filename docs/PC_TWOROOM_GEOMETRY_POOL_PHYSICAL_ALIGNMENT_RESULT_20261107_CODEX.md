# 几何候选首轮预测—真实编码—物理对齐结果

## 结果

按照[开发协议](PC_TWOROOM_GEOMETRY_POOL_PHYSICAL_ALIGNMENT_PROTOCOL_20261107_CODEX.md)，
对 40 个已曝光任务的首轮 16 链全部重放，并在第 5、10、15、20、25 步
保存预测表示和真实图像编码。640 条链中 222 条在 25 步内曾成功；
模型原选链和固定几何链各为 **40/40 开放环成功**。这与此前的闭环成功
是不同指标，不应混作额外独立成功样本。

每任务内仅比较一条成功链与一条失败链的排序，平分计半，再对 40 个
有成功和失败链的任务等权平均：

| 评分 | 任务平均成功/失败对排序准确率 |
| --- | ---: |
| 模型预测最小 packet 代价 | 0.9868 |
| 真实后继编码最小 packet 代价 | 0.9810 |
| 真实轨迹最小物理距离 | 1.0000 |

最后一行与基于物理距离的成功判据直接相关，仅作一致性检查，不是
可部署的预测器。以真实编码代价事后选择的链也是 40/40 成功，但真实
后继不可用于实际规划，不能当作规划成绩。

## 关键限制：候选生成混杂

这组高排序率不足以证明模型能够判断有价值的细粒度绕行后果：

* 增益 1.0 的五种门偏移全部成功：**200/200**；同增益内没有成功/失败
  对，无法用成功率比较偏移辨识。
* 增益 0.8 的链成功 **10/200**，增益 1.2 的链成功 **12/200**；各自
  只有 5 个任务同时含成功和失败链。阶段切换采用 `1e-4` 位置容差，
  不同增益使内部模拟接近目标点的速度不同，可能造成阶段推进明显
  不同，因此这里存在候选生成器与成功标签的混杂。
* 零动作候选 0/40 成功；即便排除零动作，模型的任务平均排序率仍是
  0.9854，但仍存在上述增益混杂。不能据此判定描述具备独立预测增量。

下一步若要判断模型是否辨识路线区别，应先修正并测试阶段切换的尺度
敏感性，固定具有同等推进机会的候选，再重新事前定义受控验证；不能
把这批已曝光任务当独立确认。若真实链依旧没有性能差别，也不能通过
改变判据制造阳性。

## 核验与边界

模型每条链重算的最小预测代价与原结果按协议容差一致；保存的预测和
真实表示可重算编码代价（最大绝对差约 `6.1e-5`），模型选择索引全部
一致。选中链最初五步的物理距离与原闭环记录逐项一致；模型权重前后
指纹一致。预测与真实编码逐元素 MSE 按五个 packet 的任务均值依次为
0.0857、0.0704、0.0748、0.0846、0.0982；该量不是物理误差。

候选池和实验任务均已曝光，环境重放与模型计算在同一程序中，未做
进程级隔离；观测类型和动作转换警告仍在。此结果既不认证未查询组合，
也不证明后果描述对普通 lookahead 或固定几何策略有增量。PC0–PC5
不改判。

测试：相关测试 **11 项通过**。
