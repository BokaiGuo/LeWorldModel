# Dev305：五步预测与实际执行时刻

## 实验与边界

在三个已知开发反馈状态、每状态四条固定候选的既有真实执行上，保留事先生成的五步冻结模型预测，使用同一 checkpoint 在主机 CUDA 编码每条轨迹第 1–5 步的真实 RGB 与同一目标图，共 60 帧加 1 张目标图。动作、历史、角色、保存帧和源文件哈希均复核；模型权重前后哈希一致。目标图未通过原可见性筛查，故本分析不构成正式 RGB-only 部署合同。

对各时间点比较同一五步预测的四候选 latent 目标距离排序与真实 RGB 编码距离排序。候选对为同根相关观测，不是独立样本；这些对照也不含可见性筛选。第 1–4 步并不是模型对这些时间的预测，而是用来量化把五步目标直接用于短执行时可能产生的时域错配。

## 结果

| 真实观测时刻 | candidate_02 排序反向 / 6 | candidate_00 | zero | 合计 |
| --- | ---: | ---: | ---: | ---: |
| 第 1 步 | 2 | 5 | 6 | 13 / 18 |
| 第 2 步 | 1 | 2 | 0 | 3 / 18 |
| 第 3 步 | 1 | 2 | 0 | 3 / 18 |
| 第 4 步 | 0 | 1 | 0 | 1 / 18 |
| 第 5 步 | 0 | 3 | 0 | 3 / 18 |

五步预测选中的均为 `toward_05`；真实第 1 步编码目标距离的最优候选在后两个状态均为 `away_02`。这不是建议事后选择后者：latent 距离本身不等于物理任务价值，而且前四步从不由该五步预测直接建模。该结果提示不能无条件将五步终态排序解释为一步执行质量；第 5 步仍有 3 对反向，说明仅修正时域也不保证解决预测与选择问题。

具体的下一步是维持模型原来的五步 token 时序，在五步边界刷新真实 RGB 和真实动作历史；如果需要更频繁的单步重规划，必须先实现和认证与 checkpoint 训练时间尺度兼容的构造，不能把相邻单步帧伪装成五步间隔历史。需另做预先固定的新物理实验检验这种修改，及同预算强基线；本分析不证明规划收益或能力重配置。
