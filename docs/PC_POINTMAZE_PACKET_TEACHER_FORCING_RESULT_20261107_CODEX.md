# PointMaze 已选 CEM 链逐包预测对齐

## 结果

在先前封存的八个曝光根上，对每根 48／160 次评分选链按 5 环境步间隔重渲染并进行同动作 teacher forcing。八根初始重渲染与原规划输入图逐像素一致；五包自回归末分数均在预设 `rtol=2e-4, atol=2e-6` 容差内复现原计划评分。动作、时钟和源文件检查通过，但不因此认证完整官方模型兼容或排除其他预处理差异。

| 原选链 | 第 25 步视觉编码 MSE：自回归 | 真实观测后单包 | 真实两帧及动作历史后单包 |
| --- | ---: | ---: | ---: |
| 48 次评分，8 根均值 | 0.03915 | 0.02247 | 0.02494 |
| 160 次评分，8 根均值 | 0.03808 | 0.02205 | 0.02153 |

误差以同一时刻的物理末态重渲染后编码为参照。两预算选链存在共享，且每组只含八根，不能把 16 条链当作独立样本。两帧历史不稳定优于单帧：它改变了模型上下文，不能从这里认定历史实现优劣。

根 1890 上，48／160 两链的最终目标代价分别为：

| 评分方式 | 48 次链 | 160 次链 |
| --- | ---: | ---: |
| 自回归预测 | 0.04857 | 0.02350 |
| 第 20 步真实观测后单包预测 | 0.04191 | 0.09587 |
| 第 20 步真实观测及动作历史后单包预测 | 0.04299 | 0.09486 |
| 第 25 步真实重渲染编码 | 0.03716 | 0.08876 |

这一具体案例中，事后提供第 20 步真实状态后，两种单包预测均与真实编码排序一致；实际物理末距依次为 0.155 和 0.784。真实观测是评价端 oracle，不能用于替原规划器选链，因而这不是闭环成功或反馈带来收益的证据。末态重渲染与现场帧也尚未逐项认证等价。

## 实现与边界

固定协议见[逐包协议](PC_POINTMAZE_PACKET_TEACHER_FORCING_PROTOCOL_20261107_CODEX.md)，代码为 `le-wm-main/experiments/pc_pointmaze_packet_teacher_forcing_v2_20261107_codex.py`，原始帧、源哈希及逐包数据前缀为 `le-wm-main/results/pc_pointmaze_packet_teacher_forcing_v2_20261107_codex_`。第一版评价时因零 batch 维度的 TensorDict 索引错误退出，未生成结果；其渲染工件保留，第二版独立重渲染并完成。时钟检查单元测试 1 项通过。

本实验使用 PointMaze 的完整 proprio，属于 **state-assisted、已曝光任务、事后开放环诊断**，不构成 RGB-only 证据，不证明更频繁反馈提升控制，更不能将失配唯一归因于模型本身。PC0–PC5 均未改判。
