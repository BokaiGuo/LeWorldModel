# P1 两候选同动作排序：已知根的固定探索对照

## 现有证据与可行性

这是一条已经看过物理与模型结果的开发根，以下对照是事后固定的探索性
诊断，不是盲测、独立确认、完整公平基线或 P1 admission。候选固定为
`structured_own` 与 `cem`，不是从更多候选中按结果挑优；选取依据是二者
均已有相同实际前缀后的完整封存计划及实际轨迹，且属于同一物理回放。
仍需承认此前观察了这些结果，不能称前瞻选定。

物理回放报告 SHA-256
`5225e645130e67699fe237e050c8bf0f1a5a0c756450b9cf22b479695eb418e9`；
两个分支同一实际 structured 5 步前缀、cp5 RGB 和 cp5 物理状态，均
实际完成 20 步，未终止／截断。已有 CEM 同动作刷新报告 SHA-256
`bff047d470e3922e05160fa468af0f88a314594733e84885d3f61f956676a3eb`。
源验证通过既有 `p1_cp5_cem_physical_20261101_leibniz.build()`：
三分支、5513 个来源，包括实际命令、计划报告和 trace。两个模型任务
的 root_context、goal、projection、动作均值／标准差与 cp5 latent
逐项相同；checkpoint tensor hashes 相同。候选尾段不同，每个预测必须
与其自身真实执行的同一尾段对应。

已封存的 cp5 开放 H3 终点 Q（越小越好）：structured-own
`0.12810702018294395`，CEM `0.335489286528884`。同动作物理 cp20
joint-XY（越小越好）分别为 `120.45650167011168` 和
`345.92363519480557`。因此**这一对已观察到模型 Q 与物理 joint-XY
方向一致**。这不是 RGB-Q 排序：当前 CEM 的 cp20 真实 RGB-Q 为
`0.462644733842353`，本核查没有确认 structured-own cp20 已有可用的
同合同真实 RGB-Q；不能从其物理 joint-XY 推断。两条结果均无 native
success。单对不能估计排序准确率或泛化，且模型 Q 与物理 joint-XY 的
单位和含义不同。

## 可执行的固定对照

在任何新编码／预测之前，封存以下完整 roster、源哈希、算子设置与报告
位置；不调整选择、增删候选、按结果重挑阈值：

1. **共同 cp5 的真正排序主对照：** 同一 checkpoint、同一 cp5 latent
   历史、原始动作归一化和目标 Q；分别按各自封存的实际后续 15 个动作
   自回归预测 H3。比较 `Q_pred(own)-Q_pred(cem)`；同动作物理对照比较
   `jointXY_actual(own)-jointXY_actual(cem)`。另外对各自实际 cp20 RGB
   编码，分别计算同一 Q，比较 `Q_RGB(own)-Q_RGB(cem)`。三项分别
   报数及符号，不合并物理和 RGB 排序。精确相等记 tie，不以阈值或偏好
   规则强行判胜；若预先需要容差必须在任何新结果前另行声明。
2. **刷新误差辅助对照：** 为每条轨迹分别编码其实际 cp5/10/15/20；
   使用各自已执行动作和实际 RGB latent 滑动历史，逐包做 teacher
   forcing。逐候选逐时点报告 predicted-Q、actual-RGB-Q、latent RMSE、
   projected RMSE 以及物理 metrics。把它与对应开放预测对比，不改变
   已封存动作、不用物理结果选择计划。
3. **关键因果边界：** cp10 后两条候选已处在不同真实物理和 RGB 历史。
   各自刷新预测比较的是不同条件分布下的一步误差，**不是同一状态下
   两候选排序**。若要在共同 cp10 评估两候选，需先锁定同一真实 cp10
   起点、固定两条后缀，再实际从该状态分别执行，取得各自物理／RGB
   终点；当前数据不能代替这种交叉干预。

模型输出的一步或 H3 Q 与真实 RGB-Q 不等价于预测物理状态；Q 的符号
一致亦不证明因果机制、闭环改善、强基线公平或普遍可排序。对潜在
数值扰动敏感的近零差值必须原样报告，不作确定胜负的超出数据解释。

## 建议的封存和计量实现

运行前将物理报告与 protocol、三分支 source closure、CEM 原报告及 trace、
structured own 报告／binding／trace/ledger、先前刷新报告和 encoder
来源全部哈希绑定。通过既有物理 `build()` 再核对每条 20 步实际执行
动作等于各自被预测计划、共同 cp5 图片及状态哈希一致、图像文件哈希
及像素哈希一致、goal/历史/normalizer/model tensor identity 一致。
任何不一致、源漂移、缺失 cp、早停或未观测终点都应失败或标记缺失，
不得复制端点或改 roster。

一个对称复算合同可固定为：每候选 3 次开放预测 + 3 次真实前缀刷新预测，
每次 1 predict/sample 与 1 action-encoder；共 **12 次 predict/sample、
12 次 action-encoder**。为强对称性重新编码两条轨迹 cp5/10/15/20，
共 **8 次 encoder/image**（同一 cp5 重复编码不得静默去重）；每条首包
开放/刷新输出应一致，两条 cp5 编码互相及既有封存 cp5 latent 一致。
校验各自重算 H3 Q 对应原先封存值；重算 structured-own 的原值是
`0.12810702018294395`，CEM 原值是 `0.335489286528884`，预设
`rtol=1e-6, atol=1e-8`；编码一致性 `rtol=1e-5, atol=1e-6`。
真实原报告数值与计算顺序可能导致容差问题，任何失败保留产物并调查，
不根据结果扩大容差。每个模型 API 必须记录 attempt/return、模型和输入
identity、同步耗时与失败；编码、predict、action_encoder 分列。若复用
既有编码或预测，则须改为明示的另一份固定预算和来源，不能把历史成本
当免费。没有 FLOPs、能耗或内部完整算子计量，不宣称等算力。

本交付仅是固定诊断设计及既有单对读取；没有实现或运行新的 CUDA
诊断，也没有物理执行或开启 P1 gate。
