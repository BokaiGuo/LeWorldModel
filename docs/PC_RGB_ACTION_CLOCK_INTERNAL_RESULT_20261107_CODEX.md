# RGB LeWM 单帧动作时钟核验

在已暴露的 PushT 接触面板固定 4 根、左右两侧共 8 个条件，使用同一冻结 RGB LeWM 和真实 GPU。每条件按原动作 normalizer 将 plus、minus 各五步组成两个连续 packet。模型输入无 proprio，未读取真实未来后继。

| 核验项 | 最大绝对差 |
| --- | ---: |
| 动作归一化后逆变换 | `7.45e-9` |
| `action` 占位从零改为一，预测轨迹与目标代价 | `0` |
| 两 packet 的 `rollout` 与显式两次 predictor 递推 | `7.16e-7` |
| 单 packet 预测与双 packet 轨迹相应前缀 | `5.97e-7` |
| 末帧目标分数与显式平方距离（独立 GPU 进程） | `0` |

8/8 条件改变第二个 packet 后终点表示有非零变化；这只证明模型对测试动作有数值响应，不代表响应物理正确。源码中单帧 `rollout` 用候选的第一个 packet 覆盖上下文 `action`，所以该字段在此协议中是接口占位而非可被模型利用的历史动作；不能把此前单帧结果解释为使用了真实动作历史。

这些测试与既有五步物理重放共同支持该受控面板的单 packet 时间对应，但本次没有重新执行环境，也未验证多帧历史的时序或真实闭环。模型仍是本地兼容加载路径，不等于官方所有配置已认证。数值重放不证明预测正确、控制收益、描述增量或 PC0–PC5 通过。

证据：`le-wm-main/results/pc_rgb_action_clock_internal_20261107_codex.json` 及 `pc_rgb_action_clock_goal_cost_audit_20261107_codex.json`；相关单元测试与权限测试共 19 项通过。训练动作数组、checkpoint、配置、模型实现及协议均分别绑定指纹；完整 HDF5 文件不在本次重新哈希范围内。
