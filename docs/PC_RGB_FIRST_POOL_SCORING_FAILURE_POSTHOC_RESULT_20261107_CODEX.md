# RGB 首轮九链子池：评分失败分解

按[事后协议](PC_RGB_FIRST_POOL_SCORING_FAILURE_POSTHOC_PROTOCOL_20261107_CODEX.md)，
对 40 个已曝光任务的首轮九条前缀—探针链进行分析；其中两任务初态
已经成功，从下表的 38 个任务中排除。成功标签来自真实执行；真实
末帧编码只在评价端使用。

| 九链子池内的选择 | 25 步内曾成功 | 第 25 步成功 |
| --- | ---: | ---: |
| 事后物理 oracle：池内任一链成功 | 20/38 | 15/38 |
| 最小模型预测末帧编码代价 | 14/38 | 10/38 |
| 最小真实末帧编码代价 | 15/38 | 11/38 |

按任务配对，两种成功定义下均为：真实编码独胜 1 个、模型独胜 0
个。对于曾成功指标，模型在 20 个有成功链的任务中漏选 6 个；
真实末帧编码漏选 5 个。因此这个子池同时存在候选覆盖限制和
评分选择损失；真实编码也不是普遍可靠的成功选择器。模型与真实
编码只差一个任务，不能凭此断言动力学误差不重要，也不能跨量纲
比较目标编码分数和物理距离。

独立从封存特征重算了 40 个任务的 720 个分数：与记录最大差
6.11e-5，两个评分器的最小值索引均一致；重算共出现一次最小值
平局，依照协议取平铺顺序首项。逐链物理曾成功标签也与原轨迹一致。
相关测试 **4 项通过**，包含中途成功与末帧成功分离、索引平局和
非法形状检查。

该九链只是原首轮搜索的一部分；真实规划器还评分父链和选中前缀的
尾部。因此 18/38 没有成功链仅是该子池覆盖结果，14/38 也不是
真实规划器成功率。分析不提供独立任务、因果机制或闭环增益证据，
不改变 PC0–PC5。机器记录和源文件哈希见
[结果](../le-wm-main/results/pc_tworoom_first_pool_scoring_failure_posthoc_20261107_codex.json)，
实现见[脚本](../le-wm-main/experiments/pc_rgb_first_pool_scoring_failure_posthoc_20261107_codex.py)。
