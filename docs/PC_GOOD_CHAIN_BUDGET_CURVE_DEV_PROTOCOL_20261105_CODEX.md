# 共享父链响应修改：多预算开发曲线

问题：上次 471 prediction-token 开发点上响应修改未优于 CEM。增加预算后，三者的质量—计算关系如何变化？本实验不使用“无限预算”或“已收敛”称谓。

固定上次 V2 的 16 个已暴露开发根、每根同一共享全局父链、两个预定随机流、响应割线与随机方向、候选构造、合法动作域、全局 incumbent 和共同 CEM。比较响应修改、免响应随机修改、直接 CEM。分别独立运行每个预算点：完整链评分 157、313、625、1249 次，即每臂 471、939、1875、3747 prediction tokens；这是一组有限预算，前一点评分不复用于后一点评分。每点响应消耗 `1+60+12` 次形成起点，随机消耗 `1+12` 次，直接 CEM 消耗 1 次，余额全部用于共同完整链 CEM。保留所有已评分链，返回其中最优者。

每根、每随机流、每臂及每预算记录完整调用、时间、token、父链、精修前与最终质量、最终动作及失败；逐根先对两个随机流平均，再计算配对终距差及更好/更差根数；成功阈值 `<0.05`，32 次并非 32 个独立根。记录 CPU 墙钟，但含日志写入和同机负载，不冒充 GPU、真实执行或完整系统成本。

此为同族已暴露任务上的条件诊断，已有父链生成成本未重新计入。严格区分同 token 比较与跨预算比较；不能由有限曲线推论无穷预算、全局最优、来源独立、PC2/PC3 或真实控制优势。更大预算若仍有差异，应在新预定开发面板及来源合格任务复核。
