# 精确 unicycle 自动响应前缀 PC2 开发协议

运行前固定。使用已有两步精确 unicycle 和 16 个暴露方向任务，动作顺序为先平移再转向；非 RGB、不称独立确认。目标半径 0.9，方向为 `2*pi*(i+.37)/16`，与原朝向开发任务相同。每个前缀、后缀都受原动作边界约束。

从归一化动作名义点 `(-.4,-.5),(-.4,.5),(.4,-.5),(.4,.5)` 出发，分别以名义后缀 `[.5,0]` 完整 rollout，按原始归一化前缀两个参数分别以 0.01 中央差分计算末端位置响应。以同一目标残差、阻尼 .001 的 goal 模态排序提议一次响应更新，最大参数分量限制 .5，最终裁入 [-1,1] 并映射到合法真实动作；加一个 zero 前缀。此构造允许平移与转向同时改变，不强迫非即时进展。记录名义点、Jacobian、SVD、实际生成与裁剪前后参数、完整 rollout 调用成本。重复前缀仍分别记录。

每条前缀以后续速度 33 点等距网格 `[-1,1]` 用共同完整 rollout 优化后缀，后续转角固定为零；最终通过完整链预测终距选最优，ties 按候选顺序。zero 即弃权控制：响应候选未严格胜 zero 则选 zero。same-bank greedy 选择即时前缀评分最优，再使用其相同后缀规划；普通 lookahead 用同库后缀子集 `[-1,-.5,0,.5,1]` 最佳终距选择前缀，再使用其已计算的相同后缀网格。随机桥接以固定种子产生四个归一化双维均匀候选加 zero，使用同一后缀网格和完整链选择。各方法成本分别记录，响应计算和 SVD 不忽略；本轮同后缀预算不是完整成本公平。

先保存实际各臂所选动作、全部生成前缀与各后缀评分及 hash，文件存在即拒绝覆盖。后验执行阶段读取这一封存，严格对所选的同一前缀测试：selected、zero、same-bank greedy 分别应用后缀族 `[-1,-.5,0,.5,1]`、已选后缀，报告绝对终距与相对于各自零后缀变化；再用同一 33 点网格给每个前缀各自重规划。预定有限见证：selected 首步终距不小于初始（1e-12 容差），selected 已选后缀相对零后缀的增益严格优于 zero 和同库 greedy，且 selected 各自规划终距严格优于两者。资格只属于实际最终执行的那条动作链；如与 greedy 或 zero 相同不能满足严格优势。

随机与 lookahead 作为独立控制同时做相同干预。结果不足不补选未执行候选、不调整规则或历史 gate。精确模型的任务机制不自动成为视觉执行证据；普通全动作强搜索和独立任务确认仍是独立的 PC3 事项。
