# v3 Reacher 真实 RGB 固定终点开发诊断协议

在运行前固定根 `20263160`、目标偏移 `(0.65,-0.65)`、预检一致的
原冻结 Reacher checkpoint、动作统计、真实支持动作热身与三帧历史。
response 和 smooth CEM 两臂各自从相同种子与热身重新开始，在
第 0、5、10 步基于自身真实 RGB 和实际动作历史分别规划剩余
15、10、5 步，并执行各选中链前五步；固定终点为 15 步，不追加。
每次核心规划上限 1920 个五步预测 token，v3 的算法与随机规则不变，
方法内 root 索引为 0。输出和已封存选择先写盘，再执行动作。

使用[通过预检的适配器](PC_RESPONSE_TEMPORAL_V3_REACHER_ADAPTER_PREFLIGHT_RESULT_20261104_CODEX.md)：
每次从实际历史编码与目标 RGB latent 构造二维投影，第一轴是
root 到 goal 的 latent 方向，第二轴是固定种子 `2027111800+step`
的正交随机方向。投影仅用于响应和后继多样性；完整链目标是原始
冻结 latent 终点与目标的均方差。统一双方模型、输入与评分。
原始动作取物理 `[-1,1]`，按相同 checkpoint 统计变为 5×2 packet；
其目标、模型和历史均合法获得。qpos 仅在每个已执行动作块后供
评价，绝不进入预测、候选、投影或评分。

每次记录输入帧、实际历史、目标、投影、提案与 float32 实际模型
动作、二维预测、全 latent 分数、模型 token/调用、编码次数、时钟、
选择及未执行尾部；执行后记录新 RGB 和物理距离。模型、统计、源
收据、协议与代码哈希绑定，独立输出排他创建；任何错误保留，不
换根、不放宽约束或伪装完成。审计核对实际输入、计量、选择、
carry、时间顺序与物理动作；额外的编码及墙钟单列，token 不等同
完整计算。模型内评分与物理 qpos 误差分开。

这是对 E1 同一 v3 编译器的单根接线和真实反馈开发诊断，不是原
Reacher 论文基线、充分调参、PC2、PC3、PC4、PC5 或独立复现；
二维投影的任务相关性、模型训练来源和 normalizer 来源需另认证。
