# RGB 单帧接口与动作历史合同：实现核查

`jepa.py` 的 `rollout()` 会将传入的 `info["action"]` 替换为候选动作序列的前 `H` 个 packet。因而旧 `RGBLeWM` 包装器虽然要求调用者显式传入 `action` 字段，但**非空历史动作不一定会被该路径消费**。合成真实 `JEPA` 实例的回归测试使用两组不同的非空历史和同一候选，验证两次最终得分相同、`info["action"]` 均被候选覆盖。这个检查针对当前本地实现，不证明历史有用，也不证明先前使用空历史的实验失效。

新增独立 `SingleFrameRGB` 适配器，供未来明确采用单帧语义的调用方使用：

- 只接受单帧 RGB、同形状目标、显式空动作历史；传入非空历史、特权字段、不合法维度或非有限数即报错。
- 检查候选 packet 长度与动作标准化后的物理范围；不截断动作、不静默补历史。
- 模型必须处于 eval 且冻结；可在开始和结束用模型 state digest 及已绑定输入文件哈希检查漂移。digest 不是权威来源认证，也不能防止任意 Python 代码绕过包装器。
- 评分保留动作 autograd，旧包装器与历史实验文件不修改。该新适配器目前是**显式调用的接口**，没有自动替换既有正式 runner。

在实际 TwoRoom 冻结 checkpoint、一个已封存开发任务和一条合法候选上，用 GPU 比较新旧包装器：得分绝对差 0；动作梯度有限且最大绝对值 24.596；非空历史被拒绝；模型前后 digest 一致。记录见 `le-wm-main/results/pc_rgb_single_frame_real_model_check_20261107_codex.json`。新旧权限、单帧合同及历史覆盖回归测试共 **26 项通过**。

该修正防止今后把“接受但忽略历史”误报为历史条件预测，并非多帧真实历史实现，也不修复模型、目标评分或已观测控制失败。真实运行只检查单个模型及单条候选，不构成 PC0 权威认证、PC1 可信性、PC4 闭环或任何科学 gate 通过。
