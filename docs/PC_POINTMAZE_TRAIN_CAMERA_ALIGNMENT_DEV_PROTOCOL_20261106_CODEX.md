# PointMaze 训练参考相机对齐修复：开发协议

此前旧目标框中心为 `(111.5,125.5)`，这是 look-at `(3,2.5)` 的开发视角；既有 1880–1883 渲染对照发现与归档图像相匹配的参考为 look-at `(3,3)`，其静态框中心 `(111.5,111.5)`。因此旧归一化把两个输入统一到了不同于已观察归档视角的参考。本次修复只以静态目标 RGB 框定位，不读取相机参数或物理状态；参考坐标来自此前已暴露开发数据，不能称为独立认证的官方摄像机参数。

在已封存的 1884–1891 初态和目标、两个视角、三个动作上，比较 `raw`、旧中心和归档参考中心。只改变当前与目标 RGB 的共同平移，动作、模型、当前 proprio 和候选保持不变；评估前封存三个选择。旧中心必须复现此前封存评分（atol 1e-6、rtol 1e-5）。对非法或超出 ±20 像素位移拒绝并保留全分母；不调整参考或阈值。新旧坐标相差 14 像素；最近边界填充仅为合成像素，必须说明。

后置诊断包括：实际后继的真实编码首选、物理 regret、视角一致性，以及输入图像与同状态归档帧的像素差。物理与归档帧均不得进入模型动作选择。只要新旧位移通过同一合法域可按位计费，计算成本和每臂相同模型调用次数也要记录。

预定开发出口：16 个视角均未拒绝；新中心相对旧中心平均物理 regret 严格降低，模型与真实编码的选择一致数严格增加，并且 1887 偏移视角物理 regret 严格下降。失败则保留作为工程对齐修复但不能宣称物理性能改善；任何结果均不可晋级 PC0–PC5，且此 state-assisted 轨道不可作为 RGB-only。该实验证明的是开发面板而非完整在线系统表现。
