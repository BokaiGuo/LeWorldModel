# 两种保留准则的同链机制开发结果

按 [事前协议](PC_RETENTION_MECHANISM_NEXT_DEV_PROTOCOL_20261104_CODEX.md)，16 个同族开发任务的两臂 32 条计划先封存、审计，再运行 selected、zero、same-bank greedy、固定预算 lookahead、random 五前缀干预。32/32 计划与干预完成；动作账本、另一同环境几何、全尾部响应重建、lookahead 和重规划提案重放、以及机制布尔条件重算均通过。相同代码及同环境重算不是独立复现。

| 指标 | ridge | probe_min |
|---|---:|---:|
| 终距 `<0.05` | 5/16 | 5/16 |
| 平均最终终距 | 0.30946 | 0.32423 |
| 非即时进展 | 6/16 | 6/16 |
| 严格光滑基础交集（zero、greedy） | 2/16 | 2/16 |
| 严格光滑全对照交集 | 0/16 | 0/16 |
| 平均规划 prediction-token | 2879.25 | 2879.25 |

4/16 根出现层级保留索引差异，但只有 root 0 的最终链不同；其终距 ridge 0.26433、probe_min 0.50055。因此本面板不重复上一面板 probe_min 的均值优势，不能支持保留策略稳定改善。索引在两臂后继候选库不同之后不必表示相同动作。

两臂的基础交集均来自 **root 8 和 root 11，且两臂各自选中的是完全相同的链**，不是四个独立见证。root 8 的实际选中链终距 0.02038，其 selected 前缀的三次重规划终距为 0.01544、0.00232、0.00729；root 11 的实际选中链终距 0.06807，三次重规划为 0.00882、0.51407、0.50571，显示求解不稳定。两根都同时满足预定的四个对照共同尾收益、重规划平均收益与响应差异，但 random 前缀至少一个尺度存在分支切换，因而均不满足全对照**光滑**交集。该限制不证明非光滑机制不存在；另一方面，也不能据此把分支差异当作已认证因果机制。

两根的精修记录中，达到最终分数的起点均标为 `carry`，即共享全局候选的最优链；root 8 的两个 `retained_final_beam` 起点精修最佳分别为 0.50284、0.50045，root 11 分别为 0.50308、0.50743。该记录不证明全局候选在反事实条件下必然独立获胜，但尤其不能把这两条链的发现归因于响应候选保留或其谱祖先。

全部对照中共同尾相对零尾的收益条件同时满足：ridge 9/16、probe_min 8/16；全部对照三次重规划均值收益条件同时满足均为 7/16；全部对照响应差异条件均为 16/16。三项不必发生在同一条链，不能相乘或拼接。`1e-6`/`1e-10` 是冻结的数值容差，不是预定最小实际效果。随机对照分支切换和四结点求解器的有限检出率限制了结果的机制解释。

lookahead 选择按同库 18 个候选加 zero，各 120 次完整链评分，**每计划另耗 6840 prediction-token**；总干预平均约 29792.875 token/计划，包含选择、共同尾、重规划和最终链响应，不属于部署规划开销，也不包含单独的碰撞分支重放。模型外总墙钟/GPU/内存成本未完整认证。该 lookahead 不代表充分优化，重规划均值也不能由此前最佳检出率校准直接认证。

原始数据、完整动作调用、逐坐标分支及三个审计位于 `le-wm-main/results/pc_retention_mechanism_next_dev_20261104_codex/`。复现时为避免覆盖先更改输出路径并重新封存依赖，在 `le-wm-main` 依次运行 `.venv/bin/python -m experiments.pc_retention_mechanism_next_dev plan`、`audit_plans`、`intervene`，再运行 `experiments.pc_retention_mechanism_next_audit`、`experiments.pc_retention_mechanism_algorithm_audit`、`experiments.pc_retention_mechanism_predicate_audit`。

这是同族开发筛查，不是 PC2/PC3 通过：虽然基础对照出现同链线索，但完整预定光滑交集为零，非光滑机制尚未建立；响应生成的因果增量、强基线、来源独立性、统一视觉真实闭环和全系统成本仍未完成。旧面板与其 0/16 结果未改写。
