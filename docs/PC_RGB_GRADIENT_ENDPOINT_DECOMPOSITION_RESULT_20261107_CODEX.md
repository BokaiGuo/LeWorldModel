# RGB 梯度候选末帧预测—真实编码—物理结果分解

## 范围与协议

按 [事前协议](PC_RGB_GRADIENT_ENDPOINT_DECOMPOSITION_PROTOCOL_20261107_CODEX.md)，对已曝光的 TwoRoom 开发任务 9000、9013、9022、9032，各自上轮封存的 5 条梯度候选进行 25 步开放环物理重放。初始已成功的 9000 保留并单独标记。该实验属于 `primary_rgb` 的事后诊断，不是独立确认、闭环收益或 gate 通过证据。

规划器选链沿用上轮仅含合法 RGB 输入的封存结果；真实末帧和物理状态仅由评价端使用。事后真实编码最优和物理距离最优均是不可部署的 oracle，不参与选链。完整 25 步重放用于统一末帧比较；曾成功并不等于末帧成功，亦不代表实际部署会继续执行。

## 验证

- 20 条链的每步距离、成功和截断记录与先前物理重放一致；未发生截断。
- 冻结模型重新计算的预测分数按 `rtol=1e-5, atol=1e-3` 与封存规划分数一致，重算选择与原选择一致。
- 保存每条链的 192 维预测表示、真实末帧编码及目标编码；独立重算了各任务 10 对候选的排序计数。排序测试 4/4 通过。
- 平局按任一比较量严格相等处理；候选对共享任务和动作，不能视为独立任务样本。

## 结果

每格为「一致 / 相反 / 平局」，末距越小越好，单位为环境距离单位。

| 任务 | 初态成功 | 预测 vs 真实编码 | 预测 vs 物理末距 | 真实编码 vs 物理末距 | 模型选链末距 | 真实编码 oracle 末距 | 物理 oracle 末距 |
| --- | --- | --- | --- | --- | ---: | ---: | ---: |
| 9000 | 是 | 9 / 1 / 0 | 9 / 1 / 0 | 10 / 0 / 0 | 8.32 | 8.32 | 8.32 |
| 9013 | 否 | 8 / 1 / 1 | 0 / 9 / 1 | 1 / 8 / 1 | 88.27 | 88.27 | 63.59 |
| 9022 | 否 | 9 / 1 / 0 | 7 / 3 / 0 | 8 / 2 / 0 | 57.46 | 57.46 | 48.84 |
| 9032 | 否 | 8 / 2 / 0 | 5 / 5 / 0 | 3 / 7 / 0 | 80.41 | 80.41 | 68.66 |

初态未成功的三个任务，其五条候选全部未曾物理成功；9000 的五条链均继承初始成功。因此这一面板无法比较不同候选的成功率。四个任务中真实编码 oracle 恰好均选中模型所选候选；这一结果不意味着两种排序完全相同。

## 判断与限制

在这些候选上，预测代价与真实编码代价的排序大部分一致；但 9013 和 9032 的真实编码排序与物理末距频繁相反。这支持继续检查冻结编码目标与物理目标是否匹配，而不是把所有退化都归因于预测动力学。不过，这不排除模型预测误差、初始化或时钟等其他问题，也不能据此证明唯一根因。

物理末距是连续诊断量，不等同任务的曾成功规则；三条非初始成功任务的候选全部失败，物理成功标签没有区分力。候选、任务与对照均已用于开发，不能推断整池覆盖、独立任务表现或 Planning Compiler 组件增量；也不能使用事后真实观测替规划器挑选动作。
