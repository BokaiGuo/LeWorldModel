# PushT 完整首轮候选池：预测时序选择的事后结果

在四个已曝光开发任务的既有首轮候选池中，比较末时刻最低模型代价和五个预测包时刻中最低模型代价。每个任务均为 630 条按动作字节去重的完整候选链；两个规则使用同一批已保存的模型预测，不重新优化或增加模型查询。

| 任务 | 两规则共同选中索引 | 两规则所选预测包时刻 | 该时刻原生成功 | 25 步内曾成功 | 第 25 步成功 |
| --- | ---: | ---: | --- | --- | --- |
| 0 | 628 | 5（第 25 步） | 是 | 是 | 是 |
| 1 | 339 | 5（第 25 步） | 否 | 否 | 否 |
| 2 | 537 | 5（第 25 步） | 否 | 否 | 否 |
| 3 | 623 | 5（第 25 步） | 否 | 否 | 否 |

两种规则在 4/4 个任务上选中同一条链，且都与原始选择一致；第 25 步成功均为 1/4。此结果不支持在这四个已评分池上通过事后改为全时域最低预测代价改善选择。它不等同于将新目标用于 CEM 的所有迭代，不排除重新优化后产生不同候选，也不能证明一般情况下提前停止无用。

按照[事前固定的本次分析协议](PC_PUSHT_FULL_POOL_PREDICTED_DEADLINE_POSTHOC_PROTOCOL_20261107_CODEX.md)，程序验证了每条链的动作哈希、同任务目标编码指纹、预测末时刻得分，并用环境原生 `eval_state` 核对所选时刻与末时刻。历史物理重放覆盖全部 2,520 条去重链的 25 个环境步，细节见[原完整池报告](PC_PUSHT_SCORED_FIRST_POOL_FAILURE_RESULT_20261107_CODEX.md)。重复动作若在不同批次出现，本次取记录中的首次 occurrence；未认证重复出现时的预测完全一致。

真实成功和首次成功时刻仅用于离线评估，不是规划器可用的特权停止信号。物理状态来自评价端；本次 JSON 保存目标编码哈希与数据路径，但没有单独记录目标物理状态哈希或完整 HDF5 哈希。四任务和候选池已曝光，本分析不是独立确认，也不是 OSFAL 逐层表示、未查询动作或闭环增益的检验。PC0–PC5 不因此改判。
