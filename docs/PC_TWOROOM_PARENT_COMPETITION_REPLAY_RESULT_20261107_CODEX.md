# 已评分父链是否被最终选择遗漏：开发面板回放

此前的 290 评分实验实际为 8 条父链、2 条来源 incumbent、64 条 A
组合及各臂选中前缀的 B 组合计费；但其最终 `choose` 只允许 A、
incumbent 和有权限的 B 进入竞争，没有显式纳入已评分父链。对于一般
搜索过程，这是一个可能遗漏已知最好完整链的选择接口限制。

本次没有改写已封存的历史运行器。新增通用已评分候选选择器，并在
同一个已曝光的 40 根 × 4 臂面板中，重新计算「原有候选 + 父链」的
选择。只允许该臂真正查询过的 B 组合参选，保留原选择的并列优先顺序。
来源计划、模型查询池、旧协议及规则哈希均已核对。

结果：**160/160 个选择不变，0/40 根的最佳父链分数严格优于最佳来源
incumbent。** 两个 incumbent 本就来自父链的来源搜索池，因此在本面板
中父链遗漏没有改变选择；不能将此前向量配置的负结果归因于这一限制。
本次只做已保存评分的 CPU 回放，没有重新运行模型或物理环境。

新增测试覆盖父链严格更优时必须被选中、其他臂 B 不能越权进入选择、
并列次序、重复身份及非有限分数；3 项通过。修复仅用于未来显式接入
该选择器的版本，不改变历史实验、成本和 PC0–PC5 状态。
