# 几何合法接触准备状态：开发协议

本协议在新结果运行前冻结。它修复旧 pilot 的中心偏移不等于形状边界
距离的问题，不覆盖旧结果，也不预设模型一定失败或成功。

## 物理合同

固定 16 个几何开发 roots：方块位置为 (220,220)、(280,220)、
(220,280)、(280,280)，角度为 0、pi/4、pi/2、3pi/4。目标方块位置
沿世界 x 加 20 像素、角度加 pi/12；目标推杆为 (80,80)，零速度。
这些是新构造的开发状态，不宣称 checkpoint 训练外或独立确认任务。

通过实际 Pymunk `body.local_to_world` 取得 T 横梁左／右边中点，
沿外法线移动实际推杆圆半径加 1 像素。两配置称为接触准备状态，
而非一开始持续接触；初始间隙必须 1±1e-6 像素，无 agent/block/wall
穿透，方块和推杆符合请求状态，速度为零。完整合法性检查包括 block
与墙的穿透。两侧 block 隐状态必须相等，重复 reset 完整快照一致。

三个共同行动为世界坐标中的 ±0.1*(cos(theta),sin(theta)) 和零，
各执行五个环境步。左侧正动作／右侧负动作应实际触发 agent-block
接触；零动作必须保持物体与推杆位置及角度在 1e-6 容差内。明确记录
不满足条件的 root，不按模型分数或成功筛除。使用真实 pair collision
callback 确认接触，不能只用未区分对象的 n_contacts。

白色和浅灰 (245,245,245) 背景由原生 renderer 生成，不是相机视角。
目标和初态使用相同背景，渲染不得推进物理。两背景完整物理轨迹须
相等。保存所有当前／目标／后继图片、动作、快照、几何、碰撞对象和
严格环境成功标签。先做完整物理采集，模型阶段只能读图片和动作。

## 冻结模型诊断

沿用冻结 LeWM 和数据集 normalizer，五步动作打成一个十维 packet。
额外记录模型预测 embedding、真实后继 embedding、初态 embedding
和 goal embedding，区分表征与动力学。模型原始 get_cost 与手工末帧
平方距离应相符。physical truth 只供评价，不能输入模型或选择器。

报告相对零动作的两个有符号后果：模型目标分数、真实编码分数、
物块位置误差除20和环绕角误差除(pi/9)的平方和；后者只作为事前固定
的诊断指标，不替代标准任务成功。比较每任务的背景一致性、不同
接触配置的效果差中差、方向符号及按模型选动作的物理 regret。
同时报告完整状态距离，但不与纯物块指标混淆。

16 个 roots 为描述性开发面板，没有正式 PC1/PC3 确认功效。不得以
常量描述的外观一致性通过、不把三动作得分本身等同超越 lookahead。
物理合同无效的条件仍保留并单列，不进入模型可信性汇总。
