# Planning Compiler 响应程序合同 V2：开发草案

状态：新版本开发草案，**未冻结、未通过任何科学 gate**。此版本不以
SVD 自身获益作为方法定义；原有明确要求谱增量的合同继续保持原状态，
本合同不替代、不修改旧合同或历史 P1/P2/P3。

## 检验对象与限制

固定模型、合法观测、目标、动作域、执行时域和反馈时刻。方法从冻结
动力学响应自动生成候选程序，以有界完整链评分进行选择，允许弃权，
并执行选中链；选中的动作及其后续反馈必须能追溯到同一版本的代码、
输入、模型和随机种子。可以对完整动作联合精修，但机制判定必须使用
精修后实际执行的前缀。非即时进展与规划性能分别验收。

现有精确 unicycle 联合精修结果作为开发证据：四臂均接近数值零误差，
机制见证为零，不能用来证明优势。PointMaze 已停止的非即时构造不重开。

## 固定比较

1. 响应程序生成及组合；随机候选程序；同候选库的即时 greedy；
   直接全时域强优化器。响应与随机程序使用共同优化器、同动作约束、
   同执行时域和同反馈机会；直接优化器可以充分利用自身可用预算。
2. 对实际事前选中并执行的同一条链，记录前缀即时变化；在 selected、
   zero、same-bank greedy 下应用同一预设后缀族，同时记录绝对终态
   和相对各自零后缀的变化；再比较各前缀在相同反馈和资源约束下自行
   规划的真实收益。后验物理结果不能进入正式选择器。
3. 从候选生成前计量编码、预测、微分、矩阵分解、筛选、反馈及耗时，
   原始单位分开报告，并明确共享成本。不得将不同调用单位相加来声称
   硬件等价；未测量值标记未知。旧 runner 账本不能追补其未记录的成本。

## 验收顺序

* PC0/PC1：分别完成同后端、动作时钟、目标、重置、冻结模型及正规化
  绑定，并验证实际多步响应及其任务相关范围。
* PC2：在预先定义的非即时条件及对照下，实际选中链通过共同后缀和
  自行规划干预；不要仅凭另一个候选满足条件，或凭胜 zero 宣称机制。
* PC3：冻结方法后在开发外配对根上比较强基线及关键消融，以事前指定的
  主要物理指标、最小实际效应和统计规则检验优势。PC2 机制成立与 PC3
  性能优势分别报告，不能互相替代。
* PC4/PC5：用同一方法完成合法 RGB 闭环及声明范围内跨目标、模型、
  架构复现。训练成员和 normalizer 来源未知时不得宣称训练外独立。

## 确认实验冻结前尚缺

尚需选定具体任务面板和合格的独立根，锁定 checkpoint/normalizer 与
依赖哈希，定义机制阈值、最小实际效应、样本量、失败处理、多重比较、
预算点和停止规则。必要的 pilot 与正式确认分离。上述参数未固定前本
文不能视作事前确认方案，也不授权由结果倒选任务或阈值。
