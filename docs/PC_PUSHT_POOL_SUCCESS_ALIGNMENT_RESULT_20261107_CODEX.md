# PushT 池内成功链的预测与真实编码对齐

针对上轮四个已曝光任务，重放全部 96 条曾成功链和另外 3 条失败的
实际选链，共 **99 条**。在第 5、10、15、20、25 步保存同一动作的
模型预测表示、真实渲染图像经冻结模型编码的表示，以及目标表示；
同时记录每个物理步的成功状态。

以下只比较每个失败任务内的“曾成功链”与该任务实际选中的失败链：

| 任务 | 成功链数 | 模型末帧评分偏好成功链 | 真实末帧编码评分偏好成功链 | 第25步仍成功链数 |
| --- | ---: | ---: | ---: | ---: |
| 1 | 13 | 0 | 3 | 3 |
| 2 | 1 | 0 | 1 | 0 |
| 3 | 1 | 0 | 0 | 0 |

例如任务 2 的实际选链预测／真实编码代价为 **9.983／21.331**，
唯一曾成功链为 **14.157／11.249**：模型与真实编码排序反转。
任务 3 的实际选链为 **24.168／20.623**，唯一曾成功链为
**58.967／49.376**：模型和真实末帧编码均偏好失败链。
任务 1 的三条末帧成功链中，真实编码仅偏好其中一条。
这些是候选级配对，不是独立任务样本；它们支持同时检查预测失配和
末帧编码目标与“曾成功”判据的差异，不能单独证明模型动力学错误
或目标评分错误。

任务 0 的选链本身成功，另外 80 条成功链未作为成功／失败对照；
仍全部保留在原始工件中。真实后继编码只由评估端事后获得，不可
作为部署规划输入。任务 2、3 的成功链在第 25 步均未成功，因此
真实末帧评分与整段曾成功判据并非相同目标；不能据此直接更改评分
或停止策略。

动作字节身份、初始物理快照、五个 packet 的物理状态、成功记录、
目标编码和预测末帧代价均已与上轮封存数据核对。加载模型在本次
编码前后权重指纹一致，但这不补足上轮模型来源及独立性认证。
真实图像来自同一环境重放；状态快照一致不证明全部隐藏状态一致。
