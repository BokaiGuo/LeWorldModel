# RGB 时序规则：预定新 episode 开发比较

固定 TwoRoom 同一 HDF5 数据集的 episode 9000–9039，从每条 episode
第 0 步出发，目标使用同一 episode 第 25 步的 RGB。选择不依赖任务
难度、是否成功或任何规划结果；将 episode ID、逐行索引、参考动作、
起点与目标 RGB 封存，并检查与上一轮 50 根 episode 不重叠。模型训练
成员、normalizer 拟合集及更早开发曝光仍未认证，因此这些是**新选开发
任务，不是独立确认集**。若 episode 长度或动作合法性不符合合同则
中止，不替换任务。

在评估前从同一物理初态和目标逐步执行封存的 25 个数据动作，记录
首成功、终点距离、动作与轨迹；不因参考链失败删除任务。后续所有
规划臂相同 reset、25 物理步上限、每 5 步重新观测；规划器仅访问
当前 RGB、目标 RGB、合法历史与冻结模型。

比较四臂：末帧保留的 lookahead 与 effect 均使用时序最终选择；
全链 CEM 分别以 16 与 300 条链评分预算、三个 CEM 更新轮次，更新
和最终选择均使用相同的五个模型后继的最小目标代价。CEM 首先评分
合法旧尾或零动作，其余预算分配为 5+5+5 或 100+100+99；每轮
elite 分别 2 或 10，整任务真实重规划次数、模型包步数、同步 GPU
时间与墙钟完整记录。当前模型只有剩余五步时，时序与末帧目标相同。
每臂首次物理成功即停止，包含初态成功的全体结果并单列非初态成功。

先冻结该方案再运行；此面板是开发比较，不计算或宣称 gate 通过。
尤其时序规则对 lookahead、CEM 共用，不能把通用评分改进归给
effect。只有同成本真实质量提升或事前明确非劣效界后的成本优势才
能支持将来正式主张，当前不设回溯性显著性标准。
