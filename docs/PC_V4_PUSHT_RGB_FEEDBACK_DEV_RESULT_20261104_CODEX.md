# V4 PushT RGB 反馈：单根开发结果

按 [事前协议](PC_V4_PUSHT_RGB_FEEDBACK_DEV_PROTOCOL_20261104_CODEX.md)，在已暴露的本地 episode 0 上，两臂分别重置、执行相同 15 步暖身，再各执行三轮真实 RGB 反馈；固定终点剩余时域为 15/10/5，每轮实际执行 5 步。两臂均完成，逐步可见性 guard 未弃权。

| 指标 | 暖身后共同起点 | v4 response 终点 | 双起点 smooth CEM 终点 |
|---|---:|---:|---:|
| 官方成功 | 否 | 否 | 否 |
| 物体位置距离 | 101.373 | 128.969 | 130.824 |
| 物体角度距离（弧度） | 2.162 | 2.360 | 1.510 |
| 官方状态距离 | 242.135 | 420.764 | 368.337 |

两臂都没有成功，物体位置距离均比暖身后增加；CEM 终点角度更接近目标。不同指标不能合成稳定的规划优势。官方状态距离同时涉及其他状态分量，不能解释为单纯物体姿态误差。该结果不证明任何一臂的总体性能。

每轮 prediction token：response 为 1920/1919/1920，CEM 为 1920/1920/1920。第二轮 response 余 1 token；剩余 10 步完整链每次预测消耗 2 token，整数预算不能再评估一条完整链。token 相近不等于结构计算、编码或墙钟成本相同。

## 重算与边界

[独立审计记录](../le-wm-main/results/pc_v4_pusht_rgb_feedback_dev_20261104_codex_audit.json) 重新加载同一 checkpoint、按保存的 RGB 重编码并显式逐 packet 展开模型，核对 response 302 批及 CEM 297 批；位置投影及评分最大差异均为零。每臂从相同 reset 重放全部 30 条命令，逐步核对物理状态（绝对容差 1e-9）、RGB 哈希、终止标记，并核对四个边界的 RGB、历史、目标和状态。还核对了来源哈希、记录的决策与派发、逐批 token 和完整时域已评分候选中的最优选择。

审计初次运行因审计脚本错误地把暖身命令转换为 float32，第一步状态产生最大约 7.2e-6 的偏差并停止；修正为执行时的 float64 命令后重放通过。原始实验结果没有修改。审计验证记录中 `sealed_ns < executed_ns`，但日志没有记录每条物理命令的独立时间戳，因此不能仅凭该字段证明每一条命令执行时刻。

实验前修复了执行脚本的异常路径：每臂单独初始化 guard 与目标检查状态，避免第二臂初始化失败时误记第一臂结果。本次两臂均未触发该异常路径。

这是已暴露训练档案根与固定诊断目标的开发实验。checkpoint 训练成员与动作统计来源仍未认证；相同 checkpoint 和后端的重算不是独立模型或环境复现。没有建立接触重配置因果机制、PC3 强基线优势、PC4 成功率改善、E3 验收或 PC5 泛化。后续应在来源和预注册条件允许时开展配对多根确认，并优先区分模型评分、接触响应、候选覆盖和优化不足；不得根据此单根结果重调旧协议直到成功。
