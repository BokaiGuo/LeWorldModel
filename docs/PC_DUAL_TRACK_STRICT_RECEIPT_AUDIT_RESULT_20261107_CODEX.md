# 双轨证据收据严格校验：工程修正

旧 `pc_track_registry.eligible` 检查轨道、执行状态、任务/协议哈希和输入通道名称，但不检查每个张量收据的内容。原测试夹具中的 `{"pixels": {}}` 也能通过旧检查；因此旧的“有输入收据”不能单独证明收据含有可用的张量指纹。这是证据登记的工程缺口，不是模型或方法表现的证据。

新增[严格登记入口](/home/gbk/code/LeWorldModel/le-wm-main/experiments/pc_track_registry_strict_20261107_codex.py)：复用旧轨道和状态检查，重新读取并哈希协议及任务文件，对每项收据要求明确、合法的 shape、dtype 和 64 字符小写十六进制 SHA-256，并要求调用方指定非空的必要操作集合。空历史允许零长度维度。旧入口与历史代码保持不变，以免破坏已经封存的哈希；因此只有调用新入口的未来登记才获得此额外检查，旧入口不应被误称为已严格修复。

- 新增异常反例和旧权限测试共 **37 项通过**，包括两轨交叉拒绝、空收据、非法维度/类型/哈希、缺少操作和错误任务绑定。
- 对既有真实 GPU smoke 结果执行严格检查：`primary_rgb` 和 `official_state_assisted` 均通过本轨检查，跨轨均被拒绝。复核使用的是已有收据和本地文件，未重新运行 GPU 模型。
- [可复现审计输出](/home/gbk/code/LeWorldModel/le-wm-main/results/pc_dual_track_smoke_20261106_codex/strict_receipt_audit_20261107_codex.json) 绑定审计代码与已有结果、协议和任务文件哈希。

这些检查只验证收据结构与本地文件绑定：收据哈希无法单独证明记录没有被伪造，也不能从哈希恢复输入或证明模型和物理执行可信。该入口尚未自动接入所有历史或未来 runner，必须在正式证据登记工作流中显式使用。执行成功不等于科学证据成立，本次不改变 PC0–PC5。
