# v10 递归响应程序：E0 开发结果

## 实现与范围

[v10 核心](../le-wm-main/experiments/spectral_reachability/pc_recursive_response_v10.py)将动作维度、响应特征维度、片段长度、组合深度、名义动作和模态上限参数化。在每个保留后继的每个名义动作处重新计算中心差分响应，按目标贡献选择前 `k` 个非零模态，以正负多尺度生成后继；谱上限实际改变了候选数。每层用即时评分与特征多样性共同保留，最终比较所有已评分完整链，并在余量允许时进行全动作 CEM 精修及同批零首段比较。

这只是一条新的开发规划核心，尚未接入真实 RGB 的正式闭环，也没有针对跨接触非局部响应实施已认证的回退。输入没有特权解析见证。五项[合成回归](../le-wm-main/tests/test_pc_recursive_response_v10.py)通过，覆盖递归展开、不同输入输出维度、谱候选数、资源不足、零秩和弃权，不是机制证据。

## 预定八根 E0 开发结果

按[固定协议](PC_RECURSIVE_RESPONSE_V10_E0_DEV_PROTOCOL_20261104_CODEX.md)，八个任务均采用 15 步、1920 token 上限，逐步 CEM 和四结点 CEM 均采用三个起点。任务与引用的旧 18 根不重复，但未认证完整历史排重、可解性或其他来源，不能称独立确认。

| 方法 | 平均终距 | `<0.05` 成功根 | 每根 token |
|---|---:|---:|---:|
| v10：前一目标模态 | 0.501010 | 0/8 | 1893–1917 |
| v10：前二目标模态 | 0.501795 | 0/8 | 1893–1913 |
| v7 | 0.501171 | 0/8 | 1920 |
| 三起点四结点 CEM | 0.500871 | 0/8 | 1920 |
| 三起点逐步 CEM | 0.501264 | 0/8 | 1920 |

所有结果接近墙前的 0.5 终距；递归生成和真正的模态截断在该配置下**没有找到成功完整链**。这不证明任务不可解、谱结构或递归搜索无效，也不能说明候选、保留或后缀中哪一环单独导致失败。前一／前二模态改变了候选成本与余下精修样本数，不能直接解释成单独谱贡献。等 token 不等于等总计算，当前运行没有完整的跨臂同步耗时认证。

[原始结果与 40 份动作轨迹](../le-wm-main/results/pc_recursive_response_v10_e0_dev_20261104_codex/result.json)保留所有实际 float32 预测输入及输出。[逐轨迹审计](../le-wm-main/results/pc_recursive_response_v10_e0_dev_20261104_codex/audit.json)重新计算 28,068 条轨迹、计数和最终选择；[结构审计](../le-wm-main/results/pc_recursive_response_v10_e0_dev_20261104_codex/structure_audit.json)另外重建 48 层、1,900 个候选及其响应探针和保留索引。两者仍使用同一解析后端；不构成独立复现。

按协议停止对这个面板修改配置。尚无 v10 精修后同链机制干预、可行性认证、来源合格确认或视觉闭环，PC2、PC3 状态不变。下一步应针对明确的新假设和预定候选库，将生成覆盖、保留损失与共同后缀优化分别测量，而不是把这次失败事后归因于某个组件。
