# Known-root prefix-null matched capability exploration

This is post-outcome exploratory work, not P1 admission, fresh-root evidence,
independent confirmation, or an equal-budget comparison. Source is the accepted
v2 MAIN01 report and all 16 pre-existing selected/zero prefix rows, in order.
Every anchor receives the same fixed 21-probe coordinate bank, giving eight
pairs, 16 anchors and 336 scheduled branches. No success-based filtering,
retry, substitution, training, or neural inference is allowed.

The five-step probes use zero and the plus/minus 0.25 logit perturbations in
each of ten coordinates passed through tanh. This bounded bank is a local
finite-difference capability probe, not the original ten-step task suffix and
not a measurement of all possible future controls. Probe bytes are identical
across every anchor, and original selected/zero plans' task suffix bytes are
checked in the source v2 prepare.

Each branch reconstructs reset and warmup, replays its own five-step prefix,
and compares all 51 saved triplet frames and state/render snapshots against
its MAIN01 anchor before any probe action. Native stop is retained with no
padding. A probe-phase canvas rejection is censored only if the original
transition, immutable first frame, action and finite out-of-canvas state meet
the existing strict proof; other errors stop the run with partial status.
Unstarted branches remain in the fixed denominator and cannot be accepted as
completed. The saved consumer verifies each journal, action, frame, trajectory,
resource census, stop and censor proof. Full acceptance requires all 336
statuses; censored or stopped endpoints remain null, not imputed.

The prepare seals source report, event journal, anchor images, code, test and
this protocol. It is rebuilt before execution and saved consumption. These
hashes do not authenticate a host or prove unrecorded simulator cache state.
Per-shard caps and unchanged RGB/physics rules are inherited from the existing
censored adapter. No external signature or separate authorization token is
introduced. Disk/wall caps can stop execution; partial reports are not a
successful saved acceptance. Fixtures do not certify physical runtime.
