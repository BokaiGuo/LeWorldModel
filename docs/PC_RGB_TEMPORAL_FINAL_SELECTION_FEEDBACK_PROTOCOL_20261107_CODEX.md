# RGB 时序最终选择：有反馈开发协议

上一轮已曝光首轮固定池在 `effect` 臂达到开发出口，但这一结果不能
替代反馈。本实验使用同一 40 根、真实 RGB 每 5 步重新观测，25 步
总执行上限、原候选生成、前缀保留、动作域及停止判据。比较
`lookahead` 和 `effect` 两种原保留策略，各自的端点最终选择与
五个预测时刻最低代价最终选择，四臂同一个模型、上下文权限、
随机种子和每次 16 条链的评分机会。

唯一变化是最终候选选择：保留决策仍使用原末帧分数；最终从各臂
实际已评分的 16 条链中按端点或五时刻最低分选择，末五步直接候选
也使用其唯一预测后继。每臂记录实际派发动作、每轮代价、候选来源、
旧尾、模型查询、同步规划耗时、全任务墙钟和真实成功。真实成功只
用于环境停止与评估，不进入 planner。两个初态已成功的根全量报告，
另行报告排除该两根后的结果。

本实验是已曝光任务的开发检验。事前固定开发出口：在初态未成功
38 根，effect 时序相对 effect 端点曾成功至少独胜 3、独负至多 1，
且 effect 时序相对 lookahead 时序至少独胜 2、独负至多 1；同时
报告完整查询及耗时。若不满足，停止将此时序规则作为该配置的
性能改进；即使满足也仅支持后续独立开发，不改变 PC gate。
