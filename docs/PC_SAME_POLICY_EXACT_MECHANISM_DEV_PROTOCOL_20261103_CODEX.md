# 同一 RGB 决策策略的精确动力学机制开发协议

运行前固定。本轮复用 `pc_multi_nominal_rgb_dev_20261103_codex.decide`，不修改其候选、预算、联合精修和选择逻辑；将其预测接口接到批量精确 unicycle，而不是视觉模型。动作归一化为 [-1,1]，每一步先平移 `0.1*v` 再转向 `0.3*omega` 弧度，初态为原点、朝向 0；目标位于半径 0.9 的 12 个均匀方向 `2*pi*(i+.193)/12`。任务为新开发面板，不声称统计独立确认。

固定执行时域 15，机制前缀 5、后缀 10；一次事前选链，无重规划反馈。执行同一策略的 svd、ridge、nominal、random、greedy、cem 六臂，均以各自同一 480 五步预测 token 上限选择完整链；同一资源单位不等于等 FLOPs。原有三个候选固定前缀分别后缀优化得到的最优完整链单列为同库普通 lookahead 开发对照；它与 svd 臂共享候选及规划缓存，不是额外独立计算试验。全部方案、候选、选择、计数及依赖 hash 在任何机制干预之前封存，已有文件拒绝覆盖。

对每个任务 svd 臂**最终选中**的五步前缀进行干预，比较同库即时 greedy 前缀及 zero。greedy 从已封存 `prefix_scores` 对应的候选选取，不采用联合精修后的另一个前缀。对三个前缀执行同一六条后缀：全零、全步 `(±.5,0)`、全步 `(.5,±.5)`，以及最终选中链的实际后缀。分别报告绝对终距和减去各自零后缀终距的变化；再以每前缀同一 120 次完整链评分、相同随机种子、同一迭代 CEM 重规划 10 步后缀。最终输出的机制标记必须同时满足：前缀终距不小于初始（容差 `1e-10`），实际选中后缀相对零后缀的变化严格优于 zero 与 greedy（容差 `1e-10`），且各自重规划终距严格优于两者。两种对照与选中前缀相同则不能满足严格条件。

机制干预记录单独计数，不混入算法选择成本；干预随机性同一 seed 不保证同一结果。完整日志保留所有被选链及每条干预评分；不能后验挑选其他链。结果无论正负均为 12 个开发任务的局部证据：没有模型误差、接触、后继响应组合、RGB 机制或独立确认；不自动改变 PC2、PC3 或历史 P1。
