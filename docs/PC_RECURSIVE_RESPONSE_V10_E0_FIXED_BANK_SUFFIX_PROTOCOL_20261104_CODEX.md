# v10 E0 固定候选后缀与保留损失：后验诊断

本协议在八根 v10 开发结果及两个解析尾覆盖结果已知后制定，不是事前确认，也不重跑或修改 v10 决策。固定每根每个 v10 臂的首层全部候选和原保留四项；不插入解析候选、后缀或任何特权动作。

对每个自动生成前缀分别使用相同四结点 10 步后缀 CEM：先评分一个零尾完整链，再评分 480 个优化候选，每根两条共同随机流，种子分别为 `2027120100+100*root+repeat`；同根同 repeat 的所有候选使用同一个种子、相同优化器和资源。完整输出与全部动作、得分、迭代信息封存。

按根和重复分别记录全集中最佳终距、原保留集合中最佳终距、同库即时最优前缀的终距，以及是否存在 `<0.05` 完整链。另给各候选可优化性；全集最佳相对保留集合的改善只能表示**此固定搜索下**的保留上界诊断，不是部署时可用的选择，也不是因果归因。不同臂候选数量不同时，不把扩展全集的额外预算忽略后作公平性能比较。

全部使用相同精确后端重算动作和分数、核对随机种子与采样代数；这是同后端一致性审计。解析见证只用于既有 PC0 可行性证明，不作为本协议搜索初始化。两条随机流共享根，不是 16 个独立任务。按协议结束后不得围绕该面板追加搜索直到出现正结果；不能据此声称 PC2、PC3 通过或理论失败。
