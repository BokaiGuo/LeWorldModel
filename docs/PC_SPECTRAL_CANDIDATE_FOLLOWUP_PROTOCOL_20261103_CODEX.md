# 谱候选后验跟进开发协议

开发诊断，不用于补记事前成功。固定检查上一轮全部 60 个候选的动作距离、线性预测响应、完整链模型评分和物理回放排序；先核对上游证据哈希。每候选代码分配 100 后缀样本，但上游没有逐次样本日志，不能据此独立认证调用真实性。

跟进候选固定为 root0 `spectral_0_+1`、root1 `direction_2`、`direction_4`、`random_1`；它们是上一轮预先报告的全部位置初筛命中，不按新结果筛掉。对于这些候选及每根的 selected、zero、same-bank greedy，固定执行共同后缀（种子 2026110350，后缀 0 为全零）和 cp5 真实 RGB 后缀重规划。全时域 CEM 每根也执行其事前封存的 5 步前缀，并以同样 cp5 真实 RGB、相同 100 次样本后缀优化后继续执行，用作反馈 CEM 对照；保留上轮开放环结果，不能将其视为闭环对照。

全部角色以相同热身、t10/t15/t20 的真实 RGB、实际动作包、100 次后缀预测和同根噪声种子 2026110360+root 规划；封存全部重规划后再执行。模型物理信息隔离，后验真实 RGB 同动作评分不参与规划。物理时钟和原点遵循上轮协议。共同后缀记录绝对终态及相对该前缀零后缀的差值；各自重规划单独列出。

资源账分阶段记录先前模型预测、谱有限差分、SVD、cp5 重编码和后缀预测，分类分别报告；由于上轮没有所有调用与全时域额外补偿的预算分配日志，不宣称完整端到端等成本或公平优势。验证数据来源仍为开发根；不更改 P1/PC gate。
