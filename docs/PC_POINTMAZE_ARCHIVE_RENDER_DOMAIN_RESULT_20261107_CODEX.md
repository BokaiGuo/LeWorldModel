# PointMaze 数据帧与重渲染输入域诊断

按[协议](PC_POINTMAZE_ARCHIVE_RENDER_DOMAIN_PROTOCOL_20261107_CODEX.md)，
使用 1880–1883 四个已曝光根，准备阶段封存原帧 0、初态和五步实际
动作；模型预测先封存，之后才读取帧 5 和此前的反事实真实后继。
模型是相同的冻结 state-assisted JEPA，评估不是 RGB-only。

| 比较 | 四根均值 |
| --- | ---: |
| 原帧 0 与相机 0 的像素 MAE（0–255） | 17.706 |
| 原帧 0 与相机 1 的像素 MAE（0–255） | 32.563 |
| 原帧输入、归档实际动作，对归档帧 5 的特征 MSE | 0.01812 |
| 原帧编码直接沿用，对归档帧 5 的特征 MSE | 0.12723 |
| 原帧输入、固定反事实动作，对两相机重渲染后继的特征 MSE | 2.22458 |
| 相应相机重渲染输入、同一反事实动作，对其后继的特征 MSE | 0.45454 |

归档实际动作的预测在四根均优于直接沿用原帧编码；但该动作和目标
轨迹不同于反事实动作及重渲染视角，数值不能直接作为单因素因果
比较。原帧输入预测与重渲染后继之间的大误差显示不能混用两种视觉
坐标，也不能把“原帧输入更接近训练数据”当成将它用于新相机的修复。
两个相机的输入差异及旧实验的非零排序误差仍需解释；本结果没有
证明哪段代码错误或模型在新视角能可靠规划。

预测和评价分别通过独立入口执行；提取 `.pth` 时需读取整个文件，
但预测输入只包含帧 0。载入模型时仍按原合同读取轨迹统计，相关静态
测试不是操作系统级隔离。协议、输入、脚本、模型和预测均有哈希，
权重前后指纹相同。原始记录：
`le-wm-main/results/pc_pointmaze_archive_render_domain_20261107_codex_result.json`。
本次相关测试 **7 项通过**。`experiment-code` 用于封存预测并分离
事后评价；未采用要求阳性结果的规则。PC0–PC5 不改判。
