# PushT 共同前缀候选池：真实末帧编码与预测分离

在四个已暴露开发任务上重新物理回放每任务全部 301 条封存共同前缀链，共 **1,204 条链、30,100 环境步**。核验了初始快照、动作指纹和合法性、每五步记录状态、首次成功及第 25 步成功；再用冻结 LeWM 编码真实末帧。真实末帧及物理标签只用于事后评价，不作为规划输入。

任务 1 的唯一末帧成功链，在单帧、三帧预测评分中分别排第 186、173；即使给评分器不可部署的真实末帧图像，它也只排第 195。故在这一固定池内，仅修正预测后继并不足以使当前末帧编码评分选择该成功链；这不能证明所有状态或其他目标评分都不可靠。任务 2 的唯一曾成功链末帧未成功，不能作为末帧成功样本；任务 3 的共享前缀池没有曾成功链。相关系数描述全部候选的分数排序，不保证顶部候选或物理成功排序正确。

与此前单独编码的 47、12、2、1 条同链末帧交叉核对，最大表示绝对差分别约 2.27e-6、1.67e-6、1.08e-6、8.35e-7；冻结模型前后指纹一致。评分统计及窗口、物理身份相关测试共 **7 项通过**。每任务数组与 JSON 独立保存，包含全部编码、分数、成功标签和动作身份。

本结果是事后诊断，不是可在线使用的 oracle，也不是独立任务、描述贡献或闭环收益证据；不改变 PC0–PC5。下一步若开发替代目标评分，必须保持冻结 RGB-only 输入权限、独立版本和同等对照，不可把真值物理状态偷偷传入规划器。
