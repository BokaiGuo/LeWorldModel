# P1 分段预算现场中点重规划：24 槽 parity

固定 24 槽的 selected、zero、greedy 前缀和第一包动作，在物理
执行第五步取得真实 RGB，再用冻结模型在主机 CUDA 重规划第二包。
24/24 现场求解结果与原离线计划动作逐字节一致，随后均完成既定
物理记录并通过保存态消费。逐槽哈希链独立审计确认：第五步
观测早于现场规划事件、规划事件早于第六步转移；动作哈希、
模型分数和赢家与封存计划一致。24/24 `row` 和物理 receipts 与
原离线重放相同；日志和报告增加现场规划事件，不能说文件完全
相同。

原生结果沿用既有动作链：selected 一槽在第十步成功，greedy 一槽
在第九步成功，其余 22 槽完成十步未成功。这些槽来自两个已知
根，不能视作独立任务成功率。第九步成功没有第十步观测，不补值。
现场规划事件声明每槽 2 次编码、44 次预测、44 次动作编码和
40 次 backward，为代码路径计数而不是独立 hook 测量；同步墙钟
均值约 0.197 秒，不包含完整前缀生成与执行成本。

首版 RUN01 在首槽因为日志容器自动注入 `index`、规划事件又传入
同名参数而触发 `TypeError`，未派发第二包；这是代码记账失败，
不是物理或理论负结果。将事件字段改为 `anchor_index` 后，另以
RUN02 重新封存和执行，保留原失败目录。

**证据边界：** RUN02 终端报告了 `cuda:0` RTX 5060 Ti 和 24 个
现场事件，代码在载入与执行后检查冻结模型哈希；但通用运行报告
没有持久化 host 和模型哈希，保存态审计无法独立复算这两个字段。
未来正式运行需要把 host、模型哈希与在线事件摘要写入绑定回执。
本实验还依赖离线计划的逐字节派发守卫，是已知根的工程 parity，
不是无守卫在线性能、完整等预算、强基线、独立确认或 P1 通过。
