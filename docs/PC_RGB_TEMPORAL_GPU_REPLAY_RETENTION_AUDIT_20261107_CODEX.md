# RGB 时序闭环：GPU 决策重算与保留策略暴露审计

## 目标与边界

上一轮仅检查结果记录内部的一致性。本轮从封存的 TwoRoom 40 任务闭环记录重置环境，逐个重建观测和旧尾，使用记录的种子及原冻结模型重新执行每次规划，并按原派发动作重放物理轨迹。规划器仍只接收 RGB、目标图像和动作上下文；物理状态用于评估器 reset 和结果核对。

重算使用原规划实现和同一环境，因此是**重现性检查，不是独立实现的正确性证明**。原实验未逐步保存观测图像，本次通过物理重放重建；距离完全一致也不能单独证明逐像素一致。模型参数与数据 normalizer 指纹、输入及原运行器和协议哈希经检查一致，但并非所有传递依赖均有独立封存指纹。

## GPU 与物理重算

RTX 5060 Ti 上实际重算全部 509 次规划（lookahead 144、effect 144、CEM16 128、CEM300 93），以及 2,260 个真实派发动作。结果：

- 所有决策的已记录时序候选分数最大绝对差为 **0**；最终动作最大绝对差为 **0**；选择索引变化 **0/509**。
- 程序臂重算后的保留集合无变化；重放物理距离最大绝对差为 **0**，成功与截断标记一致。
- 这些结论只覆盖本机、本软件栈、已执行观察历史和当前运行器；它们不能排除两次运行共享的模型时钟、评分定义或算法逻辑错误。

## 保留差异何时真正改变动作

对 lookahead 与 effect，仅比较之前派发动作完全相同的历史，并进一步要求进入本次规划时旧尾相同，且候选种子一致。对齐的 **129 次决策**中：

| 观察 | 决策次数 |
| --- | ---: |
| 保留前缀列表不同 | 70 |
| 最终完整计划不同 | 9 |
| 实际派发动作不同 | 7 |

以上为开发数据上的事后描述，不是预注册因果效应或独立样本统计。保留列表不同并不自动意味着实际可执行动作不同；最终时序选择允许从共同父链、探针和尾链中选择，因此保留器的变化并不总能进入派发动作。该结果指出应追踪“描述 → 保留 → 最终链 → 实际动作”的作用路径，而不能以保留差异次数代替控制收益。两臂首次派发差异的任务和时刻由审计脚本列出；执行路径分叉后不再当作相同观测比较。

本次没有发现可用重算解释上一轮负向比较的错误，也没有证明不存在其他代码错误。不能将该结果升级为 descriptor 因果贡献、真实重配置机制、独立质量—成本优势或任何 gate 通过。
