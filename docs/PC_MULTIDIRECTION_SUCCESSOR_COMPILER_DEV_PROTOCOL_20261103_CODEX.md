# 多方向后继编译器：精确动力学开发协议

## 假设与边界

此前首段已有两个响应方向，但每个后继只使用单个阻尼方向。新版本检验：
在每个保留后继重新提取两个非零响应方向，生成 zero 和两个方向各自正负
扰动，并以完整十步预测保留即时最优及终点最远者，能否改变自动程序覆盖。
这是新的单配置开发实验，不重启已按协议停止的旧构造，也不预设 PC2 通过。

## 方法

首段计算五步输出中心差分 Jacobian（21 次五步预测）与 SVD，候选采用
zero 加最多两个奇异值大于 `1e-10` 的右方向正负扰动；预测所有候选，保留
目标代价最小者和距其预测输出最远的另一个（如仅有一个则只保留一个）。
每个保留首段的后继单独以完整十步链提取后五步响应，按相同阈值生成后继
zero 和最多两个方向的正负动作，所有后继候选以十步链预测并执行同样的
最佳加最远筛选。不得将无响应的奇异向量称为有效方向。

各保留十步组合使用共同 floor-CEM（批 12、floor 0.05），以可支付完整链
预算的 75% 平均分配；余量用于既有联合全动作精修，最终依照完整链分数
选择，并进行 zero-first-packet 弃权比较。前缀、后继、差分、优化、精修和
比较的所有预测均按五步一 token 计入 480 上限；SVD 次数和时间另计。
不足以为各候选提供两批迭代时明确报错，不能静默超支。返回完整响应、
候选、分数、保留、执行链、结构账本及弃权结果。

## 评估

同此前已暴露的 24 个 exact Wall 根，每根对新响应臂运行一次；记录全部
预测请求和 float32 模型输入，逐批重算状态和分数，检查完整链已评分、
候选输入合法、结构成本和 token。直接 full-CEM 控制复用原封存同根
480-token 结果，验证依赖哈希和任务一致；它不是强搜索上界。报告绝对
末距、`<0.05` 成功数、跨墙候选覆盖、每根差值、token 和 SVD 开销。
不额外择根、换种子或调参。若无成功或必要机制，停止本单配置并保留结果。

仅使用 exact 模型预测，不输入已知好链。即使在此开发面板成功，也须
对精修和弃权后的同一最终链另做共同后缀和同预算重规划机制干预；视觉、
独立确认和谱增量均不由此证明。
