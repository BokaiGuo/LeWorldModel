# E0 父链时序结构与覆盖：开发诊断结果

按[协议](PC_E0_PACKET_PARENT_COVERAGE_DIAG_PROTOCOL_20261105_CODEX.md)，对已暴露的新参数面板，将 64 条共享父链库从逐步独立均匀动作换为三个五步常值随机 packet，其他 CEM 配置和每臂 **663 prediction tokens** 不变。两种库使用不同随机流；32 是 16 根×两个随机流。

| 全局父链库 | 平均父链终距 ↓ | 平均最终终距 ↓ | 成功 / 32 |
|---|---:|---:|---:|
| 逐步独立 | 0.55248 | 0.50529 | 0 |
| 五步常值 packet | 0.55109 | 0.50308 | 0 |

按根平均两个随机流后，packet 库 12 根更好、4 根更差，但平均最终终距仅低约 `0.00221`，两臂均未找到成功链。这说明**本次仅更换提案时序结构没有解决预算内检出问题**；不同随机库不能确定这一微小差值的单独因果来源，也不能由零成功推断任务不可解或理论失败。

[审计](../le-wm-main/results/pc_e0_packet_parent_coverage_diag_20261105_codex/audit.json)重建 packet 库、逐调用重放 32 次预测并核对父链、资源与返回已评分最佳链；[原始结果](../le-wm-main/results/pc_e0_packet_parent_coverage_diag_20261105_codex/summary.json)保留所有调用。审计复用同一动力学，不是独立实现；三项有关 packet 和父链/CEM 合同的测试通过。

该诊断是查看结果后的开发排查，不是预先冻结的独立确认或正式预算内 oracle。应继续检查更有覆盖力的已规定基线、动作表达、时域与可解见证，同时保持候选生成合法、不将特权解放入正式规划。PC0–PC5 不因本结果变化。
