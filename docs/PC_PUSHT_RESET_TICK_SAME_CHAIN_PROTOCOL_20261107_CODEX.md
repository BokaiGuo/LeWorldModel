# PushT 复位物理子步：固定动作链配对检查

针对已曝光 seed 85 的 50 个开发任务，复用既有两条首计划及其 25 个合法原始动作（模型动作经同一数据 normalizer 逆变换）。在相同种子、相同环境配置、同一目标状态下比较：

1. `native`: 环境 `_set_state` 原样执行，包括其中一个物理子步；
2. `no_tick`: 设置相同可见七维状态并刷新形状索引，不推进模拟时钟。

两种条件不重新规划、不选择动作；每条链严格执行 25 个环境动作，即使中途成功仍继续，以匹配既有首计划开放环诊断。记录初始化可见状态和物理快照、输入数据图像与重绘图差异、逐步动作、物理快照和成功状态。native 的逐步真实动作、初态、轨迹与先前记录按已有精度核对，末帧和曾成功标签亦核对；不一致则停止。报告按任务/候选链配对的成功变化和状态偏差，明确 10 对相同链不是独立样本。

`no_tick` 不是对数据生成时完整隐藏状态的复原：数据仅包含 agent 位置速度、block 位置角度，不包含 block 速度、角速度及接触缓存。该条件只用于诊断初始化的一步影响，不作为官方协议或 RGB 规划器输入；不得以结果反推正式成功率或改变 gate。固定面板、动作、统计和全部结果必须保留；不按成功选择候选。
