# TwoRoom 同前缀排序：近并列容差核验

此前同前缀排序分析按浮点数精确相等识别平局。它正确实现了原分析
定义，但数值重算存在有限容差，因此需要检查近并列是否影响结论。
本次复用同一 10 个已曝光任务、共同动作与物理轨迹；只评价前缀未成功
的候选，模型预测和真实编码仍仅与同一目标图比较。此前相关结果的
输入哈希、共同动作和物理前缀轨迹均重新核验。

零容差完全复现先前 `pair_counts` 结果。敏感性检查把代价差不超过
`0.002`、物理距离差不超过 `0.00002` 的配对作为平局；数值取自既有
单值重算容差 `1e-3`、物理重放容差 `1e-5` 的两倍，以覆盖两数相减。
这些只是敏感性阈值，**不是对全部模型、硬件或环境的认证误差界**。

| 环境步 | 预测与真实编码（零 / 容差） | 预测与物理距离（零 / 容差） | 真实编码与物理距离（零 / 容差） |
| ---: | ---: | ---: | ---: |
| 15 | 80.447% / 80.447% | 52.646% / 52.646% | 52.140% / 52.140% |
| 20 | 73.675% / 73.675% | 51.845% / 51.845% | 54.067% / 54.067% |
| 25 | 74.008% / 74.058% | 49.298% / 49.298% | 53.059% / 53.093% |

各项均先按任务算一致率，再对 9 个有有效配对的任务等权；原先每时刻
各有 1596 对。上述容差只在第 25 步的两列各剔除 1 对。将阈值进一步
放宽为代价 `0.01`、距离 `0.0001`，最多也只在某一列剔除 1 对。
同任务内候选共享前缀和后缀，不是独立样本。

因此，这一固定候选支持上的编码／物理距离排序差异**不能由所测
近并列解释**；未发现需要修改历史公式的代码错误。物理末距不是
“曾成功”，这不否定成功排序可能更高，也不能排除动力学、目标评分
或其他实现问题。本次没有新增 GPU 推理或物理执行，不是新方法收益、
独立任务确认或 PC gate 通过。

原分析与新增审计合计 **6 项测试通过**；包括零容差精确复现、近并列
剔除和非法阈值拒绝。`code-debugging` 用于把可能的数值逻辑风险与
实际观察分开。
