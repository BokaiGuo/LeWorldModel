# 窄束 v25 最终同链机制：新开发面板

目的：在计划输出之前固定候选及机制干预，检查精修和弃权后的实际选中链，而非挑选已知成功根。候选为 v25 两模态、beam 2、greedy 1、均分共享 CEM、总上限 2,880 prediction-token；使用原全局库、评分、动作域、响应、保留、最终比较与弃权，不接入两阶段实验策略。该配置是开发参照，不因预先写入本协议就成为独立确认的正式方法。

固定 16 根 E0 exact-Wall：起点 `(-0.5,±0.185,±1.03)`、目标 `(0.5,gy)`，`gy∈{-0.12,-0.04,0.04,0.12}`；检查对列举开发面板的精确去重，不据此声明广义来源独立。固定每根种子 `2031601000+root`，所有根规划一次；保存预测尝试与失败。**先完成、封存并审计全部 16 根计划，之后才能实施任何机制干预。**

对全部已完成计划的精修／弃权后的实际最终链，沿用原 v25 prospective 干预实现及原阈值，含 selected、zero、same-bank greedy、lookahead、固定种子 random、共同六尾和各前缀三次等预算重规划；对比非即时进展、响应/梯度间隔、分支稳定性及相对收益，报告基础与全对照机制交集及各项组成。计划或干预失败保留在 16 根分母，不替换、不按任务成功筛选、不修改原阈值。计划 token 与干预 token 分列，分支局部复算另计说明。

逐批保存计划与干预请求及结果，绑定配置、原始动作、计划文件和依赖哈希；审计计划选中链为已评分的最好完整链、账本、另一同环境几何以及干预确定性重建。该面板为开发机制检验，不是冻结确认的 PC2 通过声明；广义来源、完整成本、强基线、RGB 与跨模型仍需另证。同环境重算不是独立复现。
