# JEPA v7 输入隔离修复：开发重放协议

前一协议的同进程输入校验读取了未来帧和动作，尽管预测回调只使用合法历史，严格隔离不成立。此次是独立版本的工程回归，不覆盖旧结果、不将旧结果升级为合法证据，也不是新根、独立确认或性能调参。

准备进程可读取完整已暴露 episode 1 以校验旧封存，只输出固定 `0/5/10` RGB、这三个时刻 agent 位置和速度、`[0:10]` 已执行动作 packet、帧 25 的指定目标图像、训练统计和运行模型所需的脱敏 metadata。禁止输出帧 15、未来动作或未来状态；记录文件哈希、字段及形状。目标帧是事前指定的目标输入，不是物理后果或验证标签。其来自同一已暴露轨迹，不满足独立性。

规划进程在独立 bwrap 文件视图中启动：覆盖整个用户 home 和 `/tmp`，只只读挂载实验源码、必要外部源码、解释器、checkpoint、DINO 编码权重和最小输入包；只允许写入本实验独占结果目录，并通过固定共享 GPU 锁协调。原始 episode、历史结果和完整原始 manifest 均不挂载，网络命名空间隔离。进程须尝试读取原始视频、轨迹和旧结果并确认不可访问；同时仅加载脱敏 metadata（模型结构、权重映射、模型状态收据和源码散列）。该方案防止本次规划路径意外访问已知位置，不是形式化的信息流或恶意代码安全证明；其他系统路径／依赖可能存在未知副本。

模型接口、动作盒、二维 chart、v7 核心、CEM、种子、1920 token、计算和记录与旧开发协议一致。对同一已暴露根做工程回归；若数值不一致先排查，不能用本实验选择方法或报告未见任务泛化。输出各臂请求、计数、最终选择、隔离视图检查和哈希。之后可以采用同 checkpoint 重放核验，但仍不构成物理执行、RGB-only 或 gate 通过。
