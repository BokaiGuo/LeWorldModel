# P1 推杆位置的渲染干预与冻结编码

前一轮默认 reset 无法还原封存目标帧。源代码核查表明，这些目标是
真实预热后、十步见证动作的末帧，而非对保存的七维状态重新 reset
即可恢复的图像。本轮按各根原 seed、状态采样、预热和见证动作重放，
对两个根的终态与 off/on 两种目标 RGB 分别逐元素验证；四张基线
图像均精确匹配封存目标。

在重建后的同一个场景中，不推进物理，直接改变推杆位置并更新绘制
空间索引，固定物体位置和角度：每根每条件使用零偏移和 x/y 方向
±10、±20、±40 的原生坐标偏移，共 52 张图像。偏移不是实际动作
轨迹，也未保证各图无遮挡、无碰撞或可达；模拟器状态只用于构造
诊断图，不输入正式规划器。

冻结编码器在主机 CUDA 编码全部 52 张图。48 个非零偏移全部造成
非零像素及 latent 变化；按偏移幅度 10/20/40 分组的平均 latent
MSE 分别为 0.00506、0.02538、0.13891。16 条根／条件／方向序列
中，三个偏移幅度的 MSE 均单调上升。这表明在该固定面板和该偏移
范围内，编码器**不是完全忽略推杆位置**。不同场景、遮挡和原生
尺度不能直接推广；单调性也不证明模型预测能正确反映推杆移动、
latent 的权重足够支持任务成功，或能改进 P1 的真实执行。

首次运行因误将根 slot 字典当整数索引，在渲染前报错且没有输出；
已按 source-plan 校验 slot 身份后修复。真实重放和四组基线／物体
固定验证测试 1 项通过。模型参数与 buffer 前后哈希相同，调用
52 次编码。结果
