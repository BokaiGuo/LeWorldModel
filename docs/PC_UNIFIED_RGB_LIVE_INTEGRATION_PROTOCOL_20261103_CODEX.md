# 统一开发入口真实 RGB 反馈接线诊断协议

## 事前问题及范围

固定 `multidirection_v1_development`，验证新统一入口能否在原 RGB
桥接后端接收当前观测、封存完整选择、实际派发该选择的前五步，并将
新图像及剩余尾部用于后续重编译。冻结模型重放不能证明这些实时绑定。
这是单次接线诊断，不重启或扩充已按协议结束的性能面板，不作性能比较、
模型优劣或科学 gate 判定。预先指定历史暴露根 0，一次执行，不筛根。

## 方法与执行

- 沿用既有后端、环境起点、15 步热身、冻结 checkpoint、normalizer、
  目标图像及合法图像状态估计，校验历史热身及模型来源记录。
- 热身后固定终点 15 步；在物理时刻 0、5、10 分别用统一入口编译
  15、10、5 步，不延长终点。每次执行所选完整链的前 5 步；后两次
  输入上次未执行的尾部，并在当前观测下重新评分。
- 模型预测和真实执行均接受原始动作 `[-1,1]`；模型输入转 float32
  并按冻结 normalizer 标准化。预测回调与统一入口分别计量，核对
  调用、轨迹样本及五步 token；每轮上限 480。不得读取物理真值
  作为规划器候选、分数、初始化或记忆输入。
- 每次将上下文 RGB 及其前一帧哈希、ticks、动作历史、目标、模型、
  normalizer 和 carry 绑定为内容哈希；保存完整计划、未执行尾部、
  逐批预测、评分和计量。决策文件排他创建并关闭后才派发动作；
  保存所有实际 RGB、原始执行动作及时间戳、决策哈希及来源哈希。
- 运行前后检查列出的依赖哈希、冻结模型参数，编码、预测和同步后
  墙钟时间单列；不将 token 等同全部计算。记录依赖和来源未知边界。
- 使用 GPU 协作锁，所有产物独立命名、排他创建；任何部分产物或异常
  均停止，不覆盖、不重新挑选根。完成后独立核对输入图像、时钟、
  carry、计划封存时间先于派发、实际动作、计数及哈希。

该诊断无独立对照、未覆盖真实弃权分支、未认证来源独立性或 PC2–PC5；
不将历史表现与本次接线诊断拼为新结果。模型不代表物理真值；
是否到达目标不影响接线判定。
