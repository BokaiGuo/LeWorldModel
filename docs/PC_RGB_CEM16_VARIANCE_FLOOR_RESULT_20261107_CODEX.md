# TwoRoom RGB 低预算 CEM 方差下限开发结果

按照[事前协议](PC_RGB_CEM16_VARIANCE_FLOOR_PROTOCOL_20261107_CODEX.md)，在 40 个已曝光或独立性未知的开发任务上比较原 CEM16 与仅将 elite 更新标准差下限从 1e-5 改为 0.2 的版本。两臂每次规划评分 16 条链，使用相同任务、种子、冻结 RGB 模型、时序评分、25 步上限和反馈规则；后续真实观察与重规划次数可以不同。

| 范围 | 原 CEM16 | 方差下限 | 下限独胜 / 原版独胜 |
| --- | ---: | ---: | ---: |
| 全部任务 | 31/40 | 30/40 | 2 / 3 |
| 排除初态成功 | 28/37 | 27/37 | 2 / 3 |

排除初态成功后，原版与下限版分别评分 2,000 和 2,016 条链；全体分别为 2,048 和 2,064。全体 GPU 同步规划时间分别约 4.19 和 3.97 秒，整任务墙钟分别约 9.05 和 8.86 秒。这是单次顺序运行；原版任务墙钟包含额外的历史动作与分数核对，下限版没有对应核对，因此不能据墙钟差异宣称效率优势。模型加载和结果持久化不计入。

**未达到预定开发出口**：下限版独胜不足 3 且独负超过 1，不继续扩大这个固定下限配置。虽然原 CEM16 第三轮有大量有效坐标方差偏小，固定下限 0.2 在本面板没有改善控制；这不是代码错误的证明，也不否定其他预算分配或搜索设计。

运行器逐次核对原版所选动作、选择索引、分数及真实轨迹与此前记录一致；独立审计重建两臂全部 257 次决策的随机候选、elite 更新、选择动作与 1,149 个派发物理步。审计复用了原候选生成和 elite 更新函数，也未重新计算全部 GPU 分数；新结果没有单独保存未选中的 incumbent 分数，故该审计不能完整独立证明所有轮次的全池最优选择。五种剩余时域上的合成评分对照和更新／错误输入测试共 7 项通过；最初等价测试误将原日志多出的 `count` 字段视为差异，修正测试比较字段后通过，实验结果与运行器未改动。

这是 RGB-only 开发基线对照，不是行动后果描述增量、正式独立确认或 PC0–PC5 通过证据。参考轨迹与实际物理状态只用于环境初始化及评价，没有输入模型选择器。
