# PointMaze 同状态重渲染差异：GPU 编码诊断

本次原计划把 ±0.03 的真实末帧编码与既有模型预测对齐。物理轨迹重放通过后，±0.1 图像的编码对旧特征检查失败，最大绝对差为 **2.65877**；因此原对齐分析没有输出，也没有放宽 `1e-5` 等价容差。初次只渲染末帧，随后按历史实验每步渲染的顺序重试，像素差仍存在。两个渲染产物均保留。

后续按[诊断协议](PC_POINTMAZE_RENDER_DRIFT_DIAGNOSTIC_PROTOCOL_20261107_CODEX.md)，在四个已曝光根、两个视角的 ±0.1 动作上，用同一冻结模型对历史图像和状态一致的重渲染图像配对编码：

- 历史图像重编码与旧封存特征的最大绝对误差为 **0**；模型指纹和输入合同匹配。
- 历史与重渲染图像平均绝对像素差为 **0.02871/255**，最大单通道差为 **48/255**；对应特征均方差平均 **0.01017**，目标代价最大绝对差 **0.02562**。
- 在这 8 个任务—视角条件、仅 ±0.1 两动作的比较中，编码代价的首选均未变化；这不保证更多动作、其他任务或闭环决策稳定。

结论是：本次不一致可追踪到实际输入图像差异，而不是历史图像无法复现已保存编码；渲染顺序改为逐步渲染未消除差异。**尚未定位图像差异的根因**，不能据此断定驱动、相机、光照或特定代码存在 bug，也不能认定两条渲染路径等价。尤其不应将 v2 的 ±0.03 编码与历史预测拼接为已认证的预测—真实编码误差。

物理数据及本诊断使用完整 proprio，仅属 state-assisted；四个根已曝光，目标距离不是完整成功指标。PC0–PC5 不改判。`code-debugging` 技能用于先复现历史输入、再隔离重渲染差异；相关测试 4 项通过。
