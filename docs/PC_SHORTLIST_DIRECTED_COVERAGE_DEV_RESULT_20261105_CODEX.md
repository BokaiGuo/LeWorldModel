# 固定候选预筛与有向覆盖：开发结果

## 结论

在已暴露的 E0 候选库、固定探针和共同精修机会下，探索槽和有向机会覆盖均改变了部分保留集合，但没有发现成功链，也没有显示稳定的平均终距改善。这个结果不支持将任一规则直接升级为正式规划改进；它也不证明被剪候选不可行。

## 协议与结果

按 [开发合同](PC_SHORTLIST_DIRECTED_COVERAGE_DEV_PROTOCOL_20261105_CODEX.md)，16 根、两种候选来源、两个深度，每种配置四臂；各臂每层 36 条共同探针链及两次各 120 样本的 CEM，共 276 条完整链、828 prediction tokens。候选池及任务已暴露；未重新计入其生成费用。

| 预筛 | 保留 | 平均最终终距 ↓ | 成功层数 / 64 |
|---|---|---:|---:|
| 即时前四 | 探针最小代价 | 0.501850 | 0 |
| 即时前四 | 有向覆盖 | 0.502009 | 0 |
| 即时前三＋探索槽 | 探针最小代价 | 0.502040 | 0 |
| 即时前三＋探索槽 | 有向覆盖 | 0.501810 | 0 |

成功阈值为终距 `<0.05`。64 是根×来源×层的配置数，不是 64 个独立任务，也不是正式端到端规划的成功率。

每根先对两种来源和两个深度求平均，以下差值为后者减前者，负值表示后者终距更低：

| 配对比较 | 16 根平均差 | 保留集合改变 / 64 |
|---|---:|---:|
| 探索槽 − 即时前四（最小代价） | +0.000190 | 17 |
| 探索槽 − 即时前四（有向覆盖） | -0.000199 | 20 |
| 有向覆盖 − 最小代价（即时前四） | +0.000159 | 32 |
| 有向覆盖 − 最小代价（探索槽） | -0.000229 | 27 |

方向随对照改变，差距相对于终距很小；开发样本不足以认定改善或等效。不同预筛还会改变探针库及可进入 incumbent 的链，故预筛差异不是仅由精修起点造成。

## 审计与边界

独立审计脚本核验源依赖哈希、逐项结果、候选去重与事前随机探索；对 256 次运行的 5376 次调用检查记录哈希、动作和成本，并逐调用用相同精确动力学重放特征与分数。复用原运行器重建保留和 CEM 随机流，核对最终链为所有已评分链中的最优之一。复用相同实现的重放不等于独立实现验证，也不是独立实验。审计结果见 `le-wm-main/results/pc_shortlist_directed_coverage_dev_20261105_codex/audit_replay.json`。

只给一个预筛外随机候选探针和精修机会，不能推断整个被剪集合；CEM 未检出不代表不可行。该后验固定池诊断没有完整端到端成本、强 CEM 对照、来源合格确认或真实 RGB 执行；不能用于认定 PC2/PC3 通过。预测 token 和记录的单次 CPU 墙钟亦不构成全系统成本认证。

另见 [共享好链预算曲线](PC_GOOD_CHAIN_BUDGET_CURVE_DEV_RESULT_20261105_CODEX.md)：最高有限预算仅约为基准八倍，不是无限预算或收敛证明。下一步应基于这些负结果选择可证伪的新候选或改进，并在新预定开发任务与完整成本下比较；不以改变保留集合本身作为收益。
