# RGB 首轮候选池：真实后果与保留分解

按[事后诊断协议](PC_RGB_HOLD_RETENTION_FIRST_POOL_PHYSICAL_PROTOCOL_20261107_CODEX.md)，重放上轮 40 个已曝光任务的首轮共同候选：每任务 3 个前缀、每前缀 3 条构造探针（含零参考）和 2 条独立生成尾部，共 **600 条链、15,000 个物理步**。这是评价端反事实重放，不是规划器可免费取得的搜索结果。

- 120 个前缀后，零参考的最大位置漂移均为 **0**，仅对这些已到达状态和本地物理后端成立。
- 对两个非零探针，预测的 zero-relative 后果与物理末距差的符号一致 **139/240**；按每任务 6 次比较，22 个任务多数一致、7 个持平、11 个多数不一致。两种分数单位不同，这里只比较符号；没有将 240 个候选视作独立任务。
- 初态已成功的 2 根和前缀阶段已成功的情况未计为“尾部发现机会”。13 个任务共有 **24 个**前缀满足：初态及前缀均未成功，但两个独立尾部中至少一个随后成功。

| 首轮保留规则 | 保留的有用前缀 | 至少保留一个的任务 |
| --- | ---: | ---: |
| lookahead | 16/24 | 12/13 |
| 中心化向量 | 15/24 | 12/13 |
| zero-relative 向量 | 18/24 | 13/13 |
| 行内身份打乱 | 18/24 | 13/13 |

按任务比较有用前缀数量，zero-relative 对 lookahead 为 **3 根较多、1 根较少**；对中心化向量为 **3／0**；与打乱为 **0／0**。这些是候选保留的事后 oracle 指标，不是实际选中链的成功率；同一前缀有用也不意味着规划器能识别正确尾部。尤其打乱同样保留 18 个，未隔离动作身份的独立贡献；上轮完整反馈实验仍按其事前规则判定未通过，不因本分析改判。

另一个审计脚本核对 600 条轨迹的时钟、成功规则、前缀一致性和汇总算术；其中 **129 次**链身份与原闭环首轮实际选择一致，已比对实际派发步的物理距离。审计没有用另一物理后端重新重放。诊断和搜索的相关测试 **5 项通过**；Gymnasium 的 reset 类型和动作转换警告仍存在。
