# 多方向编译器非即时覆盖：已封存轨迹归因协议

此为事后开发诊断，不重新运行规划器、增加候选或调整已停止配置。输入是
24 个暴露 Wall 根的多方向后继编译器封存计划和逐批审计；其任务状态、
动作、评分和依赖哈希必须与原记录一致。

逐根重新计算精确动力学下每个五步前缀的终距。沿用原诊断的非即时条件：
前缀末距不小于初始末距减 `1e-10`。为防止静止 zero 机械计作有效覆盖，
另明确要求前五步中至少一个 float32 动作非零；同时记录未排除 zero 的
原条件数。分别统计第一候选库、留存十步组合的首前缀、全部已评分完整
链与最终选中链。十步组合和完整链均按条目计数，重复前缀不视为独立
任务，也不据此计算显著性。

对每根报告已评分非零非即时链的最佳终距、任意完整链最佳终距及最终
选中分数；对所有完整链重新计算终态并核对封存分数和动作 float32
转换。若更好的已评分链未被最终选择，明确作为具体实现风险，而不是
自动解释为理论失败。首前缀有覆盖但完整链最佳仍差，不能区分后缀搜索
不足与不可行；最后精修可能产生不在初始候选库中的前缀。候选等级、
生成顺序、每根全部分数和选择绑定保留以供复核。

此诊断是已暴露开发根的后验覆盖分析，非 PC2 机制干预或性能确认；
不得拿后验最佳非即时链替代事前实际选中链，不追加样本，不更改停止
条件。结果和依赖使用新文件且排他创建。
