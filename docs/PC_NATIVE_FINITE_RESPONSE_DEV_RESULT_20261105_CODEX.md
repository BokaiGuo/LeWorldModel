# 原生有限响应组合：开发结果

按[协议](PC_NATIVE_FINITE_RESPONSE_DEV_PROTOCOL_20261105_CODEX.md)
执行 seed 42、50 行、300×10 CEM。响应和随机臂每次规划在 CEM
已评分父链基础上各增加 8 条共同有限幅度探针及 1 条组合链评分；
两臂各为 **44/50**，逐任务成功布尔文件逐字节相同。
该统计不是动作轨迹或模型内部输出相同：例如任务 0 的两个视频
文件并不相同。原生均值基线 47/50、已评分最优父链 46/50，
但均未承担新增的 9 次评分，不是匹配完整预算的比较。

响应／随机 `world.evaluate` 时间为 30.87／30.37 秒，包含环境
执行及视频保存，不含全部初始化，不是完整 GPU 成本。模型调用
数量相同不意味着墙钟或所有计算相同。

单元测试共 5 项通过，合成模型上检查了两臂初始候选和探针一致、
组合候选不同、选择结果来自当前已评分池、关闭适配器的 CEM
等价及 incumbent 跨反馈重置。真实运行没有保存探针、候选和
来源日志，故无法验证最终结果来自父链、探针还是组合链；
不同臂一旦执行动作不同，后续状态及候选池也不再保证相同。
这次没有证明响应引导产生发现增量，也没有否定其他响应算法。

第一次单任务 smoke 在 `env_name` 列表上暴露适配器类型错误，
修正为与原生 CEM 一样忽略非张量／数组字段并补回归测试；
修正后的 smoke 跑通。其低预算单例失败不能当作性能结论。
数据、normalizer、独立任务和权威版本边界保持原开发评测限制。
尚未完成同目标重新规划的候选日志、额外预算 CEM 强对照、
跨 seed 及独立确认、完整成本、最终链机制或 PC0–PC5 闭环。

## 事后追加：来源记录和近似预算强基线

看到初始结果后增加审计记录，重跑响应臂的逐任务成功布尔与原运行
逐字节一致。[记录](../le-wm-main/results/pc_native_finite_response_audit_seed42_20261105_codex.jsonl)
中 64 次规划选择里，父链 2、探针 33、组合链 29。分母是规划调用，
不是独立任务或成功数；记录包含对应的完整链动作和预测代价，但不含
CEM 全部 3000 条候选或物理成功到选择来源的因果归因。
完整当前测试为 7 项通过，包括日志选择、禁止覆盖，以及合成模型中
固定父链和方向、改变目标会改变响应组合候选的测试；这不证明真实
任务上的响应质量或性能收益。

追加原生 CEM 301×10 为 46/50，每次规划 3010 评分，比新增方法
的 3009 多 1 次；响应臂仅有的成功索引为 1、17，CEM 独有为
9、16、35、48（均为 0 基索引）。CEM 时间为 28.91 秒，带日志
响应重跑 30.62 秒；仍不是完整同步资源账。该基线在观察原结果后
追加，仅是探索性对照。不能据此声称同资源优势。
