# 条件局部尾部完整查询池：物理覆盖结果

按[事后协议](PC_CONDITIONAL_LOCAL_TAIL_FULL_POOL_PROTOCOL_20261107_CODEX.md)，
对上一实验实际联合查询的 **984 条**局部链全部重新物理执行，共
**24,600 步**。其中 18 条臂级已选链的轨迹与上一实验逐步一致；
这 18 次对应 6 个共同选链、3 个臂。

| 规则 | 本臂 16 条局部链中有曾成功链 | 局部最低分链曾成功 | 原实验最终选链曾成功 |
| --- | ---: | ---: | ---: |
| 普通 lookahead | 35/40 | 33/40 | 38/40 |
| 质量约束描述 | 35/40 | 32/40 | 38/40 |
| 身份打乱 | 35/40 | 33/40 | 38/40 |

三个规则最终失败的任务均为 root 38 和 39。这两根不仅各臂可访问的
16 条局部链没有曾成功链，**实际查询的跨臂联合局部池也都没有**。
这表明，单靠重排本次已查询局部链无法修复这两个失败；对于本次固定
起点和扰动，下一步若要改生成，应考虑能离开这个局部支持的合法候选。

这不意味着两任务的动作空间无解。此前独立物理重放的共同 B 尾部池中，
两根均存在成功链；但那是不同候选池，root 38 的成功 B 未被原各臂
保留，root 39 的成功 B 虽被打乱臂保留，却没有被该臂最终选中。
因此覆盖和评分选择均可能重要，不能仅凭这次局部重放排除评分问题，
也不能把 B 的物理成功标签免费交给规划器。

局部池中，前 10 个执行步未成功、之后曾成功的任务数分别为 30、29、
29；这里没有单独检查执行前初态成功，不能把它直接计为严格 PC2
机制。25 步诊断即使中途成功也继续执行；曾成功与末步成功是不同
指标。共享任务和候选不是独立统计样本。

新增及原搜索测试共 **5 项通过**，覆盖候选访问范围、缺失候选拒绝、
成功排名与动作约束。结果绑定原候选、计划、物理记录及本次协议；
本次未新增 GPU 评分，使用同一物理后端且仍有 Gymnasium reset 类型
和动作转换警告，不是独立模拟器或任务确认。`experiment-design`
用于固定可访问池和评价口径。PC0–PC5 不改判。
