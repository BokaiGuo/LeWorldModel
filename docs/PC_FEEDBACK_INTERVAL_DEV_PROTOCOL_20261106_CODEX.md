# PushT 执行间隔与显式候选选择：开发协议

封存旧版两方向符号组合：已有三次开发比较未显示其相对普通
lookahead 的优势，不再扩大该配置的 seed 以寻找阳性。此决定只针对
旧构造，不否定其他描述或程序结构。

先做一个有界工程开发面板：原 PushT checkpoint、数据、目标偏移
25、预测时域 25 环境步、执行上限 50 环境步保持一致；任务 seed 42、
求解器 seed 42、10 个任务。执行间隔为 5、10、25 环境步，两个选择
规则分别是最终分布均值、共同评分池最低预测代价。所有臂使用同一
有界 CEM，300 样本 × 3 轮；每次再对最终均值和补全旧尾各评分一次，
无旧尾时第二个位置为均值副本，故每次总计 902 条评分。
共同池包含最终均值、补全旧尾和已评分最佳样本；均值臂也评分同样
候选，但返回均值。旧尾补全使用本地 `prepare_init_action`，不是声称
未补全的短尾可以直接与完整计划比较。

每次记录候选分数、选中来源、补全旧尾、调用数量和求解墙钟；执行
trace 记录动作和物理结果。比较每任务真实成功、整个任务的规划数与
总评分数。执行间隔越短通常意味着更多规划，本面板按每次规划预算
一致，不是完整成本相等的正式比较；不能将成功率差解释为纯粹的
反馈收益，也不能宣称效率优势。计时包含诊断记录开销，并未隔离
GPU 编码和同步；不同运行之间任务及优化流需根据实际证据核验。

这是开发冒烟，不是独立确认、非劣效试验或正式成功门槛。若发现
接口错误先修复并另存版本；若没有明确收益，不扩种子以追逐阳性。
物理数据仅用于执行与事后评价，不能进入规划候选选择。程序结构、
未查询尾部描述、固定候选单步重编码预测对照、正式预算和 PC0–PC5
确认均不由此实验代替。
