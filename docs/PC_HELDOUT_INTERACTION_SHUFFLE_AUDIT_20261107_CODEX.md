# TwoRoom 留出尾部交互打乱：事后开发诊断

## 问题与范围

原留出实验的逐行独立打乱会同时破坏跨前缀共享的动作效应，因而不能单独检验前缀特定交互是否有价值。本次对同一批已曝光的 10 个开发任务做事后重分析；不是独立确认，也不是新的端到端规划实验。原实验停止规则和结论不改变。

把 A 代价矩阵分解为行均值、列均值及双中心交互。对交互逐行打乱后再次双中心化，保持原矩阵行列均值；B 的动作可用于查找最近邻，B 代价和物理结果仅用于评价。每个任务使用 100 次固定种子打乱。再次中心化会改变交互的精确分布，因此这是一种控制而非严格的置换显著性检验。

## 结果

| 指标 | 原动作身份描述 | 交互打乱 |
| --- | ---: | ---: |
| 留出 B 预测均方误差，任务平均 | 2601.89 | 2733.53（打乱平均） |
| 物理成功任务 | 4/10 | 5.39/10（打乱平均） |
| 末帧物理距离，任务平均 | 47.01 | 39.87（打乱平均） |
| 前缀尚未成功而全链成功 | 0/10 | 未作为主指标 |

原描述的误差仅在 5/10 个任务低于该任务 100 次打乱的平均误差。原实验行列加性基线误差为 2447.73，低于原描述。100 次打乱共享同一批任务及结果，不是 100 组独立实验；打乱平均成功数不是实际单次规划器成绩。

这项审计没有建立真实控制增量，也不能据此断言不存在其他有用的行动后果描述。模型预测分数和物理结果可能不一致，仍需独立处理；原逐前缀最近邻配置继续封存，不扩大确认。

## 可复核性

脚本读取并核对已有计划、候选池和物理结果哈希，验证原描述预测能够重现；对照计算不加载物理结果参与选择。输出包含逐任务、逐打乱选择及评价。测试覆盖加性与交互分解、无交互时打乱不变、随机种子可复现。此次是 CPU 重分析，没有新增模型查询、GPU 推理或真实环境执行。
