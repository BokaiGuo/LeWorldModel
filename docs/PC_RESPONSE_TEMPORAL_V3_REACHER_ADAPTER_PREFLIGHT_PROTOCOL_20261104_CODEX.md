# v3 Reacher 冻结模型接口预检协议

在新 v3 闭环运行之前，使用已暴露 Reacher 根 `20263160`、
原冻结 checkpoint、原动作统计和原支持动作热身，仅重建一次根
上下文，不规划、不派发新动作。验证根、目标 RGB 与既有 preflight
收据一致，完整 RGB 历史和实际动作历史被绑定；读取 qpos 仅可在
环境内部生成目标，不得作为响应或规划输入。

v3 核心需要二维模型输出，而 Reacher 的冻结模型输出高维 latent：
本开发适配将第一轴固定为当前 root latent 到目标 RGB latent 的单位
方向，第二轴为预定随机种子生成并与第一轴正交的单位方向；两轴
仅由合法 RGB 编码及预定种子构造，无 qpos readout 或后训练。
二维投影只用于 v3 响应提取与后继多样性，候选完整链评分仍用
同一冻结模型原始 latent 与目标 latent 的均方距离。这个投影是否
有任务相关性尚未知，不能称谱贡献或物理坐标。

对固定随机生成的三组合法原始动作，分别在 5、10、15 步检查：
原始动作按照时间顺序和 checkpoint 的 10 维 packet 统计归一化后
可逆；带缓存实现与既有 root-anchored `_terminal_batch` 在同一动作、
历史及冻结模型下预测相等（绝对/相对容差均 `2e-5`），分数和二维
投影有限。记录原始动作、归一化 packet、两种预测、目标、投影、
RGB 与权重/统计/参数哈希和 GPU 环境。预检输出排他创建，错误时
保留，不自动调整容差或运行闭环。此步骤是接口开发验证，不能证明
物理响应、PC0/PC1 或性能通过。
