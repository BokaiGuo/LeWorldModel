# PushT RGB 合成角度容差评分：固定池开发结果

## 实验

基于已曝光任务 1 的角度评分失配，按[开发协议](/home/gbk/code/LeWorldModel/docs/PC_PUSHT_RGB_GOAL_ROTATION_SCORE_PROTOCOL_20261107_CODEX.md)，仅用目标 RGB 提取物块颜色区域，生成图像质心周围 `±8°` 的合成旋转，并把原图与两张合成图的冻结编码作为目标集合。候选和同一真实反馈时刻的模型预测不变，分别以原目标距离和三个目标距离最小值评分。没有使用物理状态作规划输入，也没有训练新模型。

四个已曝光任务各固定 301 条同前缀链；GPU 评分与选链先封存，再读取已有物理重放标签。四张目标均通过颜色检测，均未弃权。原目标重编码最大差不超过 **1.08e-6**，原评分相对既有评分最大差不超过 **9.16e-5**；模型指纹未改变。

## 结果

| 任务 | 候选中曾成功 / 终点成功 | 原评分首选：曾 / 终点 | 容差评分首选：曾 / 终点 | 原 / 容差：最佳终点成功链排名 |
| --- | --- | --- | --- | --- |
| 0 | 47 / 13 | 是 / 是 | 是 / 是 | 1 / 1 |
| 1 | 11 / 1 | 否 / 否 | 否 / 否 | 186 / 72 |
| 2 | 1 / 0 | 否 / 否 | 否 / 否 | 无 / 无 |
| 3 | 0 / 0 | 否 / 否 | 否 / 否 | 无 / 无 |

任务 0 首选动作改变但仍成功；任务 1 的唯一终点成功链排名改善，首选却未变且仍失败。两种评分均为 **1/4 首选曾成功、1/4 首选终点成功**。评分只在每任务原有候选池内比较，不证明其他动作不存在。候选共享同一前缀，候选对不能视作独立任务。

协议的开发出口写作“首选成功”，没有预先明确是曾成功还是终点成功；评估分别按两种定义计算，**两者都未达到出口**。因此停止扩大这个具体变换；不能凭排名改善宣称真实控制增益。即使这项规则达到开发出口，也必须先在新的事前冻结任务、共享评分规则的强基线及完整计算成本下比较。

## 边界与成本

模型每任务编码三张目标图，而原评分只需一张；本次三图批编码同步耗时约 **0.004–0.107 秒**，包含首次预热差异，不是完整系统计时。候选预测复用相同 301 条单帧后缀 rollout；没有运行新的闭环或统计确认。

合成图使用颜色分割、图像质心旋转和图像修补，不保证对应真实物理角度、真实背景或可达目标；即便通过检测也可能因遮挡和伪影失效。预定目标容差是评分假设，不改变原环境成功规则。本结果不否定其他 RGB 目标评分，也不支持描述组件独立贡献；PC0–PC5 不改判。

目标构造与弃权单测 **2 passed**。结果为已曝光池上的单次开发检查，物理重放来自同一既有评估后端；未做独立模型或环境复现。`experiment-design` 用于封存候选和区分开发出口与 gate。
