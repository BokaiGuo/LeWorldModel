# dev305 固定动作库：目标 guard 前置的共同后缀接口

开发对照固定使用已封存的两包物理 oracle 合同的三个前缀，首包依次
枚举全部 17 个固定动作，第二包固定使用合同内索引 16 的 zero，均各
五步，共 51 条预定分支；不读取奖励、不根据物理 outcome 选择动作。
此前历史实验已打开，本对照不是预注册确认或独立根证据。

每个分支在创建/重置物理环境、重放 warmup/shared/prefix、以及派发
任何动作前，先对封存真实目标 RGB 运行既有 8 像素 guard，源文件和
动作库通过固定哈希绑定。目标失败时记录 `blocked_before_environment`
及计划长度 10、执行长度 0；这不是 zero 控制动作，也不是完整时域
负结果。目标通过仅表示可尝试后续：本开发核验不自动触发任何后续物理
执行，必须另行检查当前 RGB、真实历史绑定、逐步 guard、截断与成本。
缺帧、源哈希错误或 guard 源变更均为工程失败且禁止任何环境动作。

本次只读取合同动作字段、前缀名称和封存目标 RGB，不读取 simulator
状态、候选 outcome 或已知物理奖励；不重置环境、不占 GPU、不训练。
记录目标检查、51 项计划的动作哈希和成本；不改变现存合同、guard 或
P1 gate。验证此接口不能证明控制质量或完整闭环。
