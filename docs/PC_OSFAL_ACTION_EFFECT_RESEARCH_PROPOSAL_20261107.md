# OSFAL 启发：冻结世界模型的逐层动作后果诊断

**性质：研究建议与待验证假设；不是实验结果，也不修改 PC0–PC5 合同。**

本文件整理用户提供的 OSFAL 研究构想，讨论其对 Planning Compiler 的潜在启发。原论文面向行人重识别，不验证世界模型 rollout、动作后果或闭环控制；其中的论断和作者报告的结果不能直接转化为本项目的实证结论。论文来源为用户提供的 *OSFAL: Orthogonal Cross-Spectral Feature Alignment and Layer-Localized Cross-View Learning for Any-Scenario Person Re-Identification*。

## 核心问题和方法边界

研究目标是区分三个不同的失败来源：

1. **信息缺失：** 合法视觉输入或冻结表示未保留足够的物理及行动后果信息。
2. **信息未传递：** 编码器某层含有相关信息，但最终表示或冻结动力学预测未正确利用。
3. **信息未利用：** 预测已足够可靠，但候选保留、程序搜索或选择未将其转化为控制收益。

OSFAL 提供的思路是区分不同变化来源，并逐层定位表征变化，而不是直接移植网络。原文的 cross-spectral 指 RGB、红外等成像模态，与动力学特征值谱或动作 Jacobian 奇异值谱不是同一概念。本文所述层级曲线、定位结论和方法收益都只是待检验假设。

第一篇主协议保持冻结模型、RGB-only：合法输入为图像、目标图像和动作历史，不允许把真实物理状态或依赖完整 proprio 的 checkpoint 冒充纯视觉模型。官方 PointMaze JEPA 若使用 proprio，则结果单独标为 **state-assisted**；两轨分别记录输入权限、checkpoint 与结果，不跨轨提升 Gate。离线评估可以使用模拟器真实状态与动作后果作标签，但不能将其泄漏给在线规划器。

## 一、冻结逐层动作后果审计

在真实可复位的物理状态和合法动作上，构造事先固定的配对数据；所有条件保留完整分母，不按事后成功筛选：

| 条件 | 保持不变 | 改变 | 目的 |
| --- | --- | --- | --- |
| View-only | 物理状态、目标、动作 | 相机视角或预先指定的外观因素 | 测量视觉干扰 |
| Physics-only | 视角、目标、动作 | 位置、朝向或接触配置 | 检查控制相关状态信息 |
| Action-only | 初态、视角、目标 | 合法动作探针 | 检查真实动作后果的可区分性 |
| Interaction | 探针和任务定义 | 视角与物理状态 | 检查行动信息的跨视角稳定性 |

相机变化时须保持动作的物理含义；若动作以相机坐标表达，应显式转换。参考动作必须根据环境合同验证，不能假设零动作等于物理静止。记录 reset 状态、真实渲染、目标、历史、动作打包、时间和预处理；先排除接口及物理对齐错误，再解释模型表现。

对冻结 encoder 各层，以预定的 token 池化和归一化规则报告：

- **视角敏感度：** 同一物理状态换视角的特征差异。
- **物理状态区分：** 同视角下位置、朝向和接触变化的可区分性，尤其关注后续动作效果不同但外观相近的状态。
- **动作后果可区分性：** 在独立物理 roots 上检索或比较真实动作后果，而非仅检验状态能否区分。

同时报告跨视角动作排序、相对真实任务代价的 regret 和失效分母。层尺度和 token 结构可能不同，不直接比较未经规范化的原始范数；也不把物理差异与视角差异的比值单独作为成功指标。统计单位为物理 root 或任务，不把共享 root 的候选对、图像或 patch 冒充独立样本。结果按开发、验证及确认数据隔离；不能在测试集选最佳层后再称为独立验证。

中间层更可辨识不意味着可直接输入冻结 predictor：其维度、分布和动力学语义可能不兼容。逐层分析首先是诊断，不自动构成可部署修复。

## 二、离线正交几何及动作条件一致性

可在与评估 roots 隔离的诊断校准集上，用配对视角特征拟合正交 Procrustes 映射，并在未见状态和动作后果上测量残差及泛化。这会估计数据相关参数，因此在严格冻结路线中仅作为**离线诊断**，不是默认部署组件。

关注的问题依次是：静态跨视角特征能否近似对应；这种对应能否泛化到未见物理状态；以及预测动作后果能否与真实后果和跨视角排序一致。最后一项不能由静态特征接近代替。

若对预测表示和目标同时施加同一个正交变换和共同平移，欧氏距离不变，因而不会单凭这一操作改善候选排序。跨视角分别映射可改变跨坐标比较，但其可用性、动作坐标转换和数据权限都必须独立验证。静态对齐也不能证明接触或动力学预测正确；动作条件化的一致性是需另行测试的假设。

## 三、最小决策实验与路线选择

在 PushT 上，优先构造两类外观相近、但对同一合法动作具有不同真实后果的接触配置；先核验状态可重置、动作和物理结果，再按 root 划分执行以下有序测试：

1. **逐层辨识：** 冻结 encoder 的哪些层能在未见 roots 上区分两类配置及真实后果？
2. **预测传递：** 如有相关信息，冻结 predictor 能否正确预测动作方向、旋转或后续可达差异？
3. **搜索利用：** 仅在预测可靠后，比较相同候选和完整计算预算下，描述是否改善 bridge 保留与事前选中链的真实执行；对照普通 lookahead、无描述方案及适用强基线。

开发集用于核验实现和选择方案；确认前冻结主要指标、任务划分、统计单位及判定规则。没有可靠差异时保留失败分母，不把单次特例升级成路线结论。

| 观察 | 合理的后续决策 |
| --- | --- |
| 各层均无法稳定区分相关真实后果 | 检查可观测性、历史及表示限制；不能靠旋转凭空恢复信息 |
| 中间层有信息，最终表示或预测失真 | 检查预测路径与模型合同；训练式修复另归第二篇 |
| 静态视角对齐成功，动作预测仍错误 | 定位动作条件动力学与接口，不把静态对齐当作修复 |
| 预测可靠但搜索无增量 | 检查保留、组合和最终选择；不得将可分特征等同于规划收益 |
| 描述在同成本真实执行中有增量 | 再冻结完整版本，进入相应机制、闭环及独立任务验证 |

上述判断均需考虑数据覆盖、统计不确定性与代码合同；负结果可能来自实现，也可能反映方法或观测限制，不能预设其中之一。
