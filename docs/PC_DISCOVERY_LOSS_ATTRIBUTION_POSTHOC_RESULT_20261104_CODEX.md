# 发现过程分层损失：事后归因结果

本分析读取并绑定 `pc_discovery_attribution_dev` 已封存的 64 条全额计费计划，不重跑、不修改结果、不引入 oracle 或特权前缀。global_cem 没有递归层，作为全局基线单独记录；其余 spectral、random_direction、diverse 共 48 条递归记录、144 个层次。

## 1. 当前没有观察到即时分数损失，但不能推出没有延迟收益损失

144 个递归层中，即时分数最优候选均被最终保留：**144/144**。保留集合相对候选库即时最优分数的 gap 为非零的层数是 **0/144**。这是 greedy 槽保护规则正常工作的结果，不是对延迟收益的检验。当前记录不能回答“即时稍差但尾部可实现质量更好的候选是否被剪掉”；需要给保留和剪掉的候选共同尾部优化机会。

响应集合相对多样性集合发生变化的层次为 **17/144**，其中 depth 0 为 15 层、depth 1 为 2 层、depth 2 为 0 层。该变化没有造成即时最优候选丢失，也没有单独证明它保留了更好的后缀。depth 2 没有后继探针，是因为 `15 - 3*5 = 0`，候选已经是完整动作链并已执行终点评分、incumbent 更新；这不是预算漏洞或待补的末层探针。若要研究末层潜力，应比较完整链精修策略，或另立延长时域合同。

## 2. 起点来源均值只能描述记录，不能作为因果效应

递归臂的精修起点按来源聚合如下；这些来源对应不同任务、起点分布和优化机会，均值跨已暴露开发任务及多臂记录，不能视为独立样本或生成器因果效应：

| 起点来源 | 数量 | 平均初始终距 | 平均精修后终距 | 平均改善 |
|---|---:|---:|---:|---:|
| carry（全局库最佳） | 19 | 0.3854 | 0.1103 | 0.2751 |
| global warm start | 48 | 0.5658 | 0.4757 | 0.0901 |
| depth1 successor reachability | 16 | 0.5072 | 0.5022 | 0.0050 |
| depth2 candidates | 13 | 0.5072 | 0.5009 | 0.0063 |
| retained final beam | 83 | 1.8240 | 0.4887 | 1.3353 |

`retained_final_beam` 的平均改善大，主要因为其初始链很差；精修后仍接近 0.49。它不是自动发现有效链的证据。`carry` 的平均结果也不能单独证明全局生成器因果上更好。相同起点、相同随机流和相同预算只适合检验优化器重放一致性；检验候选生成时应允许起点不同，但匹配下游优化器、随机流规则和机会。

## 3. 对下一轮实验的约束

现有数据不支持继续把“保留即时好候选”作为首要 bug 假设，也不支持用更多保留槽解释全部负结果。下一项有识别力的实验应直接隔离：

1. 全局候选在固定尾部优化机会下是否覆盖响应候选没有覆盖的区域；
2. 不同生成器产生的起点在匹配下游优化器、随机流规则和机会下，是否提高检出率；
3. `carry` 的优势是否只是全局动作库的优势，而不是递归响应的优势；
4. 完整链精修如何利用不同前缀，以及其成本是否值得；不把完整链终点评分误称为末层缺少后继探针。

不能把这些问题用增加 beam、增加深度或重新挑选 root 代替。全局候选必须保留为合法强对照；不能删除它来制造响应臂阳性。
