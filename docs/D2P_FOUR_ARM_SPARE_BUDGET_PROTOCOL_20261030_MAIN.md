# 四臂剩余额度探索配置：未授权物理执行

本配置在既有四臂的八个初始候选、共同 projected-gradient
优化器及同一逐轴预算上限基础上，预定让 native-style 与 random
臂的第 0、1 个候选各追加一轮同配置两步优化；另外两臂不追加。
选择索引不使用物理结果或运行中分数。随后仍对全部八个最终
候选逐一重放并按同一规则选择。该配置是在已知根探索结果之后
提出，不能称为独立预注册确认。

每节点的 cooperative 预测调用分别为 structured 75、
native-style 84、random 84、immediate-progress 88；
对应 backward 调用为 208、20、20、16。上限逐资源轴分别确定，
不将不同调用类型折算成单一数字，也不填充无用调用。
这一设计给两个基线更多搜索机会，但它并不能花掉结构化方法
所有反向计算额度：预测调用的共同上限先成为约束。因此不能
声称实现了 wall-time 等预算或完整公平；仍需事前固定多个预算
水平、覆盖所有实际计算并验证资源隔离。

代码 `p1_four_arm_spare_budget_20261030.py` 实现单节点，
`p1_four_arm_spare_budget_bridge_20261030.py` 增加持久账本和
反馈节点接口；`p1_four_arm_spare_budget_cuda_20261030.py` 连接
既有真实 RGB 反馈和物理执行器并绑定相关源码。它们保留原
优化器配置及封存代码。上线前必须验证动作、历史、目标和执行器，
实际记录推理与编码开销，完成主机 CUDA 接线及保存态验证；
旧结果不受影响，不打开 P1。
