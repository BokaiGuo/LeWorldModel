# Dev304 shared ten-step tail intervention

This is a post-outcome development experiment on the previously used
dev304 root. The two fixed prefixes are the prior single-population and
two-population candidate selections. The fixed tail family comprises the
two previously generated feedback plans (ten actions each) and ten zero
actions. Each tail was applied after both prefixes, for six trajectories.
The tail family was bound before these six executions but after the earlier
five-step outcomes; it is not an independent or preregistered confirmation.

All six branches reproduced their original prefix state and RGB snapshot,
executed the full ten-step suffix, and did not reach native success.
Results below are absolute terminal object errors, followed by change
relative to the same prefix's zero-tail endpoint. Negative relative values
mean an improvement in that error, not necessarily a task success.

| Prefix | Common tail | Position error | Position minus own zero | Angle error | Angle minus own zero |
| --- | --- | ---: | ---: | ---: | ---: |
| single population | single plan | 207.536 | -9.810 | 2.711 | -0.410 |
| two populations | single plan | 232.670 | -2.209 | 2.767 | -0.149 |
| single population | two-population plan | 180.112 | -37.233 | 3.110 | -0.011 |
| two populations | two-population plan | 205.792 | -29.087 | 2.993 | +0.077 |
| single population | zero | 217.346 | 0 | 3.121 | 0 |
| two populations | zero | 234.879 | 0 | 2.916 | 0 |

Both nonzero tails yield larger position-error reduction relative to zero
after the single-population prefix. The angle comparisons do not uniformly
favor that prefix in absolute terms. The prefixes already differed in object
position and angle before the tail, and the experimental prefix was an
RGB-geometric rather than a verified dynamics-derived program. Therefore this
result cannot establish a non-greedy reconfiguration mechanism or exclude it
generally; it is a negative/ambiguous local finding for this candidate family.
The six branches share one root and are not six independent episodes.

The saved verifier binds the pre-execution source/contract hashes, all actions,
the saved prefix replay, 84 decoded frame hashes, terminal flags and row
shards. This verifies the recorded intervention, not source independence,
full compute fairness or model prediction accuracy.
