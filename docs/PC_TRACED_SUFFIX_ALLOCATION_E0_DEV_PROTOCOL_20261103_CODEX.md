# 同库后缀预算调度与逐批动作封存：E0 开发协议

本协议在运行前固定；任务是上一轮 12 个已暴露 unicycle 方向，不是独立确认，不用于重新宣告非即时机制。动作、目标、15 步固定时域及精确动力学沿用 `PC_SAME_POLICY_EXACT_MECHANISM_DEV_PROTOCOL_20261103_CODEX.md`。预算预固定 480、720 个五步预测 token，分别报告；不能把两档预算当成独立任务。

三种同库方法共用相同多名义 SVD 生成器、zero 和两个响应候选、前缀模型评分及共同完整链评分；生成和筛选预测从同一个预算扣除，并分别记录 SVD 的调用和时间。每个方法将生成筛选后的可整除完整链样本的 3/4（向下取整）分配给固定前缀的迭代后缀 CEM，余数用于同一个以最佳完整链初始化的全动作联合精修；严格保留精修前最佳链。三种分配：

1. uniform：后缀样本尽可能平均分给三个候选，差不超过一个。
2. adaptive：三个候选先各得 12 个样本，此后每批最多 12 个样本分配给目前完整链最低分候选；中途保留各候选 CEM 的均值、方差及 RNG 状态，最后一批可缩小。按候选顺序处理平分。
3. greedy：前缀即时分数最低的同库候选取得全部后缀样本。

每个候选的随机流按同一任务 seed 初始化；不同调度只改变该候选被调用批次数，不共享额外候选。完整时域 CEM 无生成开销，可使用全部预算；它是具体开发强基线，不是全局上界。全模型使用相同精确动力学、动作边界、反馈机会和终点成本。每方法分别生成候选并独立计费，不能将共享的诊断成本归零。

所有通过预测入口的每一批动作、预测位置、评分和五步 token 均完整保存；记录候选、后缀 CEM 每批归属、各预算、精修前后选择、生成账本、耗时和执行计划，附源码及协议 hash。计划输出先封存，独立审计逐批动作重算分数、token 总和、合法性和最终链成本，并核对实验 hash；输出存在即拒绝覆盖。没有真实 RGB、模型误差、后续响应组合或独立根；等 token 不等总 FLOPs。不得把该结果升级为 PC2/PC3、SVD 优势或旧 P1 通过。
