# OSFAL 启发的逐层真实观测诊断：开发结果

## PushT：RGB 轨道

按 [预定协议](PC_OSFAL_PUSHT_LAYER_DEV_PROTOCOL_20261107_CODEX.md)，在冻结 RGB LeWM 上使用 GPU 编码既有 16 个几何开发根、左右接触就绪配置、白/灰背景和三个五步动作的真实后继。没有额外训练或将物理状态输入模型。白/灰是背景变化，不是相机视角；左右是不同物理配置，不是同状态的双视角。每根的四个条件不是四个独立任务。

在全部 64 个条件中，真实后继编码按目标特征代价选择的平均物理遗憾为：

| 事后观察的表示 | 平均遗憾 | 并列最优条件数 |
| --- | ---: | ---: |
| block 9 CLS | 0.1250 | 56/64 |
| block 12 CLS，未做最后 layernorm 和 projector | 0.2649 | 48/64 |
| 正式视觉输出 | 0.2204 | 52/64 |
| 既有冻结模型预测后继评分 | 0.2427 | 未在此表统计 |

遗憾相对该条件三个动作中最小的既有物块位置及角度代价；并列容差 `1e-9`。第 9 层相对正式输出按根平均为 4 根更好、2 根更差、10 根相同，且若干根具有重复的几何配置；不是独立确认。第 9 层是在查看 12 层结果后选出的，不能报告为预先冻结的胜出层。正式视觉输出重新计算的代价与既有结果最大绝对误差 `0.000153`，满足事前容差；模型参数指纹前后一致。

此处比较的是**真实执行后的图像编码**。真实后继在规划时不可用；中间 CLS 与预测器输出也不是同一表示空间。因此这些结果既不是动作预测结果，也不证明 block 9 可直接给规划器使用。当前面板没有真实相机变换、困难负样本检索或未查询动作确认；不能证明动作后果等价、跨视角稳健或程序搜索获益。

## PointMaze：state-assisted 模型的视觉分支诊断

按 [协议](PC_OSFAL_LAYER_OBSERVATION_DEV_PROTOCOL_20261107_CODEX.md)，使用四个已曝光根的双相机真实轨迹和三个动作，冻结官方 PointMaze JEPA 本地兼容实现。逐层检查是该 checkpoint 的视觉分支观测分析，不是 RGB-only 规划实验。

第 3 层在四根、两个相机的真实末帧评分中均选择物理距离最小动作；正式视觉输出的平均物理距离遗憾为 `0.0190`，两个视角在 1/4 根选择不同。第 3 层是事后看到结果选出的，且仅四根，不能推断泛化或声称已解决视角问题。该层平均跨视角 MSE `0.000478`，同视角动作间 MSE `0.00000274`；量纲和层间尺度不同，不能将原始数值跨层直接比较。末 block 经实际 layernorm 后与正式视觉编码输出最大误差为 `0`。

逐根原始数值：[JSON](../le-wm-main/results/pc_osfal_layer_observation_20261107_codex.json)。所用轨迹哈希与其历史物理记录一致。

## 共同结论

两套观测诊断提供了“中间层可能有值得进一步检验的目标相关信息”的开发线索，不证明其具有可预测、可利用的行动后果信息，也没有证明最终表示丢失了接触因果信息。后续需要在根隔离的新面板上固定层选择规则、验证真正相机视角与物理配置，并单独检验预测与搜索；不能根据真实后继选择动作或将两轨证据相互升级。PC0–PC5 均不据此改判。

两项新增指标测试共 3 项通过。OSFAL 中的拟合正交变换与对比学习未被接入第一篇方法。
