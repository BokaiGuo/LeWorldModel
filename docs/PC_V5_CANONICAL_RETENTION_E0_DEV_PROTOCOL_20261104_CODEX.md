# V5 固定候选身份的 E0 保留策略开发对照

旧 v4 两种保留策略把 CEM 随机种子和预算余数分配绑定到保留顺序，存在同一候选在两臂获得不同随机流或样本数的混杂。本协议另立 v5 开发方法，不改变封存 v4：沿用 v4 的候选生成、后继响应、共同尾部种子、非线性评分、全链精修及弃权；在保留后按候选库索引排序，以固定候选身份分配后缀 CEM 随机流并按索引次序分配余数。正式选择仍来自完整链的实际评分，不使用后验物理最优。

首层策略两臂：v4 的即时最佳＋局部岭价值＋响应矩阵距离；原位置消融的即时最佳＋后继位置距离。两臂均对全部候选执行完全相同的后继探针，按同样 1920 token 上限计入；两臂共享候选库、固定名义点、任务和对应候选的随机数种子。若每臂其余可用预算因相同候选库而相同，共同候选的分配数可能仍因其在各自保留集合中的索引排序不同而有至多一条样本的余数差；必须逐根报告，不称其完全等样本。全链精修随机流固定共享，但起点不同。

先运行已暴露的 24 个原 E0 根，每臂仅首次 15 步规划；封存所选完整链、全部轨迹、随机流身份、成本及所有失败。使用相同动力学逐批重算，另检查共同候选的种子和预算。主开发描述为终距均值、中位数、`<0.05` 根数、按根胜平负、共同候选数及样本数差。不能利用该面板调参直到胜利，不能作为新独立确认或 PC2/PC3 通过；特别是上述位置保留策略来自先前后验诊断。结果不覆盖任何 v4 证据，若要迁移 RGB 与机制，必须使用同一 v5 入口另做实验和干预。
