# TwoRoom 固定前缀保留：事后覆盖分解

本协议在原四臂结果已知后制定，属于事后开发分析。原 10 根和每根 8 个前缀的 36 条已评分精修链均不重新生成、不调整预算。对每个前缀，选其原模型评分最低的那一条；这 80 条链均从原始封存计划读取，真实执行满 25 步，记录动作指纹、逐步距离及成功。前缀间和与原四臂若选择同一动作，要核验轨迹一致。

逐根比较原 lookahead 实际执行链、描述臂实际执行链与 8 条精修代表链，报告：

1. 全部 8 条代表链中是否存在真实成功链，以及此集合相对原 lookahead 的事后 oracle 覆盖；
2. 原 lookahead 失败而某条精修代表成功时，该前缀是否被 lookahead 或描述臂保留，且其模型分数是否优于各臂最终链；
3. 在所选前缀内，如果物理成功链模型分数劣于失败的最终链，登记为该固定候选对上的模型选择失配；如成功前缀未被保留则同时登记覆盖／保留损失。原因可重叠。

只回放每前缀模型最优代表，而不是全部 288 个候选。未找到成功不能证明完整候选池无解；8 前缀事后 oracle 消耗了额外评分和物理标签，不能作为可部署规划器或等成本结果。物理成功、坐标或评价结果不得进入原已封存模型选择，不修改原实验及停止结论。新数据和 normalizer 来源限制不变，PC0–PC5 不改判。
