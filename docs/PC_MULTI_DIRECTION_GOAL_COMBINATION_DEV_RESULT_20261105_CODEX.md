# 多方向目标响应合成：开发结果

按[事前协议](PC_MULTI_DIRECTION_GOAL_COMBINATION_DEV_PROTOCOL_20261105_CODEX.md)运行已暴露 E0 的 16 个根、每根 2 个随机流；192/192 运行完成。平均终距越低越好，成功阈值为终距 `<0.05`。仅预测 token，不是完整系统成本；三臂均未计入共同全局父链生成费用。

| 比较 | 方法 | 平均终距 | 成功 / 32 | token |
|---|---|---:|---:|---:|
| 固定精修机会 | 目标加权 | 0.347464 | 5 | 363 |
| 固定精修机会 | 随机加权 | 0.347230 | 4 | 363 |
| 固定精修机会 | 仅探针 | 0.341512 | 5 | 327 |
| 等 token | 目标加权 | 0.333274 | 7 | 471 |
| 等 token | 随机加权 | 0.338602 | 6 | 471 |
| 等 token | 仅探针 | 0.330408 | 9 | 471 |

目标加权相对随机加权：固定机会按根平均后 4 根较好、7 根较差、5 根相同；等 token 为 6、5、5。目标加权相对仅探针：固定机会为 2、4、10；等 token 为 3、4、9。仅探针在等 token 下把节省的 12 条评分用于精修。开发数据没有显示可归因的目标加权净优势；均值与小样本差异不构成统计确认。

固定机会中目标加权和随机加权分别有 9/32 和 10/32 次以组合编辑作为精修起点，其余从探针起点开始；起点来源不是最终成功因果归因。测试证明在所构造的多方向例子中改变目标可以改变无序候选集合，而单方向反向目标只重排双侧集合；这解决了可识别性设计问题，不保证真实任务获益。

[逐调用审计](../le-wm-main/results/pc_multi_direction_goal_combination_dev_20261105_codex/audit.json)检查了所有 192 次预算、跨臂共同探针、返回链是否为已评分 incumbent，并以相同动力学实现重算所有调用，数值误差为零；同实现重放不是独立验证。[原始记录](../le-wm-main/results/pc_multi_direction_goal_combination_dev_20261105_codex/summary.json)保留每臂及逐调用动作／评分。

这些任务、父链及优化流已暴露，不能推断独立面板或真实视觉系统表现，也不证明全部响应组合方法无效。当前版本不应作为性能增量宣称；尚未接入原生 RGB 路径，也未完成端到端响应与强 CEM 的公平比较。

工程核对：当前安装的原生 `stable_worldmodel.solver.CEMSolver` 每轮根据精英更新分布，最终返回的是最后一轮的分布均值，而不是承诺返回历史已评分最优候选。均值未必恰是已评分链；这是需要显式处理的基线／新方法接口差异，不自动构成 bug。若新方法增加 incumbent，必须让同一权限的对照也能使用并计费；不能静默改写原生基线或把返回均值和返回已评分最优混为相同机制。
