# PointMaze 同渲染路径三量对齐开发协议

历史帧与当前渲染存在可复现像素差；不得混用历史目标编码和新真实后继。此试验改为：从当前原始渲染器重放文件抽取每根当前和目标初始 RGB、当前完整 proprio，单独封存输入；冻结 PointMaze JEPA 对 `[-0.1,-0.03,+0.03,+0.1]` 五步动作逐条预测并封存表示与选择。预测阶段不得读取末帧或候选物理后果。

然后使用本轮同环境 v2 渲染的四动作真实末帧，以同一冻结 encoder 编码；已核对该 v2 渲染的 ±0.1 帧与当前原渲染器逐像素相同、四动作逐时刻物理状态与先前轨迹相同。比较同状态、同动作、同目标、同视角和五步物理时刻的预测表示、真实编码及物理目标距离。报告模型与真实编码选择的物理遗憾、各动作对三种排序一致率及特征误差；两个视角先按任务平均。真实后继编码是事后 oracle 诊断，不能供部署规划器选择。

四个任务和动作此前已曝光，本试验只消除当前已知的跨渲染路径混用，不证明正式协议、官方源码等价、独立泛化或闭环收益。目标距离不是任务成功。允许完整 proprio，明确标记 `official_state_assisted`；任何结果不得晋级 RGB-only。保留预测及物理特征和依赖哈希，不追溯调整原停止规则。
