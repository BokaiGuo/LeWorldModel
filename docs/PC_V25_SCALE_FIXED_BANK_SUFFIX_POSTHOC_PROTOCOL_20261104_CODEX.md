# v25 幅度面板：固定候选共同后缀诊断协议

事后使用已封存的八根、两臂首层候选和原有 greedy、diverse、response、random 保留集合。再对每臂同一固定候选库，用每根固定种子产生的 24 条随机完整后缀加一条零后缀构造 lookahead 排名；使用相同两项 greedy 保护槽和相同容量。lookahead 选择在共同后缀优化之前写盘并封存。两臂同一根采用相同后缀、相同种子；不使用几何见证。

对库中每个候选分别使用共享逐步动作 CEM 优化 10 步尾部，固定两个重启、每重启 121 个完整链样本、batch 12、精英 4、同根同一随机种子表。各候选的后缀机会相同，保留原候选、每个重启的最优链、分代记录和全部调用；按候选实际数分配独立诊断 token。生成、lookahead 和尾部优化的 token 分开报告。

报告全部库和每种封存保留规则的最好终距、`<0.05` 成功、与全部库最好值的差距；以全部候选没有找到成功尾部为“该有限搜索未找到”，不能解释为不存在可行尾部。中断或失败保留已发生的调用与成本，不补根。

审计逐批动作、预测和 token，验证固定前缀、随机种子表、CEM 提案和所报告最优值，并用另一同环境几何实现核对结果。这是额外费用的固定库开发诊断，不是等总成本方法比较、独立复现或 PC2/PC3 通过证据。
