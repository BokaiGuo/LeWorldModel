# RGB 多帧历史显式组包：开发验证

上游 `JEPA.rollout` 以候选序列前 H 个动作包作为观测时段动作，并覆盖 `info["action"]`；因此只提供历史字段不能保证历史进入预测。新增独立接口接收 H 帧、严格 H−1 个已执行动作包和非空未来动作包，并把历史拼到每条候选之前；保留冻结旧封装和所有已有记录，不修改其依赖哈希。

固定先前真实历史面板的四根、左右各一轨迹，以其 0/5/10 步 RGB、前两个真实五步动作包与第三个未来动作包，比较新接口与先前封存预测。前两个动作必须精确匹配实际历史，每个候选共享该历史；模型与归一化动作集合哈希一致。预测独立于未来真实后继，保存结果及依赖哈希。按 `atol=1e-6, rtol=1e-5` 对逐元素预测比较，并记录最大差。额外用合成双候选检查不能分别替换历史、非法长度拒绝、梯度通路。

这是 RGB-only 开发接口验证，不是新的物理成功率或闭环收益；该接口不自动替换现有规划器。该面板与状态已暴露，未认证所有任务和历史时钟，也不改变 PC0–PC5。历史字段与未来候选均为相同归一化坐标；该接口无权凭零填充猜测历史。
