# v8 搜索诱导名义点：E0 开发协议

假设：v7 固定两条名义动作可能限制实际响应候选覆盖。v8 先在同一预算
内进行短全链 CEM，将所得链的前两个 packet（末轮不足两个时第二个沿用
合法输入 nominal）作为响应计算的两个名义点，再运行相同 v7 搜索。
该提案由目标评分和冻结动力学自动产生，不访问解析见证、物理最优索引
或手工路径；但并非纯响应生成，不能把潜在收益直接归于谱结构。

每次决策先评分全零链（有 carry 时同时评分本臂 carry），选更优者为四结点
CEM 基底，计入 48 个 CEM 样本。然后将最佳链前两个 packet 裁剪至
[-0.95,0.95] 作为 v7 两个 nominal。初始评分、CEM、全部 v7 生成、
筛选、优化和最终同批评分均从同一个 1920 packet-token 上限扣除。
最后对 v7 最终链、预搜索最优链及后者首 packet 清零链同批评分并按
固定次序取最小值（清零链排首处理平分）；不强制非即时动作获胜。
保留全链、实际 float32 动作、预算、所有响应和最终选择。

先在已暴露的 v7 18 根精确动力学任务上运行**单次首次决策**作为新版本
开发实验，逐批复算预测并比较封存的 v7 及多初始化 CEM：
目标距离、`<0.05` 根数、配对胜平负及总 token。根和旧对照已暴露，
该实验不用于独立确认，不根据结果改预算、根或超参；没有足够提升也不
等价于理论无效。同步执行结构合同检查、首轮有无更新及所有完整链入账。
此处不以成功率代替 PC2；无论性能如何，若继续推进机制，须对 v8
精修及最终选择后的同一条链另做预定共同后缀和等预算重规划干预。

仅此开发协议；真实 RGB 和跨架构尚未以该版本验证。记录源文件、原
v7 面板和基线的哈希，任何后续改动另立版本。
