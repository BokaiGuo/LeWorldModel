# 共核 RGB 反馈执行：工程冒烟协议

目标是验证当前共享固定前缀编译核的真实执行与重观测数据流，而非
证明性能。固定此前已曝光的 TwoRoom root 10、11、12，使用同一冻结
LeWM checkpoint 和数据集目标 RGB；初态及成功标签仅由评价端使用。
每次重规划以环境实际渲染的当前 RGB、目标 RGB 和单帧模型的空动作
上下文输入 `RGBLeWM`；不传入物理状态、未来观测或成功标签。

每次生成 3 条 25 步合法、五步常值动作父链，共同 2 条 15 步探针及
2 条 15 步尾部；固定前 10 步，普通 lookahead 保留 1 个前缀。
每次评分 3+6+2=11 条链。执行所选链的前 5 步后，若任务未成功则
重观测：将旧链剩余动作在尾部补合法零动作至 25 步，替换父链第 0 条，
与其余父链、探针及尾部共同评分和竞争。空旧尾与零动作是动作定义，
不假定物理保持；记录每次旧尾和实际选择。

每任务最多执行 25 环境步；环境报告成功或截断时停止并记录。
记录完整选链、实际动作、成功时间、RGB 输入收据、每轮计数与同步
规划耗时。初始化和物理成功只由评价端执行；不能以评价真值反选。
三任务、固定种子、随机生成器、输出和协议均在运行前固定。

这不是标准 benchmark，候选与预算未调优，允许的 CPU/GPU 时间也不是
完整系统成本；无基线、无独立任务、无反事实机制，不能据此判定
Planning Compiler 优势或 PC0–PC5 通过。
