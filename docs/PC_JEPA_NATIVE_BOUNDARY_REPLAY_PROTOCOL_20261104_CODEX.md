# JEPA 原生物理规划边界：确定性重放协议

## 目的与范围

在接入 JEPA v7 真实反馈前，检验能否从已记录的原生 reset 和已执行历史动作重建同一规划边界。此项仅是物理接口与时间对齐诊断，不选择候选、不调用神经网络、不创建新目标，也不估计控制收益。

使用已有 `p5_jepa_factual_nonzero_20261027_v2` 的已暴露种子 2026102701、固定环境配置及前十条公开记录的命令。新进程使用已经存在的隔离依赖目录 `.jepa-physics-site`、未经修改的原生 PushT 源码和原采集器的捕获助手；不得将主环境里的另一个 PushT 后端称为等价。

## 事前固定操作

1. 在独占目录写入协议和来源哈希、每条动作、操作前意图；用原生 env 构造并在 reset 前设置固定 seed。
2. 对 post-reset 帧 0 和原采样 `[0:10]` 的十个物理控制步，记录原生 RGB、状态、proprio、已声明完整公共物理状态和 transition。固定每控制步 10 个 0.01 秒物理子步，reset 自身另有 1 个子步；不从帧 10 的位置速度重置。
3. 将新帧 0–10 与历史同 seed、同配置 a 臂逐文件逐哈希比较，同时重算历史来源封存及实际依赖，任一不一致记录并判定重放未认证；不筛根、不以阈值吸收差异、不自动重试。
4. 用原生 Python call profiler 记录构造、seed、reset、step、render、get_obs、close 和物理子步；比较预定计数，所有动作、时间、状态及失败原因原样保留。规划动作和目标均不在本实验中生成。

公共属性和逐步重放一致不能证明内部接触缓存全部可序列化；真正后续分支必须在相同实时对象上继续，或者先分别重建并逐帧认证边界。历史运行和本次重放均是已暴露开发根，不表示训练外、normalizer 拟合外或 PC gate 通过。若不一致，保留实际差异并停止以该边界开展后续物理对比。
