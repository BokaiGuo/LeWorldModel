# LeWorldModel 研究体系总图

日期：2026-11-04。性质：研究定位、工作分工与文档导航；不是新结果、预注册或 gate 认证。不覆盖历史文档及协议。

## 1. 总问题与共同证据基础

> 世界模型是否保留了支持决策的信息？如果保留了，怎样有效利用；如果不足，怎样识别，并通过独立训练路线修复？

共同基础不再以预测准确单独作为终点，而统一检查：

- 动作—任务传递：动作变化如何影响未来任务结果；
- 行动后果描述：同一组动作在不同状态下分别能产生什么结果；
- 真实控制收益：这些信息是否帮助选择更好的可执行动作。

谱、局部响应、受控图像配对和接触分析都是诊断与验证工具，不各自构成并列方法主线。

## 2. 一套证据基础，两条方法主线

```text
共同证据基础：有限时域动作→任务传递、合法输入、真实后果、来源与成本
    │
    ├─ 冻结模型 Planning Compiler
    │    诊断已有能力 → 编译/组合动作程序 → 公平规划 → RGB闭环
    │    新候选：行动后果描述
    │      受控诊断检验可信性；合法模型查询检验规划效用
    │
    └─ 允许训练的 GDD-OPD
         在学生规划分布上获得训练信号 → 内化决策结构 → teacher-free验证
```

两条方法线不是必须顺序执行的流水线。Planning Compiler 不需要等待 GDD-OPD；训练线也不能因冻结方法出现负结果而自动获得成功结论。

## 3. 分工与边界

| 部分 | 核心问题 | 可共享内容 | 不可借用的证据 |
| --- | --- | --- | --- |
| 有限时域传递与诊断基础 | 哪些动作信息被模型传播、被任务读出，哪里失效？ | 数值检查、接口、环境、记录和评估工具 | 旧传递诊断阳性不能替代 PC2/PC3 |
| 冻结 Planning Compiler | 不更新模型参数，能否从已有动力学发现、组合并利用有效动作程序？ | 合法预训练checkpoint、动作/预测接口、评价工具 | 不得用训练后的 student、特权候选或诊断标签证明 training-free 优势 |
| 行动后果描述 | 冻结模型能否预测哪些动作会变得有效，并用于候选评价？ | 共用探针、最终链测量、成本账本、共同优化器 | 描述可信不等于规划有效；有限探针不等于完整可达集合 |
| GDD-OPD | 受约束后训练能否改善未见动作上的内生决策几何？ | 合法数据schema、环境、基础checkpoint与审计工具 | D2P推理收益不等于蒸馏收益；模型和数据指纹分别维护 |

受控诊断不是第三条方法主线，而是两条主线共享的证据方法。诊断端可以使用受控环境和物理真值；正式冻结规划器只能使用合法观测、目标、历史和模型预测。使用诊断标签训练时，必须进入 GDD-OPD 或其他明确的训练协议；仅用于评价冻结规划器时，标签留在评估端。

## 4. 将新想法嵌入第一篇，而非拆成两篇

第一篇以“冻结模型中的行动后果信息是否可信，以及能否被规划器有效利用”为中心，而非以谱方法优于其他方法为前提。描述路线把“视觉评分诊断”和“重配置发现”连接起来：

1. 用受控外观/几何/控制机会配对，验证什么差异对应真实动作后果。
2. 用合法输入和冻结模型的有限动作查询，构造临时行动后果描述。
3. 检验描述对未查询后缀的预测性，排除仅复述探针结果。
4. 将有效描述用于候选保留或优化分配，和普通lookahead、谱/岭路线及强规划器公平比较。
5. 在最终同链机制、真实闭环和独立泛化中检验价值。

不预先宣称新描述必须胜出，也不删除合法全局库来制造阳性。局部谱方向仍是生成/压缩候选，有限动作后果仍是待验证描述；可以比较、组合或弃用，但各自贡献需隔离。

完整方法、实验矩阵、数据隔离与实施顺序见
[行动后果研究整合规范](PC_ACTION_EFFECT_RESEARCH_INTEGRATION_20261104.md)。

## 5. 统一推进顺序与 gate 边界

统一排序为：

1. **验证信息**：输入、时钟、可解性、评分和动作后果是否可信；
2. **验证利用**：行动后果描述是否比即时距离、局部岭值和普通 lookahead 更有用，先固定优化机会，再比较完整成本；
3. **验证机制**：最终实际选中链是否利用这种变化，并区分“链具有机制”和“组件帮助发现了链”；
4. **验证价值**：冻结候选后完成强基线、真实闭环和独立泛化。

训练路线可以并行开展，但不改变 Planning Compiler 的冻结边界。

- PC0/PC1：接口、可解性、响应与评分可信性；新受控诊断在此提供证据。
- PC2：正式方法自动选中链的非贪心机制；描述变化、库中存在好链或人工见证均不自动通过。
- PC3：独立配对任务、强基线、实际意义、统计与完整成本；不能用组件测试或少数见证替代。
- PC4/PC5：同一冻结核心的合法真实反馈、未见目标、独立checkpoint和另一架构复现。
- 原 ATM/MSE、传递诊断、GDD 及其他历史阶段保留各自合同，不与 PC 编号混用。

每项声明同时登记实现状态、实验执行状态、科学证据状态及对应来源。行动后果描述和保留已有精确动力学开发实现与实验，但尚未建立独立规划优势；冻结视觉描述可信性和同版本真实闭环仍待验证，不是“已经闭环”。原 PC0–PC5 不重编号、不追溯改判；旧 matched-alignment 跨模型预测规划后果的问题仍是独立问题。

## 6. 机制存在与组件发现贡献必须分开

对最终选中的动作链 `Π = B ∘ P`，其中 `B` 是候选的重配置前缀、`P` 是后续进展动作，必须拆开两类实验：

- **Experiment A — Chain Mechanism Test**：在同一物理起点上比较 `B ∘ P` 与时长、动作约束和评估预算匹配的 `B0 ∘ P`。它检验 `B` 是否改变了真实后继控制条件，使 `P` 变得有效；通过的是链本身的机制性质。
- **Experiment B — Discovery Contribution Test**：在固定候选生成预算或候选全集下，比较普通目标评分、局部可达性、ordinary lookahead、action-effect description 及不同 retention 规则。它检验组件是否提高发现有效动作链的概率；通过的是方法的发现贡献。

两者不能互相替代：A 成功而 B 失败，说明环境中存在重配置但组件未显示独立搜索价值；B 成功而 A 失败，说明规划可能更好但不能归因于所声明的重配置机制。PC2/PC3 结论必须保留这两个证据分母。

## 7. Planning Compiler 的最小消融与主张

在强基线加入前，先冻结以下去重后的最小矩阵；同一任务、候选池和优化机会下做组件比较，再做包含全部查询与搜索开销的总成本比较：

| 臂 | 候选生成 | 后续评价 / 保留 |
| --- | --- | --- |
| A | 非谱、预定生成器 | 普通 lookahead |
| B | 谱生成器 | 普通 lookahead |
| C | 与 A 相同 | 行动后果描述 + 机会互补保留 |
| D | 与 B 相同 | 行动后果描述 + 机会互补保留 |
| E | 与 D 相同 | 同样计算描述，但仅按探针最小代价保留 |

A–D 检验谱生成与行动后果利用是否互补；D–E 在同探针下检验机会互补保留相对于最小代价保留的增量，不能单独证明描述本身的独立预测价值。固定候选池实验只隔离评价和保留，端到端实验允许候选不同但必须完整计费。若另设 Full，必须说明其相对 D 新增的组件。普通 lookahead 需事前定义，不能把同一探针最低分换名为新方法。global CEM 保留为合法强对照；零剩余时域直接使用完整链评分，不补造末层后继探针。

第一篇只允许逐项验证以下三类主张：

1. **Information**：模型预测的行动后果与真实后果一致，并能预测未查询动作的质量；
2. **Utilization**：行动后果描述确实改善候选保留、程序组合或优化分配；
3. **Realization**：完整成本下获得真实执行与独立任务收益。

诊断正确、代码完成、单条机制见证、组件增量、总体规划优势和独立复现分别登记，不得合并为一个“通过”。

## 8. 并行开发与联合验收

依赖顺序固定为：**协议与权限固定 → 两条并行开发路径 → 联合验收**。

- **精确动力学路径**：先验证描述与保留算法是否有作用，排除视觉误差；
- **冻结视觉路径**：并行验证受控变化、预测后果与真实物理结果是否一致；
- **联合阶段**：将同一候选接入 RGB 反馈，完成最终链机制、公平规划和完整成本比较。

诊断不成为新的全局阻塞；但描述可信性未建立前，不得宣称视觉规划机制成立。

## 9. 当前工作顺序

1. 统一数据权限、动作时钟、来源与成本口径；修正已确认的报告/审计问题，不改旧结果。
2. 在精确动力学上验证行动后果描述及同探针lookahead对照；先隔离信息作用，再做总成本比较。
3. 并行开展冻结视觉模型的受控动态配对，区分评分、预测和搜索误差。
   已有 v11/v12 及 v22 同动作视觉后验诊断；单根、有限物体变化、相关动作及特权见证限制，以及后续诊断的运行前合同，见[行动后果整合规范第 4.1 节](PC_ACTION_EFFECT_RESEARCH_INTEGRATION_20261104.md#41-既有视觉结果与下一次诊断的边界2026-11-05)。不得将旧模型版本或特权候选拼成同版本闭环证据。
4. 仅在开发证据支持后冻结候选，完成 PC2 及 PC3–PC5 确认。
5. 若必须训练新度量或表示，转入单独的 GDD/训练协议，不暗中改变第一篇边界。

若仅诊断成立，交付诊断性结论；若仅普通lookahead有效，按真实机制归因；若整体不满足优势要求，交付有界负结论。研究执行完成与全部 gate 通过是不同终点。

## 10. 最小端到端交付物

以下是后续实现的建议交付物，不表示文件已存在或实验已通过：

1. `action_effect_protocol.yaml`：输入、输出、probe bank、权限与成本边界；
2. `effect_descriptor.py` 及测试：冻结模型描述计算，不训练新 readout；
3. `controlled_effect_audit.json`：受控外观/物理/控制机会对照；
4. `effect_retention_ablation.json`：候选保留与 ordinary lookahead 消融；
5. `chain_intervention_episodes.jsonl`：最终链真实干预；
6. `planning_comparison.json`：预算匹配的独立规划比较；
7. `pc_gate_evidence.json`：按 PC0–PC5 汇总的证据索引。

受控诊断可以使用物理状态、接触位置、真实后继和任务标签作为评估真值；正式冻结规划器不得读取这些字段。若训练 readout、encoder、predictor 或 adapter，必须进入 GDD-OPD 或另立训练协议。

## 12. 最终交付结构

- 第一篇：可信的控制相关信息如何被冻结模型规划器利用，组织为“可信性 → 预测性 → 规划效用 → 真实闭环与泛化”；
- 第二篇：缺失或失真的决策结构如何通过 GDD-OPD 训练内化，并在独立动作上验证；
- 两篇共享评估工具和合法基础资产，但分别维护模型、数据、预算、来源和证据账本。

诊断正确、代码完成、机制见证、性能优势和独立复现必须分别登记，不能合并成一个“通过”。
