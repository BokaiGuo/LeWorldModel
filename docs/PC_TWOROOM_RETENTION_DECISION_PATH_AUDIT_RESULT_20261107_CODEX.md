# TwoRoom 描述保留到实际动作的路径：事后审计

按[审计协议](PC_TWOROOM_RETENTION_DECISION_PATH_AUDIT_PROTOCOL_20261107_CODEX.md)，重建了已曝光的 40 个 TwoRoom 根、四臂反馈记录中的程序选择。审计不是新实验，也没有把同一任务的多次重规划当作独立样本。

当前实现每个前缀只有两个探针，且使用行中心化代价；每个描述形如 `(x, -x)`，因此最多一维。它不等同于研究方案中明确的“同长度合法 hold 相对每个探针”的完整后果向量。行内独立置换的 shuffled 臂也不等于跨 root 打乱。两者是该具体实现的限制，不能借此否定其他描述。

代码中所有父链和探针链可直接参与最终选择；保留集合只决定额外尾部链。这是已声明的选择结构，不自动构成实现错误。vector 臂的 133 次程序决策中，29 次选额外尾部，104 次选父链或探针；另有 22 次最后一包共同直接搜索。保留信息因而并非每轮都能影响最终动作。

以 root、轮次、RGB/目标/历史收据、旧尾指纹、候选种子、时钟和共同候选指纹配对 vector 与 lookahead：

| 事后共同输入比较 | 决策次数 |
| --- | ---: |
| 可配对程序决策 | 117 |
| 保留集合不同 | 61 |
| 保留集合不同时，完整选择链不同 | 11 |
| 保留集合不同时，实际派发首包不同 | 8 |

保存的共同评分完全相同；各程序选择和保留索引均可按记录重算。不同轨迹造成的后续状态变化没有被视为共同输入比较。上述计数显示描述规则有时参与了决策，但不能证明这些变化有益、无益或解释最终成功；也不能由 8 次动作变化推断未来更丰富描述的上限。

实现路径及数据见[审计脚本](../le-wm-main/experiments/pc_tworoom_retention_decision_path_audit_20261107_codex.py)和[机器结果](../le-wm-main/results/pc_tworoom_retention_decision_path_audit_20261107_codex.json)。新增定向测试 1 项通过。后续如比较新描述，应先在合法共同候选及相同预算下单独验证 hold 定义、未查询动作预测和是否改变真实执行，不能把这次后验观察当预注册收益。PC0–PC5 不改判。
