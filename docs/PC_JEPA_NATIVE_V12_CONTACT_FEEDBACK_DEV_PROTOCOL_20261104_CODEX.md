# v12 native PushT contact-goal feedback: development protocol

Use the already generated and replayed evaluator-only witness from
`pc_jepa_native_contact_witness_dev_20261104_codex`. The observed witness
object movement is known before this protocol, so this is an exposed
development task, not a prospective benchmark or independent confirmation.
Check its manifest, dependency hashes, `summary.json`, witness hash, original
fixed root and exact physical replay before planning. The witnessed target
must fail the usual success rule at the warm boundary and be attained by the
recorded 15 legal actions. Do not search for or replace the target.

Run the same v12 compiler and zero/carry CEM comparison as the preceding
v12 feasible-feedback experiment, each once from an identical new reset and
warmup at the witness root. Three decisions have 15/10/5-step remaining
horizons and 1920 prediction tokens; dispatch five steps per decision. Retain
all failures. Witness actions and privileged goal state stay outside the
isolated planner; only the witness final RGB is passed as target. Output
physical metrics solely through the evaluator, and record whether the object
actually moved, not merely latent score.

Audit exact input-history, carry and dispatch binding, actual token counts,
pre-pair incumbent versus final pair, witness and source hashes, physical
metrics, and same-backend physical replay. Report encoding, planning and
other available costs separately; token matching alone is not equal compute.
Stop after the two fixed arms, without retries or adaptation on this goal.
Neither a witness nor a single pair is evidence of PC2 mechanism, PC3
planning advantage, generalization, or independent replication.
