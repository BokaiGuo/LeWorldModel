# RGB 单帧共享编码缓存：开发验证

新增的实验性 `CachedJEPA` 在冻结模型、单帧 RGB、`torch.inference_mode()` 下复用当前帧及目标帧编码；输入内容、形状、类型或设备改变时重新编码。它通过已有 `SingleFrameRGB` 包装器接受动作合法性和 RGB 输入合同检查，不缓存动作或预测后继，也不支持历史帧、可微动作优化或其他模型。历史运行器及历史结果未修改。

按[预先固定的协议](PC_RGB_SHARED_ENCODER_CACHE_PROTOCOL_20261107_CODEX.md)，对四个已曝光任务、每个任务五条封存合法动作、1–5 个动作包共 **20 组**运行冻结模型 GPU 对照：

- 原始与缓存实现的预测序列和末帧评分均满足预定 `rtol=1e-5, atol=1e-3` 容差；最大表示绝对差 `1.20e-6`，最大评分绝对差 `1.22e-4`。
- 20/20 组的完整五候选排序和最终选中索引一致；这不是逐位相等，也不认证近并列或其他候选。
- 4 个观测对合计发生 8 次编码；任务图像改变时重新编码。单元测试检查相同输入复用、当前图及目标图变更失效、拒绝非 inference 模式；连同原单帧合同测试共 **12 项通过**。

重复相同观测和相同五候选时，各组 30 次同步测量的中位数：单包原版约 5.6–5.7 ms、缓存约 2.7–2.8 ms；五包原版约 9.6–10.0 ms、缓存约 7.0–7.1 ms。各组中位数比值约 **1.36–2.09 倍**，仅描述这次顺序执行的热缓存微基准；包含包装器权限与收据开销，但不包含缓存首次建立、模型加载、环境交互或完整任务，也不能外推到其他批量、设备或冷启动。

这是**共享工程优化**，基线与方法都应获得相同缓存权限；不证明行动后果描述有效、Planning Compiler 更优或总任务成本下降。由于仅验证四个已曝光任务及固定五候选，也尚不能直接将该代理接入正式评估。后续需要在真实反馈过程覆盖观测变化、近并列排序和完整成本，并维持原结果及冻结输入权限。PC0–PC5 未改判。
