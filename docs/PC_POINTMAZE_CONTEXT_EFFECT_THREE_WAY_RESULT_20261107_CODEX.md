# PointMaze 预测、真实编码与物理后果分解

## 范围和方法

复用已曝光的 8 个任务及每个任务固定的 8 条合法动作链。按
[预先封存的协议](PC_POINTMAZE_CONTEXT_EFFECT_THREE_WAY_PROTOCOL_20261107_CODEX.md)，先复算并封存两个上下文窗口的模型预测，再从已保存的物理初态和末态重渲染，最后编码真实末态并对比物理末距。真实后继编码仅是评价端 oracle，未用于规划。

这里使用当前与目标的完整 proprio，属于 **state-assisted**，不是 RGB-only。任务 1886 和 1888 初态已经位于成功半径内；仍保留在全部统计中。每任务 28 对候选共享初态，不能当作独立任务。

## 核验与结果

- 128 个预测分数与前一实验封存分数复算差异均为 0；初态重渲染与规划输入的最大像素差和平均像素差在 8 根上均为 0。
- 末态图像由已保存的状态重建，不是执行当时录制的帧；初态图像一致及渲染前后物理状态不变，并不能证明末态现场图像或未记录的仿真隐状态完全等价。
- 以下为先计算每任务排序一致率、再对 8 任务取平均；所有任务均为 28 对。

| 比较 | 窗口 1 | 窗口 2 |
| --- | ---: | ---: |
| 预测代价与真实编码代价排序一致率 | 0.696 | 0.629 |
| 预测代价与物理末距排序一致率 | 0.683 | 0.652 |
| 预测与真实视觉表示均方误差 | 0.6533 | 0.6474 |
| 预测与真实 proprio 表示均方误差 | 0.00677 | 0.00659 |

真实编码代价与物理末距的平均排序一致率为 **0.763**；若在每个固定候选池上使用不可部署的真实编码 oracle 选链，其平均物理末距遗憾为 **0.0484**。例如任务 1890 的 oracle 遗憾为 0.2776，表明真实编码评分亦非物理末距的完美替代。这是末距而非完整任务成功规则的比较。

两个窗口的视觉误差和排序指标不能直接与其他实验中使用不同聚合和预测时刻的数值混为一谈。窗口 2 的平均表示 MSE 略低，但本池内排序一致率没有改善；两者衡量不同性质，不能据此判定窗口 2 提升规划。

## 解释及边界

该面板同时观察到预测代价相对真实编码的排序失配，以及真实编码代价相对物理末距的排序失配。现象不能唯一归因于模型动力学、目标评分或某个代码错误：末态图像为重渲染，输入域与未记录状态仍有边界；而且真实编码与物理末距的差异也不等价于正式成功评分错误。

没有验证视角变化下的闭环改进，也没有出现新方法的开发优势；这不是独立确认，不改变 PC0–PC5 的判定。继续保持视觉主轨与 state-assisted 证据分离。
