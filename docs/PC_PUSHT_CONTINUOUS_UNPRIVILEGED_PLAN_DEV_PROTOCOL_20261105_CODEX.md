# PushT 连续 warmup、无参考动作规划：开发协议

## 问题与权限

上轮参考条件化库两根均有成功候选，但不说明合法搜索能够发现。本实验在相同两个已筛选开发目标上，以合法 RGB 目标、连续 warmup 的三帧 RGB/proprio 和历史动作包为输入，比较已有 v22 response 与多起点 CEM 单次开环决策。两根已经暴露，不能视作独立确认。

预测 worker 仅可见冻结模型及当前输入目录；输入严格为 `context.npz`（RGB、目标、归一化 proprio、历史动作、动作统计、空 carry）、`config.json` 和模型 metadata。参考后缀、真实状态、候选标签、历史评分结果不得进入；复用已有 bwrap 隔离及 worker 的禁见源检查。动作的初始状态与 warmup 使用评价端记录；正式规划仅接收历史和目标图像。

## 算法、预算、输出

两序列 9、11 × 两臂 `response`、`cem`，共四次独立 worker；使用同一个已有 v22 worker、配置、评分与候选域，每臂 token cap 1920，记录实际预测 token、调用数、编码与同步后规划墙钟；token 相同不等于完整系统成本相同。随机种子和配置由现有 worker 固定；两个目标不是独立统计确认。所有输入在执行前写入并校验哈希，每条最终链及 worker 全量评分轨迹保留。若 worker 失败如实记录，不更换算法或种子。

规划完成、封存决策哈希后，在物理环境从初始帧连续执行十步 warmup，确认 RGB/状态与来源一致，执行最终选中的完整 15 步链；每步保存动作、状态、RGB 和中心是否超出 `[40,472]`。目标由既有目标图像提供，评价端使用记录目标物理状态。计算联合位置误差、物体位置误差、周期角误差和 `joint < 20 && angle < π/9` 的成功。不得在观察物理结果后替换候选、改变预算或重选目标。

此面板是开环开发诊断，不是 RGB 闭环、同版本新核心机制、强基线调优、完整成本或独立确认；任何算法获胜都不能据此宣告 PC0–PC5 通过。参考后缀作为可达性见证只在评价端，不得作为规划热启动或候选。
