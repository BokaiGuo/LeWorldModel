# JEPA 原生 PushT v7：单根真实反馈开发结果

按[事前协议](PC_JEPA_NATIVE_V7_FEEDBACK_DEV_PROTOCOL_20261104_CODEX.md)，在同一个已暴露 seed、原生 PushT 后端和固定目标上，v7 response 与 warm-start CEM 各完成三轮真实反馈；每轮封存完整规划链后执行前五条命令，再使用本臂实际 RGB、agent 位置与速度和动作历史重新规划。规划进程使用隔离输入、冻结 JEPA 权重和相同 v7 核心；这不是 RGB-only。

| 评价时刻 | 臂 | agent 位置误差 | 物体位置误差 | 角度误差（弧度） | 官方 wrapper 条件成功 |
|---|---|---:|---:|---:|---|
| 暖身后 | 两臂相同 | 60.2413 | 126.0126 | 2.9163 | 否 |
| 第 15 个决策动作后 | response | 9.8210 | 136.4401 | 2.8918 | 否 |
| 第 15 个决策动作后 | CEM | 13.0265 | 127.5667 | 3.0853 | 否 |

两臂均未达到预定成功条件。response 的 agent 更接近目标，但其物体位置误差比 CEM 高；单根上不能由此断言总体方法优劣。目标是第二个固定随机生成状态，未证明在 15 步或规定动作域中可解；目标 RGB 包含 agent 和物体，视觉 MSE 可能受 agent 主导，但本结果本身不能证明导致失败的唯一原因。两臂训练来源及 normalizer 拟合范围仍未知。

response 三轮使用 1920/1919/1920 prediction-token；CEM 为 1920/1920/1920。CEM 后两轮在共同评分后，分别从本臂的 zero 和 carry 近等分样本搜索。两臂 token 相同不代表总计算资源相同；完整时间、模型调用和每批轨迹均保存在原始决策中。

## 执行与审计

- [汇总](../le-wm-main/results/pc_jepa_native_v7_feedback_dev_20261104_codex/summary.json)及同目录每臂所有边界、原始帧、动作、六份完整决策和模型评分。
- [保存数据审计](../le-wm-main/results/pc_jepa_native_v7_feedback_dev_20261104_codex/audit.json)：核验 warmup、三帧与动作历史、carry、所选链确实被评分、计数、决策封存、实际派发及物理指标；不独立重算神经网络预测。额外检查六轮所选分数都等于各自全部已评分完整链的最低分。
- [同后端物理重放](../le-wm-main/results/pc_jepa_native_v7_feedback_dev_20261104_codex/physical_replay.json)：重新构造两臂并重放各 25 条命令，52 个边界的 RGB、状态、proprio、声明公共状态和 transition 均一致；这不是独立物理后端或私有接触缓存认证。
- 三个工作进程文件在 `le-wm-main/experiments/pc_jepa_native_feedback_{dev,launch,worker}_20261104_codex.py`；审计及重放脚本同名前缀。所有新结果独占创建，没有覆盖旧结果。

审计初次将源元数据文件哈希与重新序列化后的 JSON 文件哈希直接比较而报错；二者编码格式不同。审计修正为分别核验源文件哈希、worker 使用的实际文件哈希以及解析内容相等后通过。该问题位于审计比较，不改变已保存的规划输入或物理动作；没有因此重跑或修改结果。

本结果首次把该 JEPA 适配与 v7 连接到同任务的多轮原生物理反馈，但不能拼接 LeWM 的其他根宣称跨架构独立优势，也没有建立接触重配置机制、完整计算公平、来源合格面板或 PC0–PC5 通过。下一步优先进行同动作模型—物理响应及目标评分归因，确认任务可解性与目标图像因子，再决定是否另立开发协议；不得围绕此根无限调参。
