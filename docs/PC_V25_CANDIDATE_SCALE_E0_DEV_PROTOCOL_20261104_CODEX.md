# v25 候选幅度消融：E0 开发协议

在启动前固定八个 exact-Wall 任务：起点 `(-0.5, ±0.155, ±1.17)`，目标 `(0.5, ±0.11)`。与程序中列举的既有开发面板进行精确去重；更广范围的来源独立性未知。不得替换失败根。

两臂使用同一 v25 核心、nominal、种子、2 个谱模态、动作约束、递归深度、全局候选和优化器；仅候选幅度不同：

- `original`：`(0.25, 0.5)`；
- `smaller`：`(0.125, 0.25)`。

每臂总预测 token 上限均为 1920。实际候选数量、后继探针和精修样本可以因动力学响应而不同；报告实际花费与残余预算，不宣称每个组件内部开销完全相等。保留共同优化器、完整链 incumbent 和成对弃权。该消融不实施响应失效检测或自适应回退，也不单独消除幅度与候选覆盖的混杂。

每个预测请求在调用前逐批记录，保留异常及失败分母。报告各根选中链最终距离、既定 `<0.05` 成功、paired 差值、预测 token、精修样本、后继探针数、SVD 调用和含日志墙钟时间。审计每次动作与预测、完整链最优、初始全局候选及同环境另一实现的轨迹一致性。

这是工程开发实验，不是 PC1、PC2 或 PC3 确认；不依据该面板修改通过阈值，也不把 `0/8` 预设为代码错误或理论失败。物理响应、视觉费用、独立来源和充分调优仍需另行验证。
