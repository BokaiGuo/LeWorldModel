## 任务 20：从候选到选择再到重规划

普通臂初次规划的完整池有 159 条成功链。全池最低模型代价链来自
第 9 轮查询批次（call 17、slot 74），模型代价 2.1149，第 20 步
成功，第 25 步仍满足环境成功条件。求解器最终按两个分支均值的
代价选择均值链（call 19、slot 0，代价 2.2088），该链整个首个
25 步未成功；另一个均值也未成功。这是一个事后物理见证：当前
最终均值规则没有保留模型自己最偏好的成功样本。它不证明改成
样本最优在其他任务上更好；已有选择消融显示此规则也可能退化。

同一个任务、同一目标下，成功样本与选中失败均值的真实末帧编码
代价分别为 7.1742 和 7.0688，即真实末帧编码反而略偏好失败链。
这不是单凭预测误差即可解决的例子；但它只是一个配对，不能推断
整体视觉评分失配率。目标编码一致误差平方和约 `1.73e-11`，
初始预测与重渲染实际表示差异平方和约 0.3623；前提中的初态
图像差异仍需考虑。

该任务首计划完整执行 25 步后，原策略用新观测独立重规划，第 26
环境步成功；第 25 步后状态与第 26 步前状态一致。配置是
`horizon=5, receding_horizon=5, action_block=5`，旧计划已全部
执行，因此第二次 solver 的 `warm_start` 为 null，**不存在旧尾
被替换**。上述事实不能证明重规划优于其他合法续接策略。
全 50 任务中两臂均有 13 个任务进入第二次规划，记录中均无 warm
start；不代表其他 receding-horizon 配置也如此。

## 初始画面差异定位

数据首帧输入与模型采集输入完全一致；用数据状态做环境 `_set_state`
时，该实现额外执行 `space.step(dt)`。任务 0 的 agent 坐标最大变化
约 1.4608 环境单位。诊断性直接设置身体状态且刷新 Pymunk 形状索引
后，状态差异为 0，像素平均绝对误差从原生 `_set_state` 的 0.5948
降到 0.5129（0–255 标度）。直接设置但不刷新索引的误差为 6.3762，
说明不能简单绕过物理步而忽略缓存。

另将重渲染图像做不同质量 JPEG 往返，某些质量降低了残余像素误差；
这只能提示图像编码可能贡献残差，**不能认证数据的编码来源**。
这些消融只用于定位：没有更改正式 reset 或先前物理结果，也没有
证明无步进状态恢复保持隐藏动力学一致。首次像素归因写 JSON 时
出现不可序列化的 `numpy.uint8`，产生了不完整旧输出；修正后
使用独立 v2 路径，旧文件被保留且不可作为结果。

已记录；代表链按物理结果事后选择，仅供诊断。两次批量启动时 CUDA

存在且通过各自物理状态、目标编码、模型指纹核验。
