# TwoRoom 真实候选的带历史联合精修：开发协议

目的：验证带历史 rollout 能否用于程序精修，并观察模型内改进是否兑现
为物理效果；这不是行动后果描述或端到端方法的增量实验。

固定已曝光任务 10、11、38、39，起点为已有质量约束实验的普通
lookahead 实际选中链。原始 25 步动作须是 5 个恒定动作包、逐值合法；
规划端只使用 RGB、目标 RGB、动作及冻结 LeWM。评价端使用物理状态复位。

对同一初始链比较：

1. 不精修，保留原链。
2. 完整 rollout，联合优化五个动作包。
3. 前两个包与后三个包通过带历史接口组合，联合优化全部动作包。
4. 相同分段 rollout，但冻结前两个动作包，仅优化后三个包。

各精修臂使用原始动作坐标的 Adam，学习率 0.05、8 次梯度更新，每次
投影到 `[-1,1]`；包括原链在内，最终选择该臂所有已评分迭代中的
模型最低分链。目标是末时刻 latent 平方距离，不能当作物理成功。
三个精修臂均使用已有 math SDPA、禁用 TF32 导数后端；分段每轮两个
rollout，整链每轮一个，记录前向、反向和同步耗时。基线无梯度开销；
这不是同计算预算比较。保留原链作为安全候选不保证真实结果不退化。

先封存四臂动作、逐轮分数和输入／源码指纹，再由独立阶段读物理状态、
完整重放 25 步并记录曾成功、末步成功、距离和终止；每臂同一原初态。
模型与仿真在不同命令阶段，但不是 OS 沙箱；数据来源和任务均已曝光。

事前判断：若整链和分段联合精修的梯度、动作和最终选择不稳定一致，
禁止将分段实现视为等价；如果模型分数改善却真实成功无改善或退化，
不扩大这一配置。成功率分母为 4 个任务，不将候选或迭代当独立样本。
本试验不作为 PC0–PC5 或独立确认。
