# V4 固定候选配对保留质量：开发诊断

按[事前协议](PC_V4_PAIRED_RETENTION_QUALITY_PROTOCOL_20261104_CODEX.md)，24 个已暴露 E0 根、每根九个相同候选、每候选三个共同随机流及每次 120 条链；实际 77,760 条链。两种保留集合来自封存计划，未按此次结果更改；逐批动作、预测与评分在同一精确动力学实现上重算通过。源计划、协议和声明的依赖哈希已核验。

| 集合 | 每根三次平均终距的均值 | 中位数 | 根均值 < 0.05 |
| --- | ---: | ---: | ---: |
| V4 局部价值＋响应多样性 | 0.501427 | 0.501418 | 0/24 |
| 即时最佳＋位置多样性 | 0.408083 | 0.501160 | 0/24 |
| 九候选 oracle（仅诊断） | 0.407073 | 0.500536 | 0/24 |
| 同库即时 greedy | 0.506933 | 0.504589 | 0/24 |

按每根三次平均比较，V4 保留集合 12 胜、3 平、9 负；位置保留的均值优势来自少数根上较大差异，并非多数根都有大幅改善。单次随机重复中位置保留有 6/72 次低于 0.05，分布于四个根；V4 为 0/72。72 次不是 72 个独立任务，也不表示根均值成功。

该诊断排除了同一候选在两策略中获得不同 CEM 随机流这一混杂：位置保留集合在此零尾搜索协议下确实包含一些更易优化的候选。它不证明响应多样性本身无效：两套规则的价值评分和多样性定义同时变化；也不能归因原完整闭环差距，因为原方法使用不同初始化、预算分配、联合精修与反馈。离线搜索九个候选的成本不能当作部署四候选的成本。结果不构成 PC2 或 PC3 通过。

运行：在 `le-wm-main` 中执行 `.venv/bin/python -m experiments.pc_v4_paired_retention_quality_20261104_codex run`，随后以 `audit` 代替 `run`；输出使用排他写入，已有产物不能覆盖。数据和审计位于 `results/pc_v4_paired_retention_quality_20261104_codex_{plans,audit}.json`。
