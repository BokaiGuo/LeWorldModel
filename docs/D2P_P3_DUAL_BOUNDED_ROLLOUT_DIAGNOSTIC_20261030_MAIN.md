## 动作坐标与预测误差的进一步核查

源码显示，H1 Jacobian 在零点对 **raw float32 动作**求导；
`bounded_ridge` 对其返回的十维参数直接计算 `J @ params` 的
线性目标及 ridge penalty；但 `suffix_raw` 先对参数逐项 `tanh`
再转 float32，模型 rollout 接收的是这个变换后的 raw 动作。
两种坐标在零点的一阶导数一致，但有限幅度下并不相同。它属于
当前方法定义中的线性近似／动作图表差异，不能仅凭静态检查
断言为实现错误；要作为动作优化修正，须另开合同。

针对日志 49891 的 zero 和候选 6，直接使用保存的 Jacobian、
nominal、求解参数、实际后缀及 rollout 终点计算，结果为：

| 项目 | zero | 候选 6 |
| --- | ---: | ---: |
| `||params||` | 1.67705 | 1.67705 |
| `||params - raw||` | 0.25025 | 0.38199 |
| `mean((J @ (params - raw))²)` | 0.000340 | 0.001401 |
| `mean((nominal + J @ raw - rollout)²)` | 0.012760 | 0.006322 |
| `mean((nominal + J @ params - rollout)²)` | 0.015818 | 0.011340 |
| ridge penalty | 0.0000293 | 0.0000293 |

保存的 raw 与 `tanh(params)` 最大绝对偏差分别小于 `3e-8`。
这些数值显示两种参数坐标确实不同，且即使把实际 raw 用于
线性预测，模型 rollout 仍存在明显向量误差；不能把排序反转
单独归因于 tanh、正则项或代码错误。上述向量 MSE 不是目标
代价差，不能相加解释排序反转。这里没有新 CUDA 推理、真实
执行或独立实现复现，仍不能由此改变旧实验的资格判定。

## 同一目标上的成本分解

从相同日志中当前 slot 的首个 native task 读取目标 latent，并对
日志 49891 的 H1 控制及候选 6 重算同一均方目标代价。完整日志
SHA 与上面记录一致；保存的线性参数代价、rollout 代价均逐值
复算一致。两条记录的 ridge penalty 相同（约 `0.0000293`），
因此该例的原 reach 排序不由正则项差异造成。

| 同一目标的代价 | zero | 候选 6 | 候选减 zero |
| --- | ---: | ---: | ---: |
| 线性预测 `nominal + J @ params` | 0.82401726 | 0.81664758 | -0.00736967 |
| 线性预测 `nominal + J @ raw` | 0.82793605 | 0.82438050 | -0.00355555 |
| 保存的真实模型 rollout | 0.78948797 | 0.82523663 | +0.03574866 |

将线性预测中的动作替换为实际 raw 后，候选的预测优势缩小，
但仍未反转；排序反转是在比较模型非线性 rollout 时出现。
这分离了本例图表变换与有限幅度模型响应的影响，并不证明二者
以外的代码接线正确，也不等同真实环境 rollout。不得把这一个
已知根上的事后分解作为修正有效或 P3/P1 通过的证据。
