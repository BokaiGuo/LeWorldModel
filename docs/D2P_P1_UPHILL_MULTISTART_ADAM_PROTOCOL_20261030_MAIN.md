# P1 新前缀：真实 RGB 的共同多起点后缀规划

在观察零初始化与共享原后缀暖初始化结果之后，固定对已有的
24 个 selected、zero、greedy 前缀进行开发对照。输入必须为
`p1_uphill_cp5_bundle_20261030_RUN01.json`，SHA-256
`376bb8276e1544010ea2767d9c46f141c2665e223154a12b2e6c28786636676a`。
每个前缀使用各自真实 cp5 RGB 和动作历史，使用同一冻结模型、
同一初始动作生成规则：每个 logical pair 一个固定随机种子，
四个起点包含全零与三个均匀随机 raw 动作；三种角色使用同一组
起点。每起点 Adam 更新 20 次、学习率 0.05，在模型目标分数上
按最小值及固定索引 tie-break 选后缀。所有 24 个输入必须参与，
不得用物理结果选择角色或起点。

本轮仅作主机 CUDA 模型规划并保存全部起点分数和选定动作；
下一步须逐条绑定新前缀并物理执行才可比较真实收益。不同于
前期单起点，四起点额外消耗必须分类记账，不能称全流程等预算。
已知根、重复臂和模型分数不能支持 P1 或独立确认；不得用模拟器
物理真值选择候选。代码未建立操作系统级文件隔离。
