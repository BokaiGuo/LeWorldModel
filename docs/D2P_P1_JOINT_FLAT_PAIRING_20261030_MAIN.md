# P1 十步共同后缀与独立规划：配对表合同

此合同只适用于正在运行的旧 joint-selected 面板，不是模型内重选
成功前缀的干预。它使用既有固定名单，属于已知根的开发性分析。
不改变原实验准入规则，也不在观察结果后新增通过阈值。

完整面板封存后，使用 `p1_joint_flat_pairing_20261030` 重新执行现有
全量来源和物理保存态验收，然后按根、条件、臂、前缀与共同后缀
输出 1008 条 CSV。每行包括：

- 前缀前后物体位置、包角、推杆、原生联合 XY 和原生角度项，
  以及原生成功状态；每项单独报告，不把物体不动等同于任务无进展。
- 共同十步后缀的绝对终点、相对本前缀零后缀的变化，以及相对
  zero 前缀的同动作终点差；仅说明该后缀的效果。
- 各前缀真实 cp5 RGB 条件下，各自以相同优化器、20 次梯度更新
  生成十步后缀的物理终点、相对前缀的变化及相对 zero 前缀的
  独立规划终点差。数值重复出现在多个共同后缀行，但独立规划
  只有 24 条观测，重复臂与共享根也不是独立任务。
- 两种后缀的状态及实际返回步数；提前停止或删失的完整时域终点
  为 null，不填充最后状态。原生成功单独记录，不由单个误差推导。

独立后缀的优化迭代数相同不等于整个方法等预算：前缀生成、
结构计算、编码、预测、反向和墙钟时间需另行分类记录；缺失的
账本不能推定为零。后续性能对照须预先固定统一资源限制，让各基线
可使用 D2P 的结构开销对应预算，报告实际用量和预算曲线，不将
不同类型调用未经约定相加，也不要求浪费计算凑齐调用数。

完整报告 `run_report.json` 出现且状态为 `recorded_not_consumed` 后，
独立计算其 SHA-256，再从 `le-wm-main` 运行：

```bash
.venv/bin/python -B -m experiments.spectral_reachability.p1_joint_flat_pairing_20261030 \
  --directory /home/gbk/code/LeWorldModel/le-wm-main/results/p1_joint_h10_20261030_run_RUN01 \
  --report-sha256 ACTUAL_REPORT_SHA256 \
  --output /home/gbk/code/LeWorldModel/le-wm-main/results/p1_joint_flat_pairing_20261030_RUN01.csv
```

不要消费部分面板。此表不证明 P1 通过、独立泛化或公平强基线优势。
