# JEPA PushT 上的 v7 单根模型内规划

按[开发协议](PC_JEPA_PUSHT_V7_PLANNING_DEV_PROTOCOL_20261104_CODEX.md)，将同一个 v7 响应程序核心与四结点 smooth CEM 接到冻结 JEPA PushT 及显式历史动作 rollout。使用已暴露 episode 1 的前三帧和本体输入，帧 25 作为预先指定的目标图像；没有执行动作。

**事后发现的协议偏差：** 复用的 `v5.row_inputs` 为核验旧封存，在规划过程启动前读入并核对帧 15 以及真实动作 `[10:15]`；`v5.read_arrays` 也载入完整轨迹数组。这违反了本协议关于规划器不得读取真实未来动作的严格信息隔离要求。源码中模型上下文仅使用前三帧、前两段 packet，候选生成和评分回调未引用这些额外数据，但同进程内数据已经可访问，不能据此证明无泄漏。此结果降级为**信息隔离不合格的工程接线诊断**，不得作为合法输入下的规划证据；修复需另立协议、在规划进程以外准备最小历史输入并隔离未来数据，而不是覆写本结果。

[原始动作和评分](../le-wm-main/results/pc_jepa_pusht_v7_planning_dev_20261104_codex.json) SHA-256 为 `10a8cfa21c7821cd97b69cfd2c1078c9a0534c706f8251f1276dc9f88a154466`。非神经[计数和选择审计](../le-wm-main/results/pc_jepa_pusht_v7_planning_audit_20261104_codex.json)重算所有请求、完整链、最终选择及 v7 最终配对评分；同 checkpoint 的[全部请求重放](../le-wm-main/results/pc_jepa_pusht_v7_planning_replay_20261104_codex.json)覆盖两臂 1,377 条轨迹，两个输出的评分及二维 chart 与保存值最大误差均为 0。该重放复用同一实现和设备，不是独立实现、独立模型或物理重放。

**限制。** 除上述信息隔离偏差外，目标来自同一已暴露数据轨迹，规划输入包含离线真值 agent 位置和速度；不是 RGB-only，也不是合法性与来源均已认证的闭环。动作盒 `[-1,1]` 是本协议指定的开发边界，未证明等同完整物理动作域。未重新执行实际环境、完成位置／姿态成功评估或同权限强基线确认，也未检验最终链 PC2 机制。故此结果只证明 v7 核心在该 JEPA 模型接口上实际运行及同实现请求可重放，不通过 PC2、PC3、PC4 或 PC5。
