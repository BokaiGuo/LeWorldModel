# Prefix-null v2 exploratory deployment

V2 is a separate code and prepare seal; it leaves v1 untouched. It reconstructs
the source-bound v1 material, fixes all eight historical plans with both
selected and zero prefixes in the original order, and checks exact suffix
bytes. The existing action, canvas, operation, wall and storage thresholds
remain unchanged. Known-root, post-outcome exploration is not P1 admission,
fresh-root confirmation, an independent task count, or equal-budget evidence.

The preparation binds the v1 prepare, original source material, v2 runner,
v2 consumer, v2 tests and this design. Every execution and saved consumption
rebuilds and rechecks that seal; source or code drift fails closed. No external
signature or additional authorization token is required. The run uses an
exclusive output directory and the existing metered native adapter; its
consumer applies the saved journal, attempt/return, source, RGB, action, cp5,
state and censoring checks. Engineering failures retain the 16-row roster and
remain blocked; a crash that prevents a complete journal or report cannot be
treated as a completed observation.

Tests use synthetic environments and historical saved-format fixtures only;
they do not establish real physical outcomes or prove hidden state. Before
executing, the main thread should review the seal and test results, ensure the
real runtime is available and isolated, confirm output and free-space admission,
and avoid resource interference with other work. The full fixed roster is run,
not a subset selected on outcomes. This task does not start physical execution.
