# RGB-position feedback with actual action history: fixed-tail diagnostic

Use the completed `a1_pointmaze_rgb_causal_velocity_20261103_DEV01` and its
sealed source. Each of four exposed roots has two previously selected
prefixes; for each prefix, all three feedback arms share actual RGB frames
cp0 through cp5 and executed prefix, and supply three already executed
tail actions and cp10 RGBs. No new tail is selected for execution.

At each cp5 use RGB-derived position with zero velocity at both cp0 and cp5,
the same cp5 task mask and the same three distinct-or-duplicate tails. Compare
single-frame prediction with two real frames plus the actual normalized
five-action prefix and each candidate normalized five-action tail. The
two-frame low-level `forward_pred` action-token binding follows the existing
`a1_pointmaze_cp5_history_diagnostic_20261102` exploratory implementation;
it is not an authenticated checkpoint training contract. Score both methods'
predicted visual latents on the identical masked goal distance, and compare
to each already executed tail's cp10 RGB latent on that same mask. Save
per-tail predictions, target scores, latent errors, chosen index and
position-backend evaluation distance. Never use evaluation distances or
cp10 RGBs as planner inputs. Source duplication and repeated roots remain
visible; ties are not independent comparisons.

Use the frozen model on host CUDA, identical checkpoint and dataset
normalizers, fixed scene/camera geometry, pre-existing source actions and
shared prefix images, and no external training. Check source/array hashes,
actual first packet and cp0/cp5 RGB binding. Store inputs, hashes, samples
and output arrays. This is an offline diagnostic of already executed actions,
not a physical closed loop, a native-success result, a confirmation root, an
equal-total-cost comparison, or P1 evidence. The 3-tail bank was generated by
earlier adaptive planners and is not a representative random action sample.
