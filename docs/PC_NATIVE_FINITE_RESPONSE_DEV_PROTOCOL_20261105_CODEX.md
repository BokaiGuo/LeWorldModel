# 原生 CEM 后有限响应组合：开发协议

2026-11-05，运行前记录。目的：在相同原生模型与规划入口检查
目标相关有限差分组合是否比同量随机组合有增量；不是完整程序组合，
不宣称独立确认或 PC2/PC3 通过。

每次规划先用同一 CEM、同一当前求解的已评分最优父链；绘制四个
单位随机方向，分别评估正负幅度 0.25 的 8 个完整链。第九次完整链
评分：响应臂以每个方向的负向有限差分为权重合成一个单位方向；
随机臂用预定交替正负权重合成同尺度方向。两臂共享候选产生随机流、
父链、八条探针及评分次数，从父链、八探针和组合链选最低预测代价。
如响应全零，组合等于父链，仍照常评分。每次物理反馈后重新求解，
不得复用旧评分。全部动作候选必须在共同原生模型评分，无物理真值输入。

先做单元测试与单任务 smoke，再用 seed 42、50 行、300×10 CEM
跑两臂；历史原生均值和 incumbent 可作为额外未匹配额外调用的
对照，不宣称等成本。响应／随机各臂每次规划各增加 9 次完整链评分，
计算次数相等不保证墙钟相等。任何基线追加同等预算的 CEM 或完整
墙钟／显存审计留待后续，不能从此开发实验推出 PC3。

## 结果暴露后追加的归因重跑

观察 seed 42 两臂均 44/50 后，新增可选 JSONL 记录，每次求解
保存父链、8 探针、组合链、各自预测代价和最终选择来源。
在同一 seed、预算和输入上重跑响应臂，先核对逐任务结果与无
记录运行一致。写日志增加成本，归因重跑不是独立确认；预测成本
用的是同一模型，不能借此单独证明模型正确。

同时事后追加原生 CEM 301×10（每次规划 3010 次评分）强基线；
它比新增方法的 3009 次多一次评分，不是严格相同采样过程或
完整资源等价，且因在看到开发结果后追加，不能视为确认试验。

再追加 seed 43、44 的响应／随机配对，沿用同样 300×10+9 设置；
这也是看到 seed 42 后追加的开发检验。每个 seed 同时影响任务抽样
及搜索随机流，不将不同 seed 的行假定为互不重叠。
