# 统一开发入口：真实 RGB 反馈接线诊断

按照[事前协议](PC_UNIFIED_RGB_LIVE_INTEGRATION_PROTOCOL_20261103_CODEX.md)，
于 2026-11-04 在一个已暴露 PointMaze 开发根执行一次接线诊断。该版本
直接调用统一决策入口，三次分别封存完整计划后执行前五步，再以实际
RGB、动作历史及剩余尾部重编译；固定终点为热身后的第 15 步。

| 决策 | 剩余时域 | 预测调用 / 样本 / token | 规划秒数 |
| --- | ---: | ---: | ---: |
| 0 | 15 | 90 / 194 / 478 | 4.56 |
| 1 | 10 | 48 / 253 / 480 | 4.33 |
| 2 | 5 | 67 / 480 / 480 | 4.35 |

独立审计核对了三次决策的图像及前一帧哈希、ticks、动作历史、
carry、完整链与派发、逐批动作和 token、38 项列出的依赖哈希，以及
记录的决策封存与执行时钟顺序。后两次的首批模型调用确为各自 carry，
其结果等于保存的 carry 评分；模型中被选新链的分数分别为
0.0661 和 0.0010，carry 重新评分分别为 0.3324 和 0.1377。
这些是不同上下文中的模型代理分数，不是物理控制收益。

三轮总计 205 次预测调用、927 条轨迹样本、1438 个五步 token；
10 次编码包含目标编码；整个执行记录的墙钟时间为 17.62 秒。
该运行没有覆盖真实弃权：三次 `abstained` 均为 false。
预测 token 与时间不构成完整成本认证。

审计第一次运行因审计脚本把 JSON 列表与时钟函数返回的元组直接比较
而误报 ticks 失配。修正审计脚本后重新审计通过；没有更改或重跑已封存
的真实实验。这是审计代码错误，不是已证实的规划或模型错误。

## 边界和产物

这是一个暴露根上的实际 RGB 反馈与接口接线证据，不是独立性能确认、
PC2 同链机制、PC3 强基线比较，也不足以证明 PC4 或 PC5。
审计核验的是已保存时钟及记录，不是对进程执行顺序的外部证明；
它没有独立重跑模型或物理后端。列出的源码哈希不证明所有传递依赖、
normalizer 拟合成员或 checkpoint 训练来源完整。
