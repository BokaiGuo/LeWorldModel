# v7 E0：同轨迹 CPU 资源重放

按[事前协议](PC_V7_E0_RESOURCE_REPLAY_DEV_PROTOCOL_20261104_CODEX.md)，
在 18 个已暴露精确动力学根上重跑 v7、三重启 smooth CEM 和逐步 action CEM。
54 条计划的每批请求动作、float32 动作、预测位置及评分与各自封存记录一致，
最终动作、评分和 token 计数也一致。执行顺序按根循环；耗时含运行时插桩和
轨迹复制，不含进程启动或事后核验。

| 方法 | 每根 token | 轨迹数中位数 | 预测调用中位数 | CPU 规划时间中位数 | 范围 |
|---|---:|---:|---:|---:|---:|
| v7 | 1920 | 737 | 60 | 27.41 ms | 27.27–28.25 ms |
| smooth CEM | 1920 | 640 | 55 | 25.07 ms | 24.95–101.10 ms |
| action CEM | 1920 | 640 | 55 | 25.45 ms | 25.18–170.14 ms |

按根计算的规划时间比值中位数，v7／smooth 为 1.092，
v7／action 为 1.078；两个 CEM 均有明显时间离群值，因此这些数字只是
一次受调度影响的开发测量，不能解释为稳定硬件性能优势。
相同 token 不代表相同轨迹数：v7 含长度不同的部分链。

v7 每根实际执行 11 次有限差分响应、22 次 SVD，其中 231 条探针
合计 **420 token**；SVD 包容时间中位数为 0.227 ms。response 的包容时间
含预测和 SVD，CEM 的包容时间含预测，因此不能把分类时间相加。
两种对照各调用 3 次 CEM，未调用 SVD。

这是 CPU 精确动力学的规划调用计时；没有视觉编码、神经模型预测、
图像反馈、GPU 同步或跨设备内存数据，不能当作完整 RGB 成本认证或
质量—成本确认曲线。两种 CEM 仍非充分调优的强搜索上界；面板和方法
已暴露，不构成 PC3 或独立泛化证据。
