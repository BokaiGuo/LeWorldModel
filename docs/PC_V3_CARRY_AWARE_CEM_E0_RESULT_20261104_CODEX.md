# 固定终点反馈热启动 CEM：E0 开发结果

按[事前协议](PC_V3_CARRY_AWARE_CEM_E0_PROTOCOL_20261104_CODEX.md)，
在 24 个已暴露 Wall 根上运行 carry-aware smooth CEM，并与已封存
response、原 smooth CEM 的各自闭环轨迹配对比较。每根三次决策均
使用 1920 预测 token。新臂首轮选择与原 smooth CEM 的首轮选择
24/24 完全一致；之后各臂基于自身执行的状态和尾部重规划。

| 方法 | 最终距离均值 | 中位数 | 最终距离 `<0.05` 根数 |
| --- | ---: | ---: | ---: |
| v3 response | 0.396386 | 0.500058 | 5/24 |
| 原 smooth CEM | 0.458722 | 0.500050 | 2/24 |
| 热启动 smooth CEM | 0.479329 | 0.500026 | 1/24 |

按距离差 `1e-12` 内视为相同，热启动相对原 smooth CEM 为
18/0/6 胜／平／负，相对 response 为 12/0/12。许多差距极小，
不能将逐根胜数解释为具有实际意义的成功优势。均值恶化主要来自
根 0：原 CEM 距离 `0.002864`，热启动为 `0.500021`。48 次反馈
决策中，旧尾部 45 次、零链 3 次作为优化基点；选中旧尾部不保证
后续搜索能找到原零链初始化所找到的解。

事后核对根 0：两臂第 0 次选择及第 1 次决策上下文相同。第 1 次
决策时，热启动臂评得尾部 `0.501333`、零链 `0.988373`，因此以
尾部初始化，所得最优完整链距离 `0.500502`；原 CEM 从零初始化
所得为 `0.011194`。第 2 次上下文已经不同。该单根检查支持把
分叉定位到搜索初始化，而不证明尾部策略普遍较差或实现有 bug。

[逐批预测和执行审计](../le-wm-main/results/pc_v3_carry_aware_cem_e0_20261104_codex_audit.json)
对全部 24 条新轨迹重算；[原始记录](../le-wm-main/results/pc_v3_carry_aware_cem_e0_20261104_codex_plans.json)
保存全部采样、精英更新、动作、计量和后继。审计共享同一精确
动力学实现，不是独立模型复现。[manifest](../le-wm-main/results/pc_v3_carry_aware_cem_e0_20261104_codex_manifest.json)
在运行前封存声明的依赖；不宣称完整环境闭包或总成本等价。

这说明旧尾部热启动并非在该配置下无条件强化基线，也暴露了
单一起点选择的搜索风险；不能把失败预设为代码错误或理论失败。
应继续测试公平分配预算的零链／尾部多起点、充分调优及其他适用
强基线。该暴露根开发结果不能支持 PC3 独立确认，也不能单独把
response 与 CEM 的差距归因于响应或组合机制。
