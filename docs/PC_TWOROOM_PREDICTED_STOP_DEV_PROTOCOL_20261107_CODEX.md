# TwoRoom 预测时刻截断：已曝光开发诊断

固定此前 10 个开发任务及每任务 64 条 B 链。所有候选和五个预测时刻
已在前期生成，且这些任务的全长结果已经曝光：本实验不是独立确认，
也不是描述组件或端到端规划收益检验。

选择阶段只读取封存的模型预测分数、动作池及任务标识；不读取物理
结果或真实重编码。每根按以下固定规则选择，平分时按候选及时间的
原始顺序选最先出现者：

1. `final25`：最低预测第 25 步分数对应的链，执行 25 步。
2. `min25`：全部候选和 5、10、15、20、25 五个时刻的最低预测分数
   对应的链，执行 25 步。
3. `min_stop`：与 `min25` 同一链，仅执行至其预测最低分对应时刻。

选择清单和动作哈希先封存；之后评估端每臂重新 reset 并实际执行
指定动作，记录每一步。物理状态仅用于复位、成功标签和审计，不能
进入选择。`min_stop` 的轨迹必须逐步等于 `min25` 的相同前缀，
两个完整臂必须等于此前封存的对应轨迹，否则中止。连续执行到指定
时间，不用评价端成功标志提前停止；分别报告执行期间曾成功、末步
成功、执行步数以及与 `final25` 的任务级独胜／独负。

开发停止规则：若 `min_stop` 相对 `final25` 的曾成功数没有净增加，
或实际截断损失曾成功个数，则不扩大该截断规则，保留负结果。即使
达到条件，也仅说明值得另立预注册开发实验，不自动证明闭环收益、
合法停止策略在其他任务中有效或 PC0–PC5 通过。无额外模型调用，
复用历史预测的真实生成成本，不把本次离线回放成本当部署成本。
