# P3 cp15 RGB 边缘预检：探索结果

画布事故的代码原因不是简单的动作越界：规划器将每个原始动作
限制在 `[-1,1]`，但当前 PushT 环境使用相对控制，目标是当前
位置加 `100 × action`，环境内目标裁剪代码未启用。因而即使
动作本身合法，目标位置和物理后继仍可能越过画布。惯性与
接触也会影响实际轨迹；此结论不证明 normalizer 无误。

按预先写入的本次探索合同，对封存的 52 条 cp15 图像仅从 RGB
提取推杆颜色标记：40 条通过，12 条拒绝。其中 4 条因标记
触及边缘或过小，4 条因距边缘不足 8 像素，4 条因颜色标记
不连通。数字是共享两个已知根的逻辑记录，不是独立样本。

事后关联既有物理事故：逻辑对 25、34 的 old/new 四条 cp15
均属于“标记触及边缘或过小”的拒绝集合；另有 8 条未涉及
这次越界事故的记录也被拒绝。若将该预检应用于这些相同输入，
它会在 cp15 弃权，而不是证明能完成任务。此规则是在事故后
设计的，不能作为独立预测性能，也不能把已通过的其他输入
视为后续动作安全。
