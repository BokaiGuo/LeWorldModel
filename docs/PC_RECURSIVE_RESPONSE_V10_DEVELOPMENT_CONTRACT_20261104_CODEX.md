# v10 递归响应程序：开发合同

目的：检验 v7 的固定两段生成是否限制候选覆盖；这是新开发算法，不改变 v7–v9 或其停止后的负结果。此版本先是可组合的规划核心，不宣称 RGB 适配、PC2 机制或 PC3 优势已经成立。

输入为合法预测函数、目标向量、动作维度、片段长度、片段数、有限差分尺度、多组名义片段、每次响应保留的目标贡献模态数、多尺度扰动幅度、beam 宽度、资源上限和种子。预测函数返回每条动作序列的末端特征和完整任务评分；目标与特征维度一致，但可以与动作维度不同。输入动作均受 [-1,1] 限制。名义动作留有有限差分边界；非整段任务由调用方选择合适片段长度，目前不声称支持变长末段。

对每层保留链的每个后继，分别在全部名义动作处计量中心差分，SVD 并按目标残差加权模态贡献排序；只展开预定数量的方向，并以固定多尺度与正负号构造后继，同时包含名义动作。这个上限实际改变候选数，而非仅改变枚举顺序。每层在已预测的后继中，保留部分即时分数最优和部分特征空间最远者；这只是延迟收益保留启发式，不访问后验物理结果。重复到预定深度，每层后继重新计算响应。所有最终完整链参与 incumbent 选择，若剩余预算允许，以相同全动作 CEM 联合精修，再同批比较 incumbent 与其首段置零的对照；若动作在实际 float32 预测输入中相同则弃权。

预算使用片段预测 token 样本，逐调用计量、检查边界，不得只计最终搜索；SVD、响应计算、特征距离及墙钟须另行记录。预算不足时明确报错，不偷用或超出预算；最后配对比较和零链基线预留成本。规划器不接受解析见证、状态特权索引或后验物理评分。方法记录每层名义、响应、候选、保留、完整链选择及联合精修的信息。粒度、深度和谱上限是开发配置，不以本实现等同于谱独立增量。

先在合成可微线性模型和有限制的精确 E0 开发任务上做接口／成本／选择回归，再按另立的事前协议比较自动生成、同链机制、对照与消融。相同 token 不代表计算总成本相同。未明确来源和预定统计前，一律不称独立确认。
