# P3 六槽构造所有权与调用预算边界

本次新增独占 guarded host、原生适配器和保存消费者，不改动原 producer、原 driver、原封存或科学门。没有生产、GPU、模型加载或物理执行。

原主机 driver 直接使用原生 meter，未装配已有的构造所有权适配器；即使装配，Gym 的 `make` 在底层构造返回后还会设置 spec 和组装包装器，这期间失败时外层拿不到底层句柄。新适配器在底层对象进入 `__init__` 时保留引用：初始化内部失败时利用现有 metered subclass 的关闭路径；初始化已返回但 Gym 未返回时主动关闭已捕获底层对象；关闭只尝试一次、进行原有 close 计量，失败不重试且保留异常说明。journal 故障时仍尽力关闭。此处理不能证明初始化期间尚未挂到对象上的资源、或者未返回包装器独有资源已释放；无捕获句柄或关闭失败均为未解决情况，不能认证。

新 host 实际装配上述适配器及原有身份桥接和数值 backend。所有经原生 `Meter` 的非 close 调用在入口与返回前检查存储/墙钟、精度、设备 UUID 和 CUDA 峰值；编码 Session 调用前后也检查。守卫失败毒化 factory，阻止后续槽创建。close 刻意不受这些检查阻拦，确保超预算或 journal 失败时仍尝试清理；其本身仍由原 cleanup 计量，可能留下未结算或失败记录。编码内部已有存储检查，但 CUDA/精度守卫只在整个编码调用边界，不是对每个内部 kernel 的连续监控。未经过 meter 的本地辅助操作及封存后的开销也不因这些检查被完整计量。

新独立消费者检查外层哈希、固定的六次构造和 24 次编码边界计数、峰值与原报告资源计划，并调用原 source-bound 数学消费者。计数是本地记录而非不可伪造的硬件证明；原外层消费者不适用新 schema。I/O 失败时 failure 文件仅为尽力保存，不能将缺失记录当作成功。

模型和 CUDA 上下文仍由调用方预先创建；权重读取、加载、初始化以及建立上下文之前的墙钟、内存与其他成本没有纳入全成本。六槽限额、主线程授权与资源准入、运行期间全部资源的连续覆盖、不可达原生资源清理证明和真实硬件验证仍是前置缺口。本工作不声称科学通过、等算力或泛化。

验证：禁用 CUDA 可见性，CPU 替身和现有相关回归共 49 项通过。替身测试不证明真实构造器、设备或物理路径已通过。
