# 二维生成支持下的交叉描述：单因素开发协议

2026-11-08，执行前封存。问题不是重开旧一维配置，而是检验已验证的生成支持修正之后，未查询组合信息是否终于能改善真实选择。旧版停止结论保持不变。

## 动机与范围

此前一维候选来源保持版本的完整池上限为23/48，选中链已达到该上限。新二维完整链生成同128查询达到48/48，且全候选独立重放通过。因此有依据单独检验生成支持对描述利用的影响；没有依据更改描述公式、增大时域或同时调多个搜索参数。

本版本仍为24个已曝光精确墙障任务×2生成流，不是独立确认，也不是RGB-only。真实姿态和解析动力学只在这个明确的exact-state协议内使用。没有训练、视觉输入变更、未来评价端状态或免费最优尾部。

## 唯一算法因素

以已封存 `pc_lineage_cross` 为对照实现，名义链从一维改为二维waypoint：

- seed仍为`2831000+100*root+repeat`；
- lateral均匀[-2,2]；longitudinal用独立`seed+70000`均匀[-1,1]；
- 前16条完整二维链同时提供16个5步前缀和16个10步尾部，加同长hold；
- 先付费查询并始终保留16条完整原链，之后16×17池的交叉查询与提案流程保持原样；
- 4共同列、3锚点行、`rcond=1e-8`、完整链首个实测最小代价选择均不变；
- 每臂128条15步查询、1920动力学转换；成功仍为第15步终距<0.05。

比较7个同信息臂：交叉交互、加性、父链代价、行均值、probe-min、动作身份打乱、随机未知配对；另有均匀lookahead、随机配对、完整二维生成、同16原链热启动CEM。所有臂共享并计费同样的16条原链。完整二维对照须逐候选复现上一轮的纯二维臂。

不引入共享前缀缓存、不同切分长度、新精修器或其他算法改变。批量查询数、规划CPU耗时和评价成本分开记录。

## 两个决策出口

1. **信息出口**：按任务平均两个流，交互的未查询配对MSE分别在至少16/24任务上低于加性与身份打乱。未知矩阵格不能进入规划；已查询原始配对不属于未查询评价。
2. **组件利用出口**：交互相对加性、身份打乱、均匀lookahead，分别净增至少4/48成功且平均终距更低。该阈值只决定这个开发组件是否值得进入下一项成本实验，不是PC2或PC3通用标准。

已知完整二维基线在此128预算面板达到48/48，因此本轮不设置不可能的“再胜它4次成功”要求，也**不以打平它自动宣称完整方法有效**。报告相对完整二维和热启动CEM的全部结果及成本；完整方法准入始终为false。本轮若任一组件出口失败，停止此二维交叉构造，不用新增seed、调秩或删失败根挽救。

所有比较按24任务bootstrap，10000次、seed2839000；不是48独立样本，也不是独立确认显著性。没有事后非劣效或成本优势阈值。

## 实施、审计和结果分解

- 全部48份计划封存后，逐动作核验来源、预算、incumbent、随机参数、CEM采样/elite/更新和描述提案。
- 用独立最小二乘表达式复算交互公式，用独立标量动力学重放完整查询和选中链。
- 之后才评价完整272候选池，区分nominal覆盖、共同查询覆盖、全池覆盖、提案漏解和最终选择丢解。
- 同时记录新生成的完整程序被5/10切分后，组合是否仍保留原始见证；不把固定时间切分称为语义节点程序树。
- 输出源码/协议哈希、逐根断点文件、完整轨迹、成本、两类出口、图与中文研究决定。不能把正向生成、其他版本信息及同链机制拼接为Full Planning Compiler。
