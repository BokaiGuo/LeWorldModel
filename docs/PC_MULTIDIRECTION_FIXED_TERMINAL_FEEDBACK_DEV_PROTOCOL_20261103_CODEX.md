# 多方向编译器固定终点反馈开发协议

本新版本检验多方向候选与响应提取是否能够在 15→10→5 固定剩余时域中
持续使用，不能重启或修改已停止的原首次规划。24 个已暴露根复用原封存
多方向首决策，执行其首五步；对每次真实精确状态反馈，新版本重评上一
计划未执行尾部并重新规划。每个新增决策上限 480 个五步预测 token，
每次只执行五步，固定终点为原 15 步。

剩余十步：在当前状态按首决策同样的零名义动作、中心差分、最多两个非零
奇异方向及正负号生成五步前缀；对所有候选使用共同 floor-CEM 优化五步
后缀，分配可负担完整链预算的 75%，余下做联合十步精修。零方向只生成
zero。剩余五步：这些响应提案及探针本身是完整链，另以同一 floor-CEM
在全部五步上采样可负担预算的 75%，余下联合精修。每次决策先重评 carry，
每条已评分完整链均参与全局 incumbent；严格改进才替换，最后比较该链
的 zero-first-packet 对照，平分选择该对照。执行前记录最终链与原因。
响应和筛选、精修、carry、零对照全部在 480 token 内；非零秩不得凭空
产生方向，合法动作限于 [-1,1]，整链和分段使用同一 float32 物理时钟。

同根 full-CEM 反馈控制直接使用已封存的旧实验首决策及其两次 480-token
反馈决策，检查首决策同一哈希来源和任务相同；不重新规划对手，也不得
将其称作强搜索上界。逐批保存预测、请求和模型动作、输入状态、评分、
种子、前缀、精修及最终选择，并逐批重放和检查所选链为全局已评分最低
（保留上述平局规则）、预算与分段／整链重放。

仅报告暴露根上的两个臂成功数、末距、资源及轨迹；若无预定机制或强
基线优势，不追加根、调参或把反馈拼接轨迹冒充首决策事前完整链。它是
精确状态反馈开发实验，不是合法 RGB、PC2、PC3 或独立确认。
