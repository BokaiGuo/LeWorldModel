# P1 多起点规划评分与动作绑定核查

本次核对已封存的 uphill 四起点 Adam 规划、物理配对代码及
中点 CUDA 重放，不修改运行中作业或历史协议。

- `codex_p1_adam_cp5_20261030_main.py` 对每个候选完成 20 次
  更新和动作裁剪后重新计算分数；以分数和起点索引决定赢家，
  并保存赢家原始动作和 SHA-256。选择函数拒绝非有限分数。
- 24 条封存记录均有四个候选分数，赢家索引分布为
  0/1/2/3 = 11/3/5/5。物理准备程序核验起点哈希、赢家规则
  和赢家动作绑定；相关物理和配对测试本次 9 项通过。
- 主机 CUDA 的既有中点诊断对 19 条完成固定十步的赢家动作
  独立重放，均通过保存目标分数的 1e-5 容差检查；该检查
  不覆盖五条提前停止记录，也不验证训练 normalizer 来源。
  证据见 `D2P_P1_UPHILL_MULTISTART_MIDPOINT_RESULT_20261031_MAIN.md`。
- **可复算性缺口**：规划结果仅保存赢家最终动作，没有保存其余
  三个最终候选动作。因而无法仅凭封存结果独立重算所有候选
  分数并验证 argmin 的完整性；初始动作哈希与四个分数不足以
  恢复这些最终动作。这不是赢家有误的证据，也不能据此否定
  现有物理结果。

后续新合同应保存每个候选的最终原始动作、动作哈希与对应分数，
并在不使用物理结果选动作的前提下，对全部候选做主机 CUDA
评分重放；计入实际额外模型调用。保留历史封存，不修改历史
实验以制造事后完整性。已知根和重复逻辑臂仍不能视为独立样本；
P1 科学门槛不因接线测试通过而开放。

## 固定输入主机 CUDA 完整候选重放

使用原始 24 行真实 cp5 输入、冻结 checkpoint、同一四起点和
20 步 Adam 配置，重新生成并保存全部 96 个候选动作及分数。
重放前后核验原始来源文件与模型哈希，不使用物理结果选择候选。
RTX 5060 Ti 上实际完成 24/24：每组四个分数与原记录逐值相等，
24/24 赢家索引一致，24/24 赢家动作字节一致，最大分数差与
赢家动作差均为零。每行的全部候选动作及其 SHA 保存于
`le-wm-main/results/p1_uphill_adam_candidate_replay_20261031_RUN01.json`，
文件 SHA-256 `929732e4a5ed25146de3899a2ff4e1f326e813fe01260fce00a17a2adca0742a`。
每行重放使用一次编码、168 次 action encoder、168 次预测和
80 次 backward；这些是按代码路径记录，并非独立 hook 账本。

重放代码的差异报告有两项纯数组单元测试通过；这些测试没有进行
CPU 神经推理。完整重放使用与原实验相同的模型及优化实现，
因此不能排除共享实现错误，也没有改变原封存文件；新保存的非赢家
候选是重放产物，不是原运行当时封存的动作。该实验未新增物理
执行、独立样本或公平预算比较，不构成 P1 通过。

## 显式双包评分交叉检查

在主机 CUDA 对上节保存的 96 个固定候选，另用显式第一动作包、
预测后状态、第二动作包及历史裁剪的路径复算目标分数，不调用
原优化器的 `fixed.replay`。24 组的 96 个分数逐值一致，24/24
赢家索引一致。结果
`le-wm-main/results/p1_uphill_candidate_manual_score_20261031_RUN01.json`
SHA-256 `7559fc97207261188348891ff6fd476cd24dd1c7fa376962cee755388ab4b04a`。
按代码路径每个前缀使用一次编码、八次动作编码和八次预测；
模型、已绑定来源在运行前后保持一致。

该检查覆盖动作包拼接和两次模型预测的实现差异，但两路径共用
cp5 上下文构造、图像预处理、normalizer 和同一模型，不能排除
这些共享部分的错误。非赢家动作仍是重放而非原运行封存产物；
本次不涉及新物理执行或独立根。
