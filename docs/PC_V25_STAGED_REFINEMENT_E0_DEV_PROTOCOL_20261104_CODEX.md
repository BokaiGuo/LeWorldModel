# 两阶段精修预算分配：端到端开发协议

假设：固定均分预算可能把较多精修样本分给无改善的起点；先给所有起点相同的最低探索机会，再把余量分给前半数，有可能改善等 token 完整链质量。该启发式可能误删延迟收益起点，必须报告负结果。

事前固定 16 根新 exact-Wall 任务：`start=(-0.5,±0.175,±1.07)`，`goal=(0.5,gy)`，`gy∈{-0.13,-0.05,0.05,0.13}`；逐项检查与已列面板无精确重合，其他来源 unknown。每根两个 token 上限 1,920、2,880，四臂：窄束 v25 均分、窄束 v25 两阶段、共享 CEM 均分、共享 CEM 两阶段。窄束为 beam 2／greedy 1；共同全局库、动作域、目标、模型、反馈权限、起点数、最优链保留和配对弃权不变。

两阶段在总样本足以给所有起点和晋级起点各至少两批时，将约一半预算均分给全部起点，按第一阶段完整链分数稳定排序，前半数按排名均分余量并从各自最佳链重新调用共同 CEM；重新评分起点也计费。否则确定性回退原均分 CEM。初始搜索与延续使用独立预定随机流。与均分 CEM 的采样序列不同，因此这是分配策略整体比较，不是只改变一个随机样本的因果对照。基线和响应臂共享该能力，不对某一臂特供。失败计入分母、保留原始请求，不替换根或改变阈值。

逐批封存动作、预测、费用和完整结果；审计另一同环境几何、实际 token、共同全局库、全部评分中选择的最优完整链、晋级与样本分配及确定性规划重放。分别报告每臂成功根、终距、成本与分配。预测 token 不等同完整 GPU／墙钟成本；本面板为开发，不是 PC2 同链机制、PC3 独立确认或理论证明。
