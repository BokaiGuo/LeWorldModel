# 50 任务 CEM 预算曲线：开发结果

按[冻结协议](PC_EPISODE85_CEM_BUDGET_EXTENSION_PROTOCOL_20261106_CODEX.md)
复用已暴露的 50 任务，补充 300×10 和 300×30；105×6 为同一任务、
环境和求解器 seed 的先前结果。成功定义和实际执行上限不变。

| CEM | 成功 | 整任务规划数 | 完整链评分总数 | 求解器墙钟秒 | 子进程墙钟秒 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 105×6 | 44/50 | 69 | 43,608 | 6.26 | 34.70 |
| 300×10 | 43/50 | 65 | 195,130 | 19.39 | 48.67 |
| 300×30 | 47/50 | 58 | 522,116 | 49.99 | 78.91 |

配对比较：与 105×6 相比，300×10 独胜 2 个、105×6 独胜 3 个、
两者均成功 41 个、均失败 4 个；300×30 独胜 6 个、105×6 独胜
3 个、两者均成功 41 个、均失败 0 个。候选评分数包含末尾每次
规划的两条附加评分；成功及重规划不同导致整任务调用次数不同。

按 reset seed 核验 50 个任务的首个可见物理快照，三个臂均在
绝对误差 1e-4 内一致。三个臂分别执行 1560、1417、1318 步，
实际动作最大绝对值分别约 0.888、0.905、0.906，均满足合法域。
这不证明未记录的全部隐状态等价。两次新运行采用 GPU 顺序执行；
求解器计时含已有记录器开销，子进程包括启动、环境、视频和 trace，
不等于纯 GPU 计算。该开发面板已暴露，单次顺序计时不构成统计
非劣效、独立确认或正式完整系统效率认证。

**对研究决策的影响：**300×30 在这批任务上找到了更多成功，
105×6 则以较低成本取得 44/50，但任务并非逐个包含关系。不能
将这两个结果描述为已证明“同质量低成本”，也不能将它算作
Planning Compiler 贡献。新方法应和这条成本—质量曲线及各自的
逐任务结果对照，而不是仅与较弱的单一 CEM 预算比较。
