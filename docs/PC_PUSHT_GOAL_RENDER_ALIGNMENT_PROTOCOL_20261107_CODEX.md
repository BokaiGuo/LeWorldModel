# PushT 目标图与目标状态重渲染：配对开发审计

对已曝光 seed 85 的固定 50 个任务，复用两条既有首计划的预测表示、真实后继编码和原物理成功标签；不生成或重选动作。比较 HDF5 原目标图与评价端将同一个目标状态设为当前状态后重渲染的图，逐任务记录状态复位误差、像素差、同批冻结编码及对同一两条动作链的末帧分数。模型输入所见目标为原数据目标；目标状态及重渲染仅用于事后诊断，不能输入部署规划器。

先检查原图重编码与既有封存目标表示最大元素差不超过 0.001；比较两个版本的原数据目标编码与重绘目标编码。记录每任务两臂分数差的符号（绝对差不超过 0.001 记作平局）、目标替换导致的排序变化；对两臂物理成功不同的任务报告分母和与成功结果一致的数量，分别统计曾成功和末帧成功。记录初始与目标状态哈希、像素差异、模型指纹与源数据标识。对两臂相同动作的 10 对保留在全体分母，不按独立样本计算。

本实验只验证已曝光候选及同环境重绘，不声称目标状态合法可得，也不改变标准评测目标；若排序变化很少，不将失配主要归因于目标渲染差异。无论结果如何，不更改 PC0–PC5。

执行记录：首次运行在任务 0 的复位校验失败，最大状态误差为 1.5969772338867188。环境 `_set_state` 会推进一步物理时钟，不能保证渲染的是输入状态。诊断改为仅在评价端直接设置渲染姿态、不推进物理；这不是合法环境 reset 或可执行状态的认证，也不改变规划器输入。

第二次运行仍被校验阻止（任务 0 误差 68.46663865555183）：直接设置时先设位置后设角度，Pymunk 的旋转影响了物体位置。现按环境实现先设角度再设位置，仍保留状态校验。
