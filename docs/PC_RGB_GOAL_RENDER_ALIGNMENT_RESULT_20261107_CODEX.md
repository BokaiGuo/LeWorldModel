# TwoRoom 目标重绘对齐开发诊断

## 范围与方法

在固定的 40 个开发 episode（9000–9039）上，比较数据中的当前图和目标图与按评估器 reset、目标物理状态重绘的图像；对已有实际前缀动作探针，使用封存预测表示和真实编码，比较原目标与重绘目标下的效果方向。对应协议、原始 JSON 和 NPZ 分别见 `PC_RGB_GOAL_RENDER_ALIGNMENT_PROTOCOL_20261107_CODEX.md`、`le-wm-main/results/pc_tworoom_goal_render_alignment_20261107_codex.json` 和同名 `.npz`。独立汇总脚本核对输入、协议、运行脚本及结果所引用的哈希。

重绘使用隐藏物理状态，**仅为评估端诊断**，不是 RGB-only 规划器的合法输入，也不是控制性能实验。这些任务已用于开发或独立性未知；同一任务下的前缀与探针不是独立样本。

## 结果

- 40/40 个 episode 的 agent 位置与目标位置恢复误差逐项为零。此检查不认证环境全部隐藏状态或动力学。
- 当前图 1/40、目标图 0/40 与重绘图逐像素完全一致；两类图的最大单像素绝对差均为 1（uint8），最大整图平均绝对差分别约为 0.0004252 和 0.0004385。
- 目标编码最大均方差为 3.815e-6。封存原目标编码与本轮批量重编码的最大元素差为 1.383e-5；其原因尚未通过单图与批量的受控实验确认。
- 35 个具有完整前缀记录的任务，每个任务四组前缀、每组四个轴向探针，共 560 次动作效果对比。对物理效果平局采用原分析容差并排除后，预测编码与物理效果同号 295/537；真实编码与物理效果同号 292/537。原目标和重绘目标下结果相同，且预测和真实编码的动作效果符号均无变化。
- 其中实际 effect 前缀组分别为 74/134 和 74/134；其他三组前缀分别为预测 71/133、77/137、73/133，真实编码 70/133、73/137、75/133。计数为描述性统计，不视作独立任务数量。

原始实验首次运行在 episode 9034 因单图封存编码与四图批量重编码之差超过最初的 1e-5 断言而停止，没有写出结果。修订后，原目标评分严格使用封存目标向量；重编码差单独记录并设置 1e-3 上限，封存代价也用 1e-3 校验。后续完成的实验没有覆盖既有结果。该容差是开发防错边界，不是已认证的跨平台等价标准。

## 结论与限制

本样本中，轻微的目标重绘差异没有改变所检查的探针效果符号，因此现有数据不支持将这些探针的模型／真实编码与物理方向失配主要归因于目标图像的微小重绘差异。比较还包含重编码的数值差异，结论只适用于当前实现和被检查探针；不能据此认证全部预处理、时钟、训练数据、其他任务或控制效果，也不能排除共同评分失配。

相关三组测试共 8 项通过。该诊断没有建立规划收益，不改变任何 PC0–PC5 gate 状态。
