# JEPA PushT 历史动作填充：固定上下文开发诊断

目的：在已暴露的 JEPA PushT episode 1、帧 0/5/10 上，检查原生三帧预测对两个历史动作 packet 的依赖。现有规划包装器在首预测步将历史动作槽填为归一化零，而已封存的原生单步检查使用真实历史 packet；二者是否数值等价需要直接测量。

固定同一 RGB、agent 位置/速度和目标帧 15；模型、预处理和实际动作读取复用已有原生 v8 封存及校验。模型需位置、速度，故本实验不是 RGB-only。仅将两个历史动作槽改为真实值或归一化零，末 packet 分别为真实值或归一化零，共四次预测；两种历史均包含同一末动作对照。归一化零表示训练动作均值，不等于原始零。目标帧仅用于事后误差，不参与候选或方法选择。

记录两种历史下的预测差异、对同一真实目标的误差、两种末动作的误差差值、目标误差排序及响应差。输出不覆盖；保留模型哈希、输入绑定、设备、预测次数和单位。该单根诊断没有物理执行、优化、训练和统计确认；预设不以数值门槛决定 gate，排序变化也不自动证明哪种接口更接近训练或物理。若输入或原始封存不一致则失败关闭，不替换根。

共享 GPU 锁使用 `results/e3_p2_host_cuda_cooperative.lock`，检查物理设备 UUID、CUDA 及 TF32，并在同一批条件下禁用随机训练行为。读取后的目标不得回流 v7。未来若需评估包装器完整多步 rollout，须另测真实多步上下文与其实际实现，单步零填充实验不能代替。
