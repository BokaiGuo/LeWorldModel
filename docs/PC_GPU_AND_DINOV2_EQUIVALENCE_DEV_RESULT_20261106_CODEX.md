# 同步规划计时与 DINOv2 数值等价：开发结果

## DINOv2 局部实现差异

按[协议](PC_DINOV2_ADAPTER_EQUIVALENCE_DEV_PROTOCOL_20261106_CODEX.md)，
把本机 HF ViT-S/14 权重严格映射到本地 DINOv2 源码快照，源参数
全部覆盖，目标严格加载成功；三张 PushT 实际数据帧以相同张量
输入两实现。在 518×518 输入上，两个输出在本机逐元素一致；在
224×224 输入上，三个样本的 patch-token 相对 L2 差分别为
4.73%、5.03%、5.41%，最大单元素差分别为 2.43、3.34、4.01。
CLS 相对 L2 差约 1.34%–1.37%。

源码显示，两者位置编码插值存在具体差异：本地 DINO 源码默认
使用 0.1 的 scale-factor offset，HF 路径以目标 size 插值。
隔离反事实试验仅把 DINO 代码的 offset 设为 0（不改变正式模型），
224 patch 相对 L2 差降至 2.13–2.19×10⁻⁶，最大元素差不超过
1.55×10⁻⁴；518 输出仍逐元素相同。这个干预支持插值差异是本组
输入差异的主要来源，但不证明其他分辨率、训练状态和路径均等价。

未取得官方原始权重与权威源码提交的认证；使用的是**同一 HF
权重映射**，不是两份权威权重的来源对照。尚未完成 JEPA 整体
预测、动作历史、原始预处理、闭环与真实任务的上游等价认证。
不能把两种不同架构的模型预设为输出相等，也不能由编码对照推断
跨模型规划优势。原始记录：
[默认插值](../le-wm-main/results/pc_dinov2_adapter_equivalence_dev_20261106_codex.json)、
[offset 隔离](../le-wm-main/results/pc_dinov2_adapter_zero_offset_dev_20261106_codex.json)。

## 固定上下文同步计时

按[协议](PC_GPU_COST_PROFILE_DEV_PROTOCOL_20261106_CODEX.md)，对实际
重观测上下文 15、25、35、三个 solver seed 各测一次，先暖机。
下表为 9 次平均，非闭环端到端时间：

| 规划器 | 每次评分链 | 规划同步墙钟 ms | 编码 CUDA-event ms | 最大显存分配 MiB |
| --- | ---: | ---: | ---: | ---: |
| CEM 105×6 | 632 | 87.62 | 7.57 | 112.41 |
| 前缀 lookahead | 632 | 90.45 | 17.39 | 119.31 |
| CEM 300×10 | 3002 | 301.60 | 7.11 | 130.58 |
| CEM 300×30 | 9002 | 854.67 | 6.97 | 130.58 |

按实现，CEM 同一次求解重复使用输入字典中的初态和目标编码；
前缀版每次查询构造新字典。上述编码及模型时间嵌套于总时间，
不能相加。CUDA event 测的是含同步和流上等待的区间，不能称为
无间隙纯 kernel 时间；插桩和多次同步影响测量。此表不含模型
加载、CPU 图像处理、环境执行、反馈重规划、能耗或整任务视频和
日志，不是完整系统成本曲线；无效宣称正式等成本优效。

额外对三个上下文、各 16 条相同动作比较 CEM 同上下文字典缓存
与全新编码，代价及预测最大差为 0；重算与原存档成本最多差
9.16×10⁻⁵，原存档的 batch 尺寸不同。该有限检验仅适用于同上下文，
不允许跨重观测重用缓存。[逐项计时](../le-wm-main/results/pc_gpu_cost_profile_dev_20261106_codex.json)、
[缓存核查](../le-wm-main/results/pc_lewm_cache_equivalence_dev_20261106_codex.json)。

首次计时因缺少模型必需的 `action` 字段失败，补充会在 rollout
中被候选动作覆盖的占位键后重跑；首次编码对照因 HDF5 插件未注册
失败，注册后重跑。两次没有输出错误结论或覆盖旧结果。四组测试
共 11 项通过。PC0–PC5 及独立确认状态不变。
