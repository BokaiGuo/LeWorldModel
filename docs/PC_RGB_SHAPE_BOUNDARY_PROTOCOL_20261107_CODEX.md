# RGB 输入边界形状约束协议

为新的 RGB LeWM 运行提供版本化适配器，保留旧接口和旧证据。规划评分仅接收 `pixels`、`goal`、合法动作历史和候选动作：图像使用 `[batch, sample, history, 3, height, width]`，动作使用 `[batch, sample, time, packed_action]`。输入、目标和候选的 batch/sample 需兼容广播，历史/候选时钟与动作宽度需一致；图像必须为非空浮点 RGB 张量，动作须为浮点张量。允许空历史，不能以空历史自动注入额外状态。对 `encode` 单独使用 `[batch, history, 3, height, width]`。

先用明确反例验证非图像状态向量、隐藏字段、错位动作包和错误 batch 在调用模型前拒绝；再用同一冻结 LeWM、同一 RGB 上下文与候选，对旧、新边界核验输出和输入收据完全一致。运行前后验证权重指纹，日志需绑定协议和代码。这里限制的是张量结构与可见通道，**不能证明图像不含编码的真值，也不能对抗恶意 Python 调用方**；正式闭环仍须独立检验数据来源和权限。
