# 固定终点、同预测 token 的真实 RGB 反馈开发结果

按事前协议，四个已复用 PointMaze 根；两臂都在执行 15 个动作内的第 0/5/10 步获得真实 RGB，以剩余 15/10/5 步重规划，预测终点对齐同一最终执行时刻。旧计划未执行尾部在后续真实 RGB 下重评分并计费，若分数更好则保留。终距来自同 MuJoCo 2.1.2.14 后端对实际封存动作的独立重放。

| 开发根 | 目标谱臂最终物理距离 | 反馈 CEM 最终物理距离 |
|---:|---:|---:|
| 0 | 0.5942 | 0.1466 |
| 1 | 0.0819 | 0.0548 |
| 2 | 0.1956 | 0.4337 |
| 3 | 0.0357 | 0.1155 |
| 平均 | 0.2268 | 0.1877 |

两臂在每个决策均消耗 480 个五步预测 token；目标谱臂每次还做一次 SVD，CEM 无 SVD。目标谱臂在根 2、3 终距更小，CEM 在根 0、1 更小；四根是复用开发根，不能推断统计显著、独立成功率或 PC3 优势。目标谱臂最后 5 步均选中直接 CEM 而非谱候选；反馈 CEM 在两次决策保留了经新 RGB 重评分的旧尾部。完整执行记录保存每次候选及选中链，不能把非选中候选资格赋给派发动作。

已逐决策核验图片 hash、动作派发、旧尾部绑定、模型时域和费用上限；物理重放按同一动作、同一原始 reset 和同一 MuJoCo 版本进行。此重放核验保存 RGB 文件与执行决策的绑定，**未另行渲染并逐像素比较重放图像**。

相同 token 不等同全部计算相等：目标谱需响应差分和 SVD，两臂编码、预测调用及耗时分别记录，未认证总硬件成本公平；也未加入无谱、同库 greedy 或随机桥接。实现仍是开发候选生成器，非完整自动组合方法；该比较不能证明 PC2、PC3、谱增量或历史 P1 通过。
