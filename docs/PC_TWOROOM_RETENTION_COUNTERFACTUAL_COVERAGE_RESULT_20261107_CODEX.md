# TwoRoom 固定前缀保留：事后覆盖分解

在原四臂结果已知后，逐根重放全部 8 个前缀各自模型分数最低的精修链，共 **80 条、2,000 个物理步**。候选与模型分数沿用既有封存计划，没有以物理成功重新生成动作。

- 原 lookahead **6/10** 成功；将其与 8 条精修代表的真实成功取事后 oracle 并集，仍为 **6/10**。
- lookahead 失败的行 62735、82490、86996、168250 上，8 条代表链全部失败。因此本次未观察到“成功代表被前缀保留或最终选择丢弃”的实例。
- 80 条代表链中共 31 条曾成功；32 次与原四臂实际执行的是同一动作链，其逐步轨迹全部一致。数字按链计数，不是独立任务数。

这将下一步的优先问题收窄为：已有 **每前缀模型最优代表** 的真实覆盖不足，或者同一前缀其他已评分链存在成功但被模型评分漏掉。不能从这 80 条推断 2,880 条精修候选、初始候选或任务本身无解；真实参考链在这些任务上曾成功，也不意味着部署搜索可以使用参考动作。事后 oracle 使用全部前缀的额外计算与真实标签，不能作为规划器成绩。
