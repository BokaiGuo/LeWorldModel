# PointMaze 归档动作多步预测与物理精度诊断

## 窗口 1 与 2 的同轨迹比较

在八条已曝光归档轨迹上，先封存相同帧 0、完整 proprio 和动作
0–24 的两种窗口预测，再编码归档帧 5、10、15、20、25；没有用
未来编码选择动作。下表是各任务等权的视觉 token 均方误差：

| 环境步 | 窗口 1 | 窗口 2 | 沿用初始编码 | 窗口 2 更低的根数 |
| ---: | ---: | ---: | ---: | ---: |
| 5 | 0.02235 | 0.02235 | 0.11989 | 0/8（两者相同） |
| 10 | 0.04744 | 0.02998 | 0.14148 | 8/8 |
| 15 | 0.05672 | 0.04948 | 0.13110 | 7/8 |
| 20 | 0.05751 | 0.04543 | 0.12968 | 6/8 |
| 25 | 0.07963 | 0.06230 | 0.15344 | 7/8 |

首个预测包的视觉和 proprio 预测逐项相同。到 25 步，proprio
token 的任务平均 MSE 分别为窗口 1 的 0.00403、窗口 2 的 0.00226、
persistence 的 0.03275。第 10–25 步分别有 7、7、6、7 根窗口 2
的 proprio token 误差更低。

这支持在所用配置下继续使用并验证窗口 2；它是**同源归档实际动作**
的预测误差，不是未查询动作排序、真实反馈控制或统计独立性证据。
八根及模型均已曝光，本地 DINO 兼容实现也未认证为官方完整实现。

## 物理精度问题及修正

原评价使用 float32 初态与动作，7/8 根通过逐步 `1e-4` 状态误差
阈值；root 1891 在第 25 步达到 **1.3963e-4**，触发预定停止，
原评价未生成汇总。独立审计保留了全部八根及失败时刻，没有放宽
阈值或覆盖原失败。

对该根做原始／float32 初态和动作的二乘二重放：

| 物理初态 | 动作 | 最大状态误差 | 通过 `1e-4` |
| --- | --- | ---: | --- |
| 原始 float64 | 原始 float64 | 2.28e-7 | 是 |
| 原始 float64 | float32 | 2.35e-7 | 是 |
| float32 | 原始 float64 | 1.3956e-4 | 否 |
| float32 | float32 | 1.3963e-4 | 否 |

随后对全部八根使用归档 float64 物理初态及预测时已封存的
float32 动作，**8/8** 在原阈值内，最大误差 **1.006e-6**。这是
后验精度修正，不抹去原重放失败；预测器自身收到的初态仍为
float32，与物理初态最大初值差为 **2.29e-7**。

首轮预测程序还因 CPU 归一化统计与 GPU 动作混用而报错；在任何
预测写出前修正为 CPU 归一化后传入 GPU，并重新封存。相关测试
2/2 通过。`experiment-code` 用于预先固定对照、封存预测与分开
评价；不采用其要求实验结果必须为阳性的规则。

原始预测、完整八根评价、精度二乘二及全根重放记录分别使用
`le-wm-main/results/pc_pointmaze_archive_context_multistep_20261107_codex_*`、
`pc_pointmaze_archive_context_physics_failure_audit_20261107_codex.json`、
`pc_pointmaze_archive_precision_replay_20261107_codex.json`、
`pc_pointmaze_archive_native_state_replay_20261107_codex.json`。
所有结果仅属 **state-assisted**；PC0–PC5 不改判。
