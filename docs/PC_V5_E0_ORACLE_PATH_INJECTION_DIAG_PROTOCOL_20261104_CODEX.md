这是事后诊断，不改 v5、旧计划或科学阈值。使用已暴露 18 根和已保存的每根第一条解析见证。先重跑原 v5 并与封存的完整选择、候选库、保留序号和实际计数核对；不一致即终止。然后使用 Python 跟踪钩子，在 v5 进入完整链精修前调用其真实 `tracked` 一次，将好链作为额外完整链评分；这一调用计入 1920 token，因而精修预算自然减少。钩子仅触发一次，验证源文件和指定语句；检查精修起点、精修后、弃权及最终派发链，再经同一精确动力学重放。注入并非正常生成，也不测试真实 RGB。

脚本与协议、原始计划审计、见证及直接依赖哈希绑定，输出不可覆盖。明确区分真实调用路径、测试钩子和事后扩展库，不将见证计入方法成绩或独立确认。
