# TwoRoom RGB 规划进程边界：工程烟雾协议

使用 Python `spawn` 启动新的规划进程，环境、HDF5 状态及评价对象只在父进程创建和使用。模型进程按固定 checkpoint 加载冻结 LeWM，只从父进程接收 ImageNet 预处理之前的当前 RGB、目标 RGB、合法未执行旧尾、剩余时域、随机种子、预定策略及事先拟合的动作 normalizer 参数。跨进程请求键必须精确匹配白名单，图像、形状、类型、动作范围及其与时钟的一致性均须验证；不接受 state、proprio、contact、未来结果或任意附加字段。该进程不接收环境对象。这里只约束数据流，**不是操作系统级安全沙箱**；文件系统、环境变量和可信代码本身未隔离。

在已曝光任务 10、11 的真实 TwoRoom 环境反馈上，使用现有 `pc_rgb_hold_retention_search` 的 `lookahead`、相同种子和 25 步上限，每 5 步重编码真实当前 RGB，使用实际未执行尾部，重复规划直至成功或结束。与既有同算法、同种子、同初始条件的历史动作和物理轨迹逐轮比较；模型评分允许数值差 0.002，但最终动作须逐元素一致，物理距离允许 1e-4。工作进程应在关闭时再次报告冻结模型指纹。一次请求仍记录逻辑查询数与模型评分调用次数；启动与 IPC 总成本另记，单次运行不支持成本优势声明。

本实验仅为旧开发版本的进程边界与闭环等价烟雾，未测试新方法或独立任务，不能认证 PC4 收益，更不能将 state-assisted 结果提升到 RGB-only。
