# PushT 固定动作库的决策偏差：事后诊断

## 范围与方法

复用 [四根开发面板](PC_JEPA_MULTIR_ROOT_ACTION_EFFECT_DEV_RESULT_20261105_CODEX.md)已查询的每根 64 条动作及真实末态，不增加模型查询或改变规划器。分别选择预测评分最低、真实末帧编码评分最低、以及物理联合偏差最小的动作；最后一者是仅供评价的特权库内参照，不是合法规划器或全局最优。

物理位置采用原评估器对 agent 与物体四维位置的欧氏距离，角度采用 2π 周期最短角差。为便于定位选择差异，事后定义联合偏差 `max(四维位置距离 / 20, 周期角差 / (π/9))`，越小越接近两个阈值；这**不是官方连续指标**，不足以声明真实控制收益。表中动作索引是 0 起始。

| 根 | 预测评分选择：索引 / 联合偏差 | 真实编码评分选择：索引 / 联合偏差 | 物理库内参照：索引 / 联合偏差 | 库内成功数 / 64 |
|---:|---:|---:|---:|---:|
| 0 | 56 / 7.359 | 1 / 14.850 | 46 / 5.937 | 0 |
| 1 | 37 / 15.390 | 18 / 15.375 | 39 / 7.183 | 0 |
| 2 | 24 / 7.346 | 24 / 7.346 | 24 / 7.346 | 0 |
| 3 | 46 / 13.742 | 46 / 13.742 | 54 / 7.058 | 0 |

预测与真实编码评分在根 0、1 选中不同动作，在根 2、3 相同。真实编码评分选择在根 0、1、3 的事后联合偏差高于库内参照；根 2 恰好一致。这说明本库中评分与该物理诊断存在差异，但不能仅凭四根、一个事后指标或不可解的动作库判定根因。根 0 预测选择反而比真实编码选择的该指标更低，因此不能把预测—编码不一致一律解释为更差的物理选择。

四根都没有成功动作，也未证明目标在此时域可解：不能测定成功动作漏选率，不能将库内参照作为成功率 oracle，更不能把分析当作搜索或闭环实验。

## 发现的原评估器边界

原 `PushTWrapper.eval_state` 使用 `min(abs(Δ角), 2π-abs(Δ角))`。当原始角差超过 `2π` 时，第二项为负，可能错误地满足角度阈值。新增测试以合成角度重现此问题；本批 256 条的原始计算均无负角差，原规则和周期规则的成功结果一致，因此该缺陷**不能解释本批负结果**。尚未修改外部评估器或追溯变更历史成绩；后续正式评估应明确角度范围并单独修复、重测其影响。
