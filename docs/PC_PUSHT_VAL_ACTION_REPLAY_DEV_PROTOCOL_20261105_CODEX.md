# PushT 验证序列动作对齐与物理重放：开发协议

筛查得到的本地验证序列 9、11 作为开发样本，按文件原顺序固定，不声明来源独立。数据状态与相对动作的索引关系在执行前保持待检。

1. 对两个序列、每个有效动作索引，计算 `abs_action[t] - state[t,:2] - rel_action[t]`，报告坐标最大绝对误差及分位数；同时记录两个数据文件和状态文件哈希。该代数关系本身不能证明动力学时间对齐。
2. 用既有 JEPA-WMS 物理后端和已封存的 `T` 形状配置，分别从记录的状态、agent 速度在 `t=0` 和 `t=10` 重新初始化，执行 `rel_actions[t:25]/100`。比较重置状态与记录、每步预测状态与 `state[t+1]`、速度及周期角误差，保留所有帧。
3. 对 `t=10..24` 额外逐帧重置、执行一条相对动作，报告单步误差。不同模式均不使用真实动作进入规划器；本实验没有规划器。

固定数值描述而不事后阈值改判：记录 agent/物体位置欧氏误差、周期角绝对误差、agent 速度误差，报告首步、末步与最大值。源数据只保存 agent 速度；物体线速度、角速度、求解器接触缓存、数据生成后端及初始内部状态未知。当前环境的重置还执行一次 0.01 秒物理小步，故结果只能判断指定重置方式下的可重现性；单步失败不能单独确定动作索引、状态恢复或动力学哪个有错。数据和 checkpoint、normalizer、开发集独立性均为 unknown。

不改既有环境、不裁剪动作、不用这些数据作模型的独立确认；若因输入或物理失败，记录错误和已有原始结果，不跳过失败序列。
