# PointMaze 状态辅助编译器批处理结果

新增可选批处理适配器 `pc_fixed_prefix_state_batched_20261107_codex.py`；
原逐条适配器和历史结果不变。候选共享观察，但每条动作单独归一化、
以 `(模型时间, 候选批次, 10)` 打包，继续由同一共享搜索核进行
保留和选择，逻辑候选评分数不因批处理而减少。

依照 `PC_POINTMAZE_BATCHED_COMPILER_PARITY_PROTOCOL_20261107_CODEX.md`，
使用冻结 PointMaze JEPA、三个已曝光任务，每任务热身后各重复三次：

| 指标 | 结果 |
| --- | ---: |
| 分数最大绝对差 | 6.56e-6 |
| 保留前缀、最终候选及动作一致 | 各 9/9 |
| 每次逻辑候选评分 | 两臂均 11 |
| 每次底层预测调用 | 逐条 11；批处理 4 |
| 同步编译耗时中位数 | 逐条 0.329 秒；批处理 0.139 秒 |

批大小依次为 3、4、2、2。该耗时不包含模型加载、环境执行或完整
闭环；三次重复共享任务，不能当作九个独立任务。硬件及其余系统
负载不同可能改变结果，近并列任务亦可能受到 6.56e-6 数值差影响。
22 项单元测试通过，含四种保留规则和多个批大小的合成检查；真实
JEPA 只验证了 lookahead、一个保留前缀。初次测试错误地对浮点
代价要求逐位相等，已改为分别检查候选身份和 1e-5 容差。

模型权重前后指纹一致；逐次时间、分数误差、选择、批大小与输入
收据见 `le-wm-main/results/pc_pointmaze_batched_compiler_parity_20261107_codex.json`。
这是完整 proprio 的 **state-assisted** 单机工程结果，不是 RGB-only
结果、物理收益、正式成本曲线或 PC0–PC5 通过证据。
