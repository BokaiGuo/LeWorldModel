# 四结点机制求解器的已知可行前缀校准

预定协议：`PC_FOUR_KNOT_WITNESS_CALIBRATION_POSTHOC_PROTOCOL_20261104_CODEX.md`。16 个已暴露任务各取两条特权可行前缀，共 32 条；每次以零尾初始化四结点 CEM，初始评分 1 次、后续评分 480 次。独立重启累计预算如下，终距阈值 0.05：

| 每前缀完整链评分 | 检出前缀 | 平均最佳终距 |
|---:|---:|---:|
| 481 | 6/32 | 0.4151 |
| 962 | 9/32 | — |
| 1924 | 12/32 | 0.3177 |

协议写的是 `<= 0.05`；既有逐步 CEM 校准使用 `< 0.05`。本次没有恰好等于阈值的结果，因此两种计数均为 6、9、12，但未来比较应事前统一边界。成本分别包含每次重启的初始评分；不是模型之外全系统成本。四结点尾部可能无法表达见证尾部，因此“已知存在可行尾部”不等于“四结点族内必有可行尾部”。

全部 16 根完成，调用动作及输出逐批持久化；审计重放了优化器动作和分数，并以同环境另一几何实现核对端点与目标距离。审计通过不等于跨实现独立复现或 PC2 通过。这些结果不证明某个自动候选不可行，也不能作为等成本正式方法优势：任务及见证均已暴露且前缀是特权输入。原机制面板结果保持不变。

运行及审计：在 `le-wm-main` 分别执行 `.venv/bin/python -m experiments.pc_four_knot_witness_calibration_posthoc run` 和 `.venv/bin/python -m experiments.pc_four_knot_witness_calibration_posthoc audit`。运行器拒绝覆盖已存在目录，复现前需保留原始产物并将输出路径改为新路径。原始调用、结果与审计位于 `le-wm-main/results/pc_four_knot_witness_calibration_posthoc_20261104_codex/`。
