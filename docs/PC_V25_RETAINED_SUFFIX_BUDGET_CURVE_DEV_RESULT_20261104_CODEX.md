# 自动保留前缀：等预算重启曲线结果

对已封存的八根任务，原幅度和小幅度规划各自取实际 response 保留的四个自动首层前缀；两种初始化各按预定 2、4、8 次重启比较，共 32 个根×规划臂×初始化诊断完成。每个前缀、每次重启 121 个完整链样本，未使用特权前缀或尾部。

| 规划候选 | 尾部初始化 | 2 次：至少一个保留前缀成功的根 | 4 次 | 8 次 |
| --- | --- | ---: | ---: | ---: |
| 原幅度 | 零 | 0/8 | 0/8 | 0/8 |
| 原幅度 | 随机 | 0/8 | 1/8 | 1/8 |
| 小幅度 | 零 | 0/8 | 0/8 | 0/8 |
| 小幅度 | 随机 | 0/8 | 0/8 | 0/8 |

唯一成功出现在原幅度 root 0 的原保留候选索引 8；使用四次或八次随机初始化重启后可找到成功尾部。两次重启为每个前缀 242 样本，四次为 484，八次为 968；每根每规划臂完整八重启诊断使用 11,616 prediction-token。它们是**额外诊断成本**，不能算进原先每臂最多 1,920 token 的规划成绩。

所有保留索引、预测尝试和优化器提案经账本审计、确定性重放及另一同环境几何实现核对。结果表明在暴露开发面板上，较大预算和随机初始化能使一个自动保留前缀找到成功尾部；这不是事前选中的最终链机制、等总成本优势或独立复现，也不证明其他前缀不可行。
